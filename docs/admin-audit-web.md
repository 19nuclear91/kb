# 审计查询管理页面

入口为 `/admin/audits`，沿用用户端登录、强制改密与退出流程。当前账号必须具有精确的 `audit:read`；旧 `identity:audit:read`、角色名或写权限不代替该资格。空间目录读取失败不影响已确认的审计读取资格。

页面展示已记录的管理、本地登录和企业 SSO 登录／绑定事件。AI 调用审计和独立向量重建记录不在本页范围内；未查到事件不表示操作没有发生。

## 筛选与时间

常用条件为时间、结果和操作域，高级条件为操作、操作者 ID、目标类型与 ID、请求标识和本地登录用户名。条件按 AND 精确匹配，保留大小写和特殊字符，空字段省略。非空文本含首尾空白、控制字符或超长时提示错误，不静默修剪。

操作域和操作最多 128 个 Unicode 字符，目标类型 64，请求标识 256，用户名 128。ID 须为正整数且不超过 Long.MAX_VALUE；填写目标 ID 时须同时填写目标类型。未知但合法的操作域或类型仍可查询。本地登录用户名只匹配本地登录事件，与 SSO 操作域组合通常为空结果。

默认时间为服务端确定的最近 7 天。自定义时间按设备本地时区输入，必须同时填写两端，起点早于终点，跨度最多 31 天；起点包含、终点不包含。页面显示服务端实际窗口，时间显示格式不改变请求中的微秒精度。

## 继续读取与恢复

每次读取 20、50 或 100 条，按服务端顺序继续追加。页面显示已加载数量和本次实际时间范围，不提供总数或跳页。新事件不会改变已经确定的续页窗口；需要读取最近事件时使用刷新。

编辑筛选草稿不会自动查询，也不影响现有列表的继续读取。提交合法筛选、改变每次条数或刷新会关闭详情并重新开始；刷新使用已提交条件，默认范围重新定界，自定义范围保留。重置恢复最近 7 天和每次 20 条。

续页暂时失败保留已确认部分，手动重试沿用失败页游标，成功后只追加一次。参数或游标失效时重新查询。列表或详情收到 403 时立即清理整页资料和筛选，再有界核对当前权限；清理不等待身份核对或错误响应体取消。即便核对结果仍显示有资格，也不会自动循环读取，需要显式重试。空间目录的加载、清空、恢复或故障不解除拒绝，也不重置正常查询及筛选草稿；真正的权限事实或身份代次变化可重新确认后恢复。401 沿用既有登录恢复。

## 事件详情与资料隔离

点击事件打开详情抽屉，按该事件 UUID 读取元数据及字段前后变化。摘要不可用时保留元数据并明确提示；摘要可用但变化为空时显示“无可展示变更”。详情 404 只清理该详情，不把整页列表解释为空。切换事件、关闭抽屉或刷新时，旧响应不能恢复旧内容。

事件和主体 ID、版本及计数完整显示，超过 JavaScript 安全整数范围也不舍入。`false`、`0`、空字符串和 `null` 分别展示，未记录的操作者或目标保持“未记录”，不猜测为系统用户。未知代码与 HTML 标记都按文本展示。页面不联查账号、角色、空间或文档名称。

筛选、列表、时间窗口、游标和详情仅保留在当前页面内存，不写入页面地址、浏览器存储或遥测。进入后台、退出、强制改密、切换身份或失去资格后清理资料；恢复时先确认身份和权限，再使用最近 7 天默认条件重新读取。

## 部署与回退

使用现有 `kb-web` 静态托管和 SPA 回退。登录后的安全返回路径只接受精确 `/admin/audits`，不携带筛选。页面使用已有后端 GET API，不需要新增数据库迁移或权限 code；需要的角色通过既有管理流程获得 `audit:read`，前端不自动授权。

回退时恢复前一版静态产物；审计数据和原权限绑定保持原状。认证与审计 API 继续使用 no-store；代理日志沿用现有敏感参数保护约定。
