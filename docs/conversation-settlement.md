# 轮次账本与恢复

新轮次按领取时服务器解析的当前部门计请求、并发与 token 配额。稳定 leaseId/eventId、部门与预留必须在模型调度前由 app 确认，才允许
dispatch；重放不再次领取。领取结果不确定时禁止调用模型，不更换 ID 自动再领，遗留租约由 TTL 清理。

生成终态与结算状态独立。配额关联初始 RESERVED；终态事务固定 usage、chargedTokens、generationStatus、intentDigest，进入
PENDING。AI 尝试结算并向 app ack，确认 SETTLED 后才能发送 done；失败发送通用 error，完整保存的生成状态保持
COMPLETED。生成失败/取消仍诚实结算已发生的使用。

Redis 固定意图脚本将并发释放、预留转费用及租约摘要标记一并处理。相同 ID/摘要重复返回已确认，不同意图拒绝；审计按固定 eventId
和摘要单独去重，仅保存账本元数据。账本成功而审计失败时，重试相同意图补审计，不重复扣费。Lua 仅人工审查，本次未执行。

app 调度器按有限批次 SKIP LOCKED 领取 PENDING，网络投递在领取事务外。回写按领取期限及 attempts 做条件更新，旧领取者不能覆盖新领取。失败指数退避上限
300 秒；默认自动重试窗口 3600 秒，去重保留 86400 秒。超过安全重试期转 REVIEW 并停止自动投递，不能等标记过期后换身份扣费。

纯结算与 ack 不依赖原用户令牌，因此自然过期、停用或删除后仍可清理原账本；不能读取正文或启动模型。删除只清敏感正文，保留最小固定意图。Redis
灾难性丢失后需人工核对，不保证跨此类故障恰好一次。

账号撤销不延长 AI 输出许可，收尾和账本失败不能让输出恢复。明确撤销使用 CANCELLED/ACCOUNT_REVOKED；未派发保持 NOT_INVOKED，已派发且无可靠最终用量保持 UNKNOWN 并沿用预留额度结算，不伪造零用量。身份依赖无法确认按 FAILED 或过期恢复处理，不伪报离职。

输出已经停止时不再尝试把缓冲正文追加为新的已保存批次，只保留服务端确认的前缀。取消写入暂不可用时，原轮次及配额关联仍持久存在；租约到期恢复检查原认证代次，即使用户后来复职，新代次也不能复活旧执行。恢复后生成原固定账本意图，继续幂等释放和结算。已合法完成的终态不会改写为取消。
