# 权限诊断发布与回退

`authorization:diagnose` 是独立的功能资格。可在现有角色权限配置中绑定普通角色；持有者仍需当前目标空间的 manage 或 `space:manage-all`。包含 manage 的预演再要求 `space:grant-manage`。新资格不赋予文档阅读、身份目录查询或实际授权能力，角色名称不参与推导。

V43 仅在 Flyway 首次执行时给既有 `ROLE_ADMIN` 绑定新权限；新建管理员角色的正式引导从 `Permission.codes()` 取完整目录。已存在角色的引导只告警缺项，不补回主动撤权。撤销所有角色中的该权限后，下一次请求按新事实拒绝。重新构造组件或重启不会恢复撤权。

发布前排空旧 app 实例，再由支持新目录的版本执行 V43。旧版 `RolePermissionValidator` 遇到未知持久 code 会拒绝启动，滚动混跑不能被视为兼容方案。前端须与新契约版本配套，未确认诊断及资源资格时不加载诊断数据。

回退优先使用保留 `authorization:diagnose` 目录识别、关闭诊断入口的兼容版本。不要为回退直接删除角色绑定或篡改 Flyway 历史；需要修改角色资格时使用原角色管理流程并保留审计。任何旧版本重新上线前，须人工核对其目录与当前持久 code 是否兼容。

本次交付迁移文件和操作方案，未执行部署或数据库迁移。内存替身回归覆盖新角色引导、撤权与重新构造组件；这些结果不证明真实数据库迁移或部署行为。
