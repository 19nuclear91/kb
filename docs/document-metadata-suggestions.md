# AI 辅助整理文档资料

## 编辑资料

在文档详情打开「编辑资料」，点击「根据当前发布版本生成建议」。即使详情正在展示历史文件，整理的来源也是当前发布版本。依据处显示版本、实际章节、页码或结构块。可逐项采用标题、摘要、分类，继续手工修订并保存。没有合适分类时保留现值，标签由编辑者维护。

输入超过单次上限时，整理在调用模型前结束。模型输出超限时，页面会单独提示；若供应商已返回可靠的最终用量，本次按实结算。无发布版本、缺少快照、解析截断、额度不足和服务故障也会分别提示。

建议默认保留 30 分钟。点击「重新读取资料」会刷新当前发布版本，并按原请求核对已采用的建议。核对通过后可直接保存手工修订过的草稿。若暂时无法核对，可稍后点击「核对原请求」。读取资料、分类或标签时发现编辑资格失效，编辑器会清除草稿和建议。

若整理仍在运行或生成回执尚未收到，重读资料后仍可查询或取消原请求。生成时遇到「请求过于频繁」，可稍后核对原请求或按原标识重试。若原请求尚未查到且来源和资料版本一致，也可按原标识重试。生成已结束但结算仍待确认时，重读也会查询原请求，之后可点击「核对原请求」查看已扣金额或待核查状态。

来源或资料版本变化后，原请求返回的建议无法采用。点击「舍弃已采用的建议并恢复手工草稿」可恢复采用前的手工值，继续编辑或基于当前版本重新生成。重新生成会发起一次新的调用。显式取消后以服务端查询结果为准。

## 启用与预算

启用前须由 `kb-app` 完成 [V41 迁移](../kb-app/src/main/resources/db/migration/V41__document_metadata_suggestions.sql)，建立整理请求、短期结果和审计事件三张表。文档的当前发布版本须有完整、未截断的结构快照。

在 kb-app 和 kb-ai 设置 `KB_METADATA_SUGGESTIONS_ENABLED=true`，两端配置相同的专用 `KB_METADATA_SUGGESTIONS_SECRET`（至少 32 个字符）。app 通过 `KB_AI_BASE_URL` 访问 AI，AI 通过 `KB_APP_BASE_URL` 回查 app，仅服务间可以访问内部路径。开关默认关闭。执行中仅在内存传递起始会话，模型侧仅收到模型凭据及拟发送的消息。

AI 使用显式启用的 `kb.ai.chat-model` 内置模型配置。严格预算要求模型地址、模型名及格式 `kb-document-metadata-v1` 匹配专用计数策略。估算须显式配置 `kb.ai.chat-model.budget.mode=estimated`、窗口及安全余量。上限同时受模型窗口、单请求预留上限、输出上限和编码后的字节限制约束。完整快照、表格、可选路径、系统指令和包装一起计数，无法一次发送时整次结束。

## 审计、恢复与停用

按 `request_id` 查询 `kb_document_metadata_suggestion` 和其事件表。生成终态与配额收尾分别显示。未登记发送意图的 `NOT_INVOKED` 应扣零，有可靠统计的 `KNOWN` 按输入与输出之和扣除（含零），`UNKNOWN` 的实际数为空，按预留额计划扣除。

尚未发起配额预留时，收尾状态为 `NOT_REQUIRED`。已发起预留时，`PENDING` 会重试原结算。有额度拒绝凭据可以确认零扣费，有预留凭据可以释放预留并确认扣费。凭据过期、缺失或不匹配时，即使计划扣零也会进入 `REVIEW`，需核对事件、原租约及部门账本。页面仅在 `SETTLED` 时显示已确认的扣费金额。短期结果表受有效期约束，运行审计仅记录身份和额度事实。

停用时先关闭 app 新请求，保持两端内部地址、认证密钥和 Redis 账本可用，等待在途请求终结及结算。AI 的开关关闭后仍接收原结算请求。默认执行期限两分钟，建议有效期由 `kb.metadata-suggestions.result-ttl-minutes` 控制。

## 公开协议

集合路径为 `/api/documents/{id}/metadata-suggestions`。接口沿用当前登录、查看、编辑和固定版本阅读资格，并返回 `Cache-Control: no-store`。

| 操作 | 请求 | 结果 |
| --- | --- | --- |
| 生成 | POST 集合，`X-Request-Id` 为 UUID，JSON 含 `sourceVersionId`、`expectedMetadataVersion` | 执行中为 202，原标识重试只返回原状态 |
| 查询 | GET 集合下的 `/{requestId}` | 返回请求身份、来源、生成状态、原因和独立结算事实；可用的成功结果附建议及 `expiresAt` |
| 取消 | POST 集合下的 `/{requestId}/cancel` | 返回胜出的终态；已完成与已取消分别展示 |
| 保存 | PUT 集合下的 `/{requestId}/metadata`，独立保存标识、完整资料表单与 `adoptedFields` | 返回最小资料回执；匹配重试重新鉴权后可核对原回执 |

无效输入为 400，会话及资格拒绝沿用 401、403、404。初次请求的来源或资料冲突为 409。若部署方另设入口限流，其 HTTP 429 表示请求在受理前受到限制。部门额度在受理后检查，额度不足时 GET 返回 HTTP 200，响应中为 `status=REJECTED`、`reasonCode=QUOTA_REJECTED`。查询接口自身不可用时返回 503。
