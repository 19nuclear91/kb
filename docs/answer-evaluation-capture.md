# AI 测试采集

采集只用于专用测试部署，默认关闭，不增加公开导出 API。实际材料仍只能来自原授权检索流程，测试登记不提供任何业务授权。

## 配置与部署

配置项：

| 配置 | 含义 |
| --- | --- |
| kb.ai.evaluation.enabled | 默认 false，显式 true 才启用 |
| kb.ai.evaluation.instance-id | 测试实例逻辑标识，必须匹配登记 |
| kb.ai.evaluation.allowed-users | 允许的正整数用户 ID，逗号分隔 |
| kb.ai.evaluation.directory | 本地受控共享目录，拒绝网络 URI、UNC 和链接跳转 |

启用时必须同时提供后三项；prod profile 强制拒绝开启。配置错误仅返回固定诊断。关闭时不访问采集目录，也不解析其中的正文。

首期只支持单个 AI 测试实例和串行运行器。测试 gateway、app、数据库、模型配置及语料应是专用资源；同机目录或容器挂载目录只允许 AI 与运行器服务账号访问。配置标识和用户白名单不能证明物理隔离。模型必须使用内置文本适配器；自定义适配器标记 UNSUPPORTED，不用编排前材料伪装实际输入。

AI 依赖 `kb-answer-eval` 的普通 Java JAR，复用文件契约、摘要和路径校验；可执行工具另附 `-cli.jar`。工具本身不依赖业务 Spring 容器或数据库。

## 本地交换与身份

运行器先预检全部用户，创建每例独立会话后，发布冻结的数据集和登记。目录中的 `registrations/<userId>-<conversationId>.json` 绑定数据集摘要、runId、caseId、attemptId、targetId、instanceId、用户、会话、第一轮序号 0、问题摘要、到期时间及随机 artifactKey。

AI 仅在可信 begin 结果为首轮 turnSeq=1、非重放、用户获准时尝试匹配；取 userId、authEpoch、conversationId、turnId 自服务端执行，不保存执行票据。登记读取在独立有界线程执行，超时或失败只丢失评测证据。原请求的许可和取消机制仍控制业务流。

`claims/<attemptId>.json` 通过不覆盖创建持有一次登记，防止并发轮次及重启后重用；文件不会自动删除。内存索引最多 1,000 项，同时保留最多 4 个活动采集会话，到期或完成后释放活动状态。

`captures/<artifactKey>/input.json` 保存最终消息、实际材料、模型阶段和业务阶段，目录完成清单 `complete.json` 绑定文件摘要。来源不符合审定范围时只发布无正文的 `failure.json`。缺少目录或完整清单代表采集不完整，不能根据暂存文件补造成功。

## 采集边界

输入只在最终预算通过、实际请求编码完成后取得，使用同一编码字节计算请求摘要。预算计数阶段不采集。模型阶段 INPUT_READY、REQUEST_SUBSCRIBED、MODEL_COMPLETED、MODEL_FAILED、CANCELLED 与业务保存、结算阶段分别记录。订阅不证明供应商已接受或停止计费。

解码输出只累计摘要和 code point 数，不另存一份原始回答；正常最终 usage 缺失时保持未知。NO_RESULTS 不伪造模型输入或用量。模型已结束而业务保存失败、结算待确认时，不产生完整成功的评测事实。

文件写入使用独立线程、有界队列；最多接纳 4 份待写记录、32 MiB 队列正文，单例快照最多 8 MiB，存储容量上限 2 GiB。启用时将已有受控目录占用计入容量，失败预留保守保留。队列满、超限或写盘失败只使此次证据不完整，不等待写入结束来撤销输出许可，不增加模型订阅。

目录由可信服务账号共同持有，不是抵御拥有该目录写权限者的签名系统。路径及原目标逐次核对，发布不覆盖；Windows 无 fileKey 时以创建时间辅助检测替换，链接和根目录边界仍独立核对。

## 关闭与回退

停止发起新评测，按原业务机制取消在途请求并等待收尾，再将 enabled 设为 false 并更新 AI 实例。既有业务终态、配额结算和已发布文件不因关闭而回滚。

保存与清理由运行方根据明确运行清单安排；清理登记、claims、正文快照前先停止相关运行，确认绝对路径和保留期。工具不自动删除业务会话或原件。离线副本不会随线上撤权自动撤回，旧证据的正文、审批版本或摘要发生变化后，原初评与复核绑定失效。

本次仅验证离线组件与依赖 mock，真实部署、网络联调和供应商兼容性未验证。
