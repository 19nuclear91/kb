# 批量文档导入运维

## 受理与处理阶段

`ACCEPTED` 表示原件已写入，文档、首个版本、持久解析任务及固定回执已一并保存；不代表解析完成、审核通过、已发布或可检索。解析器未配置时允许受理并保持现有排队状态。

当前文档或版本是否可读、可下载，由现有文档接口独立鉴权。原文件项的历史回执不随文档删除、搬迁或解析失败改变，也不能用于复活文档。

## 故障核对顺序

1. 核对当前账号及认证代次，再读取本人任务和项。无权限时只保留允许的最小历史，依赖故障不能当作空任务。
2. 创建响应未知时，使用原 `X-Request-Id` 调用只读 resolve；未查得不证明原请求取消。主动匹配重试必须保留原清单和请求标识，不新建替代批次。
3. 项响应未知时，先读单项状态。`ACCEPTED` 使用固定三元组；`PROCESSING` 等待核对；可恢复 `FAILED` 或 `PENDING` 由用户重新选文件并主动继续。
4. 新尝试必须使用最新 revision、新请求标识以及原文件名、大小、摘要匹配的完整文件。旧尝试标识不能重新领取，409 后重新读取，不循环重发。
5. 同名同大小但内容不同属于新意图。格式不合法或超限的固定项需要新的正确清单，不能修改原项。

已成功项不因其他项失败被回滚。不同项和新批次允许同名同内容的新文档，避免误把主动重复导入当作幂等重放。

## 原件残留与结果未知

- 每次尝试都有独立 `documents/imports/` 对象键；失败恢复不会复用旧键，迟到旧 PUT 不会覆盖新原件。
- 在最终受理事务开始前，内容检查或存储调用确定失败会通过独立事务持久失效。若失效记录本身未确认，仍按待核对处理。
- 一旦进入最终受理，异常不证明事务未提交。批量路径不直接删除原件，也不把该异常写成 FAILED。
- ACTIVE 尝试在持久失效前保护原件，即使租约时间已过。恢复只撤销执行资格，不依据对象存在自动创建文档，不自动读取用户本地文件。
- 失败或失效的残留原件交由对象对账按宽限期回收；禁止直接按文件名、摘要或“请求已超时”手动批量删除。
- SDK 调用使用既有 `kb.storage` 桶与凭据；导入 PUT 不自动创建桶，部署时需保证该桶已存在并可写。导入专用客户端没有自动重试，旧单文件存储行为保持其既有配置。

## 离线证据范围

本变更测试只使用进程内 Mock、事务/仓储/SDK/流替身和模拟 DOM。事务代理加入、回滚分支、调用顺序及取消信号均属于离线证据，不等同于真实数据库隔离、网络终止或部署验收。文档采用人工审阅，不以文档内容断言作为验证结果。

## 容量与时间预算

公开能力来自实际配置；默认每批 100 项、1 GiB，单文件沿用 `kb.storage.max-upload-bytes`。每实例实际处理上限 8、每用户每实例 2，multipart 解析之前进行身份和容量检查，无等待队列。429 表示上传繁忙，用户主动稍后继续。多实例总容量随实例数增长。

数据库尝试期限默认 120 秒、最大 120 秒，不续租。导入 SDK 完整调用默认 60 秒，不超过本次剩余预算；连接与连接池获取最多 5 秒且不超过存储预算。所有 SDK 阶段共享完整调用期限，文件读取检查单调时钟和线程中断。最终受理仍检查数据库时间、ACTIVE 状态和执行代次。

网关导入响应等待配置为 150 秒，前端逐项请求等待为 180 秒；二者必须大于尝试预算，并预留接收及数据库处理余量。网关响应等待不是上传请求体的总传输期限。部署反向代理必须另行限定入站体传输、空闲连接及请求体大小；Servlet multipart 临时文件需要受限磁盘和清理策略。

响应超时或浏览器取消不能证明 SDK 已退出。导入使用同步请求线程，校验、存储和最终事务实际退出后才释放一次本地容量；不以响应 committed、HTTP 超时或前端取消触发提前释放。故障测试中的响应已提交屏障验证的仅是此本地占用语义。

进程退出后，本地占用随进程消失，但持久 ACTIVE 仍保护对象。恢复每 30 秒扫描最多 100 项，短事务按项 `SKIP LOCKED` 竞争并重核数据库截止。先检查恢复调度是否运行及数据库是否可用，再核对项是否已 ACCEPTED；到期但尚未持久失效的对象仍不可删除。恢复失败只记录固定诊断类别，下一轮继续核对。恢复不要求用户在线、解析器可用或 AI 开关开启。

## 对账、升级与回退

清理保护为未软删除文档的全部版本键与 ACTIVE 尝试键的并集。扫描、删除前复核、空集合保护检查都读取该并集，缺失 HEAD 仅抽样已建立的版本。过期不等于失效；历史 ACCEPTED 也不等于原件永久保留。

1. 发布前在全部 app 实例关闭 `KB_STORAGE_RECONCILIATION_DELETE_ENABLED`，确认旧删除扫描已退出。
2. 由 app 执行 V36 增量迁移；旧文档无需回填。升级全部 app，使新导入、恢复和联合保护查询同时就绪。
3. 核对全部实例版本后恢复原删除配置，再按 app → gateway → web 顺序开放入口。禁止旧 app 删除扫描与新导入混跑。
4. 回退先隐藏入口并停止新上传，等待实际执行退出或持久失效；保留三张账本表和全部回执。不得通过删除导入历史“重置”幂等。
5. 回退旧 app 时持续关闭对象删除，直到重新部署理解 ACTIVE 保护的版本。历史任务暂不可查询时不引导用户自动建新批次。

清理失败的原件以及迟到旧 PUT 重新出现的对象，在没有版本／ACTIVE 保护且超过宽限期后由后续扫描回收。对账不会把“桶里存在对象”解释为应自动受理，也不会删除幂等历史。详见 [对账运维](storage-reconciliation-operations.md)。

## 配置模板与临时文件

`kb-app/application.yml` 已提供全部 `kb.document-import` 模板，对应环境变量依次为 `KB_IMPORT_MAX_ITEMS`、`KB_IMPORT_MAX_TOTAL_BYTES`、`KB_IMPORT_MAX_CONCURRENT`、`KB_IMPORT_MAX_CONCURRENT_PER_USER`、`KB_IMPORT_ATTEMPT_TIMEOUT_SECONDS`、`KB_IMPORT_STORAGE_TIMEOUT_SECONDS`、`KB_IMPORT_RECOVERY_INTERVAL_MS`、`KB_IMPORT_RECOVERY_BATCH_SIZE`。具体默认值和范围见 API 说明。

单文件配置同时设置 `KB_MAX_UPLOAD_SIZE`（默认 `50MB`）与 `KB_MAX_UPLOAD_BYTES`（默认 `52428800`），两者必须等值；`KB_MAX_UPLOAD_REQUEST_SIZE` 默认 `51MB`，为 multipart 封装预留 1 MiB，允许额外开销 64 KiB–1 MiB。关系不合法阻止启动。`file-size-threshold=0B` 让文件直接使用临时磁盘，避免并发文件在堆内聚合。

`KB_UPLOAD_TEMP_DIRECTORY` 可设置容器可写的独立临时卷；留空使用 Servlet 容器临时目录。按每实例最大并发 × 请求上限预留磁盘并设置卷配额、运行用户隔离和退出清理，默认导入路径上界约 8 × 51 MiB，既有其他上传路径另计。网关不聚合完整文件。反向代理入站总期限、读空闲期限和请求体限额应独立配置；150 秒网关等待／180 秒前端等待不能代替慢请求体限时。

## 浏览器恢复与权限变化

`/imports` 和 `/imports/:importId` 只查询本人任务，跨刷新、登录保留记录；浏览器没有持久化清单或 File 缓存。新页面先核对身份，逐页读取摘要及文件项。原件未传完时需重新选择对应项的完整文件，匹配名称／大小／摘要后再主动继续，不支持字节级断点续传。

隐藏、切页、退出或换号立即停止本地调度、摘要和核对，清除私有显示与文件引用；服务器事实可能继续变化。当前会话恢复后只读当前任务，绝不据旧 File 自动发送。上传资格丧失会隐藏原清单，账号有效时仍能读取最小受理回执；写资格与固定版本的阅读资格独立。

页面对待确认项每 3 秒读取一次，连续故障 3 次或单次窗口 3 分钟后停止，允许手动刷新。429 暂停上传并提示实例／用户容量，不倒计时自动重试。403/401 暂停并重核资格。旧服务返回 404/405 时明确提示不可访问或不支持，不回退为循环调用单文件上传。
