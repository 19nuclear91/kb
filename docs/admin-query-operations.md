# 管理查询公共协议与升级说明

新增查询均通过既有网关 `/api/admin/**`、`/api/auth/**` 路由访问，使用 `satoken` 会话。身份来自服务端，用户/主部门停用和强制改密均拒绝；旧用户数组列表与
`/api/auth/me` 结构不变。

## 查询协议

响应沿用 `R<T>`；分页 data 为 `items`、`hasMore`、`nextCursor`，不提供全局总数。limit 默认 20、范围 1–100。同一查询可调整合法
limit；改变目标或筛选条件须重新从第一页读取。游标不是授权凭据，每次重新判定资格。新接口不接受未知、重复、空参数；文本关键词按
Unicode code point 限长，LIKE 特殊字符按字面匹配。

审计分页另返回实际生效的
from/to；默认时间窗口写入游标，续页不会随当前时间漂移。完整入口与投影说明见 [后端管理查询接口](admin-query-api.md)。

成功及失败响应均为 `Cache-Control: no-store`。HTTP 400 表示参数无效，401 表示无有效会话，403 表示资格或主体状态拒绝，404
表示目标不存在或不可访问，503 表示依赖暂不可用；不将依赖故障伪装为空结果。错误内容不回显筛选值、SQL 或原始异常。

## 权限与兼容

新增 `audit:read` 保护全局管理/登录审计，`identity:external:read` 保护外部身份绑定查询。旧 `identity:audit:read` 和
`identity:external:write` 不自动蕴含新读取资格。其他管理资格、空间 manage 和 ROLE_ADMIN 名称也不能替代精确权限绑定。

V19 只向迁移时已有 ROLE_ADMIN 一次性绑定两项权限；首次正式引导的新角色纳入完整目录。既有角色明确撤权后，重启或重复引导不补回。其他角色通过现有角色权限接口显式授予。

新权限入库后，不认识新目录的旧 app 仍会按既有未知权限检查拒绝启动。部署说明要求排空旧 app 后由新 app
单点迁移，不得混部或直接回退旧目录二进制；不自动删除绑定或修改 Flyway 历史。本次只交付迁移文件，不执行迁移、部署、重启或回退。

源码中的迁移顺序为 V18 后接 V19。V19 仅增加两项权限绑定、查询索引及安全 username
提取函数，不改历史迁移、原审计载荷或业务记录。既有用户部门单列索引、文档空间/状态索引、审计 actor/target
时间索引与新增复合排序索引不等价。username 查询和部分索引共用 `kb_audit_login_username`，只接受长度 1–128 的 JSON 字符串，其余产生
null；不做异常字符串数值转换。索引创建使用普通 Flyway 事务内 DDL，可能带来锁等待，需要部署窗口；本次未测量建索引时间和查询性能。
