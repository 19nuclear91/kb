# 知识订阅协调发布

V45及新app/Worker必须协调升级。提交时约束要求每次新正式发布的版本证据、VERSION_PUBLISHED事件及订阅上下文同事务提交，旧发布写入代码会被拒绝。迁移尚未在本次实施中执行，以下为发布说明。

变更已于2026-11-27同步8份主规格并[归档](../openspec/changes/archive/2026-11-27-knowledge-subscriptions-and-digests/archive-record.md)。归档仅完成研发流程收尾，下列迁移与部署步骤尚未执行。

## 顺序

1. 暂停涉及发布的写入并排空旧app、Worker在途事务；准备保留V45结构和协议的兼容回退版本。
2. 由app单点执行V45迁移并升级全部app，登记覆盖起点；消费者可先关闭，正式发布仍必须保存上下文。
3. 升级全部Worker。启动检查必须确认order/capture函数、表及协议版本1，Worker不执行迁移、不匹配订阅者。
4. 三条发布入口全部升级后恢复发布写入，依次升级gateway和web。gateway显式把四组业务路径路由到app，继续执行会话、认证代次和强制改密门禁。
5. 需要派生提醒时，确保 `KB_NOTIFICATION_DERIVATION_ENABLED` 与 `KB_KNOWLEDGE_SUBSCRIPTIONS_DERIVATION_ENABLED` 同时为true。查看快照可用性、匹配/周周期/提醒积压及失败，不以零通知推断任务已完成。

## 兼容范围

缺省通知合同只返回原审核/评论四类；KNOWLEDGE_GAPS_V1增加原问题类型；KNOWLEDGE_SUBSCRIPTIONS_V1再增加订阅发布与周报。三档的游标不可混用。新web统一声明第三档且不自动降级，旧客户端维持原类型与计数。标记已读仍只按本人通知身份执行。

新来源不复制旧收件箱行，不改变旧UUID、内部顺序、创建时间或首次已读；不重开旧协作DONE。覆盖起点以前的发布不回填；迟到发现的新协议发布仍按原归属、频率、代次和业务周处理。

## 止损与恢复

先撤下新web，再关闭新订阅派生。既有审核/评论/问题消费者可继续运行；关闭总开关会同时暂停所有提醒派生。保留关系、代次、频率历史、原命令回执、发布上下文、进度、终态和通知。

后端和Worker只能回退到理解V45发布协议的兼容版本。不得删列、删除迁移历史、Flyway repair掩盖失败、修改dispatchPosition或重开DONE/NOTIFIED/NO_ELIGIBLE。恢复开关后按持久游标和原周期继续，已确认取消的原代次仍不具备待提醒资格。
