# 生命周期协调发布与止损

此变更同时涉及 app、gateway、AI、Web、数据库迁移及告警通知器。必须把认证代次门禁、内部签名协议和 AI 输出许可作为一个兼容边界发布，旧节点与新节点混跑不能保证离职撤销。下面是发布操作方案，本次编码未执行部署或数据库迁移。

## 发布前准备

- 交付并评审新增迁移 V29–V35：人工启用状态/认证代次、生命周期登记与证明/回执、Inbox/逐项状态/会话清理、四项权限目录和存量管理员一次性绑定、员工项稳定游标/解决标记、轮次执行认证代次与取消原因，以及接收/撤销/本地停止证据。保留既有迁移原文；存量 `manual_enabled` 从原 `enabled` 回填，历史轮次没有可信代次，旧事件没有提交观测，不伪造回填。
- 准备数据库备份、所有服务一致的新制品、前端构建和九类新增固定告警目录；新增 ROLE_ADMIN 权限属于一次性迁移，运行期不会自动补回管理员后来撤销的权限。AI 要求内部检查返回主库 checkedAt 锚点，app 同时提供独立签名的停止证据接口，不能与旧 app 混部。
- app、gateway、AI 配置同一独立 `KB_AUTH_INTERNAL_SECRET`（至少 32 UTF-8 字节）；gateway/AI 的 `KB_APP_BASE_URL` 指向固定内部 app。沿用独立的轮次协议秘密，不能混用。内部认证接口只允许受控服务访问，不通过公网路由暴露。
- 钉钉生命周期订阅保持默认关闭，先配好同企业内部应用、准确统一应用 ID、权限与可见范围。秘密通过既有秘密配置渠道交付，不能写入仓库、构建日志或工单正文。

## 切换顺序

1. 暂停新增登录/生成和管理写入入口，排空旧 app/gateway/AI 节点以及在途 SSE、轮次生成、Office 预览连接和后台旧写入。超时无法排空时主动终止并保留已有确认前缀及结算意图；从流量与内部调用路径移除旧节点，不能仅移除网关而留下可直连 AI。
2. 在受控维护窗口执行 V29–V35，核对迁移结果和存量状态回填。迁移前旧节点必须停止相关读写，避免新列回填后旧二进制继续直接改 enabled 或写缺少认证代次的轮次。
3. 部署新 app/gateway/AI 并核对内部签名协议和执行 key 的 `authEpoch` 兼容。重启后旧历史轮次不具备可信代次，应按既有过期恢复进入中断收尾；没有代次的 token 一律重新登录，不可在读取时补写代次使其复活。
4. 发布新 Web 和同步的监控规则、告警目录、通知器。只在新协议节点就绪后恢复受保护流量。内部认证不可用必须保持 503/失败关闭，不能临时绕过检查或使用用户声明头兜底。
5. 由独立候选本人本地登录、完成初始改密并登记应急保障，读取当前合格状态；再核对受管覆盖并逐步纳管员工。纳管提交会检查历史未解决事件，可能立即停用目标，确认时应核对最终状态。
6. 应急与覆盖准备就绪后再显式启用钉钉订阅。启动和重连会复核保障；无合格应急管理员应拒绝接收启用。随后依据管理页和独立监控读取连接、接收、逐项处置、AI 停止及清理结果。

原本有密码的本地员工和 SSO 员工都需要新会话。用户完成复职后也必须重新登录；不能通过重新启用旧会话、用户全量注销或批量重设认证代次处理切换问题。内部秘密只有单一当前值，轮换应协调调用双方，期间允许失败关闭，不承诺无缝双密钥切换。

## 止损边界

| 情况 | 可采取的止损动作 | 必须继续保留的事实与行为 |
| --- | --- | --- |
| 平台事件持续异常或接入配置错误 | 关闭新的 Stream 接收，修正固定配置并调查原记录 | 已有生命周期限制、认证代次门禁、原事件/冲突/恢复边界和系统审计。 |
| app/Redis/内部认证依赖故障 | 隔离故障节点，保持 503；修复后恢复原请求及持久任务 | 旧会话永不恢复；清理按原撤销代次重试，新会话不可被迟到清理误注销。 |
| AI 调度或输出许可异常 | 停止新生成并排空/隔离故障 AI 节点 | 已确认回答前缀、受限取消/失败收尾、固定结算意图和恢复任务；不能为了结束回答放行成功终态。 |
| 错误纳管或迟到事件 | 保持限制，核对准确员工、当前成员及事件边界，再按受权流程复职 | 不直接删映射、改 enabled、清 Inbox 或改小认证代次绕过限制。 |
| 应急保障异常 | 由合格新候选本人完成先建后换，再处理旧保障 | 关闭订阅仍保留持久应急保护；不能自动扩权或补回角色权限。 |

`enabled=false` 只阻止新的 Stream 接收/重连；成员核验和管理员处置仍独立可用，持久失败项恢复、会话清理、认证门禁与结算恢复不能随接收开关关闭。关订阅期间平台事件不保证已进入本系统，重新启用后应核对投递/遗漏及覆盖，不能只依据“连接已恢复”宣布全部处理完成。

## 旧版本回退与备份恢复

旧 app 不认识新增权限/状态和执行 key，旧 gateway/AI 不执行当前代次检查与短时输出许可。因此不存在“保留新库、直接把旧二进制放回线上”的安全回退路径。优先采用保留这些门禁与事实的前向修复版本；需要暂时回退其他功能时，也必须使用兼容新协议和持久约束的制品。

若只能恢复旧备份，先隔离全部用户入口和内部生成调用。旧备份会丢失部分离职、代次推进、映射和结算事实，必须从受控事件、审计及备份记录中核对恢复区间，重新建立限制、去重和结算依据，再决定是否恢复流量。不能在恢复后接受旧 token 或自动解除限制；不能将一个未经核对的较早数据库状态当作员工仍有权访问的证据。

本次可提供的证据是代码/迁移评审、进程内事务与依赖替身、可控时钟、jsdom、类型检查/构建和离线告警规则计算。没有执行真实数据库并发、平台联调或跨服务部署测量；生产接收后 30 秒目标需在实际环境单独收集证据，未测量不得记为达标。
