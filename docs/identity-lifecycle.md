# 企业员工生命周期

## 权限与数据迁移

生命周期使用四项独立权限：

| 权限 | 用途 |
| --- | --- |
| `identity:lifecycle:read` | 受管摘要、事件处置及应急保障读取 |
| `identity:lifecycle:manage` | 成员核验、映射管理及原事件重试 |
| `identity:lifecycle:restore` | 人工复职核对及确认 |
| `identity:emergency:manage` | 候选本人登记、轮换应急保障 |

写权限不隐含通用读取资格，以上权限不授予 SSO 绑定、角色、密级或文档正文权限。

V29 保留用户最终启用状态，以原 `enabled` 回填 `manual_enabled`，初始化正数 `auth_epoch`。V30 建立互斥的员工/应急登记、只追加历史、短期确认摘要及管理请求回执。V31 保存离职事件、逐员工处置和按原代次限定的清理意图，不自动删除事件幂等身份或未完成记录。

V32 仅在执行迁移时，为当时已有的 `ROLE_ADMIN` 绑定四项新权限。空库引导沿用 `Permission.codes()` 的完整目录；已有角色不因启动或重启补回被撤销的权限。迁移不自动登记应急管理员或纳管员工。

V35 为接收提交增加可空时间界限，新建按原认证代次关联的撤销依据和按执行 UUID 幂等的本地停止报告。历史事件没有的界限继续为空，不用迁移时间填充。证据视图仅供受控内部排障，包含用户/事件关联键，不扩展普通账号详情，也不将这些键加入指标标签或外发告警。

新增权限必须配合认识该目录的新 app 发布，旧 app 不得混部承接流量。这里描述的是交付的迁移与代码行为，本次没有执行真实数据库迁移或第三方联调。

## 状态转换与数据字典

`manual_enabled` 保存管理员意图，`restriction` 保存外部访问限制；最终 `enabled = manual_enabled && restriction == CLEAR`。`auth_epoch` 是从 1 开始的单调认证代次，不能重置或借复职复用旧值。`sys_user.version` 保护用户写入，登记的 `version` 独立保护映射和限制事实。

| 操作 | 人工状态 | 限制 | 认证代次 |
| --- | --- | --- | --- |
| 人工停用 | false | 保留 | 人工状态变化时增加 |
| 普通启用 | true | 必须为 CLEAR，否则 409 | 人工状态变化时增加 |
| 首次离职/待核对限制 | 保留 | OFFBOARDED / REVIEW | 增加，即使原已人工停用 |
| 原事件重放 | 保留 | 保留 | 不变 |
| 人工复职 | 保留 | CLEAR | 增加，人工停用者仍不可登录 |

身份状态、用户版本、登记版本、只追加历史、审计和旧代次清理意图在同一事务提交。审计或历史写入失败必须回滚全部写入；清理异步执行，不能代替请求入口对当前认证代次的判断。新事件在同一限制状态下可以更新事件依据和版本，但不重复推进认证代次。

`kind` 在 NONE / MANAGED / EMERGENCY 中互斥；准确的 `(source, enterprise_id, employee_id)` 仅对 MANAGED 唯一。原始员工标识仅供内部核验和事件关联，不能直接返回登记实体。`last_event_id` 引用永久保留的业务事件，`restored_at` 记录最近复职边界；映射历史只追加。短期操作凭据仅存 token 哈希及服务端绑定事实，请求回执使用操作者与请求标识联合键，防止未知响应被错误重复执行。
