## 当前基线与总体顺序

当前已有登录与身份管理、空间和文档授权、文档版本与审核、分类标签、评论收藏、站内通知、批量导入、混合检索、会话持久化、模型协议适配、索引运维及监控评测框架；另已完成知识问题闭环首期实现及离线验证，未部署。不宜重复从零开发，也不把仓库实现当作部署证据。

优先解决的实际断点是：**第三方解析适配器尚未提供，新上传文件不能自动完成内容抽取。** 真实模型协议与 `estimated` 多轮预算已有实现；生产模型专用的 `verified` 预算策略是独立的条件性缺口，不应把所有默认关闭能力都列为未实现。

建议顺序：

1. 先推进 **E-01 → E-02 → E-03**，打通真实内容链路并补齐数据库、存储、浏览器及跨服务安全验收。
2. 根据部署预算模式处理 **E-04**，并推进 CI、发布、恢复、安全扫描和真实检索回归等 P1 工作。
3. **F-01 首期已实现并归档**，已形成主动反馈、人工分派、方案与本人确认闭环；后续优先评估 **F-02 → F-03**。资料发布和提问者确认是不同事实，不因审核通过自动解决问题。
4. 在基础链路及权限边界稳定后，再评估标准答案、专题研究、知识影响分析和外部连接器。

以上表示依赖与建议顺序，不要求所有任务严格串行；真实验收环境、测试数据及选型可以提前准备。

E-02/E-03 等工程建议保持独立，不因 F-01 归档自动立项，也不追加为该变更的隐藏完成条件。F-01 的真实数据库、联调、浏览器和部署行为仍未验证。

### E-01 第三方文档解析适配器

- **现状与价值**：缺少第三方 `DocumentParser` 实现时 Worker 暂停领取普通解析任务。接入后才能形成真实上传、解析、分块和索引闭环。
- **最小交付**：实现选定供应商的 Spring Bean；转换为统一 `ParsedDocument`，保留标题路径、表格、真实来源坐标、解析器版本、截断及质量问题；补齐认证、限额、超时、取消与失败分类。
- **依赖与待决策**：解析供应商、API 契约、支持格式和真实样本；app / Worker 的 Embedding profile 一致且完成首次激活。TXT/Markdown 同样通过第三方抽取，不恢复本地解析引擎。
- **安全与验收**：隔离出站客户端与凭据，不向供应商传播用户令牌、内部签名或追踪头；错误不保存原件正文或远程错误体。验证远程异常、失租、取消和迟到结果不能发布。
- **涉及与依据**：`kb-worker`；[第三方解析接入](third-party-document-parsing.md)、[Embedding 初始化与重建](embedding-rebuild-operations.md)。

### E-02 真实数据库与存储集成测试工程

- **现状与价值**：已有部分可选 PostgreSQL 烟测及大量替身测试，但不构成完整真实链路验收。补齐数据库语法、事务和存储一致性的运行证据。
- **最小交付**：在专用环境执行全新库及支持的存量升级迁移、实际 Mapper 的 BM25/向量检索、解析与审核发布并发、导入幂等、对象保护和多实例租约恢复测试。
- **依赖与待决策**：固定数据库扩展版本、专用 PostgreSQL/ParadeDB、Redis、S3 测试资源及可清理的数据集；端到端解析发布用例依赖 E-01，其他集成用例可提前开发。
- **安全与验收**：禁止指向生产库或生产桶；缺少依赖、测试跳过、执行失败分别报告，不把跳过计为通过。覆盖软删除、搬迁、升密和 ACTIVE 导入尝试不能被误删或迟到发布。
- **涉及与依据**：各后端模块测试目录、`db/`；[现有验证入口](../README.md)、[批量导入运维](document-import-operations.md)。

### E-03 浏览器端到端及跨服务安全回归

- **现状与价值**：前端现有测试主要为模拟 DOM，真实 SSE、浏览器文件访问及跨实例撤权仍需验收。测试重点是实际入口行为，而非重复组件单测。
- **最小交付**：新增可重复运行的浏览器测试工程，覆盖登录改密、上传与导入、审核、搜索、问答、停止生成、断连、换号、权限收缩和离职停权；记录各链路的可核对结果与时间证据。
- **依赖与待决策**：受控入口代理和真实多服务环境、E-02 测试数据、可控模型流及必要的真实供应商专项验证；对齐会话开关与预算模式。
- **安全与验收**：不以 Redis 清理或费用结算替代停止输出。跨实例撤销从有效事件可靠持久接收起按既有目标核验；不承诺撤回已经交付的内容或供应商停止计费。
- **涉及与依据**：`kb-web`、`kb-gateway`、`kb-app`、`kb-ai`；[前端运维](user-web-operations.md)、[生命周期运维](lifecycle-operations.md)。

### E-04 生产模型专用 token 预算策略

- **现状与价值**：通用模型适配和 `estimated` 模式已有实现；默认 `verified` 缺少匹配严格策略时，多轮新生成返回 503。此项只在需要严格预算时成为必要前置。
- **最小交付**：实现与实际 API 根地址、模型和消息格式绑定的 `ChatTokenBudget`，核验上下文窗口及完整消息输入上界，包含角色、system、历史、材料包装和原问题。
- **依赖与待决策**：生产模型及其 tokenizer、消息包装规则和可验证上界；若无法证明上界，不能标为 `verified`。部署方可以另行明确接受已有 `estimated` 模式并校准参数。
- **安全与验收**：计算须本地、确定性、有界；身份不匹配或计算失败继续拒绝，不自动转为估算。预算、配额预留和供应商实际 usage 必须分别表达。
- **涉及与依据**：`kb-ai`；[模型接入与预算扩展](chat-model-adapter.md)、[多轮预算](conversation-model-budget.md)。

### E-05 持续集成流水线

- **现状与价值**：仓库未见 CI 配置；现有构建、测试和监控校验入口可以复用，目标是持续执行和留存证据，而非重写工具。
- **最小交付**：接入选定 CI 平台，执行后端测试、前端类型检查/测试/构建、包体隔离及监控配置与规则校验；将离线回归和真实依赖测试分为明确的作业。
- **依赖与待决策**：CI 平台、运行器、依赖缓存、版本固定和 E-02/E-03 环境；准备监控脚本要求的真实工具版本。
- **安全与验收**：secret 不进入产物、日志或缓存；缺工具及测试跳过不能伪装通过。不为得到绿色结果永久排除失败测试；独立报告既有规格警告和真实依赖未验证项。
- **涉及与依据**：后续 CI 配置、`kb-web/package.json`、`ops/monitoring/scripts/`；[监控验证记录](monitoring-verification.md)。

### E-06 业务服务部署与发布自动化

- **现状与价值**：Maven 制品及独立监控部署已有基础，根目录 Compose 仅包含中间件。补齐业务部署和协调发布，避免把进程启动视为业务就绪。
- **最小交付**：根据目标平台提供业务镜像或制品部署模板、prod 配置模板、依赖就绪检查、迁移及发布顺序脚本、前端哈希资产上传与 HTML 原子切换；固定验证过的中间件版本。
- **依赖与待决策**：部署平台、网络拓扑、制品仓库、secret 注入方式和 E-02/E-03 验收环境；复用现有监控发布模式，但不强制引入新平台。
- **安全与验收**：app 单点迁移，Worker 不运行 Flyway；管理网络隔离。身份协议和导入保护升级按既有协调方案执行，不能回退到绕过新门禁或不识别 ACTIVE 保护的旧实例。
- **涉及与依据**：后续业务部署配置、`ops/`、`docker-compose.yml`；[生命周期协调发布](lifecycle-rollout.md)、[批量导入运维](document-import-operations.md)、[前端运维](user-web-operations.md)。

### E-07 备份恢复与一致性验证脚本

- **现状与价值**：仓库未见完整恢复自动化；外部环境可能已有备份平台。需要可重复证明数据库、原件和派生索引能够恢复，而非仅确认备份任务执行成功。
- **最小交付**：按选定平台提供数据库备份/时间点恢复、对象恢复、引用完整性核对、索引重建及演练结果报告脚本，记录实际 RPO/RTO。
- **依赖与待决策**：备份服务、保留期、加密及访问策略、目标 RPO/RTO、数据库扩展兼容性和独立恢复环境；区分原件权威数据与可重建索引。
- **安全与验收**：备份中的敏感内容与 secret 同样受控，演练不覆盖生产数据。身份与授权恢复方案必须防止恢复旧状态重新放行已撤销账号；跨数据库和对象时间点的不一致需显式检测。
- **涉及与依据**：后续 `ops/` 恢复脚本；[架构决策记录](../架构决策记录.md)、[认证撤销](authentication-epoch.md)、[存储对账](storage-reconciliation-operations.md)。

### E-08 真实检索质量与性能回归工程

- **现状与价值**：已有真实搜索采集 CLI 和离线评测 CLI，开发本地向量及本地 rerank 不证明生产语义质量。需要真实中文与企业术语基线和容量数据。
- **最小交付**：准备受控标注集，复用采集与评测工具；新增并发驱动、实际执行计划和时延/资源报告，覆盖 BM25、向量、融合及 rerank 配置差异，以及严格权限过滤后的召回情况。
- **依赖与待决策**：E-01 的真实内容、已激活的真实 Embedding profile、rerank 选型、业务查询样本和目标质量/性能门槛；必要时再根据测量修改 SQL、候选数量或索引参数。
- **安全与验收**：不能靠放宽权限改善召回；受控保存问题、语料和身份快照。CLI 运行耗时不是搜索耗时，合成样例和未配置门禁不能作为真实质量通过证明。
- **涉及与依据**：`kb-app` 搜索链路、`kb-eval-collector`、`kb-eval`；[结果采集](retrieval-result-collection.md)、[检索评测](retrieval-evaluation.md)、[检索韧性](search-resilience.md)。

### E-09 恶意文件扫描接入

- **现状与价值**：当前已有文件签名、宏、外部关系和压缩包限制，但不等于病毒扫描。此项是候选安全增强，不是认定现有格式校验未实现。
- **最小交付**：接入选定扫描服务，定义隔离与放行状态、超时、不可用和重检处理；覆盖单文件、批量导入、解析、下载及预览路径的一致门禁。
- **依赖与待决策**：扫描供应商、扫描位置、失败时的阻断策略、历史文件处置及与现有导入/版本状态的兼容方式；改变读取和发布行为前需修订对应规格。
- **安全与验收**：扫描未知不能标记安全；隔离对象不能通过其他入口绕过，扫描载荷和诊断不泄露原件或凭据。用受控恶意样本及服务故障验证，不扫描生产文件作测试。
- **涉及与依据**：`kb-common` 文件策略、`kb-app`、`kb-worker`；[文件安全现状](p0-hardening.md)、[批量导入运维](document-import-operations.md)。

### E-10 对象存储全量轮转巡检与持久报告

- **现状与价值**：桶方向孤儿检测已按分页扫描；反方向缺失检测仅抽查最近一批存活版本。增强的是旧引用覆盖与可追踪报告，不是重新实现孤儿清理。
- **最小交付**：为缺失检测增加可恢复的轮转游标、检查时间及持久结果，提供受控查询入口，明确覆盖进度、失败和最后成功时间。
- **依赖与待决策**：库/桶规模、单轮预算、游标并发协议、报告保留期和独立查询资格；复用既有存活引用及多实例互斥语义。
- **安全与验收**：继续保护全部存活版本及 ACTIVE 尝试；未 PUT 的尝试不是缺失对象。区分 NotFound 与网络/权限错误，查询入口不能泄露对象键；本项不默认扩大删除范围或自动修复。
- **涉及与依据**：`kb-app` 存储对账及候选管理页面；[存储对账运维](storage-reconciliation-operations.md)。

### E-11 回答质量与引用证据评测

- **现状与价值**：当前 `kb-eval` 主要评测文档版本命中，不评测精确片段或生成答案。新增框架用于发现引用不支持结论、拒答不当和提示注入影响。
- **最小交付**：定义固定版本的题目、答案要点、证据片段和评分口径；采集受控回答及引用，评测片段相关性、关键结论支持、正确拒答和注入回归，并输出失败样例。
- **依赖与待决策**：E-08 语料、真实模型、人工标注与复核流程、调用成本和数据保留方式；是否扩展既有 CLI 或新增独立工具需另行设计。
- **安全与验收**：citation 只是本轮参考来源，不证明模型实际采用或逐句受到支持；自动评分不作为真实性证明。评测数据受原权限与外发边界约束，不改变历史引用版本或自动触发业务写入。
- **涉及与依据**：候选评测工具、`kb-ai` 的受控采集边界；[检索评测](retrieval-evaluation.md)、[引用溯源](citation-provenance.md)。

| F-09 | 第二梯队 | 专题研究工作台 | 在用户限定范围内比较和汇总资料 |
| F-10 | 第二梯队 | 知识订阅与变更摘要 | 让用户及时获知关心的知识更新 |
| F-11 | 第三梯队 | 新员工学习路线 | 将零散资料组织为岗位学习任务 |
| F-12 | 第三梯队 | 文档变更影响助手 | 找出需要复核的衍生内容 |
| F-13 | 第三梯队 | 知识健康雷达 | 指导负责人下一步建设什么 |
| F-14 | 第三梯队 | 外部知识源连接器 | 纳入既有企业知识并持续同步 |

### F-01 知识缺口闭环

- **当前状态**：首期实现及离线验证完成，2026-11-14 已同步七份主规格并[归档](../openspec/changes/archive/2026-11-14-knowledge-gap-feedback-loop/)。47/47 项实施任务完成；[验证记录](../openspec/changes/archive/2026-11-14-knowledge-gap-feedback-loop/verification.md)与[逐场景证据](../openspec/changes/archive/2026-11-14-knowledge-gap-feedback-loop/traceability.md)保留实际范围，不代表已部署或真实环境验收通过。
- **价值**：用户标记“没找到答案 / 回答不准确”后，不只留下反馈，还能追踪补充知识的结果。
- **首期已交付**：独立手工、搜索及已保存问答轮次反馈入口；统一受理、单一合格负责人及人工改派；六态及共享历史；说明型或固定已发布资料型方案；提问者明确确认、退回方案、撤回及带原因关闭；独立问题事件与共享站内收件箱。
- **已确认边界**：只保存用户明确确认分享的描述，不保存回答、完整聊天、会话/轮次/搜索 ID 或引用快照；访问限于原提问者、当前合格负责人和独立 read 受理人员，read/assign/handle/close 互不蕴含。资料提交核验双方可读，后续逐次核验原固定版本；只有提问者确认才解决，三类终态不重开，撤回不删除已分享记录。
- **非首期范围**：自动归因、相似反馈自动合并、模型代写方案、自动解决及外部 IM 内容推送均未纳入；不把检索故障等同于全库缺少知识。未来扩展须另行确认，不从本条推导实施授权。
- **验证与发布**：已完成离线服务/事务代理、内存替身、模拟 DOM、SQL/配置静态检查及构建打包；真实约束、触发器、锁/回滚、SQL 计划、迁移、旧二进制启动、前后端联调、真实浏览器和部署均未验证。按 app→gateway→web 协调发布，旧 app 不混部，回退不删记录、权限绑定或反迁移。
- **涉及与参考**：业务持久化在 `kb-app`，界面在 `kb-web`，入口在 `kb-gateway`；不为反馈增加 AI/Worker 数据访问。见[主规格](../openspec/specs/knowledge-gaps/spec.md)、[问题 API](knowledge-gap-api.md)、[受理运维](knowledge-gap-operations.md)、[协调发布](knowledge-gap-rollout.md)和[站内通知](in-app-notifications.md)。

### F-02 知识有效期与复审

- **价值**：为制度及流程明确何时适用、由谁维护，减少使用过时知识。
- **最小交付**：生效/失效日期、责任人、复审周期与到期提醒；在阅读和搜索结果展示当前适用状态，复审保留人工确认记录。
- **依赖与待决策**：确认字段属于整份文档还是固定版本，定义时区、无日期含义及过期是否影响搜索/问答。首期建议先做标识和提醒，不默默改变现有发布状态。
- **安全边界**：有效期不能替代 ACL、密级或审核；过期不等于可删除，也不触发对象清理。改变检索和发布行为须先确定正式契约。
- **涉及与参考**：`kb-app`、`kb-web`，检索/问答规则按需涉及 `kb-ai`；[文档资料](document-metadata-api.md)、[版本审核](document-review.md)。

### F-03 版本差异与变更摘要

- **价值**：帮助审核人和读者快速定位两个版本之间的关键变化。
- **最小交付**：指定两个版本的段落与表格差异、关键日期/金额变化，以及候选变更摘要；人工确认后再展示为正式变更说明。
- **依赖与待决策**：E-01 的结构化来源质量、版本读取资格、对齐算法及摘要审核方式；无法稳定对齐时应明确提示，不伪造精确差异。
- **安全边界**：两个版本分别授权，不能借比较泄露不可读候选版本；摘要需保留来源版本及人工确认状态，不改写原件或固定审核对象。
- **涉及与参考**：`kb-app`、`kb-web`，AI 摘要按需涉及 `kb-ai`；[解析结构契约](../openspec/specs/document-parsing/spec.md)、[版本审核](document-review.md)。

### F-04 权限解释与授权预演

- **价值**：让合格管理者理解规则命中原因，并在提交授权变更前检查影响。
- **最小交付**：受控诊断空间授权、文档例外、密级、归档及发布条件；对拟议变更计算影响范围但不写入，展示结果时间与假设。
- **依赖与待决策**：诊断及模拟的独立资格、可检查主体和资源范围、输出粒度与规模限额；复用当前授权规则，不创建另一套判断语义。
- **安全边界**：管理资格不自动授予文档阅读权，诊断不能暴露未授权资源的存在或正文；预演结果不是后续写入许可，实际提交必须重核权限与版本前置条件。
- **涉及与参考**：`kb-app`、`kb-web`；[空间与文档管理](admin-space-document-web.md)、[资源能力](user-resource-capabilities-api.md)。

### F-05 搜索纠错与企业术语词典

- **价值**：支持简称、旧名称和同义表达，使用户用自己的语言也能找到企业资料。
- **最小交付**：受控词条管理、同义词与简称关系、查询纠错提示；展示实际采用的检索表达，并允许用户回到原始查询。
- **依赖与待决策**：词典的公开/空间可见范围、人工维护方式、匹配规则及 E-08 回归样本；自动学习热门查询属于另行评估范围。
- **安全边界**：词条及建议不能暴露隐藏空间、术语或他人查询；扩展查询仍经过两路召回原权限过滤。词典修改不能默默改写已绑定会话请求或绕过输入限额。
- **涉及与参考**：`kb-app` 搜索链路、`kb-web`；[搜索筛选](search-filtering-api.md)、[检索韧性](search-resilience.md)。

### F-06 AI 辅助整理文档资料

- **价值**：从文档内容生成候选标题、摘要、分类和标签，减少重复录入。
- **最小交付**：对固定版本生成候选资料，展示来源和差异；用户选择接受后通过已有受控写入路径保存，不直接发布文档。
- **依赖与待决策**：E-01、真实模型及明确预算模式；定义资料辅助任务的配额、审计、取消和失败语义，不能未经设计直接套用聊天轮次账本。复用已有分类与标签目录。
- **安全边界**：读取来源和写入资料分别核验；撤权或来源变化后旧建议不能直接提交。正文外发遵守现有边界，分类/标签名称同样受控，AI 不创建权限或自动审核。
- **涉及与参考**：`kb-app`、`kb-ai`、`kb-web`；[资料与目录](document-metadata-web.md)、[模型接入](chat-model-adapter.md)。

### F-07 矛盾知识提示

- **价值**：发现同一事项在不同资料中出现不同金额、日期、流程或责任部门，交由负责人确认。
- **最小交付**：人工指定可读资料或限定专题，生成“疑似冲突”清单，附固定版本片段和定位，支持确认、忽略及后续复核。
- **依赖与待决策**：E-01、E-11、真实模型或受控规则、事项匹配与适用范围定义；需区分时间、地区、岗位不同造成的合理差异。
- **安全边界**：不能跨权限集合暴露冲突；不输出模型自行裁定的权威结论，不自动废止或修改文档。来源不可读或版本变化时原提示需重新核验。
- **涉及与参考**：候选 `kb-app` 任务与 `kb-web` 页面，分析按需涉及 `kb-ai`；[引用溯源](citation-provenance.md)。

### F-08 经审核的标准答案卡

- **价值**：将高频问题沉淀为可维护、可核验的标准答案，而不是永久复用某次聊天输出。
- **最小交付**：问题及答案、适用范围、来源版本、有效期、责任人和人工审核状态；支持搜索及问答引用，来源变化后进入待复核。
- **依赖与待决策**：答案卡的版本、授权和审核模型，F-02 的适用期规则及来源变更检测；不假定现有文档审核接口可以直接管理新资源类型。
- **安全边界**：每次使用重核答案卡与全部必要来源资格；来源失效或不可读不能回退旧答案。标准答案不得绕过原检索授权或用跨用户缓存共享私有内容。
- **涉及与参考**：`kb-app`、`kb-web`、`kb-ai`；[版本审核](document-review.md)、[引用溯源](citation-provenance.md)。

### F-09 专题研究工作台

- **价值**：让用户在选定空间或文档范围内比较、汇总和连续提问，例如比较多个项目的验收要求。
- **最小交付**：持久保存专题的选定范围、限定检索、固定版本引用及私有会话；首期不增加共享工作区或模型工具执行。
- **依赖与待决策**：多轮会话可用、明确预算策略、选定范围大小及其与版本更新的绑定规则；限定检索失败、空结果和范围失效要明确区分。
- **安全边界**：选定范围与当前可读范围取交集；不因无结果自动扩展到全库。每轮与历史读取仍重核来源，资料中的指令不能触发额外读取或写操作。
- **涉及与参考**：`kb-web`、`kb-app`、`kb-ai`；[会话历史](conversation-history.md)、[搜索筛选](search-filtering-api.md)。

### F-10 知识订阅与变更摘要

- **价值**：用户订阅空间、标签或文档，及时获知关心的资料更新。
- **最小交付**：本人订阅管理、更新事件归并、站内通知及按需生成的每周更新清单，提供频率和取消入口。
- **依赖与待决策**：复用发布事实和现有站内通知，定义事件去重、保留期、未读口径及摘要生成成本；首期不扩展外部 IM 内容推送。
- **安全边界**：派生和读取均按当前资格核验；优先发送受控链接，不把原正文固化在撤权后仍可读的通知中。订阅关系不授予权限，业务通知不复用运维告警适配器。
- **涉及与参考**：`kb-app`、`kb-web`；[站内通知](in-app-notifications.md)、[独立告警适配器](alert-notifier-operations.md)。

### F-11 新员工学习路线

- **价值**：将岗位资料组织为入职第 1 天、第 1 周、第 1 月的学习任务，并根据测验缺口推荐后续内容。
- **最小交付**：人工配置岗位路线、固定资料链接、本人阅读确认、简单测验和学习进度；个性化推荐可后续增加。
- **依赖与待决策**：岗位与路线映射、资料版本及过期处理、学习记录的本人/管理者可见范围和保留期；测验成绩用途需明确。
- **安全边界**：路线分配和推荐不自动授予文档资格；岗位名称不能代替 permission code。不可读资料不展示旧标题或隐藏数量，学习成绩不默认对全体管理员公开。
- **涉及与参考**：候选 `kb-app` 学习业务与 `kb-web` 页面；[身份管理](admin-identity-web.md)、[资源能力](user-resource-capabilities-api.md)。

### F-12 文档变更影响助手

- **价值**：制度更新后，提示哪些标准答案、学习路线和专题依赖旧版本，需要负责人复核。
- **最小交付**：基于固定来源版本建立衍生资源依赖记录；发布新版本后生成待复核清单，关联责任人和处理状态。
- **依赖与待决策**：F-08/F-09/F-11 中已立项资源的来源关系、版本发布事实和 F-10 提醒能力；可用现有关系存储表达依赖，不要求引入知识图谱服务。
- **安全边界**：影响明细按资源及来源资格展示，不用管理汇总权限读取全部内容；提示不自动改写原答案或历史会话，历史引用继续绑定原文档/版本/分块。
- **涉及与参考**：`kb-app`、`kb-web`；[引用溯源](citation-provenance.md)、[会话历史](conversation-history.md)。

### F-13 知识健康雷达

- **价值**：从“有多少文档”进一步回答“下一步该维护或补充什么”，展示长期未复审、无责任人、疑似重复/矛盾和高频缺口主题。
- **最小交付**：先基于已确认的责任人与复审规则生成受控维护清单；逐步接入 F-01 的反馈、F-07 的冲突提示和重复候选，展示口径及检查新鲜度。
- **依赖与待决策**：F-01/F-02 等基础事实、缺口与重复定义、查询规模及后台计算预算；复用运营报表布局不等于复用其全部授权或指标语义。
- **安全边界**：现有 `operations:reports:read` 只允许固定全局汇总，不授权文档明细。新诊断清单需单独定义资格并校验资源可读性；疑似重复仅供人工处理，不改变同名同内容允许新建的导入契约或自动删除。
- **涉及与参考**：`kb-app`、`kb-web`；[运营报表边界](knowledge-operations-reports.md)、[批量导入契约](document-import-api.md)。

### F-14 外部知识源连接器

- **价值**：按需纳入 Git、企业 Wiki 或受控网页，并检测增量更新和删除，减少人工重复导入。
- **最小交付**：先选择一种数据源，支持受控连接配置、稳定来源身份、增量同步、来源版本记录、变更送审、删除检测及人工重试；不一次性接入全部平台。
- **依赖与待决策**：E-01、源系统 API、凭据及速率限制、目标空间、源权限映射、冲突和删除策略；先验证接入范围及授权语义，再决定调度和管理页面。
- **安全边界**：源权限与本地权限兼容且可验证，不能抓取后默认全员可见；源权限收缩必须有可收敛的撤销机制，无法确认时不能继续信任旧可见性。限制地址、重定向及内网访问范围，源凭据不进入浏览器或日志，删除不默认物理清理。
- **涉及与参考**：候选 `kb-app` 同步业务、`kb-worker` 任务及 `kb-web` 管理入口；[空间授权主规格](../openspec/specs/space-authorization/spec.md)、[解析接入](third-party-document-parsing.md)。

## 所有候选能力共同遵守的边界

1. **资格与资源授权分开**：功能权限不自动授予阅读、下载、编辑或审核资格；推荐、比较、摘要、诊断明细和新资源来源都要覆盖当前权限、密级、归档、删除和版本参与规则。
2. **AI 只提供受控候选**：不自动修改权限、执行工具、裁定制度效力或发布资料。授权材料保持不可信数据身份，提示词隔离不代替访问控制。
3. **固定来源，保留历史**：衍生内容记录实际来源版本；变更提醒触发复核，不把旧引用补成最新版本或改写历史回答。
4. **失败、未知与关闭分别表达**：不通过占位回答、旧统计、虚假零值或自动扩大检索范围掩盖故障；自动建议不是事实证明，模型自报置信度不能充当可信度验收。
5. **延续模块边界**：业务持久化由 app 承担，AI 不连接数据库，Worker 承接受控异步工作；新用途的预算与账本需单独设计，不盲目复用聊天结算语义。
6. **限制敏感信息扩散**：secret 不进入前端构建，问题、答案及原件不无差别进入日志、报告或外部通知；新增采集先明确用途、可见范围和保留期。

本文不扩展当前明确排除的知识图谱/KAG、音视频、对外分享外链或显式 deny，也不建议为性能未经设计直接加入跨请求权限缓存。若未来希望改变这些边界，应单独确认需求与架构决策。

## 从路线图进入实施

1. 选择编号和最小范围，确认负责人、业务目标、选型、依赖及非目标；需要模型或外部服务的项目先明确供应商与数据边界。
2. 核对当时的代码和正式规格，确认是实现缺口、集成验收还是新增契约。不要根据本文的历史检查直接覆盖后来新增的实现。
