三个应用角色（建议部署方案）

A · 业务主应用（模块化单体）

用户 / 部门树 / 角色 / 空间与文档 ACL / 密级 · 文档、版本、审核 · 文件与授权预览 · 权限约束的统一检索 · 审计、通知、统计

异步链路：A 写文档版本与任务 → B 领取 → 读 S3 原件 → 解析 / 嵌入 → 写 PG 双索引并原子发布检索版本。模型调用在短事务之外，失败可重试。

检索链路

BM25 + 向量两路召回 → RRF 融合 → rerank 重排 → top-k → LLM

一致性与召回边界：PG 减少跨库索引同步，但仍需异步状态、版本发布、重试与 S3 孤儿对象清理。授权以空间为主（粗粒度），可见集不稀疏，缓解 HNSW 加严过滤掉召回；首期不默认将授权检索转异步副本，以免复制延迟暴露旧 ACL。

权限模型（已定型）

知识空间为主 + 文档例外 · 部门层级树 + 角色 · 含文档密级 · 首期不做外链 / 显式拒绝

主体

有效主体 = 用户 ∪ 角色 ∪ 所在部门及全部祖先部门；授权某部门则其子树用户命中

客体

空间级 ACL 为主，文档默认继承；少数文档设例外（EXISTS 防重复行）

密级

可见 = 通过 ACL 且 文档密级 ≤ 用户可见密级；例外首期只扩权、不收紧
