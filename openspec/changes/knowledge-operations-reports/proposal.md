# Proposal

## Why

现有统计只覆盖聊天用量及离线检索评测，缺少文档、审核与评论的运营概览。需要提供有明确口径、权限和覆盖起点的全局安全汇总，而不是从当前状态或通知条数猜测历史行为。

## What Changes

- 新增管理端全局脱敏概览：当前文档数、版本数、格式与解析状态分布，当前待审量，窗口内通过／驳回量和处理时长，窗口内评论／回复创建量。
- 使用独立 `operations:reports:read` 读取资格，输出仅为汇总，不返回个人排行、资源名称、ID 明细、评论或审核内容；元数据读取不授予正文资格。
- 当前库存与历史事件分别统计，公开 asOf、定义版本、时间窗口、UTC 日界及分能力覆盖状态；未知或上线前历史不得补零。
- 复用既有 AI 用量页面及 `ai:usage:read`，报表页只在相应资格确认后显示入口，不复制调用采集、账本或 AI 数据。
- 暂不提供阅读量、下载量、搜索行为、费用推算、导出、定时推送、自定义 BI 或部门／个人排行。

## Capabilities

### New Capabilities

- `knowledge-operations-reports`：全局安全运营汇总、统计口径、一致性及覆盖边界。
- `admin-web-operations-reports`：管理概览页、筛选、独立授权及 AI 入口复用。

### Modified Capabilities

- `functional-authorization`：新增独立报表读取 code，按当前角色权限并集判定，一次性初始化且不恢复撤权。
- `admin-web-access`：增加受独立资格保护的报表导航、直接访问及安全登录返回。

## Impact

- 依赖先实施并同步审核、站内通知、评论三个变更；统计读取审核／评论的持久业务事实，不依赖通知投递完成。
- `kb-app` 新增 reporting 服务、只读汇总 Mapper、查询 API 和必要索引；授权目录及新迁移增加 code；`kb-web/src/admin` 增加概览页。
- 复用现有查询参数校验、精确整数、会话与管理生命周期；网关沿用 `/api/admin/**`，不增加外部分析服务或用户行为埋点。
- 本次仅交付规划；真实执行计划、查询成本、迁移及事务一致性仍须在实施后区分离线证据与真实环境验收。
