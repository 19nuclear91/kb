# Proposal

## Why

后端已经提供按文档 `edit` 权限执行的整文档删除接口，但用户端没有操作入口，资源能力响应也没有明确表达删除资格。本变更补齐详情页删除交互，让用户能够确认删除范围、识别实际结果，并在响应丢失或权限变化时安全核对当前状态。

## What Changes

- 文档能力响应新增 `canDelete`，按当前目标文档的 `edit` 资格计算，保留既有父文档 `view` 门禁、密级、归档与删除过滤。
- 在文档详情页增加单文档删除入口和确认弹窗，明确操作影响整份文档及全部版本、取消未完成处理和审核、当前不支持恢复；选中版本不改变删除范围。
- 复用 `DELETE /api/documents/{documentId}`，提交期间互斥，确认成功后清理页面资源并返回重新读取的文档中心。
- 建立明确成功、明确拒绝、结果未确认的交互；网络或无法确认的服务异常不自动重发，核对得到的 404 不冒充删除成功，200 不证明原删除请求失败。
- 将删除状态绑定当前会话与文档，处理退出、页面隐藏、切换文档和迟到响应，防止旧内容或旧成功提示恢复。
- 更新相关行为测试和用户资源能力、用户端使用说明。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `user-resource-capabilities`：扩展最小能力投影及编辑能力计算，新增 `canDelete` 并保持实时授权与最小披露。
- `user-web-documents`：增加详情页整文档删除、确认、提交互斥、结果核对和生命周期约束，并扩展现有操作按钮规则。

## Impact

- 后端：`DocumentCapabilities`、`DocumentCapabilitiesService` 及对应接口/序列化测试。删除 API、权限目录、ACL 模型及数据库结构保持兼容，不新增权限位、删除回执表或数据库迁移。
- 前端：`kb-web` 的能力类型、文档详情与文档中心、局部删除状态和对话框，以及与上传、审核、评论、文件预览等已有交互的互斥衔接。复用现有 Session、Ant Design 与路由能力，不新增运行时依赖。
- 文档：更新 `docs/user-resource-capabilities-api.md`、`kb-web/README.md` 和相关用户端操作说明。
- 首期入口限定文档详情页；列表快捷删除、管理后台删除、批量删除、单版本删除、回收站恢复、独立删除权限、删除幂等回执及跨标签页实时通知不在本次范围。
- 仅有 edit 而没有 view 的用户仍无法通过详情页操作，本变更不为提供入口而扩大其阅读资格。新前端遇到缺少 `canDelete` 的旧服务响应时禁用删除。
