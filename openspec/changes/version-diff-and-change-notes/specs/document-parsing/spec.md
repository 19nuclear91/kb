# Spec Delta

## ADDED Requirements

### Requirement: 解析发布必须同时保存版本结构快照

解析发布 SHALL 在保存分块的同一原子操作中，按解析顺序保存该版本归一化后的全部非空结构块（类型、文本、标题路径、页码与来源坐标、表格单元格），以及解析器身份、截断标记和所属索引执行周期，并替换同一版本此前的快照。发布失败 MUST 不留下快照，已有发布证据的版本快照不再改变。快照不参与检索、向量重建或发布门禁。

#### Scenario: 解析成功并保存快照
- **WHEN** 一个版本的解析、切块和向量化成功并完成索引提交
- **THEN** 该版本同时保存分块和结构快照，快照的块顺序与解析结果一致，并记录本次执行周期

#### Scenario: 同一版本重复处理
- **WHEN** 待审版本因刷新索引被再次处理并成功提交
- **THEN** 最终只保留一份与最新成功结果一致的快照，不残留上一次的块

#### Scenario: 发布过程中失败
- **WHEN** 分块、快照或索引状态任一写入失败
- **THEN** 整个提交回滚，该版本既没有新分块也没有新快照

#### Scenario: 大表格
- **WHEN** 一个表格块因超过分块容量在分块中被按行切分
- **THEN** 快照中该表格仍是一个完整的块，保留全部行和单元格

#### Scenario: 快照不影响检索与重建
- **WHEN** 系统执行搜索、问答召回或 Embedding 重建
- **THEN** 不读取也不改写结构快照，召回结果与是否存在快照无关
