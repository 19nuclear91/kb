# Spec Delta

## ADDED Requirements

### Requirement: 文档详情必须展示选中版本的变更说明

文档详情 SHALL 为当前选中版本读取并展示变更说明：文本、对应的基准版本（“相对 vX”）、“已更正”及“发布后补写”标记，并可查看修改历史。没有说明时显示“没有变更说明”；读取失败只显示“变更说明暂不可确认”，不阻止详情、预览、下载或对比。说明正文 MUST 作为纯文本显示。

#### Scenario: 查看已更正的说明
- **WHEN** 用户选中一个说明已更正的版本并打开修改历史
- **THEN** 页面按服务端分页显示每次写入的时间、前后文本、是否发布后写入和原因，不显示操作者

#### Scenario: 说明读取失败
- **WHEN** 说明读取返回 503
- **THEN** 说明区域显示暂不可确认，详情其余内容照常显示，不显示为没有说明

### Requirement: 变更说明的写入必须按版本状态提示规则

当服务端表示当前用户可修改时，详情页 SHALL 提供说明编辑，并显示保存后将使用的基准版本。待审版本不要求原因，可以清除说明；已对读者可见的版本首次写入不要求原因，修改已有说明必须填写原因，并提示修改立即生效、原因对可读该版本的用户可见，且不能清除。审核中只显示冻结说明；没有可用基准时说明第一个版本不能写变更说明，不提供提交入口。

#### Scenario: 发布后首次补写
- **WHEN** 用户为一个已发布且没有说明的版本写入说明
- **THEN** 页面不要求原因，并提示该说明将标记为发布后补写

#### Scenario: 版本在编辑时已经发布
- **WHEN** 用户按待审规则修改已有说明时服务端返回 REASON_REQUIRED
- **THEN** 页面重新读取该版本说明，并要求填写原因后由用户重新提交，不自动带入原因

#### Scenario: 并发冲突
- **WHEN** 保存返回 NOTE_VERSION_CONFLICT
- **THEN** 页面重新读取最新说明，提示他人已修改，由用户决定是否重新编辑，不自动覆盖

### Requirement: 变更说明写入结果未确认时必须保留原请求

说明保存超时或网络中断时，页面 SHALL 只提供以原请求标识重试、重新读取核对或放弃，不自动重发。同一身份与固定版本内，重新读取返回旧值、新值或失败，以及关闭后继续核对，都 MUST 保留原请求标识与精确载荷；读取结果不作为写入回执或隐式放弃。只有核对到成功回执、明确拒绝或用户显式放弃后，才允许以新请求重新编辑。

#### Scenario: 重新读取后看到新文本
- **WHEN** 保存结果未确认，用户重新读取后看到的说明已是提交的新文本
- **THEN** 页面仍保留原请求标识，只允许以原标识重试确认回执或显式放弃

### Requirement: 变更说明写入必须参与详情页操作协调

说明提交 SHALL 与详情页既有的删除、元数据和适用期写入共用在途和结果未确认事实：删除确认期间阻止新的说明保存，说明保存在途或结果未确认时禁止确认删除。删除成功、切换文档或版本、身份变化、页面隐藏或离开时清除说明草稿和旧回调，恢复后不自动保存。

#### Scenario: 切换版本后响应迟到
- **WHEN** V1 的说明保存响应到达时页面已选中 V2
- **THEN** 不更新 V2 的说明或编辑状态，也不显示 V1 的成功提示

### Requirement: 版本历史必须提供两个版本的对比入口

当版本历史中至少有两个可见版本时，详情页 SHALL 提供对比入口，让用户从可见版本中选择基准与目标。目标默认为当前选中版本；基准默认为目标说明的基准版本（该版本在可见列表中时），否则为列表中比目标旧的最近一个已发布版本，没有时由用户选择。确认后打开对比页，不预先判断快照是否可用，不提供不可见版本。

#### Scenario: 目标有变更说明
- **WHEN** 用户选中 V3，V3 的说明基准为 V1，且 V1 在可见列表中
- **THEN** 对比入口默认基准为 V1、目标为 V3

#### Scenario: 目标没有变更说明
- **WHEN** 用户选中已发布的 V3，没有说明，列表中 V2 为比它旧的最近已发布版本
- **THEN** 对比入口默认基准为 V2、目标为 V3

#### Scenario: 只有一个可见版本
- **WHEN** 普通读者只能看到文档的一个版本
- **THEN** 页面不显示对比入口，也不提示存在其他版本
