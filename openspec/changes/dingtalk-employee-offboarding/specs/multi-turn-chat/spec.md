# Spec Delta

## MODIFIED Requirements

### Requirement: 新旧流式协议必须具有明确兼容边界

既有 `POST /api/ai/chat` SHALL 保留单轮请求、占位兼容、引用及正常终止协议且不自动写入历史，但检索失败按新契约改为安全 error，不再输出成功无结果回答；单轮和多轮均须遵守账号撤销的有界中断要求。新入口首次接受使用 SSE，返回会话/轮次标识响应头，事件继续使用 citation、delta、done、error；匹配重放使用 JSON 并由 Content-Type 明确区分。检索 error SHALL 附带固定 code=SEARCH_UNAVAILABLE，原消息字段仍可读取。SSE 来源仍是本轮实际新材料，不以继承依赖宣称逐句证据。新流与历史响应 MUST 禁止存储缓存。

#### Scenario: 旧调用方与新轮次首次接受
- **WHEN** 旧客户端调用原单轮接口，或新客户端首次成功提交会话轮次
- **THEN** 旧客户端继续消费原事件类型与字段，并按新规则接收检索 error；新客户端在流开始前取得 X-Conversation-Id、X-Turn-Id
- **AND** 新流持续输出既有四种事件，正常完成、错误、客户端取消和账号撤销均能有界结束

#### Scenario: 流开始前拒绝和重放
- **WHEN** 身份、归属、参数、预期序号或配额在 SSE 建立前拒绝，或者请求为匹配重放
- **THEN** 拒绝使用相应 HTTP 状态；重放返回 application/json 身份与状态
- **AND** 不通过第二个 SSE 订阅重启生成，不在错误或重放 JSON 中附带回答正文

#### Scenario: 两类单轮观测模式
- **WHEN** 单轮 AI 采集开启或关闭时发生检索故障
- **THEN** 两种路径都以安全 error 结束，不发送成功 done；开启采集时记录失败而非 COMPLETED/NO_RESULTS

#### Scenario: 前端识别检索错误
- **WHEN** 用户端消费带 SEARCH_UNAVAILABLE 的 error
- **THEN** 显示“检索暂不可用，请稍后重试”，结束本次消费并按已有协议核对持久状态
- **AND** 缺少或未知 code 时使用通用错误提示，不直接展示任意服务端 message

#### Scenario: 单轮兼容分支遇到账号撤销
- **WHEN** 原单轮接口在正常模型、占位或任一种采集模式下进行回答，而账号被撤销
- **THEN** 全部路径均有界停止本地输出并取消上游，不以未启用多轮历史或用量采集为由继续生成

## ADDED Requirements

### Requirement: AI 输出必须具有独立的短时身份许可

所有单轮和多轮 AI 输出 MUST 具有绑定当前用户、认证代次与执行的短时许可，独立于执行租约和用量采集。许可最长有效 10 秒，按本地单调时间从身份核对发起时起算；不能因迟到响应、网络重试或任务续租延长旧许可。许可失败或过期必须停止输出并取消上游，整体满足离职可靠接收后 30 秒的撤销目标。

#### Scenario: 模型持续输出期间撤销账号
- **WHEN** 生命周期限制已持久提交，而另一节点仍持有此前取得的 AI 输出许可
- **THEN** 最迟在该许可期限结束时停止引用、正文及成功 done，不依赖撤销广播到达或原任务租约到期

#### Scenario: 身份检查失败或响应迟到
- **WHEN** 刷新许可失败、无法确认身份，或响应到达时已超过从请求发起计算的期限
- **THEN** 不签发或延长输出许可，不输出新的业务内容，并取消该执行的上游订阅

#### Scenario: 旧执行的检查响应返回
- **WHEN** 某次许可检查响应属于已经取消或被替换的执行
- **THEN** 丢弃响应，不为另一个执行补发许可

### Requirement: 无模型输出和进程暂停不得绕过撤销期限

输出许可的到期处理 MUST 独立于模型 token、正文持久化和原执行续租。每次写出 citation、delta 或 done 前均须核对许可仍有效；模型长时间无输出、写入队列堵塞或进程恢复运行时也不得继续使用过期许可。服务端只能承诺停止本地输出和取消订阅，不能宣称撤回已发送数据或供应商停止计费。

#### Scenario: 上游阻塞且持久化缓慢
- **WHEN** 模型没有新 token，或正文保存阻塞，而身份许可过期或被撤销
- **THEN** 独立停止本地流和取消订阅，不等待下一条 token、数据库恢复或账本写入完成

#### Scenario: 暂停进程恢复
- **WHEN** AI 进程恢复时本地许可已经过期，仍有之前排队的引用、正文或 done
- **THEN** 写出前拒绝这些内容并终止该执行，不能先发送缓存再检查身份

### Requirement: 轮次执行资格必须随账号认证代次撤销

轮次执行资格 MUST 绑定开始时的认证代次。预留调用、派发、来源封存、增量追加和续期均须核对当前资格；撤销后的旧票据不得读取新材料、继续模型调用、追加正文或转为成功。仅已有合法终态可保持不变，撤销后不得向原客户端补发正文或成功 done。

#### Scenario: 旧执行票据继续写回
- **WHEN** 用户已离职或认证代次变化，生成服务使用原执行票据请求追加、续期或派发
- **THEN** 拒绝继续执行，不追加新的助手正文、不产生新的模型调用意图

#### Scenario: 完成与撤销并发
- **WHEN** 正常完成提交与账号撤销同时发生
- **THEN** 按提交时当前资格判定，先合法提交的完成状态不被覆盖；先撤销则不能再提交成功
- **AND** 本地输出仍受短时许可约束，已经停止的流不能补发成功事件

### Requirement: 账号撤销后必须保留受限的取消与结算能力

撤销后合法服务 MUST 仍可使用绑定原执行的资格封存已确认前缀、取消轮次、释放并发及生成或重试固定账本意图，不能读取新历史或恢复生成。离职导致的取消 SHALL 使用 CANCELLED 和固定原因 ACCOUNT_REVOKED；身份依赖故障按既有失败或中断规则处理，不伪报已确认离职。

#### Scenario: 离职时模型已调用但无可靠 usage
- **WHEN** 账号撤销发生在模型调用意图建立之后，但没有可靠最终用量
- **THEN** 有界停止输出，按既有 UNKNOWN 语义结算并释放执行占用，不伪造成功或零用量

#### Scenario: 离职时尚未调用模型
- **WHEN** 账号在调用意图建立之前被撤销
- **THEN** 取消执行并保留 NOT_INVOKED 语义，不因取消补建模型调用

#### Scenario: 取消持久化或结算失败
- **WHEN** 本地输出已停止，但终态写入或费用结算依赖不可用
- **THEN** 保留可恢复的原执行和固定结算意图，恢复后幂等收尾，不延长输出或把账本成功伪作撤销时限的前提

#### Scenario: 试图通过收尾路径重新生成
- **WHEN** 调用方用合法旧结算或取消资格请求新材料、正文追加或模型派发
- **THEN** 拒绝该请求；原用户会话过期不妨碍纯结算，但纯结算也不授予业务访问
