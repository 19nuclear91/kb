# Proposal

## Why

当前文档中心一次只能上传一个文件，缺少可跨刷新、重新登录查询的导入清单；单文件上传也没有持久幂等回执，响应丢失后重新提交可能创建重复文档。需要建立逐项可核对、可主动恢复的批量导入流程，降低集中整理知识资料的操作成本。

## What Changes

- 支持浏览器本地多选及拖拽文件；每批统一目标空间和密级，每项标题可编辑并默认使用文件名，提交后冻结整份清单。
- 新增本人导入任务、文件项及上传尝试记录，任务与受理结果跨刷新、跨登录保留；未传完的文件由用户重新选择并核对后主动继续。
- 通过独立的逐项上传协议提供批次创建幂等、项级并发互斥和持久受理回执。同一项重试至多创建一份文档；不同项或新批次允许同名、同内容的新文档，已有文档更新继续由明确的版本上传入口承担。
- 文件逐项受理，允许部分成功。单项明确失败不回滚已受理项；结果未知先读取服务端状态，禁止自动重传；身份失效或目标空间上传资格丧失时暂停后续上传。
- 新增“我的导入任务”及固定任务详情，分别展示上传受理事实与当前有权查看的解析、审核、发布状态；上传资格与文档阅读资格保持独立。
- 上传前登记尝试对象键，文档、版本、解析任务和项受理回执同事务提交；失败或失效尝试使用新执行代次及新对象键恢复，协调对象存储对账，防止未知提交后的误删和失效执行的迟到写入。
- 增加有界批次、文件、并发及查询限制，通过 Mock、内存替身与模拟 DOM 覆盖后端、前端及网关的进程内离线回归，保留类型检查、构建和包体隔离。

## Capabilities

### New Capabilities

- `document-imports`: 本人批量导入任务、固定清单、逐项幂等受理、上传执行恢复、任务查询、权限和资源限界。

### Modified Capabilities

- `user-web-documents`: 增加批量选择、任务列表与详情、文件匹配、队列调度、部分失败和跨会话恢复交互；明确新批量协议与既有单文件上传的不确定结果处理。
- `storage-reconciliation`: 将仍有合法提交资格的导入尝试对象纳入清理保护，确保租约失效、原子转为版本引用及失败对象回收的一致性；缺失版本检测保持原口径。

## Impact

- `kb-app`：新增 `document/imports` 业务包及 Flyway 迁移；新增 `/api/document-imports` 系列接口；复用文件策略、身份/空间授权、文档版本创建和解析队列，补充对象对账引用查询。
- `kb-web`：新增导入队列及任务页面，接入现有 Session、精确整数 JSON、路由懒加载、页面恢复与当前身份隔离；保留单文件和已有文档版本上传入口。
- `kb-gateway`：dev/prod 增加导入 API 路由及独立有界上传响应等待，保留认证门禁和真实错误状态。
- `kb-common` / `kb-worker`：复用现有文件策略、公共错误约定和解析契约；不需要新增消息中间件或浏览器持久文件缓存。
- `docs` 与模块测试：补充批量导入操作说明、恢复状态和发布顺序，并记录实际离线验证证据。本变更不交付或执行依赖前后端联调、真实应用/浏览器及外部组件的集成测试，也不编写说明文档内容或存在性断言测试；文档采用人工审阅。
- 首期范围为新建文档的本地多文件导入；文件夹、ZIP、外部链接、自动同名覆盖、全库内容去重和分片断点续传属于另行需求。
