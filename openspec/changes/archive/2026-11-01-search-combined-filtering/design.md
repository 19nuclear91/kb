# Design

## Context

动机见 `proposal.md`。本变更涉及搜索后端、前端候选选择、网关响应保护以及权限和性能边界，符合需要独立设计的条件。

当前关键实现：

- `kb-app/.../search/web/SearchRequest.java` 只有 query、candidates、topK；`SearchInputAdvice` 在反序列化前限制正文，现有 `SearchTextOnlyControllerTest` 明确覆盖忽略伪造身份等未知字段的 200 行为。
- `SearchService` 负责准入、总截止、权限解析、Embedding、召回和 rerank；`QueryRetrievalService` 通过 `SearchTransaction` 在实际召回前复核 profile。`SearchMapper.xml` 在两路 WHERE 中约束权限和当前版本，再 LIMIT、RRF。
- 文档列表的 `MetadataQueryMapper.xml` 已表达分类后代、标签全部匹配、文件类型与时间语义。V27 已有分类树、标签关系及相关索引。
- `CategoryService.filter`、`TagService.filter` 面向文档列表可见范围，包含合法可查看的未发布候选，不直接满足搜索候选语义。
- `kb-web/src/pages/Search.tsx` 使用一个关键词表单；`documents/metadata/Selectors.tsx` 已有分层分类和标签分页组件。`MetadataFilters` 自带文档列表表单和 UNPUBLISHED 类型，不能整体嵌入搜索表单。
- 网关已路由 `/api/search/**`。`GlobalExceptionHandler.isSearchRequest` 当前只识别精确 `/api/search`，新增子路径需要一起覆盖。ArchUnit 要求服务层边界，搜索不能直接调用文档模块 mapper。

## Goals / Non-Goals

**Goals:**

- 让一份不可变筛选值贯穿验证、双路召回和降级；授权范围与用户选择分开传递。
- 用数据库当前文档关系完成筛选，保持同一召回语句的一致快照，避免元数据副本同步。
- 搜索专用候选与实际召回共用发布及权限规则，复用已有选择组件的分页体验。
- 对旧服务忽略新字段的情况提供可观察、可拒绝展示的协议边界。

**Non-Goals:**

- 不新增服务、模型、消息队列、分块元数据副本、业务表或向量迁移。
- 不改变当前相关性算法和命中数量契约；候选不计算关键词分面或命中计数。
- 不修改 AI 的轮次输入、历史、幂等或来源封存协议。

## Decisions

### D1. 扩展原 POST 请求，限定解码到搜索端点

主搜索采用扁平可选字段，与文档中心命名一致：

```json
{
  "query": "报销流程",
  "candidates": 50,
  "topK": 20,
  "spaceId": 12,
  "categoryId": 34,
  "tagIds": [56, 78],
  "fileType": "PDF",
  "updatedFrom": "2026-10-01T00:00:00+08:00",
  "updatedTo": "2026-11-01T00:00:00+08:00"
}
```

保留 `SearchInputAdvice` 的配置化实际字节上限，默认 128 KiB。在搜索专用解码器中检查根对象、未知字段、重复属性、尾随 JSON、精确整数和 Unicode，再构造请求；不修改应用全局 ObjectMapper。

- query 的 8000 code point 上限和原文本保持原规则，不进行自动查询改写。
- candidates/topK 的省略或 null 继续使用现有默认值，保留 topK 大于 candidates 的合法行为。
- 筛选的省略、null、数组、布尔和时间规则完全按 `search-filtering`。时间转换为时间点比较，正整数不经浮点转换。
- 未知字段统一 400，包括原来被忽略的身份、裸向量、profile 字段。这是已在 proposal 标记的请求校验收紧；合法的既有三字段请求保持兼容。

备选：嵌套 filters 可以分组，但与既有文档查询字段不一致；全局开启严格 Jackson 会影响其他 API，均不采用。

### D2. 筛选值对象与权限集合明确区分

在搜索模型中引入不可变 `SearchFilters`，空实例代表不限。标签在完整校验后按 ID 排序并防御性复制。服务的旧无筛选重载委托空实例，新增重载向 `execute`、`retrieve`、`QueryRetrievalService` 和 `SearchMapper` 传递同一值。

权限仍由 `PermissionService` 解析。Mapper 的授权 `spaceIds` 与用户选择的 `filters.spaceId` 使用不同参数，不能把用户选择直接放入授权集合，也不能以“所选空间不在空间授权列表”提前拒绝合法文档例外。空授权依旧走现有拒绝全部谓词；空筛选不改变授权。

备选：复用 `MetadataInputs.Query` 会混入标题查询、列表页码和 UNPUBLISHED，错误地耦合两个接口，因此只复用字段规则和适当的纯值工具。

### D3. 同一条召回 SQL 在每路 LIMIT 前筛选

在 `SearchMapper.xml` 提取可复用的当前已发布分块基础谓词和组合筛选片段，供 BM25、向量及候选依据引用。

```text
SearchRequest --> SearchFilters + PermissionScope
                            |
                +-----------+-----------+
                v                       v
        BM25 + base + filters   Vector + base + filters
                |                       |
              LIMIT                   LIMIT
                +-----------+-----------+
                            v
                       RRF --> rerank --> topK
```

- spaceId、categoryId、tagIds、updatedAt 取 `kb_document` 及当前关联表；现有分块的空间、密级冗余过滤继续保留。
- 分类后代在同一语句内通过递归 CTE 表达，限定根分类实际空间，遵守既有最大八层结构并防止重复节点；与文档空间相交。categoryId 可以独立提交。
- 对每个已验证 tagId 使用 EXISTS，避免 JOIN 标签造成分块和 RRF 名次倍增。
- 类型判断在各路截取前关联当前版本，沿用 `DocumentFileTypes` 提供的规则；最终固定引用仍为原 docId/versionId/chunkId。
- 不先查询一批文档 ID 到 Java 再拼 IN，不把分类/标签名称或摘要传给 Embedding 或 rerank。
- profile 变化仅关闭向量分支，筛选参数始终存在；rerank 回退使用已经筛选的本次候选。

全部关系计算纳入原召回阶段剩余预算。一次 SQL 的语句快照使 BM25、向量分支读取同一组资料事实；下一次请求看到已提交的资料、分类树和搬迁变化。

备选：召回后过滤会浪费候选名额；把标签和分类冗余到每个分块会引入额外更新与一致性协议，因此不采用。

### D4. 增加搜索用途的候选读取

新增 `POST /api/search/categories`、`POST /api/search/tags`，请求和结果见 `search-filtering`。候选由搜索自身的只读服务及 mapper 实现；Java 不引用文档 mapper，通用文件类型规则通过文档元数据 model 中的纯值规则复用。

候选依据是：当前文档 published、当前版本及其实际分块存在、空间未归档、当前 ACL 和密级满足。使用与召回同源的基础谓词，不要求 active 向量 profile，因此维护期间授权 BM25 仍能贡献候选。

分类先从上述文档直接使用的节点构造可见节点集合，再补必要祖先，按 parentId、sortOrder/id 分层读取。路径仅投影这些节点的必要祖先。标签在本人全局可检索文档上做 EXISTS，含停用关系，nameQuery 采用字面 ILIKE 转义。两者均不接受正文关键词、其他组合条件或命中数量请求。

候选仅说明当前范围内存在关联，不保证任意关键词或组合条件都能命中。文档中心的候选 API 保持原语义，不能让两个用途互相回退。

备选：直接复用旧候选服务会暴露用户能看但不能全文检索的首版候选条目；每次输入重新执行动态分面增加搜索负担和交互复杂性，因此采用独立稳定目录。

### D5. 候选分页、预算和不可见上下文的处理顺序

分类返回 items、hasMore、nextCursor、treeVersion；标签返回 items、hasMore、nextCursor。每页最多 100 条，以多取一条判断 hasMore。游标编码可复用现有纯编码工具，但用途必须是搜索专用，并绑定当前用户、资源/父节点、名称条件和位置；分类另绑定树版本，禁止使用文档中心游标。

分类请求顺序：

1. 验证输入及游标结构、用途、用户、请求上下文。
2. 在 AUTHORIZATION 阶段经 `principalOf` 解析当前主体、显式 `requireEnabled`，再复用同一主体解析权限；停用身份直接拒绝。在有预算的同一只读快照中确认上下文是否仍有可见节点。
3. 无可见上下文时返回统一空页及 treeVersion=0；不读取后再向调用方泄露隐藏目录的树冲突。
4. 可见上下文再核对游标树版本，不符返回 409；合法时读取当前页和路径。

候选通过 `SearchExecutor` 共享现有实例/用户实际在途名额。使用 AUTHORIZATION、RETRIEVAL、RESPONSE 阶段和原总截止，不调用模型或关键词召回。为目录元数据与路径多次读取提供 `SearchTransaction` 的只读 REPEATABLE_READ 变体，仍设置同连接 statement_timeout、lock_timeout 与实际取消。正文在读取时限制为 16 KiB，输出沿用搜索默认 4 MiB 上限；有界编码可将原编码器扩展为内部通用 R 载荷，原主搜索接口保留。

候选计数不解释成正文检索命中数；观测仅使用固定的操作类别区分主搜索、分类候选和标签候选，维持低基数。

备选：新增候选线程池及独立容量会使同一页面绕过现有资源预算；无限加载目录不符合已有分页边界，因此共享执行设施并保留有限页面。

### D6. 用响应版本头确认筛选执行能力

新主搜索的所有 200 成功响应增加 `X-Search-Filter-Version: 1`，包括空结果、无筛选和降级。该头由实际执行搜索的 app 产生；网关和代理只透传，不固定添加，也不改变原 R 数组。

前端搜索 API 使用现有 Session 的原始 Response 能力：先检查状态和身份代次，再在存在有效限制时检查版本头，最后解码成功数组。缺失或值不精确为 1 时取消/丢弃正文，显示固定“无法确认服务端筛选支持”提示；这些材料不能进入结果、收藏状态查询或引用抽屉。有效限制判定基于规范化字段，null 空间/分类、false 和空标签不是限制。

无筛选请求不要求版本头。新候选端点的 404 显示候选不可用，不映射为空成功、不回退旧候选。

备选：只靠前端构建开关或先探测一次能力，无法保证后续请求不会落到旧实例；更改成功 JSON 包装会影响 AI 和原客户端，因此采用每次响应的附加头。部署仍要求先更新所有后端再发布新页面。

### D7. 前端复用选择组件，分离目录与搜索状态

在搜索功能目录中建立请求构造及候选 API 封装，为 `CategoryBrowser` 和 `TagPicker` 增加明确的 search 用途或注入读取策略；保留其文档编辑、管理和文档中心行为，不嵌套完整 `MetadataFilters` 表单。

- 空间沿用既有可查看且未归档目录，不通过搜索候选额外暴露文档例外所属空间名称。不选空间时服务端仍检索所有合法例外文档。
- 关键词和五类筛选保存为草稿，提交时冻结已提交快照；条件摘要与结果绑定该快照。修改草稿、清除筛选或候选名称查询都不自动发起正文搜索。
- 切换空间清空分类及未分类标记，分类请求更换代次；标签全局候选与已选 ID 保留。父分类标注包含后代，标签标注全部匹配，停用项标注状态。
- 标签名称查询、分类层级分页与正文搜索各有独立 AbortController/代次。旧目录响应不能污染新空间，旧搜索响应不能覆盖新提交。
- 标签名称输入框的 Enter 只提交标签查询，阻止外层表单提交；输入法确认文字时不发起查询。
- 目录故障停止新候选选择并提供主动重读，不自动删除既选限制；分类树冲突停止拼页并重新读取目录。用户显式修改限制后才提交新的搜索。
- 使用既有大整数 JSON 编码，ID 不经 Number。时间输入转为带时区时间点；fileType 采用发布类型子集。
- 离页、隐藏、退出、身份变化清理草稿、已提交快照、目录、游标、结果与引用；恢复后按当前身份重新读取目录，正文搜索保持用户显式提交。

备选：对现有 hits 在浏览器筛选无法补回被 topK 截掉的材料；表单每次变化自动查询会改变已确认的显式提交交互，因此都不采用。

### D8. 完整覆盖搜索子路径的响应保护

搜索主接口及新增候选由精确路径集合识别，纳入固定消息、脱敏错误日志及 no-store 响应策略，包括解码、认证、强制改密、容量和未知异常。网关对同一路径集合的提前拒绝也设置 no-store；核对 `/api/search/**` 的现有目标路由和版本头透传。现有允许的跨源开发配置如需读取新头，则仅扩展 exposedHeaders，不增加来源权限。

权限服务自身的身份解析失败日志同样只输出固定阶段、枚举错误类别和状态，不记录原始异常消息或原因链；验证同时覆盖实际权限服务与 HTTP 异常处理链路。

备选：仅在 Controller 成功返回时设置响应头会遗漏拦截器和网关错误路径，因此覆盖完整响应生命周期。

### D9. 验证限定为离线单元测试与静态检查

- 后端仅执行进程内单元和架构测试。解码器、standalone MockMvc、服务和异常处理器的依赖均使用内存 Mock/Stub，数据库连接、Statement、认证和模型调用使用无真实连接的替身；受控时钟验证预算、取消及释放逻辑，不启动应用或监听 HTTP 端口。
- 前端仅使用模拟 DOM、内存路由和请求替身进行单元/组件测试，覆盖草稿/提交分离、空间切换、全局标签、分页错误、旧响应、隐藏清理、原版本引用及旧后端缺头；不启动真实浏览器或开发服务器。
- 网关仅测试路由谓词和过滤器组件，请求、响应及下游均由内存替身提供，不启动网关、下游应用或测试 HTTP 服务。
- SQL 的过滤位置、关联去重、当前版本、文档例外、分类后代、标签及时间约束通过代码审查核对；编译和 Mapper 替身仅验证接口、参数传递、服务编排及投影。既不执行实际 MyBatis 查询，也不通过读取 XML/SQL 文本的自动断言代替查询行为验证。
- 本变更不编写或执行集成、端到端或进程烟测，不启动 PostgreSQL/ParadeDB、Redis、MinIO、Docker、模型等外部组件，不执行迁移，不保留可选外部测试入口。现有测试只按已确认符合上述范围的明确名单运行。
- 交付验证包含模块编译、上述单元/组件/架构测试、前端类型检查、静态构建及 OpenSpec 结构校验。说明文档仅编写和人工审阅，不针对 README、Markdown、Javadoc、文档示例或 Java/XML/SQL 源文件文本编写测试。

## Risks / Trade-offs

- [组合条件与 HNSW 近似召回可能返回不足] → 保持权限和筛选语义，不通过减少条件补满结果；本次离线验证不承诺实际召回率或执行计划，也不预先扩大索引或预算。
- [分类递归及候选存在性查询增加成本] → 复用 V27 索引，同语句计算后代，候选有限分页，纳入总截止；后续索引调整以实测为依据。
- [稳定全局标签与当前空间没有交集] → 明确全部匹配，允许合法空结果，用户主动调整条件；目录不承诺关键词命中。
- [候选与正文搜索共享并发名额] → 每个读取流仅一个活动请求，页面明确提示 429/503 并支持主动重读，不自动形成重试循环。
- [分类/标签更新与候选、搜索之间发生变化] → 每次重新授权和读取当前关系；类别树游标检测变更，已提交搜索按 ID 执行，不依赖旧名称快照。
- [旧实例静默忽略筛选] → 严格的新解码、每次响应版本头及先后端后前端的发布顺序；旧无筛选请求继续兼容。
- [离线替身不能证明真实 SQL、索引选择与数据库隔离] → 验证记录明确区分单元测试、代码审查和编译的结论范围，不将其表述为真实数据库或端到端验收。

## Migration Plan

### 实施中确认的架构修复

2026-11-01 离线回归暴露已有文档元数据模块的分层依赖与跨空间 Mapper 依赖，用户确认纳入本次修复范围：`MetadataInput` 的非 HTTP 解码移至 support，HTTP 请求适配保留 web；`DocumentFileTypes` 纯规则移至 model；`MetadataAccess` 经 `SpaceQueryService.findManaged` 取得同一主体可管理的当前空间事实。保持原校验、缺失投影及归档语义，补跑元数据、空间读取和搬迁的进程内测试，不放宽架构规则。

### 发布说明

以下仅作为交付文档中的发布与回退说明，本变更的开发任务不执行部署、迁移或外部环境核查。

1. 无新增 DDL。交付适配既有 V28 数据结构的 app、gateway 构建产物及筛选协议、候选查询和响应保护说明。
2. 先更新全部 app 与 gateway 实例，确认主搜索有版本头、新候选接口可用，再发布新前端；不由代理补版本头。
3. 新前端继续兼容合法无筛选调用；若带条件响应缺少版本头，明确提示并保留输入，不能假称筛选成功。
4. 回退优先恢复旧前端或撤下筛选入口，再回退后端。只回退后端时新页面会拒绝带条件成功结果；无数据回填、索引重建或逆迁移。
5. 实施时只补充 D9 范围内的离线验证记录，说明实际执行的命令与结果；部署操作及真实数据库、浏览器端到端验证不属于本任务清单。
