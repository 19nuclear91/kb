# Proposal

## Why

文档中心已经支持元数据组合筛选，知识搜索仍只能在全部可见内容中召回，用户难以按空间、分类、标签、文件类型和时间定位资料。将同一组组织规则接入权限受控的混合检索，可以在保持相关性排序和固定版本引用的同时缩小检索范围。

## What Changes

- 为 `POST /api/search` 增加可选的空间、分类及未分类、标签、文件类型和更新时间条件；条件按 AND 组合，多个标签全部匹配，关键词保持必填。
- 筛选在 BM25 和向量两路召回截取候选之前执行，Embedding 与 rerank 降级仍保留同一组条件；读取当前文档资料和当前发布版本。
- 增加搜索专用的分类、标签候选查询，仅反映当前用户可检索的已发布文档；分类保留必要祖先，标签包含仍有关联的停用项。
- 知识搜索页面复用分类、标签选择交互：分类随空间切换，标签使用全局候选，候选目录独立加载，点击搜索统一应用草稿；保持片段结果和引用查看方式。
- 成功搜索响应增加筛选协议版本标记，前端在展示带条件结果前确认支持，防止旧服务静默忽略筛选。合法无筛选请求及 AI 既有调用继续兼容。
- **BREAKING**：搜索请求的未知字段、重复字段及不合法的筛选类型明确返回 400，替代原先忽略未知字段的行为；夹带身份或裸向量字段也按非法输入拒绝。

## Capabilities

### New Capabilities

- `search-filtering`：组合条件语义、召回前筛选、搜索专用已发布候选、候选分页及筛选协议确认。

### Modified Capabilities

- `search-resilience`：扩展筛选输入验证，确保筛选计算进入既有时间预算，降级保留全部条件。
- `search-query-confidentiality`：搜索条件与候选名称查询经 POST 请求体传输，严格拒绝未知输入，扩展搜索子路径的日志与响应保护。
- `user-web-documents`：知识搜索支持显式提交组合条件、独立候选目录、筛选协议确认及相应页面生命周期。

## Impact

- `kb-app`：搜索请求解码、服务参数传递、`SearchMapper.xml`、搜索专用候选读取、错误响应与日志路径识别；复用现有分类、标签、文件类型和权限规则。
- `kb-web`：`src/pages/Search.tsx`、搜索 API 封装、`src/documents/metadata/Selectors.tsx` 的用途扩展及相关行为测试。
- `kb-gateway`：核对既有 `/api/search/**` 路由，保护候选响应并透传筛选协议版本头。
- 首期使用既有 V27 分类标签表与索引，不增加业务迁移、解析任务或向量重建；性能证据不足时再单独决定索引调整。
- 用户范围为知识搜索页面；AI 会话筛选、动态命中分面、搜索结果分页及命中总数不属于本变更。
