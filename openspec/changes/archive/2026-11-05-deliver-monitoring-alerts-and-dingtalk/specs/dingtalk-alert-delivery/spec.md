# Spec Delta

## Purpose

为知识库运行告警提供独立且受控的钉钉通知边界，将受认证的聚合告警转换为有限的中文消息，明确外部发送成功、失败重试、资源限制和可观测语义，避免影响业务处理或泄露业务资料。

## ADDED Requirements

### Requirement: 通知适配器必须独立运行且拒绝不完整配置

适配器 SHALL 独立启动，运行不依赖业务数据库、Redis、用户会话或业务服务。入站服务凭据、钉钉机器人凭据、加签密钥、环境／部署身份和管理链接根地址 MUST 显式配置；缺失、示例值或非法配置须在接收通知前安全失败。凭据 SHALL 从受控文件加载，启动错误只能报告配置名或固定类别。

#### Scenario: 未配置钉钉凭据
- **WHEN** 适配器缺少必要的凭据文件或文件内容无效
- **THEN** 不接受待发送通知，不使用示例机器人、空签名或日志成功替代外部发送

#### Scenario: 业务依赖中断
- **WHEN** PostgreSQL、Redis 或主应用不可用，但监控和钉钉网络仍可用
- **THEN** 适配器仍可接收并投递已经形成的合法聚合告警

### Requirement: 聚合通知入口必须使用独立服务认证

适配器 SHALL 通过内部 `POST /internal/alerts/dingtalk` 接收通知，要求独立 Bearer 服务凭据，不接受业务用户令牌替代。认证 MUST 在请求解析和发送前执行；缺失或错误返回 401，不发外部请求。凭据比较和日志不得泄露原值，响应 SHALL 为 no-store。

#### Scenario: 未认证请求
- **WHEN** 调用方没有提供有效入站凭据
- **THEN** 返回固定 401，无钉钉调用、无正文回显

#### Scenario: 持有用户会话
- **WHEN** 请求只有知识库用户的 satoken
- **THEN** 不获得通知发送资格

### Requirement: 接收协议必须有界并保持原始聚合状态

入口 SHALL 接受 Alertmanager 标准 Webhook version=4、UTF-8 JSON 和 firing／resolved 状态，校验必要身份、时间及告警项结构。请求体、条目数、嵌套深度和字符串长度 MUST 有界；损坏结构或重复属性返回 400，超大载荷返回 413，不发送部分通知。未知元数据可有界忽略，不成为消息内容或地址。

#### Scenario: 同组包含不同状态
- **WHEN** firing 组中同时含 firing 与 resolved 条目
- **THEN** 消息保持组的 firing 状态，并准确区分实际接收条目的状态数量

#### Scenario: 上游截断了告警列表
- **WHEN** truncatedAlerts 大于零
- **THEN** 消息明确说明还有未包含条目，不声称本地条目就是完整清单，也不据此推断全部恢复

#### Scenario: 无效或超大请求
- **WHEN** 载荷状态、条目、时间无效，或超过配置资源边界
- **THEN** 返回对应 400 或 413，不调用钉钉且不把损坏数据当作空成功

### Requirement: 通知内容必须由受控模板生成

适配器 SHALL 按固定告警目录生成中文故障及解除消息，只展示受配置约束的环境、部署、服务、级别、时间、数量、固定摘要与管理入口。不得原样转发 annotations、任意 URL、任务／用户标识或完整标签。未知告警类型或不匹配的服务／部署身份 MUST 拒绝，不以任意文本模板兜底。

#### Scenario: 上游注解含敏感文本
- **WHEN** 合法告警的 annotation 含问题、正文、凭据或远程错误文本
- **THEN** 这些内容不进入钉钉消息、响应或日志，消息仅使用固定摘要及有界结构事实

#### Scenario: 消息超出长度
- **WHEN** 合法聚合内容不能完整放入单条消息
- **THEN** 保留状态、摘要、数量及管理入口，以 Unicode 安全方式省略细节并标注，不拆成无界多条发送

#### Scenario: 条件解除通知
- **WHEN** 收到 resolved 组
- **THEN** 使用“告警条件已解除”文案，并提示核对采样和当前状态，不把规则消失表述为端到端业务验收成功

### Requirement: 管理链接必须由部署配置和固定路径构造

管理与面板链接 SHALL 来自服务端配置的根地址和固定告警目录，不采用请求中的 externalURL、generatorURL 或任意链接。链接不得携带会话令牌或绕过原系统鉴权；生产根地址 SHALL 使用明确 HTTPS 来源，开发替身地址必须显式隔离。

#### Scenario: 请求夹带外部地址
- **WHEN** Webhook 元数据含攻击者地址或非预期的管理链接
- **THEN** 适配器不访问或展示该地址，仍仅使用受控入口

#### Scenario: 收件人无管理资格
- **WHEN** 收件人打开死信或 AI 管理入口但没有对应权限
- **THEN** 原应用继续按当前身份拒绝，通知不提供额外资料或凭据

### Requirement: 钉钉出站请求必须隔离并经过加签

适配器 SHALL 只向配置选定的钉钉群机器人发送加签消息，包含有效时间戳和签名。出站 MUST 禁止自动重定向，不传播入站 Authorization、Cookie、用户令牌、traceparent、tracestate 或 baggage。机器人目标不能由通知载荷更换；远程错误体和含 token 的地址不得进入日志或监控标签。

#### Scenario: 正常出站
- **WHEN** 有效通知通过准入并发送
- **THEN** 发送受控 Markdown 消息及按机器人密钥计算的签名，使用独立有界超时

#### Scenario: 钉钉返回重定向
- **WHEN** 目标返回重定向响应
- **THEN** 不跟随新地址，不向第二个主机发送消息或凭据，并按发送失败处理

### Requirement: 成功回执必须以钉钉业务确认作为依据

适配器 SHALL 仅在钉钉返回成功 HTTP 状态且有界 JSON 响应确认 errcode 为整数零时向 Alertmanager 返回 204。非零业务码、损坏响应、超时或网络失败 MUST 返回固定 503，不伪造成功。单次接收最多发起一次出站尝试；不自动重试 POST，后续重试交由 Alertmanager。

#### Scenario: HTTP 成功但业务拒绝
- **WHEN** 钉钉返回 HTTP 200，errcode 非零
- **THEN** 适配器返回 503，记录固定失败类别，不确认已送达

#### Scenario: 业务成功
- **WHEN** 钉钉成功响应包含合法整数 errcode=0
- **THEN** 适配器返回 204，发送成功计数只增加一次

#### Scenario: 发送结果不确定
- **WHEN** 已发送请求但响应丢失或调用方先断开
- **THEN** 不报告已确认成功，不启动后台补发；后续重试可能重复通知，不能保证恰好一次

### Requirement: 限流和超时必须限制单实例资源

适配器 SHALL 对同一机器人执行单实例滑动窗口限流，并限制并发出站和单次总时长；每次实际尝试均占用速率预算，包括失败。超过容量 MUST 立即返回 503，不创建无界队列或提前返回成功。首期仅支持单实例，进程重启后的内存限流不构成跨重启或多实例的全局额度保证。

#### Scenario: 瞬时告警洪峰
- **WHEN** 请求超过速率或并发上限
- **THEN** 多余请求被安全拒绝且不调用钉钉，Alertmanager 按既有失败机制处理

#### Scenario: 连续上游失败
- **WHEN** 多次实际请求均被钉钉拒绝
- **THEN** 失败尝试仍受相同速率上限限制，不能绕过额度持续发送

#### Scenario: 适配器重启
- **WHEN** 适配器在速率窗口内重启
- **THEN** 运维说明揭示内存状态重置，验收不宣称跨重启精确限流或持久去重

### Requirement: 投递指标不得包含敏感或无界维度

适配器 SHALL 暴露请求结果、出站结果、发送耗时、当前并发及限流次数，标签只能为固定结果／原因枚举。日志只记录安全类别和受限运维身份，不记录原始请求、消息正文、响应体或凭据。健康检查 SHALL 反映本地配置和进程状态，不主动发送钉钉消息，不将本地就绪等同于远程可达。

#### Scenario: 钉钉拒绝
- **WHEN** 一次请求被钉钉拒绝
- **THEN** 固定失败指标增加，可定位发送故障，但原始业务错误体和机器人 URL 不被导出

#### Scenario: Prometheus 抓取
- **WHEN** 监控读取适配器指标或健康端点
- **THEN** 不产生钉钉调用或业务依赖访问，端点按监控网络访问策略隔离

### Requirement: 协议验证必须覆盖失败与重复边界

本变更测试 SHALL 使用注入的进程内内存传输替身，覆盖签名、认证、业务错误、响应丢失、超时、重定向、限流、截断与解除通知，不启动 HTTP 替身服务、Alertmanager、其他外部组件或真实群发送。测试结果 MUST NOT 由 HTTP 成功、模拟成功或配置校验推断真实送达；本变更不交付真实群验收入口。

#### Scenario: 默认执行测试
- **WHEN** 执行本变更的协议测试
- **THEN** 通过内存传输替身模拟响应和异常，不监听 HTTP 端口或访问真实钉钉

#### Scenario: 故障后重投
- **WHEN** 首次模拟发送失败，测试在进程内再次提交相同聚合状态以模拟 Alertmanager 重投
- **THEN** 适配器重新按当前准入和签名发送，只有本次明确成功才确认，不用失败缓存伪造成功
