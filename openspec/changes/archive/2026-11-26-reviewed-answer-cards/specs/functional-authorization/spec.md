# Spec Delta

## ADDED Requirements

### Requirement: 答案卡必须使用独立维护与审核功能资格

服务端固定目录 SHALL 定义 `answer:card:write` 和 `answer:card:review`，分别保护卡片创建、保存、送审及合格责任人确认，和非自审批准、驳回。两项按当前有效主体的角色权限并集精确匹配，彼此不蕴含；空间 edit、review、manage、space:manage-all 或管理员角色名称都不能单独代替。功能资格不授予卡片空间或来源文档的读取权。

#### Scenario: 目录可配置专门人员
- **WHEN** 合格角色管理者查询权限目录并分别为业务编辑与审核角色绑定新权限
- **THEN** 两项 code 与用途可查询及配置，角色持有者仍须另满足当前资源范围

#### Scenario: 仅有原空间审核权
- **WHEN** 用户有空间 view/review，但没有 answer:card:review
- **THEN** 不能审批答案卡，不因原文档审核资格扩大到新业务

#### Scenario: 下一次请求撤销
- **WHEN** 用户全部角色中的卡片维护资格被撤销
- **THEN** 下一次维护、准确性确认及相关回执核对拒绝，既有会话不延续资格

### Requirement: 卡片动作资格必须与所属空间和来源访问合取

维护 SHALL 同时要求 answer:card:write、卡片所属空间当前 view/edit；审核要求 answer:card:review、空间 view/review 及非自审条件。内容读取和处理必须按相应修订核验全部来源当前访问。普通卡片阅读不要求上述功能权限，仍须空间 view 与全部来源访问及展示条件。责任人管理只使用空间 manage 或 space:manage-all，响应限最小管理投影。

#### Scenario: 功能权限没有空间范围
- **WHEN** 用户持有卡片写权限但在目标空间没有 edit
- **THEN** 不能创建或修改该空间卡片，不把全局功能资格解释为跨空间编辑

#### Scenario: 文档例外不能授权卡片空间
- **WHEN** 用户只有来源文档的 view 例外而没有卡片所属空间 view
- **THEN** 无法读取卡片，来源例外仅用于来源自身的访问核验

#### Scenario: 管理者无内容访问
- **WHEN** 用户只有当前空间管理资格
- **THEN** 可以查看卡片最小管理清单和配置合格责任人，不能读写答案或代为审批、确认

### Requirement: 卡片鉴权必须先于回执与私有事实披露

新增卡片动作 SHALL 先核当前身份与对应精确资格，再核目标空间及内容访问，最后读取私有回执和可披露冲突事实。每次匹配重放或核对必须重新鉴权；缺功能资格为 403，目标不存在或越资源范围统一 404。无来源草稿使用所属空间规则，创建回执按原空间及当前维护资格核对，不因尚未知卡片 ID 放宽鉴权。

#### Scenario: 撤权后重放批准
- **WHEN** 审核人曾批准成功，随后失去审核功能资格再重放
- **THEN** 返回 403，不返回旧轮次回执或正文

#### Scenario: 猜测他人回执
- **WHEN** 用户提交他人的请求标识或不同目标绑定
- **THEN** 不返回该人的回执、目标存在信息或原始输入

### Requirement: 卡片权限初始化必须一次性且保留撤权

新迁移 SHALL 仅向当时已有 ROLE_ADMIN 一次性绑定两项卡片权限；空库正式引导新管理员时纳入完整目录。其他角色不隐式获权，后续启动和重复引导不得补回已撤销绑定。新增绑定前排空不认识新目录的旧 app；保留未知权限拒绝启动规则，不删除绑定或数据伪装兼容回退。新增功能资格不修改任何空间或文档 ACL。

#### Scenario: 存量与空库
- **WHEN** 存量系统首次升级，或空库后来正式引导新管理员
- **THEN** 分别获得一次性绑定或完整目录，其他主体及资源授权保持原事实

#### Scenario: 撤销后重启或旧版回退
- **WHEN** 新权限被撤销后重启，或旧二进制在新权限仍存在时启动
- **THEN** 前者不恢复权限，后者按未知目录约束拒绝启动
