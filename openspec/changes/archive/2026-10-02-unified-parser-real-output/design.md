# Design

## Context

当前解析流水线已经有结构块、来源坐标和解析问题模型，但默认解析器仍可退化为纯文本，发布结果只写入分块正文、页码和标题路径。现有数据库以
`kb_document_version.index_status` 表示发布状态，以 `kb_doc_chunk` 保存检索字段；Worker 与主应用通过同一套 PostgreSQL
表协作。详见 proposal.md 和 `specs/document-parsing/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让统一结构模型成为解析、切块和发布之间的唯一数据契约。
- 保存可用于引用和质量诊断的版本级解析状态、问题明细和分块来源范围。
- 保持旧纯文本解析器、现有检索字段和同版本重试幂等性。
- 让警告结果可检索但可诊断，让错误结果不能被发布为已索引。

**Non-Goals:**

- 本变更不选择或部署具体 OCR/复杂版面外部服务。
- 本变更不改变对象存储、embedding 服务或 kb-ai 的数据库隔离边界。
- 本变更不重写权限谓词和混合检索排序算法。
- 本变更不要求为历史文档伪造缺失的页码或坐标。

## Decisions

### 1. 以统一结构结果作为解析器的规范接口

保留现有纯文本入口作为兼容适配，但流水线内部只消费结构化解析结果。结果除结构块外携带解析器标识、解析器版本、截断标记和问题列表；解析器无法确定的坐标保持为空。这样新旧解析器可以并存，切块和发布不需要依赖
Tika 或外部解析器的私有类型。

替代方案是让每个解析器直接返回分块，放弃统一模型；这会把结构恢复、来源范围和错误处理复制到各个解析器，无法保证引用行为一致，因此不采用。

### 2. 用版本级问题表加分块显式来源列保存元数据

新增 Flyway 迁移：

- 在 `kb_document_version` 增加解析器标识/版本、截断标记和问题计数。
- 新增版本关联的解析问题表，保存严重级别、代码、消息及可选页码、行范围、字符范围和 locator。
- 在 `kb_doc_chunk` 保留现有 `page_no`、`heading_path`，并增加块类型、来源行/字符范围、locator 和受限大小的结构元数据
  JSONB，用于表格行列等无法用固定列表达的语义。

新增字段保持可空或带兼容默认值。历史数据标记为 legacy/unknown，不补写无法证明的来源位置。结构元数据只保存必要的检索与引用信息，限制单字段大小，避免把原始文件或完整解析树写入数据库。

替代方案是把全部解析结果序列化为单个 JSONB；它难以建立来源查询索引，也会让引用和检索映射失去稳定列，因此只把扩展性强的表格/结构细节放在受控
JSONB 中。

### 3. 切块按结构块渲染，并对超长表格按行切分

切块器先为每个结构块建立渲染范围，再在段落、句子和块边界选择窗口终点。表格在容量不足时按行分组，保留表格类型、行列数据和首尾来源范围；普通块可以跨越相邻内容，但每个分块的标题路径、页码和首尾来源范围必须可确定。所有窗口都必须推进，空白内容直接丢弃。

这样可以继续支持现有字符窗口参数，同时避免把表格和标题上下文静默压平。对无法取得精确范围的块，输出未知坐标而不是根据归一化文本猜测位置。

### 4. 在一个发布事务内写入问题、分块和版本状态

Worker 的解析结果携带版本元数据传给发布器。发布器在租约校验后清除同一版本的旧分块及旧问题，写入新问题和分块来源数据；仅当所有写入成功时才把版本设为
indexed，并在同一事务中更新当前版本指针。错误级问题在发布前转为失败，不写入可检索结果；警告级问题与成功分块一起保存。

重复任务沿用现有按 version_id 清理后重写和唯一约束策略，保证重试不会产生重复分块。租约失效或事务回滚时不改变可见版本。

### 5. 通过解析器能力和契约测试扩展格式支持

Tika 继续作为常见格式的默认适配器，但其输出先转换为统一结构模型。Markdown/纯文本等可获得明确边界的格式输出标题、列表、表格和字符范围；PDF、Office
或扫描件缺少可靠结构时可输出基础文本和未知坐标，并通过同一接口替换为更强的专用适配器。新增解析器契约测试验证空输入、截断、警告、错误、分页和不支持格式的行为。

## Risks / Trade-offs

- [风险] 现有 Tika 文本抽取无法提供所有 PDF/Office 的真实页内坐标 → 只保存可靠坐标，未知值显式暴露，并把复杂格式适配器作为后续实现。
- [风险] 结构元数据 JSONB 过大导致写入和查询成本上升 → 只保存表格/来源摘要，设置大小上限，超限记录警告并保留正文。
- [风险] 新切块规则改变分块数量和向量结果 → 通过解析器/切块版本标识区分结果，迁移后按版本重建索引，不覆盖旧版本的可见指针。
- [风险] 旧数据缺少解析元数据 → 迁移字段允许为空并标记 legacy，引用接口继续返回已有 page_no，不能推断的字段保持 null。
- [风险] 发布器先删后写时发生故障 → 所有删除、插入和状态切换在同一数据库事务中执行，失败自动回滚；重试使用相同的幂等路径。

## Migration Plan

1. 先部署向后兼容的 Flyway 迁移，增加版本级解析元数据、解析问题表和分块来源字段；历史行保留为空或标记为 legacy。
2. 部署能读取空字段、写入新字段且仍兼容旧解析器的 Worker 和主应用代码。
3. 在灰度期间启用统一结构输出和新的发布路径，检查警告/错误状态与引用来源。
4. 对需要精确来源的历史版本重新提交解析任务，成功后再替换其当前索引版本。
5. 回滚代码时保留迁移产生的可空字段；旧代码继续使用现有 page_no、heading_path 和 index_status，不执行破坏性降级。

## Open Questions

- 具体复杂版面解析器（原生 Tika 增强、外部服务或专用库）的选择可以在不改变统一接口和持久化契约的前提下后续确定。
