# Proposal

## Why

查询侧与 Worker 各自选择 embedding 实现，数据库仅保存模型名称，检索未约束向量空间身份；同为 1024
维的不同模型可以被静默混查。当前也没有成功索引内容的独立向量重建流程，需要在接入真实模型前建立一致性边界和可恢复的模型切换能力。

## What Changes

- 引入部署预配置、语义不可变的 embedding profile，明确模型来源与版本、1024 维、余弦距离、查询/文档配套预处理和适配器版本；endpoint
  与密钥仅来自部署配置。
- 数据库保存 profile 身份、当前 profile、维护状态及单调执行代次；查询、普通解析发布和重建提交在运行时验证身份与代次，防止同维度混查和旧实例迟到写入。
- 新增受独立功能权限保护的 profile 状态查询、重建发起、进度查询和恢复 API，使用请求标识幂等及不含正文/密钥的审计。
- 重建期间仅运行既有受权限保护的 BM25 召回；上传继续，普通解析与发布暂停，新内容排队。已发布内容的预览和下载保持原语义。
- 只重建未删除文档的当前版本分块，包括归档内容；基于现有正文原地更新向量，不重新解析，不改变分块 ID、来源、内容版本、ACL
  或密级。历史版本不重算，不改写其来源身份。
- 向量与进度按批原子提交，支持租约恢复、退避重试及人工断点续建；失败保持维护状态，不提供即时回滚。实际覆盖校验和目标客户端就绪校验通过后才恢复混合检索及普通解析。
- **BREAKING**：生产不再允许默认 local-hash 或未声明身份的向量参与检索/发布；现有单客户端环境变量需要迁移为显式 profile
  配置。旧数据无法由 `embed_model` 推断完整身份，首次升级进入受控 BM25 模式并完成当前版本重建，不能静默认领旧向量。
- **BREAKING**：首次启用此协议需排空并停止不支持 profile/执行代次的旧应用与 Worker，不支持与旧二进制混部执行重建。

## Capabilities

### New Capabilities

- `embedding-consistency`: profile 定义、生产配置保护、可信向量身份、查询与写入一致性及旧数据初始化。
- `embedding-rebuild`: 受控 BM25 降级、当前版本向量重建、持久状态机、进度与故障恢复、完成校验和安全切换。

### Modified Capabilities

- `document-parsing`: 新增维护期间上传排队、普通任务暂停、在途任务无失败收敛及携带 profile/执行代次发布的要求。
- `functional-authorization`: 新增 embedding 管理读取与重建操作资格，沿用精确匹配、幂等审计和一次性管理员权限初始化语义。

## Impact

- `kb-common` 增加无 Spring 运行时依赖的 profile 描述与向量结果契约；`kb-app` 调整检索服务/SQL、生产检查、权限目录、管理 API
  和迁移；`kb-worker` 调整客户端注册、解析领取/发布/恢复，并增加独立重建执行器。
- 保留 PostgreSQL `VECTOR(1024)`、既有 HNSW/BM25 索引、PG 持久队列和授权主库路径，不新增中间件，不让 `kb-ai` 直连数据库。
- 新增数据库迁移脚本，不修改已发布的 V1-V14；补齐无需外部服务的单元测试、进程内 HTTP 契约检查、SQL/映射静态检查及维护操作说明。
- 本次交付不包含集成测试、端到端测试、真实迁移执行或多进程部署验证，不启动或连接
  PostgreSQL/ParadeDB/pgvector、Redis、MinIO、Docker 或真实模型服务。测试使用进程内
  Mock/Stub；运行时预检、数据校验、事务及持久化功能仍需实现，离线检查不代表真实数据库锁、回滚、崩溃恢复或检索效果已验证。
- 不包含跨维度迁移、双份在线向量、即时回滚、历史版本重建、解析器/分块规则重建、在线 endpoint/密钥编辑、前端管理页面或更换检索引擎。
- 恢复旧模型也需要完整重建；首期未完成作业只恢复原目标，不在半途切换目标。外部模型调用不承诺
  exactly-once，数据库提交和已成功批次的恢复行为必须幂等。
