# Proposal

## Why

空间授权已经可以一次批量授予，但撤销仍只能逐条提交、逐条等待回执：清理一个部门在空间上的多项权限，或在人员调整后收回十几条授权，都要重复多次确认。批量授予上线时把批量撤销列为非目标，也留下了一个重放缺口：相同请求标识携带不同内容重试时，服务端仍返回首次回执，调用方无法发现自己提交的并非原批次。本变更补齐同一空间上的批量撤销，并让两个批量接口按同一规则判定重放。

## What Changes

- 新增 `POST /api/admin/spaces/{spaceId}/acl/batch-revoke`：请求体携带显式条目列表（主体类型、主体 ID、权限位），1 至 300 条且不得重复；全部校验通过后在同一事务内逐条撤销。撤销按条目而非主体 × 权限位笛卡尔积进行，未提交的组合不受影响。
- 资格沿用批量授予规则：条目含 manage 时整批要求 `space:grant-manage`，否则要求该空间 manage 或 `space:manage-all`；不校验角色存在性，已删除角色的残留授权同样可撤。撤销不存在的条目视为成功；服务端不阻止撤销空间的全部 manage。
- 回执逐条标明是否实际移除，并给出移除数与原本不存在数。新增审计操作域 `SPACE_ACL_BATCH_REVOKE`，一批只产生一条审计事件；审计查询摘要只投影空间与计数。
- 两个批量接口统一重放规则：同一请求标识在事务内串行化；重放核对操作者、空间、快照空间，以及快照逐条记录的条目集合与本次请求是否一致（仅顺序不同视为一致），任一不一致返回 409。**BREAKING**：批量授予以相同请求标识提交不同内容时，由返回首次回执改为返回 409；既有批量授予快照已逐条记录主体与权限位，核对同样适用于本变更上线前写入的快照。
- 空间授权面板为可撤销的授权行提供多选与批量撤销：确认前展示条目数，并在包含本人直接 manage 或全部直接 manage 时提示；结果不确定时只允许按原内容重试、重新读取核对或放弃核对；批量撤销路由不可用时只禁用批量撤销，单条撤销、授予与列表不受影响，也不拆成多次单条撤销。
- 不在本次范围：文档例外批量授予或撤销、跨空间批量、服务端"最后一名 manage"保护、修改单条授予与撤销接口及其重放实现、数据库迁移。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `space-authorization`：新增同一空间上按显式条目的原子批量撤销要求（资格、请求边界、幂等、回执与审计）；修改批量授予的幂等要求，加入请求内容摘要核对与同标识串行化。
- `admin-web-spaces`：空间授权列表新增多选与批量撤销交互、确认摘要与 manage 提示、回执与结果不确定时的表现，以及批量撤销路由不可用时只禁用批量撤销的要求；文档例外面板保持单条撤销。

## Impact

- 后端：`SpaceAclService` 新增批量撤销并调整批量授予的重放核对；`SpaceController` 新增路由；新增请求与回执 record；`AuditScope` 新增操作域并在 `AuditSummaryProjector` 补充投影；`SpaceMapper` 新增按请求标识加事务级 advisory lock 的方法。ACL 表结构、权限目录与单条接口不变，不新增迁移。
- 前端：`kb-web/src/admin` 的 `AclPanel.tsx`、`spaceApi.ts` 的类型与写意图，以及对应单元测试；文档例外面板保持现状。
- 审计：`/admin/audits` 对新操作域显示计数级摘要；`docs/admin-query-api.md`、`docs/admin-space-document-web.md` 与 `kb-web/README.md` 需同步说明。
- 兼容与部署：后端先行。批量授予的重放收紧只影响"同标识不同内容"的提交，现有前端对内容变化会生成新请求标识，不受影响；回退 kb-app 后新前端的批量撤销显示不可用，已写入的审计行保留且可读。
