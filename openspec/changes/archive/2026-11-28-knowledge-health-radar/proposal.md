# Proposal

## Why

空间管理员目前需要分别查看复审状态清单和可读版本的适用期，难以集中判断哪些资料需要维护，也缺少口径一致的数量与去重清单。知识健康雷达将已有维护事实汇集到单空间诊断页，帮助管理员找到问题并进入现有处理流程。

## What Changes

- 面向空间管理员提供单空间健康雷达，允许切换当前可管理空间；每次只查询一个空间中未删除、未归档的文档，归档空间暂停诊断。
- 首期固定六类信号：未指定责任人、责任人需重新指定、复审已逾期、即将复审、当前发布版本适用期已届满、适用期即将届满。沿用现有状态优先级、业务日期及 30 天边界，不以复审逾期推断内容失效。
- 提供六类精确数量、命中至少一个可见信号的去重文档数、单类或全部筛选、有界游标清单和本次统计时间；同一文档合并展示可见原因，明确数量不代表内容正确性或全空间适用期检查覆盖率。
- 新增独立 `knowledge:health:read` 功能权限，并要求当前目标空间 manage 或 `space:manage-all`。责任人与复审四类使用现有最小管理投影；适用期两类只对操作者当前可读的当前发布版本计算、计数和展示，不披露其他版本的身份、日期、状态或隐藏数量。
- 在空间详情增加入口，提供受保护的单空间页面、空间切换、显式刷新和原处理页面链接。责任人指定、改派、编辑及本人复审确认继续使用各自既有资格和流程。
- 查询使用同次一致快照及固定业务日期；撤权、归档、搬迁、换号、翻页与迟到响应均按当前事实处理。故障明确返回不可用，不以零问题、部分成功或旧结果代替。
- 首期不增加健康评分、历史趋势、跨空间汇总、提醒推送、独立整改任务、忽略/关闭诊断记录，也不纳入重复、矛盾或高频缺口主题分析。

## Capabilities

### New Capabilities

- `knowledge-health-radar`：单空间六类维护诊断、不同信号的授权范围、精确汇总、去重分页、时间一致性、错误与容量边界。
- `admin-web-knowledge-health`：单空间雷达页面、数量和清单表达、空间/原因切换、原处理入口及页面生命周期。

### Modified Capabilities

- `functional-authorization`：新增独立雷达读取资格、与空间管理资格合取、一次性初始化及撤权持久性。
- `admin-web-access`：新增雷达受保护路由、资格加载、懒加载及合法登录返回规则。
- `admin-web-spaces`：空间详情提供受当前资格控制的雷达入口，连接现有管理流程。

## Impact

- `kb-app`：新增只读诊断 API、分层查询服务与 Mapper、明确 DTO/VO、权限目录及迁移；复用空间管理、文档访问、版本访问、复审资格和适用期规则。新 Java 文件置于既有 `controller`、`service`、`service/impl`、`mapper`、`domain`、`enums` 分层下。
- `kb-web`：新增独立懒加载页面、严格响应解码、单空间筛选和会话隔离，扩展权限目录、登录返回及空间详情入口。
- `kb-gateway`：沿用 `/api/admin/**` 路由，补齐新诊断端点的响应缓存保护与相关回归。
- 新增权限按既有目录兼容约束交付发布说明；不需要新增业务事实表、外部供应商、模型或后台分析任务，不修改文档发布与检索协议。
- 实施验证限定为独立进程内单元/组件测试、Mock/Stub、内存替身、模拟 DOM、编译、类型检查和静态构建；不安排前后端联调、应用/HTTP 测试服务器或外部组件启动，也不安排文档存在性、内容匹配、文本快照或生成文档内容断言测试。说明文档和迁移脚本人工审阅交付；真实数据库、迁移、性能及浏览器联调仅保留为未验证范围，不作为本变更实施完成或归档条件。
