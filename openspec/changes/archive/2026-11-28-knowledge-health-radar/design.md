# Design

## Context

动机与确认范围见 [proposal.md](proposal.md)。当前已存在以下可复用行为：

- `document-stewardship` 提供四类维护状态及本人/空间清单。`StewardshipState.of` 固定按未指定、需改派、逾期、即将到期、正常判断；`StewardshipMapper.xml` 已包含当前责任人的资格谓词。空间清单是 ID 级管理投影，包含归档文档，且不提供总数。
- `document-applicability` 将日期绑定到版本。`ApplicabilityState`、`ValidityProperties` 和数据库时钟定义业务日期及 30 天边界；现有批量标识读取必须逐版本授权。
- `DocumentMapper.xml` 与 `AuthorizationRules.xml` 提供当前文档 view、活动空间及发布证据共享谓词；`DocumentVersionAccessService` 可核对固定版本。管理资格与内容读取资格相互独立。
- 运营报表可复用短只读一致事务的做法，但 `operations:reports:read` 只开放固定全局汇总，不能作为新诊断明细的授权。
- 前端已有 `SpaceDetailPage`、`SpaceStewardship`、`StewardshipBox`、页面级懒加载和身份代次隔离。普通文档详情默认选择当前可访问版本，没有现成的固定版本详情路由；`VersionPreview` 已支持固定版本的授权预览。
- 新近答案卡与订阅代码采用 `controller/<业务>`、`service/<业务>`、`service/impl/<业务>`、`mapper/<业务>`、`domain/.../<业务>`、`enums/<业务>`。新诊断沿用这一技术分层，不增加混放各层的顶层功能包。

本变更涉及读取授权、跨表一致性和前后端协议，符合创建设计文档的条件。现有能力的真实部署、迁移及数据库验证仍不能从离线归档状态推断。

## Goals / Non-Goals

**Goals:**

- 用一次有界、只读的服务调用交付同一快照的数量和当前页，并让权限与业务规则在筛选前生效。
- 让四类管理信号与两类内容信号共享一个去重文档集合，同时保留各自授权范围。
- 最大限度复用现有状态与访问语义，新增可独立测试的聚合层和界面，不产生另一套整改状态。
- 为正常空结果、不可访问、归档、业务日期变化及依赖故障提供可验证的不同结果。

**Non-Goals:**

- 不持久化健康结论、历史快照或任务，不调整既有清单的归档范围与无总数合同。
- 不更改发布、搜索、适用期、复审确认和账号生命周期协议，也不新增跨请求权限缓存。
- 不引入模型、正文分析、调度器、自动修复、推送、导出或统一健康分。

## Decisions

### D1. 采用独立诊断查询，保留已有清单用途

新增 `GET /api/admin/spaces/{spaceId}/health-radar`，返回汇总及当前页。独立只读服务把授权、时间锚点和全部查询放在同一事务中；不由前端遍历旧复审清单、拼装适用期标识或求和。

选择原因：旧空间清单包含归档文档且明确不返回总数，本期范围与聚合目标不同。直接改变旧清单会影响已有复审页面；前端拼装则无法保证权限过滤、完整数量和时间一致性。新端点只增加诊断契约。

### D2. 功能、管理与内容三层授权

1. 服务入口使用现有会话和 `AdminQueryAccess` 在事务内取得当前有效主体，要求新增 `Permission.KNOWLEDGE_HEALTH_READ` / `knowledge:health:read`。
2. 使用 `SpaceQueryService.findManaged` 复核目标空间，禁止由角色名或前端 manageable 值直接放行。
3. 四类管理信号按该空间活动文档计算，不要求管理员本人 view，只返回现有管理允许的文档 ID、责任人 ID/显示名及日期。
4. 两类适用期信号额外使用调用者 view 范围、密级、活动空间和固定当前版本的发布/读取规则。无阅读资格只影响该文档的适用期分支，不删除其合法管理信号。

所有持久权限事实在同一读取事务内重新取得；网关的身份检查是入口保护，不替代 app 的本次读取授权。`space:manage-all` 仍只替代空间 manage，不替代新功能权限或文档 view。

未采用“管理即可看全部日期”，因为这会扩大版本信息访问；未采用“全部诊断必须 view”，因为它会使管理员看不到本应能指定或改派的维护事项。结果不返回适用期跳过数、不可读数或隐藏版本占位。

### D3. 规则映射和计数集合

| 信号代码 | counts 字段 | 条件 |
|---|---|---|
| STEWARD_UNASSIGNED | stewardUnassigned | 既有复审状态 UNASSIGNED |
| STEWARD_NEEDS_REASSIGN | stewardNeedsReassign | 既有复审状态 NEEDS_REASSIGN |
| REVIEW_OVERDUE | reviewOverdue | 既有复审状态 OVERDUE |
| REVIEW_DUE_SOON | reviewDueSoon | 既有复审状态 DUE_SOON |
| APPLICABILITY_EXPIRED | applicabilityExpired | 可读当前发布版本按既有规则为 EXPIRED |
| APPLICABILITY_EXPIRING_SOON | applicabilityExpiringSoon | 可读当前发布版本按既有规则为 EXPIRING_SOON |

四类管理状态互斥；两类适用期状态也互斥。因此每份文档最多命中两类，`affectedDocumentCount` 对非空信号文档去重，不能把六个数相加。

最外层文档范围固定为 `space_id` 匹配且状态不是 deleted/archived；目标空间也必须未归档。没有复审记录视为未指定；取消后的旧到期日不覆盖未指定状态。复审确认不消除仍存在的适用期信号。

适用期只读取 `current_version_id` 对应且属于该文档的版本。发布证据沿用 `AuthorizationRules.publishedEvidence`（包括项目已有的 LEGACY_COMPAT 规则），不能仅凭 indexed、上传者或审核参与身份放行候选。父文档存在任意可读候选的 `parentVersionVisibility` 不足以替代固定当前版本的判断。

未声明、明确长期有效、未来生效等沿用既有优先级；不从正文、上传时间或历史版本推断日期。不新增主观严重级别或内容可信评分，管理者通过原因筛选选择处理顺序。

### D4. 一次数据库时间和一致快照

服务实现使用只读 REPEATABLE_READ 事务，完整服务读取预算 6 秒。取得一次 `BusinessClockMapper.now()`，按现有 `ValidityProperties.zoneId()` 得到 T，并同时返回该瞬时的 asOf、T 和时区。雷达不再另外调用只能返回日期的 `BusinessDate.today()`，避免跨午夜时取得两个时间锚点。

授权、目标归档、当前责任人资格、当前版本、数量和清单均在该事务/连接内读取。先固定 T，再向全部 SQL 和 Java 规则传入该日期；不持久化计算后的日期状态。事务不使用序列高水位或应用主机时间伪装快照。

6 秒预算从服务入口开始，所有诊断 SQL 使用剩余事务期限，单语句不超过 3 秒；实现时通过事务/JDBC 超时及数据库事务级语句超时限制实际读取，并在返回前检查完整预算，超限返回 503。不能仅给多条语句分别设置 6 秒而宣称总预算已满足。

替代的分接口卡片/清单会引入不同快照；异步物化需要额外新鲜度、撤权和历史语义。本期选择同步查询，真实性能不足时先依据执行计划优化，不自动降级为旧快照。

### D5. 共享关系查询与真正有界的输出

新 Mapper 使用共享 SQL 片段表达以下关系，汇总和分页都引用同一个定义：

```text
active documents in one managed space
        |
        +--> current stewardship + eligible responsible user
        |
        +--> authorized current published version + applicability
        |
        v
one row per document + six visible signal flags
        |
        +--> counts and distinct affected documents
        |
        +--> selected signal --> document ID cursor --> limit + 1
```

责任人资格引用已有 `StewardshipMapper.responsibleEligible` / `stewardEligible` 相关片段，保留其别名约定和全部当前条件。调用者版本阅读分支引用已有文档授权及发布证据片段，并带当前密级；使用 EXISTS 及一对一连接，不通过多条 ACL、多版本或 chunks 放大结果。

统计始终对全部当前可诊断集合聚合，signal 只筛选清单。SQL 先计算获准可见信号并过滤，再执行 LIMIT，不能限量后在 Java 删去不可读项。数据库侧完成聚合，应用只接收常量规模的汇总及最多 101 个候选行。关系中不选择标题、正文、原件键或额外身份信息。

Java 投影复用 `StewardshipState.of`、`ApplicabilityState.of` 校验返回行的状态及可见原因；SQL/Java 不一致、异常数量或缺失必需事实均整体 503，不静默修正计数。针对同一内存事实集在进程内单元/组件中运行参考规则，使用仓储替身验证查询编排，并进行无连接的 Mapper 加载及参数绑定检查。真实 SQL 语义、隔离与执行计划不在本变更测试范围内；离线检查不能证明真实规则等价。

实现前基于现有迁移定义和查询形状复核空间/状态/文档 ID 与复审索引。需要新增索引时说明查询用途并交付数据库元数据注释；本次不执行数据库或查询计划验证，不宣称实际性能收益，也不预先创建新业务事实表。

### D6. 固定响应、分页与错误

采用 `R<KnowledgeHealthRadarVo>`；所有对外类型和字段使用完整中文 OpenAPI 注解。固定字段如下：

| 字段 | 约定 |
|---|---|
| definitionVersion | 固定 KNOWLEDGE_HEALTH_V1 |
| spaceId | 正十进制字符串，限制在现有正 bigint ID 范围 |
| asOf / asOfDate / dayTimeZone | 数据库瞬时、对应业务日期、现有地区时区 ID |
| signal / limit | 回显 ALL 或合法单类，以及有效页大小 |
| counts | 六个固定字段，各为规范非负十进制字符串 |
| affectedDocumentCount | 命中至少一个可见信号的去重数量字符串 |
| items | 最多 limit 条，一个文档一项，documentId 升序 |
| hasMore / nextCursor | 下一页是否存在及相应非空游标，否则 false/null |

每项包含 documentId、signals、stewardship、applicability。stewardship 包含 state、responsible（userId/displayName 或 null）、dueDate；applicability 仅在命中适用期信号时包含 versionId、state、effectiveFrom（可空）、effectiveUntil，否则为 null。所有 ID 使用规范正十进制字符串。六类 signals 按 D3 表格顺序且不重复，单类筛选也保留该文档其他可见原因。

游标编码使用项目既有的有界、上下文绑定方式，载荷含协议、用户、空间、signal、limit、T 和最后 documentId。输入长度上限 2048，严格解码及校验值域；绑定不是授权，仍须按 D2 重新校验。只按 documentId 升序续页，跨日返回 RADAR_DATE_CHANGED。游标不表示不可变快照，同一天的改派、确认和权限变化允许改变下一次结果。

| HTTP | 处理 |
|---|---|
| 400 | 非法 ID、未知/重复参数、非法信号、越界 limit 或游标绑定/格式错误 |
| 401 | 无有效会话或认证代次失效，遵守既有入口身份语义 |
| 403 | 无功能资格、主体失效或强制改密 |
| 404 | 空间不存在或不可管理 |
| 409 SPACE_ARCHIVED | 当前空间归档，暂停诊断 |
| 409 RADAR_DATE_CHANGED | 游标业务日期已过期，需从首页重新读取 |
| 503 | 任何必要事实、授权、规则一致性或完整预算不可确认 |

优先完成当前身份及目标授权，再披露归档和游标日期冲突。严格区分“确定不可读”与“读取资格依赖故障”；后者不能转换为空适用期分支。接口不支持客户端时钟、任意排序、包含归档、导出或批量空间输入。

### D7. 页面与已有处理流程衔接

页面路由为 `/admin/spaces/:spaceId/health-radar`，由当前空间详情入口打开；功能资格通过后才加载页面模块，再独立核验目标。切换器使用现有空间目录的 manageable 且未归档子集；它只用于导航，诊断仍重新核验真实目标。切换器失败时禁止使用旧候选，但已单独核验的当前目标不因此假装失去管理权。

页面展示统计时间、范围说明、六类数量卡片、去重总数、ALL/单类筛选、当前页、下一页、返回首页与刷新。固定每页 20 项，后台 API 仍保留 1–100 合法值。前端不计算总数，不加载全部文档或身份目录，不逐行补标题。

翻页采取替换当前页，连同汇总一并替换。新请求启动即清理旧结果；失败显示重试，分页重试保留当前请求绑定但不保留旧数据展示。刷新、换空间、换筛选和从处理页返回从首页读取。每页是一份当前查询，页面不累计旧页或提供冻结导出，避免累积已撤权条目。

所有行可进入原文档管理面板，由原流程提供指定/改派等操作。适用期项提供两种有明确文案的入口：

- “核对此次诊断的版本”：复用 `office/VersionPreview.vue`，显式点击后以返回的固定 documentId/versionId 调用既有预览入口。组件仍执行文件阅读/Office 配置规则，不新建固定版本详情路由；失败不自动下载、不替换版本，资格拒绝时关闭预览并失效本次诊断。
- “打开文档详情处理”：进入原文档详情，明确重新读取文档及当前可访问版本；编辑者在原页面选择需要处理的版本并按原资格操作。此入口不声称打开的默认版本仍是诊断版本。

非责任人不能通过雷达直接确认，处理结果以随后重新查询为准。复审已确认但适用期仍届满时，行仍保留适用期原因。

### D8. 状态隔离、严格解码与响应保护

新页面沿用 Session epoch、请求代次、AbortController 与现有受保护路由外壳。空间/筛选变化、后台、离页、退出、换号及撤权都清理当前数据、游标与预览；迟到成功或失败不能恢复内容。恢复重新核验后读取默认首页；无轮询或浏览器持久存储。

响应解码校验包装成功、definitionVersion、目标/筛选绑定、完整六类计数、精确 ID、日期、原因集合、文档唯一性及分页一致性。计数每类不超过并集、signals 与可选适用期结构一致、不可读项不暴露版本字段；不接受缺字段的部分成功。不把旧服务 404/405 或 HTML 错误体当成无问题。

app 为雷达路径增加早期响应保护，gateway 在认证过滤之前为同一路径设置 no-store；覆盖成功、校验拒绝、401/403/404/409/503 及旧端点不可用。不扩展现有公开网关路径。日志只保留固定失败阶段/类别，不记录 URL 参数、游标、空间/文档身份、责任人、响应或底层异常；不创建成功业务写审计。

### D9. 按现有分层放置实现

| 职责 | 拟放置位置 |
|---|---|
| 诊断控制器、输入适配和受控异常投影 | `kb-app/.../controller/health/` |
| 查询服务接口 | `kb-app/.../service/health/` |
| 查询编排、规则/游标协作组件 | `kb-app/.../service/impl/health/` |
| 关系查询与时间查询接口 | `kb-app/.../mapper/health/`（时间优先复用既有 Mapper） |
| 查询参数、内部行、响应对象 | `kb-app/.../domain/req/health/`、`domain/dto/health/`、`domain/vo/health/` |
| 六类信号枚举 | `kb-app/.../enums/health/` |
| SQL 映射 | `kb-app/src/main/resources/mapper/health/` |
| 响应保护 | 现有 `kb-app/.../config/` 与 gateway 过滤器位置 |
| 前端页面与协议状态 | `kb-web/src/admin/KnowledgeHealthPage.vue` 与对应 API、状态及组件测试 |

仅新增有实际职责的类和目录，模型为查询投影，不引入无用途的持久实体。Spring 新组件采用与近期分层实现一致的构造器注入；必要的手写构造器保留实际参数语义。控制器精确描述路径/查询参数及 R 包装响应，嵌套 VO 同样带字段说明。测试在各被测类对应包下。

### D10. 验证与交付证据

本变更只安排独立进程内单元/组件测试、Mock/Stub、内存替身、固定时钟、模拟 DOM、编译、类型检查与静态构建。后端测试使用显式离线白名单，控制器可用 standalone MockMvc 或直接调用，网关使用请求/响应及过滤器链替身，前端使用传输和预览组件替身。均不启动完整应用、HTTP 测试服务器，不连接或启动 PostgreSQL、Redis、对象存储、Office 等外部组件，也不用 Testcontainers 或内嵌服务替代。

离线行为覆盖六类状态和日期边界、未指定优先/需改派优先、两类授权范围、候选不能替代发布、LEGACY_COMPAT 一致性、去重/筛选/稀疏分页、精确整数、游标上下文及跨日、依赖故障、响应完整性、复审与适用期独立消除；前端在模拟 DOM 中覆盖懒加载、固定预览交互、原处理入口、切换、换号、后台、迟到响应和归档恢复。

Mapper 检查限无连接加载、参数绑定及进程内关系/仓储替身；事务测试限事务边界配置、连接替身、预算传递及故障处理，不证明数据库实际 SQL、隔离、锁、执行计划或真实性能。前后端联调、真实浏览器、多服务及迁移验证均已从本变更任务移除，只在交付记录中如实注明未验证，不作为实施完成或归档条件。

不新增或执行文档存在性、内容匹配、关键词/章节检查、文本快照和 Swagger 等生成文档内容断言测试。API、使用、发布说明与迁移脚本仍作为交付物人工审阅；OpenSpec 使用其标准格式校验，不增加针对文档正文的测试套件。

任务同时交付 API、使用和发布说明，并更新路线图中的实际状态；方案和离线完成不能记为真实环境验收通过。

## Risks / Trade-offs

- [同页信号授权范围不同] → 页面分别标明四类管理范围与两类可读版本范围，不输出不可读数量或统一健康率。
- [大空间的责任人资格查询较重] → 共享 EXISTS 谓词、数据库聚合、短事务及输出限额；通过可控时钟和故障注入检查预算处理，实际查询性能保留未验证状态。
- [SQL 与 Java 状态漂移] → 复用现有规则/谓词、统一输入日期、行级一致性校验和相同内存事实集回归，真实 SQL 等价性保留未验证状态。
- [两次翻页之间数据改变] → 明示每页为当前结果、替换展示、更新汇总、跨日要求回首页，不承诺历史完备遍历。
- [并发撤权已经在当前快照之后提交] → 当前请求只承诺其读取快照内的授权；每次后续请求重新核验，前端已获知撤权即清理。不能承诺撤回已交付内容。
- [既有预览格式或服务不可用] → 按原预览规则说明不可用，诊断不推断可下载，不自动选择其他版本；原管理入口仍执行其独立规则。
- [新增权限影响旧版本启动] → 遵循目录兼容发布，保留绑定及业务数据，回退使用认识新目录的兼容版本。

## Migration Plan

以下为交付的发布与回退操作说明，不是本次实施测试任务，不要求为完成或归档本变更而启动服务、执行迁移或进行联调。

1. 实施时核对最高 Flyway 版本，使用下一个未占用版本交付权限初始化脚本；当前最高为 V45，暂预计 V46，但不得覆盖并行变更。脚本说明用途和一次性绑定范围，不创建新的健康事实表。
2. 离线完成新权限目录、初始化及撤权持久性回归；需要索引时附完整 SQL 说明和数据库 COMMENT。提供 API/使用文档，明确真实数据库、迁移和联调未验证。
3. 实际发布时先排空不识别新权限的旧 app，再由 app 执行迁移及完成全部实例升级；本变更只交付该顺序说明。
4. 确认 gateway 的新路径响应保护已部署，再发布 web 的哈希资源并原子切换 HTML；前端不得在服务端缺新协议时拼装旧接口。
5. 为实际空间管理员通过既有角色权限流程显式授予新权限；迁移仅一次性绑定当时已有 ROLE_ADMIN。确认只具新权限而无空间管理、只具管理而无新权限两种身份均不能读取。
6. 回退先撤下 web 入口或撤销新读取资格，再回退到识别新权限目录的兼容 app/gateway；保留权限绑定和全部原业务事实，不删绑定或忽略未知权限迁就旧二进制。归档空间的原管理能力保持原契约。

部署容量与实际环境地址由后续发布工作确定；它们不改变本次六类信号、单空间范围或授权方式，也不引入本次已移除的测试任务。
