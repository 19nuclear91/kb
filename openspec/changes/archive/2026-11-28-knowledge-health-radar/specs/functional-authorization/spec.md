# Spec Delta

## ADDED Requirements

### Requirement: 健康雷达必须具有独立精确读取资格

服务端固定权限目录 SHALL 定义 `knowledge:health:read`，用途为在当前可管理空间读取最小文档维护诊断。资格按有效主体全部持久角色权限并集精确匹配；空间 manage、space:manage-all、运营报表读取、权限诊断或管理员角色名称不能代替。新资格不授予文档阅读、编辑、责任人确认、问题受理或其他管理动作。

#### Scenario: 查询及授予新权限
- **WHEN** 合格角色读取者查询目录，或普通角色被显式绑定 knowledge:health:read
- **THEN** 目录返回该精确 code 和中文用途，角色有效持有者取得雷达功能资格但仍需目标空间管理资格

#### Scenario: 原权限不能替代
- **WHEN** 用户只有 operations:reports:read、authorization:diagnose 或 space:manage-all
- **THEN** 不因这些权限获得健康雷达读取资格

#### Scenario: 多角色撤权
- **WHEN** 两个角色共同授予雷达权限，随后一个或全部绑定被撤销
- **THEN** 尚有绑定时资格保留，全部撤销后下一次雷达请求为 403，不等待会话失效

### Requirement: 雷达功能资格必须与目标资源范围逐层合取

雷达读取 SHALL 先核验 knowledge:health:read，再核验目标空间当前 manage 或 space:manage-all；适用期信号还须核验操作者对当前发布版本的阅读与密级资格。前四类维护信号限最小管理投影，不以新资格或统计结果授予标题、正文、版本或人员身份目录访问。每次翻页和刷新均重新核对当前事实。

#### Scenario: 有功能资格但无目标管理资格
- **WHEN** 用户可读取雷达功能但不可管理指定空间
- **THEN** 请求按目标不存在的相同 404 拒绝，不返回该空间数量

#### Scenario: 可管理而无内容阅读权
- **WHEN** 用户满足雷达及空间管理资格，但不能读取空间中某份文档
- **THEN** 仅可取得该文档允许的维护管理投影，不能据此取得适用期信号、标题或正文

#### Scenario: 雷达资格不能代替复审确认
- **WHEN** 用户有雷达与空间管理资格，但不是某文档当前合格责任人
- **THEN** 既有复审确认仍拒绝该用户，诊断读取不改变确认资格

### Requirement: 雷达权限初始化必须一次性并遵守目录兼容

新增迁移 SHALL 仅向迁移时已有 ROLE_ADMIN 一次性绑定 knowledge:health:read；空库正式引导新管理员角色时纳入完整目录。其他角色不隐式获权，后续启动或重复引导不恢复已撤销绑定。新增权限入库前排空不认识目录的旧 app，保留未知 code 拒绝启动约束，不以删绑定或忽略未知项实现兼容回退。

#### Scenario: 存量首次迁移
- **WHEN** 含管理员和普通角色的数据库首次应用新迁移
- **THEN** 仅当时已有 ROLE_ADMIN 获得新绑定，其他权限及全部资源 ACL 保持原事实

#### Scenario: 空库引导及撤权后重启
- **WHEN** 空库正式引导首次创建管理员，或既有角色撤销新权限后再次启动
- **THEN** 前者纳入当时完整目录，后者保持撤销而不被自动补回

#### Scenario: 不识别目录的旧版本
- **WHEN** 旧 app 在新权限绑定仍存在时启动
- **THEN** 按现有未知权限约束拒绝启动，发布说明不得声称可混部或直接回退
