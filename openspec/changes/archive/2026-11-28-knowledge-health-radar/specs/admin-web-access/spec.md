# Spec Delta

## ADDED Requirements

### Requirement: 健康雷达路由必须同时受功能与资源资格控制

用户端 SHALL 注册 `/admin/spaces/:spaceId/health-radar`，仅在当前身份及 knowledge:health:read 确认后加载专用页面代码；页面再核验目标空间管理资格后读取诊断。空间管理、运营报表、权限诊断或角色名称不能代替雷达资格，旧模块缓存也不能延续访问。该页面从空间上下文进入，不新增跨空间统计导航，不改变既有空间管理入口的资格。

#### Scenario: 只有空间管理权限
- **WHEN** 用户可管理空间但没有 knowledge:health:read，直接打开雷达路径
- **THEN** 显示无雷达访问资格，不加载雷达专用代码或读取诊断，原空间管理页仍按原资格开放

#### Scenario: 有功能资格而目标不可管理
- **WHEN** 雷达功能资格已确认，目标空间摘要表明不可管理或不存在
- **THEN** 页面显示目标不可访问，不发出诊断请求

#### Scenario: 页面下载期间撤权
- **WHEN** 雷达页面代码下载期间 knowledge:health:read 被撤销
- **THEN** 迟到模块不能挂载旧页面或发起诊断，导航及退出仍可使用

### Requirement: 雷达登录返回必须只接受合法目标路径

登录返回 SHALL 接受含合法正整数 spaceId 的完整雷达路径，拒绝筛选、游标、查询串、片段、未注册后缀和站外地址。登录和必要改密完成后重新核验功能与目标资格；非法 ID 在发出管理请求前被拒绝。返回地址不构成授权，默认登录落点继续使用既有规则。

#### Scenario: 合法雷达登录返回
- **WHEN** 未登录用户访问 `/admin/spaces/123/health-radar` 并完成登录及必要改密
- **THEN** 可恢复该路径，重新确认 knowledge:health:read 和空间管理资格后才读取诊断

#### Scenario: 带筛选或非法目标
- **WHEN** 返回地址带 signal、cursor、其他查询、片段，或空间 ID 为 abc、0、负数
- **THEN** 不接受该返回地址，按既有安全落点处理且不查询对应空间

### Requirement: 雷达恢复必须清除旧范围并重新核验资格

雷达 SHALL 沿用管理页面的身份代次、后台恢复和局部加载错误规则。页面隐藏、换号、退出、强制改密、功能或空间资格变化时清除诊断数据及在途回调；恢复重新核对本人权限和目标管理资格。空间切换器独立处理其目录故障，不能以旧候选或已下载代码替代当前目标授权。

#### Scenario: 只撤销雷达权限
- **WHEN** 用户仍可管理空间，但全部角色中的雷达权限被撤销
- **THEN** 雷达页面及入口清除受保护状态，原空间管理能力按其既有规则继续使用

#### Scenario: 从空间 A 切换到 B
- **WHEN** A 的数据或模块仍在途时用户切换到 B
- **THEN** A 的迟到成功或失败不能更新 B，B 按自身目标资格重新加载
