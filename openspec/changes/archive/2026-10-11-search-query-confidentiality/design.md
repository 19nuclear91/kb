# Design

## Context

参见 [proposal.md](proposal.md) 的 Why。当前 `SearchController` 仅映射 GET，`RetrievalClient` 将问题拼入 `q`
；搜索控制器用服务端会话取得用户身份，AI 只透传会话。`GlobalExceptionHandler`、`ChatService`、`ChatController` 与部分配额日志会记录原始
Throwable；网关现有身份头净化日志只记录 path。`citation-provenance` 要求保留检索 JSON 与 SSE 引用字段。本变更跨 `kb-app`、
`kb-ai` 和部署访问日志，符合设计工件的安全与迁移条件。

## Goals / Non-Goals

**Goals:**

- 消除项目自身正常检索调用产生的含词 URL；明确拒绝旧 GET 与带查询字符串的 POST。
- 使检索、问答及配额失败的应用日志只输出受控诊断字段，同时保持授权与引用语义。
- 给同步部署及访问日志核查提供可执行的验证边界。

**Non-Goals:**

- 不改变 SQL、权限模型、排序算法、引用 JSON 或 SSE 事件结构。
- 不引入跨请求缓存、模型适配器或新审计存储。
- 不声称能阻止外部客户端自行构造含词 URL；前置代理日志仍需在部署环境核查。

## Decisions

### 1. 使用单一 POST 搜索入口

`SearchController` 改为 `@PostMapping`，请求体使用明确的 `query`、`candidates`、`topK` 字段。缺省候选数为 50，缺省 `topK`
等于候选数；保持原有数量范围、服务端会话取用户 ID 和 `SearchService` 调用。控制器拒绝任何 URL 查询字符串并返回不回显内容的
400；GET 映射移除，由现有方法错误处理返回 405。现有登录与强制改密拦截器仍可先返回 401/403。

选择拒绝查询字符串，是为防止调用方以 POST 方法继续把输入放在 URL。仅给 AI 增加 POST、保留公开 GET
的方案无法消除浏览器搜索入口的风险；用户已确认可以直接停用 GET。请求体中伪造的身份或向量字段不得进入服务层，控制器只传白名单字段。

### 2. AI 调用固定 URI 并保留原有结果处理

`RetrievalClient` 使用 `POST /api/search` 与 JSON body，URI 不含动态问题或数量；继续透传原 `satoken` 头、解析既有 `R`
数据、逐条过滤损坏引用，并保持召回失败转空列表的既有对外行为。不新增服务账号或无权限重试。以真实序列化的请求捕获测试验证方法、URI、body、头和响应解析，避免只检查构造器参数。

### 3. 请求相关异常采用安全字段日志

对 `kb-ai` 的召回、问答、配额和审计失败日志，以及 `kb-app` 搜索请求进入全局异常处理的路径，统一只记录代码中固定的阶段/错误类别和安全的数字状态。不得传
`Throwable` 给日志框架，也不调用 `toString()`、`getMessage()`、打印原因链、请求/响应 body 或原始 URI。未知异常记固定
`UNEXPECTED` 类别；对外仍使用既有通用错误文案。对业务应用其他请求的全局异常策略不在此次迁移中改变。

选择白名单字段而非对异常字符串做正则脱敏：上游可能把查询词放在
URI、异常消息、嵌套原因或响应体中，字符串过滤难以证明完整。代价是日志少了堆栈；用处理阶段、类别、状态与现有监控定位，再通过可复现测试排障，不在生产日志中保留原始异常。

### 4. 访问日志按路径记录并核查边缘代理

项目控制的网关日志不得输出原始 request URI 或 query string；现有过滤器使用 path
的方式保留。部署文档明确要求前置代理访问日志仅记录路径/状态等安全字段，不记录查询字符串或请求体，并以含哨兵词的旧 GET
请求核查。应用返回 405 发生在请求进入代理之后，不能代替此核查。

## Risks / Trade-offs

- [旧调用方仍发送 GET] → 返回 405 并在迁移说明中给出 POST JSON 示例；上线前查找并迁移调用方。
- [旧 AI 与新业务应用混部时协议不匹配] → 采用同步切换，排空旧实例并阻断旧调用后再开放新版本。
- [旧 GET 被拒绝但边缘代理已记录完整 URL] → 核查访问日志格式及哨兵词，未通过时不宣称日志保密完成。
- [安全日志降低故障细节] → 保留固定阶段、类别和状态，并对异常消息/原因链/响应体包含哨兵词的情况做日志捕获回归。
- [POST body 被基础设施主动记录] → 在部署核查中检查网关、代理和 APM 的请求体采集规则；本仓库内禁止新增请求体日志。

## Migration Plan

1. 更新业务应用、AI 客户端、测试和调用文档；通知使用 GET 的外部调用方改用 POST JSON。
2. 在部署环境确认网关及前置代理不记录原始查询字符串或请求体，并用哨兵词核查访问日志。
3. 排空旧 AI/搜索流量，成组部署新版 `kb-app` 与 `kb-ai`，再恢复流量；验证授权 POST、旧 GET 的 405、SSE 引用及错误日志。
4. 若需回滚，成组回滚两服务并保持流量受控；旧版本重新存在含词 GET 风险，回滚期间须继续使用访问日志脱敏配置并尽快修复后重新部署。
