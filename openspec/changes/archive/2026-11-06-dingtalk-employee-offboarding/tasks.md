# Tasks

任务按实现依赖排序。P0 是访问撤销与恢复正确性的必需工作；P1 是管理与运维交付工作。实现进度以各项勾选状态为准。

本清单仅保留无需启动前端服务、业务服务或外部组件的测试，以及编译、类型检查和构建检查。测试中的数据库、Redis、钉钉、模型、Office 及跨服务调用均使用进程内 mock/stub、内存替身或可控时钟；前端组件测试使用 jsdom。数据库迁移脚本交付不要求启动数据库验证，集成测试、真实平台联调和部署演练不列为任务完成条件。文档编写仍属交付内容，不编写或运行“文档必须包含指定标题、关键词、段落”等内容断言测试，也不要求演练文档步骤。

范围依据：[proposal.md](proposal.md)、[design.md](design.md) 及 [生命周期规格](specs/enterprise-account-lifecycle/spec.md)。其余规格按组内涉及的认证、身份、SSO、AI、权限和管理页面能力核对。

- [x] 1.3 建立事件 Inbox、逐员工处置及按认证代次限定的清理意图模型，保存来源作用域、eventId、内容摘要、版本和恢复位置并配置有界查询索引；使用内存仓储替身测试重复事件的领域处置和未完成记录的保留策略。

- [x] 1.5 在 `IdentityService` 相关领域入口统一计算人工状态与生命周期限制的最终 enabled，并原子写入版本、认证代次和安全审计；用事务与仓储替身测试人工停用叠加离职、普通启用 409、重复处置及审计失败处理，交付状态转换和数据字典文档。

- [x] 2.2 在 app 的受保护入口加入当前代次、有效身份及原强制改密检查，保留精确公开白名单与独立资源授权；以模拟请求扩展 `SaTokenConfig` 等单元测试，覆盖不依赖网关的身份检查、无代次/旧代次 401、当前身份禁用 403 和依赖未知 503。
- [x] 2.3 在 `kb-common` 定义最小内部认证检查契约，并在 app 实现独立签名校验、固定 caller/操作、时间窗、nonce 防重放及目标令牌绑定；验证替换目标、过期、重放和伪造请求均被拒绝，且会话功能关闭时仍可使用。
- [x] 2.4 在 gateway 与 AI 接入内部认证检查客户端及超时处理，禁止仅信任用户头、跨请求正向缓存或直接读取数据库；扩展两侧认证配置测试，验证绕过网关、内部检查不可达及公开路由隔离。
- [x] 2.5 将 Office 当前身份检查及后续预览请求/消息纳入认证代次，保留原文档权限和回调边界；用已有预览测试覆盖离职前会话在停权及复职后不能继续取新数据。
- [x] 2.6 实现按撤销代次或令牌限定的可恢复会话清理，禁止迟到的用户全量 logout；用 Redis 接口替身模拟清理故障、任务重试及复职新会话，测试撤销范围和新令牌保护逻辑。
- [x] 2.7 编写认证内部协议与升级说明，说明缺失代次统一重登、秘密配置、故障状态和候选 token 清理；以说明文档交付为完成标准。

## 3. P0 — 独立应急管理员及并发保护

- [x] 3.1 扩展 `ManagementInvariant`，按显式权限集合、账号/部门状态、本地凭据与非受管事实判断登记保障，保留原最后管理员检查；测试权限分散于多个角色、仅有角色名称及无效部门均不能误判。
- [x] 3.2 实现候选本人应急登记/轮换接口，要求真实本地会话、再次密码验证、短时操作证明、原因、版本及请求标识；测试 SSO/开发会话、他人目标、过期证明和重复提交，确认密码及证明不泄露。
- [x] 3.3 将用户停用、密码重置、主部门变更或失效、角色解除及角色权限收缩接入应急全局保护；逐路径验证削弱最后保障返回 409 且事务不写入部分结果，不静默补回权限。
- [x] 3.4 统一应急变更、纳管和身份写入的锁顺序；通过代码评审及内存状态交错单元测试检查双保障退出、应急登记与员工映射冲突时的领域决策，不将其作为真实数据库并发保证的证明。
- [x] 3.5 实现接入启用前的应急就绪检查和持续保护，关闭接收仍保留已有保障；测试无保障拒绝启用及关闭后不能绕过，文档说明本地凭据保管、候选本人登记、先建后换和合法退役条件。

- [x] 4.2 新增默认关闭的独立生命周期配置及企业内部应用身份校验，限制出站 HTTPS/WSS、消息大小、员工数量、线程和队列；配置测试覆盖秘密缺失、范围错误、越界值及 SSO 开关独立性，更新无秘密的配置示例。
- [x] 4.3 实现准确员工标识的服务端当前成员查询与有界超时，隔离 SSO 绑定写入并禁止姓名/手机自动合并；用供应商替身验证成员不可见、无效、响应损坏及依赖故障不会错误纳管或恢复，检查出站无内部凭据和追踪头。
- [x] 4.4 实现 Stream 生命周期、事件解析及事务结果到 SUCCESS/LATER 的 ACK 适配，按业务 eventId 保留身份、去重员工列表；协议测试覆盖错企业/应用、损坏载荷、超限拒绝、提交失败、重投及有限关闭，文档明确成功 ACK 必须晚于第 6 组接收事务提交。

## 5. P0 — 员工映射管理与受控查询

- [x] 5.1 实现成员核验凭据，绑定操作者、内部目标、来源、员工和当前版本并限制有效期；测试换目标、换来源、过期及复用凭据被拒绝，核验结果仅返回最小确认信息。
- [x] 5.2 实现明确纳管、映射变更和退出的事务入口及幂等回执，检查未解决离职记录、当前限制和在途复职；测试本地用户纳管、并发关联冲突、事件先到后补映射及离职后删除映射不能绕过限制。
- [x] 5.3 实现生命周期状态、用户摘要、应急摘要和事件/员工项的有界分页读取，使用独立最小 DTO 和 no-store；接口测试验证稳定游标、无原始员工 ID/事件载荷、无权读取及未知状态不伪装为未纳管。
- [x] 5.4 按四项精确权限接入管理控制器，鉴权先于查询、回执和供应商调用；提交权限矩阵、版本/幂等冲突和撤权后重放测试，并记录 API、400/401/403/404/409/503 语义及 SSO 绑定独立性。

## 6. P0 — 可靠离职接收与持久访问限制

- [x] 6.1 将 Stream 处理接入短事务，在统一管理/映射/用户锁序内保存 Inbox、逐员工结果、最终停用状态、认证代次、系统审计及清理意图；用事务回调及仓储替身测试只有提交成功才返回成功 ACK、失败返回重试结果且不发起外部成员查询。
- [x] 6.2 实现来源作用域内业务事件去重、同键不同内容隔离、员工列表去重及明确忽略非离职事件；测试重复投递不重复停权或推进代次，冲突不覆盖首份依据，入职事件不建号或自动复职。
- [x] 6.3 实现 UNMAPPED、REVIEW、失败项查询与原事件重试、崩溃后恢复及有界重试调度；验证已完成项保持幂等、未匹配补映射后可重新核对、客户端不能替换载荷且恢复不依赖接收开关开启。
- [x] 6.4 记录可靠接收、访问限制及清理的独立结果，并补充处置流程文档；以可控时钟和事务回调替身测试计时起点、未匹配/隔离项不计为停权成功、接收前故障不伪造成功及关闭订阅不解除既有事实。

## 7. P0 — 人工复职与迟到事件

- [x] 7.2 实现确认前再次成员核验和事务内事实复核，原子解除限制、前进认证代次并保存审计和回执；测试并发变更、凭据过期/复用、响应未知匹配重试及人工停用继续生效。
- [x] 7.3 实现复职与离职事件的竞争规则，保留已处理 eventId 和恢复边界；测试复职后旧事件重复不再次停权、新有效离职再停权、未见过的更早事件进入 REVIEW 及复职确认不能覆盖新事件。
- [x] 7.4 完善复职 API 文档和管理反馈，明确仅解除生命周期限制、保留部门角色密级且旧会话不可复活；分别用控制器和领域服务单元测试覆盖普通启用无法代替复职、撤权后回执不可读及平台故障不自动重试写入。
