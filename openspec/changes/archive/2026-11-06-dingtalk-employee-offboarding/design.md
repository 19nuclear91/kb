# Design

## Context

动机与已确认范围见 [proposal.md](proposal.md)。当前实现提供了可复用的权限与事务边界，但未提供完整的自动撤销机制：

- `IdentityService.setEnabled` 使用用户版本、行锁、管理面 advisory lock 和身份审计；`resolvePrincipal` 与权限 SQL 读取 `sys_user.enabled`，没有认证代次。停用不注销已有 Sa-Token。
- `sys_user_identity` 的受管 SSO 绑定使用平台、企业、应用及标识类型作用域。`DingTalkLoginProvider` 最终保存企业 `userid`；原始绑定管理接口禁止伪造受管 SSO 绑定。生命周期映射必须是另一种授权关系。
- gateway 只检查 Sa-Token 会话；app 负责身份事实，AI 不访问数据库。强制改密、部门有效性与资源授权继续使用原有规则。
- 多轮 `append/renew/dispatch/finish` 使用执行票据。`ConversationSettings` 默认执行租约 120 秒、续租 30 秒，不能承担 30 秒撤销目标。旧单轮也有独立输出及取消路径。
- `ManagementInvariant` 当前只保护最后一名同时具有角色分配与角色写入资格的启用用户；独立本地应急保障还需覆盖部门、凭据和生命周期恢复权限。
- 当前没有活跃 OpenSpec 变更。此次只新增规划文件，不修改主规格或实现代码。

官方协议核对依据（2026-11-06；仅公开文档，未连接企业实例）：

1. [通讯录用户离职](https://open.dingtalk.com/document/orgapp/event-v3user-leave-org.md)：企业内部应用支持 Stream/HTTP；事件具有 `eventCorpId`、`eventId`、`eventBornTime` 及 `data.userId[]` 等字段。
2. [Stream 协议](https://open-dingtalk.github.io/developerpedia/docs/learn/stream/protocol/)：传输 `messageId` 与业务 `eventId` 不同，事件 ACK 使用 SUCCESS/LATER，正确 ACK 后仍可能重复投递；多个连接可能接收不同推送。
3. [Stream 概述](https://open-dingtalk.github.io/developerpedia/docs/learn/stream/overview/)及[官方 Java SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-java)：出站 TLS 连接接收事件，无需暴露公网回调。

## Goals / Non-Goals

**Goals:**

- 以数据库持久事实和有界输出许可实现撤销，避免把 SDK 回调返回、Redis 删除或前端隐藏当作停权完成。
- 对重复、迟到、映射变化、登录签发和人工复职的竞争给出可检验规则。
- 将“可靠接收”“禁止访问”“停止本地输出”“终态/费用收尾”分别记录，不让结算故障延长输出。
- 保留现有权限 SQL 的最终状态入口、人工停用语义和用户内部 ID，降低权限路径遗漏风险。

**Non-Goals:**

- 不增加独立微服务、消息中间件或业务数据库访问方，不把职责放入文档解析 Worker 或告警通知器。
- 不将钉钉事件时间当成严格序列，不承诺跨系统 exactly-once、事件必达、供应商停止计算或已发送数据撤回。
- 不实现全量目录同步或无人确认的自动映射；只对明确受管且有准确映射的账号提供自动停权。

## Decisions

### D1. 独立生命周期接入，Stream 运行在 app

在 `kb-app` 新增 `auth.lifecycle` 领域及隔离的 Stream 适配组件，使用官方 Java SDK 固定版本。初始化、重连、队列及停止必须有界，进程关闭停止接收并等待有限在途事务；不让外部网络等待占用身份行锁。接入参数采用独立 `kb.identity.lifecycle.dingtalk` 命名空间，默认关闭，固定单个企业及企业内部应用。SSO 登录开关关闭不影响生命周期订阅，反之亦然。

生产只允许受控 HTTPS/WSS 目标，不向供应商传播用户令牌、内部签名或追踪上下文。验证 SDK 日志、重连与连接 ticket 处理，不输出凭据、完整员工标识或事件原文。订阅连接的应用身份与返回事件的企业/应用范围一并校验；`eventUnifiedAppId` 不直接等同 OAuth clientId，按真实协议建立校验关系，不能随意忽略不匹配。

替代方案：HTTP 回调需要公开入口和另一套签名/解密生命周期；新增接入服务会扩展部署与内部信任边界。本期选 Stream + app，保留领域与传输解耦以便未来单独变更。

### D2. 员工映射独立于登录绑定

新增受管登记，逻辑唯一键为 `(source, enterpriseId, employeeId)`；一个受管内部账号在本期至多有一条当前员工映射。映射保存连接身份、内部用户 ID、版本、登记人/时间、状态及撤销历史。员工标识只在受控管理输入和必要服务端查询中使用，对外读取仅给内部映射 ID、目标账号、连接别名、状态与版本，不返回原始标识或可逆片段。

登记流程为管理员选择已有内部账号、输入准确钉钉员工 ID、服务端以配置企业应用查询当前成员、显示最小核对信息并由管理员确认；核对结果短期有效且绑定操作者、账号、连接、员工和版本。查询结果不能按名字/手机号自动认领账号。已有 SSO 绑定可以生成候选，但必须显式确认，不能将所有历史绑定自动纳管。所有网络核验在短事务外完成，提交前检查证据仍适用。

这是人员管控关系，不写 `sys_user_identity`，也不授予扫码登录。SSO 解绑不撤销生命周期受管关系。受管映射变更/退出要带原因、当前版本并保留历史；账号存在离职限制、未解决事件或在途复职时拒绝变更/退出。退出受管本身不解除账号限制或恢复旧会话。映射登记必须检查同员工既有待处理离职记录，不能在收到离职后通过补建映射获得访问。

替代方案：只复用 SSO 绑定无法覆盖本地账号；姓名/手机匹配没有唯一授权依据；删除映射历史会使迟到事件无法解释。

### D3. 人工状态、离职限制与认证代次分开

为用户增加 `manual_enabled` 与单调 `auth_epoch`，为生命周期记录增加 `restriction`（CLEAR / OFFBOARDED / REVIEW）及版本。`sys_user.enabled` 继续表示最终状态，统一写入规则为 `manual_enabled && restriction == CLEAR`；无受管记录等价于 CLEAR。迁移以原 enabled 回填人工状态，不改变任何用户的既有可用性。

所有状态写入经同一领域入口，在短事务中更新来源状态、最终 enabled、必要的认证代次、处理记录及不可变审计；不通过批量 SQL 绕过此入口。首次施加离职/待核对限制，即使人工状态早已停用，也使认证代次前进一次；重复事件不重复推进。人工有效停用同样使旧会话永久失效。解除离职限制不会把 manual_enabled 改为 true，且再次前进代次，要求重新登录。

普通启用接口遇到离职/待核对限制返回固定 409，不能先写人工启用再报告成功。管理员可继续独立调整合法部门、角色或密级；恢复不自动补回任何授权，也不删除文档、历史、收藏或角色/ACL。

替代方案：只有 enabled 无法区分来源；给所有授权 SQL 添加独立外部状态连接容易漏掉路径。保留有效 enabled，增加来源事实并约束所有写入口。

### D4. 持久接收时先建立访问屏障

逻辑数据分为事件 Inbox、逐员工处置项、映射/状态和独立清理任务。去重键为固定来源作用域加 `eventId`，另保存规范化内容摘要；相同键不同语义内容转隔离异常，不能覆盖首份记录。传输 messageId 仅用于 ACK，不充当业务幂等身份。

有效 `user_leave_org` 按如下短事务接收：

1. 校验企业/应用/事件类型、必填身份、时间字段和有界员工集合；不支持的已知事件只记录固定忽略结果，绝不触发建号或启用。
2. 取得固定管理保护锁、生命周期连接/映射锁及按内部用户 ID 升序的用户锁；与映射登记、恢复、应急轮换及权限收缩遵守同一锁序。
3. 插入 Inbox 与去重后的员工项。对当前准确映射的受管账号，当次事务立即施加 OFFBOARDED 或 REVIEW、更新有效 enabled/auth_epoch，并保存系统来源审计及清理意图。无需等待后台 Worker 或远程成员查询才阻断访问。
4. 未映射员工保存 `UNMAPPED`，已处置重放保留原结果；提交成功才返回 SUCCESS。数据库失败返回 LATER，不伪报可靠接收。业务待人工项有持久记录后可以 ACK，但界面不能称“停权成功”。

`receivedAt` 是接收事务的持久时间，30 秒验收起点为该事务提交可见时刻；提交前不返回成功 ACK。完成后后台任务负责 Redis 清理、状态核对与可重试收尾，不再决定第一道访问屏障。单个事件及用户数量有固定配置上限，首版建议 1 MiB、1000 个员工；超过上限拒绝成功 ACK 并告警，不能截断后确认整条事件。

应急身份和受管身份互斥由持久约束及上述锁保证。若发现越过管理入口造成的数据损坏，事件隔离并告警，受影响受管身份保持拒绝访问，不能因“最后管理员”保护把普通离职账号放行或标记成功；修复须通过独立应急流程。

替代方案：先 ACK 再写库会丢事件；仅入队、等后台调度停权无法在工作进程失效时维持 30 秒目标。

### D5. 复职使用显式证据与冲突核对

复职分为受保护的核对和确认两步。核对服务读取当前员工成员事实、内部用户/映射/角色版本、当前限制及待处理事件位置，生成 5 分钟内有效的一次性服务端确认凭据。确认要求独立复职权限、原因、当前版本和幂等请求标识；提交前再次核验成员，随后在与事件接收相同的锁序内验证事实没有变化，原子解除离职限制、推进认证代次并审计。外部查询故障、成员不存在/不有效、主部门无效或新的离职事件导致拒绝，不自动重试写入。

普通在职/加入企业事件仅是核对信息，不恢复账号。同一已处理 eventId 在复职后重放只返回原处置结果。新的有效离职事件仍施加限制；若其时间落在复职核对之前而未见过该事件，不能证明完整顺序，置 REVIEW 并等待再次人工核对。不得仅凭到达顺序或较大的时间戳覆盖事实，也不把复职前旧事件重放当成新的离职。

角色/密级/部门核对只用于说明和冲突检测，不把复职扩展成批量授权事务。若人工停用仍存在，复职响应明确“离职限制已解除，账号仍被人工停用”。暂不提供覆盖成员查询失败的强制恢复入口。

### D6. 统一认证代次门禁及安全的登录签发

本地、SSO、开发登录统一签发全新的、不可与旧登录共享的 token，在服务端 token 元数据绑定认证时的 auth_epoch 和可信认证方式；客户端不能设置这些值。认证方式用于区分应急登记要求的真实本地登录，开发登录不得充当本地凭据证明。签发前取得当前有效身份，完成会话存储后再次核对代次与启用事实，失败清理本次候选 token。停权若发生在最后核对之后，候选仍携带旧代次，下一次业务访问必须被拒绝，不能通过回填 token 元数据使旧会话获得新资格。

app 在所有受保护用户请求统一检查会话、代次、启用及原有改密规则，资源权限继续独立判定。gateway 和 AI 通过新的、始终可用的签名内部认证检查协议调用 app，禁止直连数据库或仅依赖 gateway 检查；app 直接访问同样不能绕过。内部接口使用独立 `KB_AUTH_INTERNAL_SECRET`（至少 32 UTF-8 字节）、固定 caller/操作、时间窗、nonce 和 token 摘要绑定，不依赖会话功能开关或复用用户自报头。该协议不返回角色、正文或员工资料。

普通请求不使用跨请求的有效身份缓存。旧/缺少代次令牌返回 401；当前代次身份仍被禁用时按既有 403 处理；数据库/内部校验不可确认返回 503，均不继续业务。匿名登录、SSO 精确公开路径和健康检查保持原白名单，内部路径不公开代理。Office 会话的当前身份检查也纳入代次，后续预览请求/消息不能因保留旧会话继续访问。

Redis 清理是可恢复的辅助工作。清理项绑定需撤销的代次/令牌，不能对用户进行无条件迟到的全量 logout，以免误注销复职后新登录；停权确认不依赖清理成功。

### D7. AI 输出许可与原执行租约分离

新增仅允许短时本地输出的授权许可，覆盖单轮、多轮、占位分支及 AI 用量观测开关的所有组合。许可绑定用户、认证代次与当前执行，从 app 主库核对取得。采用硬上限 10 秒有效期、默认每 3 秒刷新、单次检查最多 2 秒；许可过期、身份撤销或检查失败立即停止输出并取消上游，不以旧许可重试延长。

有效期从本地发起核对的单调时钟时刻起算，网络耗时计入预算；迟到响应若已过期或属于旧执行代次就丢弃。每条 citation/delta/done 写出前核对本地许可期限，独立定时器处理上游无输出/卡住的情况，检查不能排在模型正文或落库队列后。恢复暂停的进程也先检查期限再输出。这使接收事务已建立屏障后，仍在正常运行的 AI 节点在 10 秒许可上限内停止本地输出，留出 30 秒验收余量；广播通知只能加速，不能作为正确性前提。

多轮执行记录绑定开始时 auth_epoch；reserve、dispatch、seal、append、renew 重新检查该代次，撤销后不得追加正文、续期或转为成功。取消/失败收尾与纯结算有独立权限：合法旧票据只能封存已确认前缀、结束原轮次、生成或重试同一账本意图，不读取新材料或继续生成。并发完成以先提交的合法终态为准；已提交 COMPLETED 不被覆盖，但撤销后不再向客户端补发正文或 done。

离职取消使用 CANCELLED 与固定原因 ACCOUNT_REVOKED；无法确认身份依赖时使用既有失败/中断规则和安全错误。模型有调用意图但缺少可靠最终 usage 继续 UNKNOWN，未调用为 NOT_INVOKED，结算与并发释放不伪造成已完成。若持久化不可用，SSE 仍按许可期限结束，之后用原恢复机制收敛，30 秒不包括数据库不可用期间无法确认的费用结算。

内部认证与会话执行协议只在服务验签通过后，用 401/403 加唯一、精确的 `X-Auth-Result: ACCOUNT_REVOKED` 表示可信身份撤销；无标记、重复/未知标记或服务签名拒绝不能证明离职。AI 对认证检查的此类未知拒绝按 AUTHENTICATION_UNAVAILABLE 失败关闭，不能只凭 HTTP 状态记录 ACCOUNT_REVOKED。该结果只由内部响应产生，输入同名头无效；app/AI 须协调发布。

若执行入口先于许可刷新确认撤销，复用当前许可取消模型并提交一次停止证据，再走受限取消。普通错误的缓冲保存与失败收尾也保留原许可上下文，清理阶段首次收到可信撤销时不得吞掉或继续追加缓冲。输出建立前 reserve 被撤销不虚构停止报告；后续 finish 明确无持久结算意图时释放先取得的配额租约，已有意图按原账本结算，响应未知则不能推断零用量释放。

替代方案：只降低已有任务租约会影响结算及崩溃恢复；只调用 logout 不影响执行票据；只推送撤销通知可能在断连或跨实例时漏失。

### D8. 应急账号成为持续不变量

启用接收前登记至少一个独立本地应急管理员：非受管、无受管 SSO 登录依赖、有效本地密码、已完成强制改密、用户及主部门启用，并拥有角色目录/分配/写入、用户读写/密码、部门读写及本次四项生命周期/应急管理权限。所需 code 以显式集合检查，不依据 ROLE_ADMIN 名称。

登记/轮换由候选本人使用有效本地会话、再次校验本人密码执行，产生短时凭据证明；不会要求管理员提交他人密码。先赋予合法权限并完成本地登录，再原子登记/替换保障。密码明文和证明不持久保存或进入审计。

用户停用、密码重置导致强制改密、主部门失效、用户迁移、角色解除、角色权限收缩及登记替换均在统一管理锁内检查变更后的应急保障。不得让受管账号、无本地凭据账号或已失效部门充当保障。最后一名保障的退出/资格削弱返回固定 409，不静默补权。普通员工管理员离职不触发例外放行，因为独立保障已满足原最后管理员不变量。

停止订阅不会取消应急保护；只要存在受管账号或限制，保障必须持续。退役受管能力必须先合法处置限制及登记，不能通过改配置解除保护。操作人实际保管密码仍属运维职责，系统只证明可校验的登录能力和持久资格。

### D9. 管理接口、权限与前端

新增四项精确权限：`identity:lifecycle:read`、`identity:lifecycle:manage`、`identity:lifecycle:restore`、`identity:emergency:manage`。读写互不蕴含，不额外授予文档、SSO 绑定或角色权限。首次迁移对当时已有 ROLE_ADMIN 一次性赋予；后续不恢复撤销项，空库新管理员按完整目录初始化。

规划接口均位于 `/api/admin/identity` 下，采用原 R 包装与 no-store：

| 接口组 | 主要行为 / 权限 |
| --- | --- |
| `GET /lifecycle/status`、`GET /lifecycle/events`、`GET /users/{id}/lifecycle` | 连接健康、受控事件/员工处置及目标摘要；lifecycle:read，列表 limit/cursor 有界 |
| `POST /users/{id}/lifecycle/verification`、`PUT /users/{id}/lifecycle/mapping`、`DELETE /users/{id}/lifecycle/mapping` | 服务端核验、显式纳管/修改/退出；lifecycle:manage，版本、原因、请求标识 |
| `POST /users/{id}/lifecycle/restoration-check`、`POST /users/{id}/lifecycle/restore` | 复职核对与确认；lifecycle:restore，固定确认凭据和版本 |
| `POST /lifecycle/events/{id}/retry` | 重放原持久事件，不接受客户端更改来源/员工/载荷；lifecycle:manage |
| `GET /lifecycle/emergency`、`POST /lifecycle/emergency` | 最小保障摘要由 lifecycle:read 读取，候选本人登记/轮换由 emergency:manage 执行 |

管理接口鉴权先于目标查询、回执读取及供应商调用。写请求标识绑定操作者、操作、目标、规范化请求与版本；匹配重试返回首个回执，绑定不同返回 409，撤权后重试仍拒绝。供应商故障为安全 503，输入400，未登录401，无权限403，合法不可见目标404，状态/版本冲突409。普通账号启用冲突仅返回固定类别，不向无生命周期读取资格者泄露离职事件详情。

账号详情通过额外生命周期读取面板展示人工状态、有效状态、受管/限制状态和处置时间，不扩大原用户 DTO 的外部身份投影。已有“启用”不能替代“确认复职”。写成功、响应未知和复职后仍人工停用明确区分；未知结果保留原请求绑定，不自动重发。切换身份/目标、撤权或页面隐藏按原规则清理敏感状态；员工输入不进入 URL/浏览器持久存储。独立事件视图提供未匹配、待核对、处理失败与重试入口，分页不得虚构全局总数。

普通账号启停、主部门、密级、密码或角色绑定操作成功，以及相关 404/409 后的重读，通过显式刷新代次同步重新读取独立生命周期摘要；仍由 lifecycle:read 控制读取，不从普通 DTO 推断生命周期事实。刷新代次变化会卸载旧摘要对应的确认表单、证明和在途等待，读取完成前不保留可操作的旧事实；生命周期操作反向刷新普通详情不推进该代次，避免反馈刷新循环。

生命周期写入响应未知时可按原绑定精确重试，即使证明过期也只核对原回执。“放弃核对”不会撤回原写入，而是撤销旧证明、退出旧确认并重新读取当前事实；重新进入操作后必须显式重新核验、填写原因和确认，以新请求标识建立新操作。该重新开始规则仅适配生命周期流程，不改变其他管理写入的共用 reset 语义。

### D10. 运维、时限与验证证据

低基数指标至少覆盖连接可用性、最后成功连接/接收、未映射及 REVIEW 深度、最老待处理年龄、接收至限制提交/AI 本地停止耗时、认证校验失败、清理失败及应急保障就绪。无事件不等于订阅故障；未能确认的样本不能作为零延迟或成功。标签仅使用固定来源、状态与错误类，不含用户、企业、事件 ID。

接收事务保存数据库时钟的提交前界限，提交后独立补记数据库时钟的可见性上界；无法观察提交后时刻时保留未知。按用户和原认证代次保存不可变的撤销依据，关联原事件。内部身份检查返回同一主库语句的时间锚点；AI 记录该请求发起、响应及实际停止的单调时刻，先取消输出，再通过固定 kb-ai 签名的有界后台通道报告停止证据。以请求往返区间计算停止时间上下界，与接收提交区间相减，保留区间而不宣称跨进程精确单点。证明缺失、区间不一致和仅补映射才限制的情况不能计入首轮已映射员工的达标样本。持久证据含受控内部关联键，监控标签及外发通知不包含这些键。耗时下界超过 30 秒表示已确认违规；仅上界越界或证据不完整表示不可确认。

接入现有监控规则，并同步扩展 `kb-alert-notifier` 固定告警目录及中文受控模板，区分连接故障、30 秒处置目标违规、积压、应急保障损坏及依赖故障；继续拒绝未知类型和任意文本，不改为转发原始 annotations。告警链接只指管理入口，不包含员工详情。30 秒仍是产品行为要求；本次编码任务不以真实多实例或外部环境验收为完成前提，也不能将单元测试或定时器配置表述为已完成真实环境验收。

本次任务只安排不启动前端服务、业务服务或外部组件的领域/协议单元测试、基于 jsdom 的组件测试，以及编译、类型检查和构建检查。数据库、Redis、钉钉、模型、Office 与跨服务调用使用进程内 mock/stub、内存替身和可控时钟；以这些替身覆盖旧单轮、估算/严格多轮、观测关闭及 Office 身份检查的行为分支，不据此声称已经证明数据库事务、真实并发或跨节点时限。集成测试、真实企业联调、部署演练及压测不列入当前任务或任务完成条件。

文档按实现结果编写并交付，不为标题、关键词、段落等文档内容编写断言测试，也不要求执行文档中的环境部署或演练步骤。配置解析、规则计算和通知消息生成属于代码行为测试，可在无需启动服务的前提下保留。

## Risks / Trade-offs

- [事件漏投或订阅中断] → 本期不承诺未收到事件的停权时限；监控订阅健康与缺口，管理员可依原接口先停用。补投按同一幂等路径处理，不以查询不到成员的单次错误批量停权。
- [独立映射覆盖不足] → 仅准确映射的受管用户计入自动保障；启用前输出覆盖检查，未匹配事件可见且不能假称已处理。
- [事件乱序/复职竞态] → 事件去重、映射版本、事务锁与复职证据共同判定，无法确认时限制访问并人工核对，不用时间戳充当总序。
- [新增主库校验开销] → 普通请求保持请求内复用，AI 用独立短时许可；限制并发与超时，压测确认容量，不能以延长许可突破时限。
- [SDK 依赖、自动重试或日志行为] → 固定版本和包隔离，验证重连不重放管理命令，屏蔽原始事件/凭据日志，确认 ACK 在事务提交之后。
- [数据库/网络分区] → 新请求失败关闭，AI 许可到期停止；未提交事件不 ACK，已接收事件保持访问屏障。持久终态与结算可延后但不伪报完成。
- [跨节点时钟差] → AI 使用本地单调时间控制许可，服务端事件时刻用于审计；跨节点时延统计单独校准，不能用客户端时钟判定事件新旧。
- [应急凭据丢失] → 登记时证明本地可用、运维保管与定期演练；不添加绕过认证的网络恢复接口，不自动重置管理员密码。

## Migration Plan

以下保留实际发布时的部署说明，不属于本次编码任务的测试或演练清单；当前任务不要求执行这些环境操作。

1. 备份并盘点现有用户、权限、绑定及在途会话；确认既有部署具备维护窗口。新增 Flyway 版本（实施时使用下一个未占用编号），回填 manual_enabled、初始化 auth_epoch，建立事件/映射/恢复/保障表及唯一约束；不自动纳管或自动指定应急账号。
2. 排空不认识新权限的旧 app，以及不识别认证代次和 AI 撤销协议的旧 gateway/AI。排空旧在途生成，保留结算恢复，不混部承接用户流量。
3. 部署 common/app/gateway/AI 的新协议和前端。缺少认证代次的旧 token 一律401，要求重新登录，禁止后台给旧 token 补当前代次；部署应急操作者也重新进行本地登录。
4. 在订阅仍关闭时登记并校验独立应急管理员，核验出站域名/企业应用/成员权限，建立员工映射。已有本地/SSO登录和文档权限回归通过后才启用订阅。
5. 在受控测试账号验证真实离职事件、持久接收、两种登录拒绝、旧令牌、跨实例 AI 停止、人工复职及迟到重放；记录事件接收至本地停止不超过30秒的证据，再扩大纳管范围。
6. 止损优先关闭新事件接收，保留现有限制、代次校验、应急保障和结算恢复；不能通过关闭开关恢复员工。重新启用处理已持久事件，不能清空去重记录。
7. 不支持直接回退旧认证二进制：新权限目录及会话语义不兼容。优先修复前进；必须退版本时先停止用户流量、终止全部旧/新会话和生成、保留限制及审计，由单独迁移方案证明旧程序无法放行受限用户，再执行恢复。不得自动删权限绑定或清空限制伪装兼容。
