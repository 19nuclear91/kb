# Spec Delta

## Purpose

为企业知识库提供用户主动发起的知识问题单，在明确分享范围内追踪统一受理、合格人员分派、解决方案与提问者确认，且不将私人会话、文档引用或处理记录变成绕过当前权限的新内容入口。

## ADDED Requirements

### Requirement: 问题单必须由有效用户主动且明确分享

系统 SHALL 通过 `POST /api/knowledge-gaps` 接受 category、description、source 和 shareAcknowledged，归属只取当前有效会话。description 去除首尾空白后为 1–4000 个 Unicode code point，shareAcknowledged 必须为 true。category 只接受 MISSING_KNOWLEDGE、INACCURATE、OUTDATED、OTHER；source 只接受 MANUAL、SEARCH、CONVERSATION，它只说明入口而非根因证明。首次创建返回 201，匹配重放返回 200。

#### Scenario: 独立提交
- **WHEN** 有效用户明确确认分享并提交合法描述
- **THEN** 创建归属本人的 SUBMITTED 问题单，不要求其持有管理或处理权限，不调用检索或模型

#### Scenario: 隐式采集或夹带原文
- **WHEN** 请求未确认分享，或包含归属、会话 ID、轮次 ID、模型回答、引用正文或其他未知字段
- **THEN** 返回 400，不后台补查原问题、回答或搜索记录

#### Scenario: 用户报告零结果或故障
- **WHEN** 用户将问题类型选择为缺少知识，或从发生检索故障的页面主动提交
- **THEN** 类型仅记录用户诉求，不宣称全库无资料，不将故障转换成已确认的知识缺口

### Requirement: 问题单必须按当前最小参与范围读取

每次列表、详情、历史、能力及回执读取 SHALL 核验有效身份，问题单可见范围为原提问者、仍持有 `knowledge:gap:handle` 的当前负责人、持有 `knowledge:gap:read` 的受理人员三者并集。曾经处理、管理角色名称或其他管理权限不构成资格。未认证返回 401，身份停用或强制改密返回 403，不存在或无问题单访问权统一 404；无法可靠鉴权返回安全 503。

#### Scenario: 改派后旧负责人访问
- **WHEN** A 被改派为 B，A 既非提问者也没有受理读取资格
- **THEN** A 下一次详情、历史及原写入回执核对均拒绝，不能凭旧链接或已读通知访问

#### Scenario: 多种身份及撤权
- **WHEN** 负责人失去处理资格，但仍是提问者或仍持有受理读取资格
- **THEN** 只按其剩余身份保留相应读取，处理资格本身不能由剩余读取身份代替

### Requirement: 问题列表与历史必须有界并先鉴权后分页

`GET /api/knowledge-gaps` SHALL 接受 view=mine 或 assigned，默认 mine；assigned 要求当前 handle 资格且只返回当前分派项。统一受理列表位于 `GET /api/admin/knowledge-gaps`，要求 read。列表仅接受 view（普通列表）、status、limit、cursor；limit 默认 20、范围 1–100，按固定创建位置倒序。详情及独立历史分页每次重核资格，历史按不可变操作位置正序，不返回隐藏总数。

#### Scenario: 稀疏可见范围
- **WHEN** 使用旧游标继续读取，较新的若干问题已不再可见
- **THEN** 从当次可见范围取页并正确给出 hasMore 和 nextCursor，不返回不可见占位或因先截取原始行制造虚假末页

#### Scenario: 游标或筛选非法
- **WHEN** 游标属于其他用户、视图或筛选，或输入重复/未知参数、未知状态、越界 limit
- **THEN** 返回 400，不把错误解释为空列表或全部问题；改变筛选须从新游标遍历开始

### Requirement: 分派必须是单一当前负责人且不延续历史授权

持有 assign 且当前可访问该单的受理人员 SHALL 为任一非终态问题选择一名当前有效、已完成必需改密且持有 handle 的负责人。分派或改派使状态为 IN_PROGRESS，使原待确认方案失效但保留历史。每次提交必须重新验证候选资格，不能自动授予角色或文档权限；处理人无直接改派能力。停用或失权的分派关系保留供受理人员人工接管，不自动算作处理完成。

#### Scenario: 候选读取后失效
- **WHEN** 已选择的负责人在实际分派前停用、部门停用或失去 handle
- **THEN** 返回 409，不建立新分派、不改变旧负责人和原方案

#### Scenario: 待确认期间改派
- **WHEN** 合格受理人员改派 AWAITING_CONFIRMATION 问题
- **THEN** 新负责人接手 IN_PROGRESS，旧方案不再可确认，迟到确认不得将该单解决

### Requirement: 补充说明与退回受理必须受当前参与资格约束

提问者、当前合格负责人和具有 assign 的可见受理人员 SHALL 可为非终态问题追加 1–2000 个 Unicode code point 的共享纯文本说明，不可编辑或删除已提交说明。说明不改变状态；无隐藏内部评论。当前合格负责人 SHALL 可带原因退回受理，清空当前分派并进入 SUBMITTED；若原有待确认方案则使其失效，历史仍保留。

#### Scenario: 提问者补充背景
- **WHEN** 提问者在处理中追加合法说明
- **THEN** 记录原操作者及服务端时间，同单有权人员可读，不自动重跑检索或改写原描述

#### Scenario: 负责人退回
- **WHEN** 当前合格负责人对非终态问题提交合法退回原因
- **THEN** 问题回到受理队列，该人下一次读取不因旧分派保留访问权；本次仅返回不含正文的命令回执

### Requirement: 解决方案必须由当前合格负责人明确提交

当前合格负责人 SHALL 仅在 IN_PROGRESS 提交 1–4000 个 Unicode code point 的纯文本处理说明，可不关联文档，也可关联一组 documentId/versionId。每次方案具有不可变身份，提交后状态为 AWAITING_CONFIRMATION。受理、文档管理或提问者身份本身不能代替当前负责人及 handle 资格；不自动从模型回答生成方案。

#### Scenario: 说明型方案
- **WHEN** 当前合格负责人提交纠正搜索方式的说明且不关联文档
- **THEN** 保存方案并等待提问者确认，不要求额外上传、解析或审核

#### Scenario: 不完整或越权方案
- **WHEN** 说明为空、仅提供文档 ID 或版本 ID 之一，或提交人已不再是合格当前负责人
- **THEN** 分别按非法输入或当前资格拒绝，不保存部分方案

### Requirement: 文档型方案必须使用双方当前可读的固定发布版本

关联文档型方案时，系统 MUST 在当前提交请求中核对固定版本属于目标文档、具有可信发布证据、文档与空间未归档未删除，且处理人和有效提问者均有当前 view 及足够密级。索引完成或私人候选查看资格不能替代发布证据；无法满足返回不泄露目标事实的 409，依赖故障为 503。关联只保存固定身份，不复制标题或正文、不补授权。

#### Scenario: 新版尚未发布
- **WHEN** 处理人关联已索引但从未发布的候选版本，即使本人有审核资格
- **THEN** 拒绝方案，不将送审或解析成功认定为知识已补齐

#### Scenario: 提问者不能读取或已停用
- **WHEN** 提问者无权读取固定版本或已不再是有效主体
- **THEN** 文档型方案提交不成功，受理人员仍可按自身资格带原因关闭问题

### Requirement: 关联资料读取必须独立于问题单资格

详情与每个历史方案的资料身份 SHALL 按当前查看者逐次校验。资料不可访问时仅给固定不可用提示，不返回该资料的 ID、标题、正文或隐藏数量，问题单内明确分享的人工文本仍按问题单资格读取。新版本发布不替换旧关联；语义撤回不覆盖用户主动粘贴的人工文本，系统 MUST NOT 自动把受限材料复制进人工字段。

#### Scenario: 受理人员无文档阅读权
- **WHEN** 用户持有问题单 read 但不能读取方案所关联的资料
- **THEN** 可读问题单共享记录，不取得资料身份或标题，不调用越权文件入口

#### Scenario: 资料撤权或更新
- **WHEN** 已提交方案的资料后来撤权、归档、删除或发布了新版本
- **THEN** 前三者隐藏原资料，后者仍核对原版本；已有问题状态不自动改变，资料权限故障返回 503 而非旧快照

### Requirement: 方案资料候选必须受当前处理和文档资格约束

`POST /api/knowledge-gaps/{gapId}/solution-documents` SHALL 只向当前合格负责人提供其本人可读、未归档未删除且当前版本有发布证据的资料候选。请求仅接受 nameQuery、limit、cursor，名称最多 128 个 Unicode code point，分页默认 20、最大 100；游标绑定本人、问题和条件。只返回已授权标题及固定文档/版本身份，不预筛或暴露提问者的授权范围；双方资格在提交方案时另行核验。

#### Scenario: 处理人选择资料
- **WHEN** 当前合格负责人提交合法资料名称查询
- **THEN** 名称仅经 POST 正文传输，返回本人当前可读的最小固定版本候选，不读取全局文档管理目录

#### Scenario: 旧负责人或未知游标
- **WHEN** 已被改派的人员读取候选，或游标不属于当前问题、用户或查询条件
- **THEN** 分别按当前资格或非法输入拒绝，不通过候选恢复旧访问或枚举他人权限

### Requirement: 只有提问者才能确认当前方案或退回继续处理

原提问者 SHALL 仅对 AWAITING_CONFIRMATION 的当前方案，携带匹配方案身份和预期问题版本，明确确认或说明仍未解决。确认使状态为 RESOLVED；退回需 1–2000 个 Unicode code point 原因，使状态为 IN_PROGRESS，并保留原负责人及方案历史。文档型确认须重核本人对原发布版本的当前阅读资格，不可读时返回 409，仍可退回或撤回。

#### Scenario: 处理资格不能代替本人确认
- **WHEN** 非提问者仅凭处理、受理或管理员资格确认
- **THEN** 拒绝请求，不标记解决；兼具其他资格的原提问者仍仅以本人身份确认

#### Scenario: 确认过期方案
- **WHEN** 提问者确认旧方案，但问题已被改派、退回或存在更新方案
- **THEN** 返回 409，不能解决当前问题

#### Scenario: 文档型确认时来源不可读
- **WHEN** 提问者在待确认页面停留期间失去该资料阅读权
- **THEN** 确认拒绝且不返回资料详情，仍未解决和撤回入口按当前问题资格可用

### Requirement: 关闭撤回与解决必须是不同且不可重开的终态

提问者 SHALL 可带原因将任一非终态问题撤回为 WITHDRAWN。当前可见且持有 close 的受理人员 SHALL 可带原因将其关闭为 CLOSED，包括提问者停用的情况。两类原因均为 1–2000 个 Unicode code point。RESOLVED、CLOSED、WITHDRAWN 终态不接受新处理、改派、说明或重开；用户有新需求须另建问题，不将关闭或撤回记作已解决。

#### Scenario: 关闭无人确认的问题
- **WHEN** 提问者已停用，受理人员明确带原因关闭待确认问题
- **THEN** 记录 CLOSED 而非 RESOLVED，不伪造本人确认或自动超时解决

#### Scenario: 终态操作
- **WHEN** 对已解决、已关闭或已撤回问题提交新的分派、方案、说明或重开
- **THEN** 返回 409；匹配的既有命令重放另按当前鉴权与幂等规则处理

### Requirement: 业务记录保留必须明确告知且不扩权

系统 SHALL 保留已提交描述、说明、方案和操作历史，首期不提供正文删除、编辑或自动清理。提交及撤回界面必须说明分享范围和“撤回停止处理、不等于删除”。不保存搜索 ID、会话 ID、轮次 ID、原回答或引用快照；删除原会话不删除也不恢复独立问题单。记录不会仅因已终结、人员离职或曾参与而变得公开。

#### Scenario: 撤回与原会话删除
- **WHEN** 提问者撤回问题或删除发起反馈的原会话
- **THEN** 已明确分享的业务记录仍在原权限范围内保留，不可通过问题单找回原会话正文

#### Scenario: 未知删除或编辑入口
- **WHEN** 调用方试图通过新增载荷或非支持方法修改已提交描述、删除正文
- **THEN** 严格拒绝，不静默暗删或把撤回当作内容删除成功

### Requirement: 问题写入必须绑定载荷并重新鉴权后幂等

创建、说明、分派、退回、方案、确认、拒绝、撤回及关闭 MUST 要求 1–128 个非控制 Unicode code point 的 X-Request-Id，绑定操作者、动作、目标、预期版本及规范化载荷；非创建写入须携带非负整数 expectedVersion。匹配重放在重新核对当前身份、问题访问权及该动作身份/功能资格后返回首次无正文回执，不重复业务；绑定冲突为 409，不返回旧内容。

#### Scenario: 响应丢失并发重试
- **WHEN** 相同操作者以相同标识和载荷并发创建或提交方案
- **THEN** 至多产生一次业务变化与一次事实，成功重试返回相同身份和已确认结果

#### Scenario: 旧负责人重放
- **WHEN** 原负责人失去访问权或 handle 后重放曾成功的方案请求
- **THEN** 当前鉴权拒绝，旧回执不延续权限；不会返回问题正文或方案资料

#### Scenario: 退回受理导致本人失去访问
- **WHEN** 退回已提交而响应丢失，原负责人不再有该单访问权
- **THEN** 匹配重试仍拒绝，不为方便核对重新开放旧处理记录

### Requirement: 状态事实与回执必须原子且竞争只允许一个合法结果

每次合法新写入 SHALL 在同一原子提交内更新问题版本、保存必要说明/方案、不可变操作事实、无正文通知意图及命令回执。按预期版本和当前状态处理竞争，失败不得留下部分成功。已结束状态与旧方案不能因迟到写入复活；通知派生失败不回滚已提交源业务。

#### Scenario: 确认与撤回关闭竞争
- **WHEN** 同一版本的确认、撤回或关闭并发提交
- **THEN** 至多一个新终态提交，其他非匹配命令返回 409，不留下相互矛盾的解决和关闭事实

#### Scenario: 事件或回执失败
- **WHEN** 已开始更新状态但事实、通知意图或回执无法保存
- **THEN** 源事务整体回滚，重试仍可作为未成功请求处理

### Requirement: 输入响应与容量必须保持有界及真实错误

问题单请求正文 MUST 限于 64 KiB；文本必须是合法 Unicode、不得包含 NUL，拒绝未知/重复 JSON 键、尾随 JSON、非整数身份或版本。每个提问者最多有 100 个非终态问题，新建超限为 409，匹配创建重放不新增占用。所有新入口含网关提前拒绝均 no-store；敏感内容只经请求体传输，不进入 URL、日志、审计摘要、指标或原始异常。正文超限 413，其他非法输入 400，事实依赖失败 503。

#### Scenario: 并发创建达到容量上限
- **WHEN** 本人已有 99 个未结束问题，两次不同的新创建并发到达
- **THEN** 至多一项新增成功，另一项为容量冲突；事务回滚或匹配重放不产生额外占用

#### Scenario: 错误含敏感内容
- **WHEN** 数据库或校验异常包含问题描述、处理说明或原始载荷
- **THEN** 对外及受控日志只保留固定错误类别，响应禁止缓存，不将故障伪装成成功空结果
