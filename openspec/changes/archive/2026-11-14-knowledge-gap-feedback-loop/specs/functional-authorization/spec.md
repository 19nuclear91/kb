# Spec Delta

## ADDED Requirements

### Requirement: 知识问题单必须具有独立精确功能资格

服务端固定目录 SHALL 定义 `knowledge:gap:read`、`knowledge:gap:assign`、`knowledge:gap:handle`、`knowledge:gap:close`，分别用于统一受理读取、分派、处理和带原因关闭。四者按当前有效主体的全部持久角色权限并集精确匹配，互不蕴含；身份管理、文档管理、空间 manage、运营报表及管理员角色名称不代替。它们不授予文档、文件、私有会话或他人通知的读取权。

#### Scenario: 目录与显式授予
- **WHEN** 合格角色读取者查询权限目录，或普通角色被显式绑定 handle
- **THEN** 目录返回四项准确用途，普通角色的有效持有者进入合格处理候选范围，但不能枚举全局问题或读取他人私有会话

#### Scenario: 只有读取权限
- **WHEN** 当前用户只有 read
- **THEN** 可读取统一队列，不能分派、代处理或关闭问题；原提问者自身操作另按归属规则判定

#### Scenario: 角色名称或其他管理资格
- **WHEN** 用户只有管理员角色名称、空间管理或 identity:user:read，没有对应问题单权限
- **THEN** 对应受理与处理动作拒绝，不隐式开放新页面或问题内容

### Requirement: 问题单功能资格与当前参与访问必须同时满足

问题单分派、处理和关闭 SHALL 分别核对动作所需的单项精确权限及问题当前可访问范围，不从动作权限推导全局 read。分派和关闭先核对动作资格再读取目标；处理还须为当前负责人。提问者的本人提交、补充、确认、退回方案和撤回不要求管理权限，但不能藉此处理或确认他人问题。每个新请求和匹配重放都重新鉴权，无跨请求授权快照。

#### Scenario: 写权限不授予队列
- **WHEN** 用户持有 assign 但没有 read，也不是目标提问者或合格当前负责人
- **THEN** 不能读取或分派该单；不存在与无问题访问权统一拒绝，不能枚举队列或取得旧回执

#### Scenario: 处理资格下一次请求撤销
- **WHEN** 原负责人全部角色中 handle 已撤销，且不再以其他身份获得问题访问
- **THEN** 下一次处理和匹配重放拒绝，原分派、页面、游标和回执不延续资格

#### Scenario: 分派与本人确认分离
- **WHEN** 用户有 assign 或 handle，却不是提问者
- **THEN** 不能通过其功能权限代替提问者确认解决

### Requirement: 问题分派候选必须为受控最小身份投影

对当前可访问问题持有 assign 的用户 SHALL 可按名称及有界游标检索有效、主部门有效、已完成必需改密且持有 handle 的处理候选，返回 userId 和显示标签，不要求或授予 identity:user:read。候选为当次事实，实际分派必须重新核验。候选接口不开放用户名、部门、角色、密级、SSO 或生命周期资料，不提供身份目录回退。

#### Scenario: 人员池搜索
- **WHEN** 合格分派人员以 POST 正文提交合法名称搜索、limit 和 cursor
- **THEN** 只返回当前合格的最小候选，名称不进入 URL，候选失败返回 503 而非成功空目录

#### Scenario: 候选资格变化
- **WHEN** 选择后目标账号、主部门、改密状态或 handle 变为不合格
- **THEN** 实际分派返回 409，不基于旧候选扩大权限或回显失效身份的管理资料

### Requirement: 问题单权限初始化必须一次性且保留撤权及兼容边界

首次迁移 SHALL 向当时已有 ROLE_ADMIN 一次性绑定四项知识问题单权限，其他角色不隐式获权；空库正式引导新管理员角色时纳入完整目录。普通重启、重复引导和角色加载不恢复已撤销绑定。新增绑定前排空不认识权限目录的旧 app，保留未知 code 拒绝启动规则，不以删除绑定或忽略未知项实现回退；不调整任何文档 ACL。

#### Scenario: 首次升级与空库引导
- **WHEN** 已有管理员首次升级，或空库随后正式引导创建管理员
- **THEN** 对应角色获得持久精确绑定，其他角色及全部资源授权不变；运行时不依据 ROLE_ADMIN 名称放行

#### Scenario: 撤销并重启
- **WHEN** 管理方撤销其中某项权限后重启或重复执行引导
- **THEN** 该权限保持撤销，不因目录默认值自动恢复

#### Scenario: 旧实例启动
- **WHEN** 不认识新权限的旧 app 在新绑定存在时启动
- **THEN** 仍拒绝启动，不宣称新旧实例可安全混部或直接回退
