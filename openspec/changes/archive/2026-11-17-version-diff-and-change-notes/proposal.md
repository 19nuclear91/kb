# Proposal

版本差异与变更说明，对应[开发路线图 F-03](../../../../docs/development-roadmap.md)。本文保留探索阶段已确认的决定和首期边界；实施、核验及归档现已完成，状态见[归档记录](archive-summary.md)。

## Why

同一文档上传新版本后，审核人只能分别预览两个版本，读者也无从知道新版本改了什么。系统只为每个版本保存相互重叠的检索分块，解析器产出的结构块在切块后即被丢弃，没有可以直接用于对比的版本内容。现在加入结构快照成本最低：第三方解析适配器（E-01）尚未交付，任何环境都还没有真实解析过的版本，不存在存量补齐问题。

## What Changes

### 已确认的决定

1. **首期三部分**：结构差异（段落、列表、表格行与单元格的新增、删除、修改、移动）；关键数值变化（从修改部分提取日期、金额、百分比和条款编号）；可选的人工变更说明。不涉及 kb-ai，AI 起草摘要以后与 F-06 一起设计模型调用的预算和计费。
2. **对比输入来自结构快照**：Worker 在保存分块的同一事务中保存该版本的结构块快照，随重新处理一起替换。没有可用快照的版本明确提示“无法对比”，不从分块拼接，也不重新调用解析服务。
3. **两个入口**：审核工作台默认对比当前发布版本与待审版本；文档详情的版本历史可选任意两个可读版本。两处共用同一接口。
4. **对比不硬给结果**：两个版本解析器不同或有截断时附带提示；内容超过上限、计算超时或可对齐内容过少时返回明确状态，不返回差异明细。
5. **变更说明沿用 F-02 适用期的规则**：挂在版本上，另记基准版本；待审阶段可改，审核中冻结；修改历史不可删除且不显示操作者；写入带请求标识与预期版本。上传和批量导入接口不变。
6. **发布后首次补写不需要原因**：已有说明的修改需要原因并永久标记“已更正”；修改历史记录每次写入时版本是否已对读者可见，读者可以看出说明是发布后补写的。
7. **基准版本**：写入时比目标版本旧的最近一个已发布版本，发布后不再改变；页面始终显示说明对应的两个版本，不改标。没有更早发布版本时不提供说明。
8. **权限**：每次请求分别检查两个版本的交互访问资格，任一不可读统一返回 404；对比结果不缓存。

### 首期范围

- Worker 发布事务内保存版本结构快照，读取时核对快照与当前索引执行周期一致。
- 版本对比接口：块级对齐、段内逐字差异、表格行与单元格差异、移动识别、关键数值提取，以及规模上限、计算限时、实例并发上限和失败状态。
- 变更说明的读取、写入、修改历史与审计。
- 用户端独立对比页（按需加载），文档详情的说明编辑区与版本选择入口，审核工作台的对比入口与只读说明。
- 新增迁移（预计 V40）及发布顺序说明。

### 首期非目标

不做以下内容：AI 起草摘要；把说明送入检索、问答或模型上下文；说明变化或新版本发布触发站内通知、订阅（F-10）；上传或导入时填写说明；比较不同文档；导出或打印差异报告；为旧 Worker 发布的版本回补快照；新增专用监控指标与告警；说明及其历史的删除或清理接口。这些是首期边界，不表示永久排除。

## Capabilities

### New Capabilities

- `document-diff`：版本结构快照的读取一致性、两个版本的对比接口、对齐与差异输出、关键数值变化、规模与时限及失败状态、授权边界。
- `document-change-notes`：版本变更说明的基准版本规则、待审与已发布的写入规则、审核冻结、修改历史、请求绑定与审计原子性。
- `user-web-document-diff`：用户端对比页的展示、状态表达、说明联动及身份与迟到结果隔离。

### Modified Capabilities

- `document-parsing`：新增要求，解析发布必须在同一原子操作中保存并替换版本结构快照，快照不参与检索和向量重建。
- `user-web-documents`：文档详情新增变更说明展示与编辑、版本历史的对比入口，说明写入参与详情页操作协调。
- `user-web-document-review`：审核工作台新增与当前发布版本的对比入口，并只读展示所审版本的变更说明和冻结提示。
- `audit-query`：变更说明写入进入既有审计范围，并只投影固定结构。

## Impact

- **后端**：`kb-worker` 的 `ParsePipeline.ParsedDocument` 携带结构块，`ChunkPublisher` 同事务写快照；`kb-app` 新增 document 下的 `diff` 与 `changenote` 子包、迁移 V40、审计操作域。复用 `DocumentVersionAccessService` 的 INTERACTIVE 规则和 F-02 的写入流程，不新增功能权限。`kb-ai` 不变。
- **前端与入口**：`kb-web` 新增对比页及路由，修改文档详情和审核界面；新接口位于 `/api/documents/**`，`kb-gateway` 配置不变，只补路由回归。
- **保持不变的约束**：分块、检索 SQL、引用身份、发布门禁、向量重建范围和 AI 协议均不改变。对比只需要 view，不需要 download，返回的是解析文本而不是原件。
- **依赖与验证边界**：真实对齐效果取决于 E-01 选定的解析服务；首期只能用统一中间模型构造的数据离线验证。E-01 完成前，任何环境都没有可对比的真实版本。
- **上线影响**：每个版本多存一份约等于抽取文本大小的正文。发布顺序为 app（含迁移）、Worker、web；旧 Worker 发布的版本没有快照。
