# Proposal

## Why

当前文档只能在上传时设置密级，无法对已存在的文档纠正定级或执行升降密。文档读取与检索分别使用文档表、分块表中的密级，新增调整能力必须同时解决权限边界和两处数据的一致性。

## What Changes

- 新增文档密级管理查询与调整接口，调整独立于上传、空间搬迁和 ACL 管理。
- 新增专用功能权限 `document:security-level:write`。采用用户已确认的规则 A：文档原密级和目标密级均不得超过操作者当前密级；管理权限不赋予正文阅读权限。
- 引入独立的密级版本号，拒绝过期写入；目标值取自服务端密级字典。
- 在同一事务内调整文档及所有历史版本分块的密级，并记录操作者、原因、请求标识和前后状态；与 Worker 发布共用文档行锁。
- 绑定幂等请求的操作者、文档、目标密级、预期版本和原因，合法重试返回首次回执，复用标识提交不同内容返回冲突。
- 保持文档内容、向量、所属空间与 ACL 不变；提交后的新检索和读取按新密级判定。

## Capabilities

### New Capabilities

- `document-security-level`：文档密级查询、升降密、权限上限、并发一致性、幂等审计及读取生效边界。

### Modified Capabilities

- `functional-authorization`：扩展服务端权限目录，定义文档密级调整权限的独立性，以及既有管理员迁移和新管理员引导的授予规则。

## Impact

- `kb-app`：新增 `GET/PATCH /api/admin/documents/{documentId}/security-level`；新增专用控制器、服务与
  Mapper，接入现有会话主体、密级字典和审计设施。
- 数据库：新增正式 Flyway 迁移，为 `kb_document` 增加密级版本号、为既有管理员绑定新增权限；不改写已发布迁移。`kb_doc_chunk`
  沿用现有密级字段。
- `kb-worker`：保留 `ChunkPublisher` 的同文档加锁与按当前密级写入行为，复核现有发布单元测试与写入契约。
- 验证：按用户要求，仅保留不连接外部服务的单元测试、MockMvc standalone 测试、静态检查和文档核对；移除集成测试及依赖
  PostgreSQL、Redis、pgvector、ParadeDB 等组件的验证任务。事务、并发与读取一致性的功能要求仍按规格实现，但不将单元测试结果表述为真实环境验证。
- 本变更限于后端能力；不引入前端页面、降密审批、正文重解析、向量重建或在途下载/AI 流的撤回机制。
