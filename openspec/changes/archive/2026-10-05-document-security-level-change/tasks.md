# Tasks

验证范围仅包含不连接外部服务的单元测试、MockMvc standalone 测试、静态检查与文档核对。按用户要求，本清单不包含集成测试，也不要求启动或连接
PostgreSQL、Redis、pgvector、ParadeDB 等组件。数据库相关编码仍需完成；单元测试通过不代表真实数据库的迁移、锁、回滚或检索行为已实测。

## 1. 权限目录与数据库迁移

- [x] 1.1 在 `kb-app` 的 `Permission` 目录增加 `document:security-level:write`
  及用途说明；扩展目录和权限解析测试，验证普通角色显式绑定可用、其他管理权限不能替代、`ROLE_ADMIN` 名称本身不放行。
- [x] 1.2 新增正式 Flyway 迁移（当前预计 V14），为 `kb_document` 增加非负且默认 0 的 `security_version`，并一次性给既有
  `ROLE_ADMIN` 绑定新权限；静态核对迁移中的默认值、约束、授权范围及已有迁移校验和，不执行数据库迁移。
- [x] 1.3 扩展 `AdminBootstrapRunnerTest`，验证新建管理员角色包含新权限、既有角色撤销权限后重复引导不恢复、其他角色和用户密级不变；运行对应引导测试通过。
- [x] 1.4 在项目说明中补充新增权限的授予、升级和回退步骤；核对文档与迁移及引导逻辑一致，明确旧应用遇到新权限绑定时的启动兼容边界。

## 2. 管理状态查询与授权入口

- [x] 2.1 新建文档密级管理投影、Mapper 查询及服务授权入口，接入服务端会话、精确权限和 `IdentityService.resolvePrincipal`

- [x] 2.2 提供 `GET /api/admin/documents/{documentId}/security-level`；使用 MockMvc standalone 测试验证 `200/401/403/404`

## 3. 调整事务、并发版本与审计

- [x] 3.2 在专用 Mapper 和服务中实现文档行锁、规则 A、版本比较及文档更新，锁等待后刷新身份事实；以服务单元测试覆盖合法升降密、等于操作者上限、两端越界、同级无变化、过期版本及
  A→B→A，所有拒绝均不调用写入操作。
- [x] 3.3 在同一事务按 `doc_id` 同步全部版本分块密级；通过代码审查核对同步范围与事务边界，使用单元测试验证零分块处理及同步失败向外抛出异常，不把
  Mock 结果作为真实回滚证明。

## 4. 幂等请求与调整接口

- [x] 4.1 为新操作实现按操作域与请求标识的事务级 advisory lock，绑定操作者、文档、目标、预期版本和规范化原因；以单元测试验证匹配历史事件时不再次写入、跨文档或操作者复用标识返回
  `409`，代码审查核对锁顺序。
- [x] 4.2 从成功审计重建首次回执，重试重新检查资格、当前文档存在性和当前/历史密级上限；单元测试覆盖后续调整后重放、撤权或降密后
  `403`、删除后 `404`、首次时间不变和规范化相同原因的匹配。
- [x] 4.3 提供 `PATCH /api/admin/documents/{documentId}/security-level`，接入请求体与 `X-Request-Id` 双来源规则并拒绝夹带字段；MockMvc
  standalone 测试验证 HTTP 状态、成功回执、非法 JSON、双标识冲突及伪造操作者，服务单元测试确认关键校验不能绕过。
