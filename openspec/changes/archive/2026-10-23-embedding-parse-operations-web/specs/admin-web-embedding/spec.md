# Spec Delta

## Purpose

为有运维资格的用户提供可核对的向量配置、维护状态和重建进度页面，使发起与恢复操作遵守既有模型身份、并发版本及请求幂等契约，并准确说明维护对搜索与新解析任务的影响。

## ADDED Requirements

### Requirement: 向量管理页面必须按读取与操作资格分别开放

用户端 SHALL 在 `/admin/embedding` 提供向量管理页面，只有当前持有 `embedding:read` 时才加载配置、状态和作业。发起及恢复 SHALL 额外要求 `embedding:rebuild`；写权限、角色名称或空间管理资格 MUST 不代替读取资格。权限未确认或失效时 MUST 停止请求并清除受保护数据和表单。

#### Scenario: 只有读取权限
- **WHEN** 当前用户持有 `embedding:read` 而没有 `embedding:rebuild`
- **THEN** 可以查看状态与进度，不能提交发起或恢复操作

#### Scenario: 只有写入权限
- **WHEN** 用户仅持有 `embedding:rebuild` 并直接访问页面
- **THEN** 页面显示无读取资格，不请求配置、状态或作业数据
- **AND** 不改变后端既有独立写入资格

### Requirement: 模型配置与就绪状态必须来自服务端事实

页面 SHALL 展示已登记 profile 的标识、模型摘要、维度和双侧联合就绪结果，并分别说明全局模式与返回状态的当前应用实例就绪情况。只允许选择清单内的 profile；缺失、未就绪或无法确认的目标 MUST 不用于新提交。页面 MUST 不提供 endpoint、密钥或模型语义覆盖输入，不将单实例就绪解释为全体实例健康。

#### Scenario: 目标未就绪
- **WHEN** profile 的联合就绪结果为 false 或最新清单读取失败
- **THEN** 页面解释目标暂不可用于操作，并禁止依赖该目标的新提交
- **AND** 不回退至手填 profile、地址或密钥

#### Scenario: 全局已激活但当前实例未就绪
- **WHEN** 全局状态为 ACTIVE，而返回的当前实例状态为不就绪
- **THEN** 页面分别展示两项事实，不宣称当前实例已恢复混合检索

### Requirement: 重建阶段与计数必须准确表达维护结果

页面 SHALL 区分 UNINITIALIZED、ACTIVE、QUIESCING、REBUILDING、VERIFYING 和 BLOCKED，展示当前及目标 profile、作业标识、总分块数、成功数、跳过数、下次尝试时间及安全错误码。非 ACTIVE 时 SHALL 说明授权 BM25 与上传仍可用、向量召回关闭及普通解析等待。阶段未知或状态不可确认时 MUST 禁用新操作。

#### Scenario: 计数完成而仍在校验
- **WHEN** 成功与跳过数量达到总数，但作业仍为 VERIFYING
- **THEN** 页面显示后台校验中，不展示整体完成或向量已恢复
- **AND** 未知总量或尚未确定范围时不显示虚构百分比

#### Scenario: 空库初始化
- **WHEN** 零目标作业通过校验并成为 SUCCEEDED，且全局 ACTIVE 指向该作业目标
- **THEN** 页面可以确认初始化完成，不因总数为零自行推断成功

#### Scenario: 刷新后没有当前作业
- **WHEN** 页面重新加载且全局 ACTIVE 的 runId 为空
- **THEN** 展示当前系统状态，不伪造上一作业的计数、身份或完成回执

### Requirement: 发起重建必须绑定最新代次与确认的操作内容

页面 SHALL 仅在最新全局状态为 UNINITIALIZED 或 ACTIVE、无未完成作业、目标已就绪且资格完整时开放发起。提交 SHALL 携带所选 profileId、精确 expectedEpoch、去除首尾空白后 1–500 个 Unicode code point 的原因及请求标识。确认界面 SHALL 告知全局维护影响；202 只表示受理，不表示完成。

#### Scenario: 发起修复性重建
- **WHEN** 用户选择当前已激活且就绪的同一 profile，填写合法原因并确认
- **THEN** 允许按当前 epoch 发起修复性重建，受理后读取返回 runId 的作业进度

#### Scenario: 确认期间代次变化
- **WHEN** 发起提交因其他操作者先启动作业而返回 409
- **THEN** 页面重新读取事实，要求重新确认目标与版本，不自动覆盖或使用新请求标识补发

### Requirement: 恢复只允许针对当前阻塞作业

页面 SHALL 仅对最新状态确认为 BLOCKED、仍为当前作业且目标已就绪的作业开放恢复。恢复 SHALL 携带原 runId、精确 expectedVersion、合法原因及请求标识；目标不可修改。页面 MUST 不提供取消、暂停、手工激活或手工触发最终校验操作。

#### Scenario: 修复依赖后恢复
- **WHEN** 用户对当前 BLOCKED 作业重新确认目标就绪并填写原因
- **THEN** 恢复请求使用该作业版本，202 后继续追踪原 runId，不新建作业

#### Scenario: 恢复时预检失败或作业已变化
- **WHEN** 恢复返回 503、404 或 409
- **THEN** 页面保留正确的拒绝或待核对状态并允许显式重新读取，不声称已恢复或自动再提交

### Requirement: 作业轮询必须有界且服从页面生命周期

页面 SHALL 只在可见、身份及读取资格已确认且作业为 QUIESCING、REBUILDING 或 VERIFYING 时自动刷新，间隔不小于 5 秒，同一时刻最多一轮进度读取。隐藏、卸载、身份或权限失效、进入稳定状态及读取故障时 MUST 停止轮询；后台恢复后先重新确认身份与权限，故障后由用户显式重读恢复。

#### Scenario: 页面隐藏或读取失败
- **WHEN** 用户切换标签页使页面隐藏，或轮询发生不可用错误
- **THEN** 自动读取停止，故障时明确标记状态未确认并禁用新操作
- **AND** 不持续请求、不把读取失败显示成完成或无任务

#### Scenario: 当前任务结束后开始另一任务
- **WHEN** 读取到的全局 runId 已变化，而上一轮作业响应随后到达
- **THEN** 旧作业结果不覆盖当前作业数据或恢复表单

### Requirement: 运维写入必须可核对并保持数据精度

发起与恢复 SHALL 绑定方法、目标、规范化原因、预期版本及请求标识；提交中禁止重复触发，网络、5xx 或无法读取成功回执时保留原绑定，仅允许显式匹配重试或核对。epoch、版本和计数 MUST 精确保留；资料、原因和绑定只保存在当前内存。错误 SHALL 使用固定安全提示，不消费身份管理专用 reasonCode 或任意服务器 message。

#### Scenario: 受理回执丢失
- **WHEN** 发起可能已被后端受理，但客户端未取得可靠回执
- **THEN** 显示结果待核对，按原内容重试复用原 expectedEpoch 与请求标识
- **AND** 后台刷新不得悄悄替换待核对提交中的预期版本

#### Scenario: 大整数及身份切换
- **WHEN** 返回超出安全整数范围的合法 epoch 或版本，随后用户提交或切换身份
- **THEN** 提交保持精确 JSON 整数；身份切换清理表单、轮询和绑定，迟到回执不恢复旧内容
- **AND** 清理浏览器请求不被描述为撤销已受理作业
