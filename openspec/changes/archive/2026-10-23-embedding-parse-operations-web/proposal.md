# Proposal

## Why

Embedding 重建与解析死信已有后端接口，但管理员仍需手工调用 API 才能查看状态和处置故障。补齐管理页面时，需要同时修复死信重放未绑定完整请求内容、并发重试结果不稳定及输入被静默截断的问题，使页面能够可靠说明操作是否已受理。

## What Changes

- 在既有 React 管理区新增 `/admin/embedding` 与 `/admin/parse/dead-letters`，复用登录、强制改密、当前权限和身份切换隔离。
- Embedding 页面提供无密钥 profile 摘要、就绪状态、当前作业阶段和计数，支持填写原因后发起重建或恢复阻塞作业；明确维护影响、后台自动校验及受理与完成的区别。
- 死信页面提供状态、失败分类、时间筛选及分页，支持查看脱敏摘要、填写原因并单条重放；查询默认手动刷新，重放成功只表示重新入队。
- 继续使用现有四项独立权限控制读取与操作；补齐绑定原内容的显式重试、版本冲突处理、大整数精度及迟到响应隔离。
- 后端死信重放绑定操作者、目标与规范化原因，匹配请求返回原结果，冲突返回 409；并发匹配请求至多产生一个新执行周期和一条成功审计。
- **BREAKING**：死信接口的超长请求标识及原因由静默截断改为 400；未知筛选枚举或无效时间范围由空结果等隐式行为改为 400。合法既有请求路径、成功封装、权限和任务维护语义保持兼容。
- 首版不增加历史重建清单、批量重放、手工标记解决、文档正文联查、模型配置编辑或重建取消/强制激活能力。
- 本变更的实现验证仅采用隔离的进程内单元/组件测试、类型检查和静态构建；移除集成测试、真实数据库或其他外部组件运行、真实浏览器验收及文档内容测试任务，文档更新仅交付说明。

## Capabilities

### New Capabilities

- `admin-web-embedding`：按资格查看向量配置与作业状态，发起和恢复重建，并准确表达维护、轮询及不确定操作结果。
- `admin-web-parse-deadletters`：按资格分页查询解析死信、查看安全摘要并执行可核对的单条重放。

### Modified Capabilities

- `admin-web-access`：将两项运维页面纳入受保护路由、站内返回地址及按独立读取权限开放的管理导航。
- `document-parsing`：明确死信功能权限、查询及输入校验，以及重放请求内容绑定、并发收敛和审计原子性。

## Impact

- 前端：`kb-web/src/App.tsx`、`navigation.ts`、`admin/access.tsx`，新增两项页面、运维 API/类型与行为测试；按需扩展既有管理写入状态机，保持身份管理 `reasonCode` 的原适用范围。
- 后端：`kb-app` 的解析死信 Controller、Service、内部映射与 Mapper SQL，以及使用 Mock/Stub 的对应单元测试。Embedding API 和 Worker 状态机沿用现有契约；不新增或执行 PostgreSQL 并发烟测。
- 数据：复用死信表的 `replay_request_id`、`resolved_by`、`resolution_reason` 和既有唯一约束，预计无需新增迁移；不改历史迁移或补授权限。
- 文档：补充运维页面使用、筛选边界、重试约定、输入兼容性变化和进程内验证边界说明，不为说明文档、注释或静态文本新增测试。无需新增运行时依赖或外部服务。
