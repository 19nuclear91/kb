# Spec Delta

## MODIFIED Requirements

### Requirement: 文档操作按钮必须结合独立能力和版本状态

详情页 SHALL 依据当前独立操作能力、所选版本的访问及审核状态控制下载、新版本上传、失败重试和审核相关操作；整文档删除 SHALL 仅按父文档当前可查看事实及 canDelete=true 开放，不受所选版本是否已发布、可读或可重试影响。能力读取失败或缺少 canDelete 不默认启用删除。重试 MUST 满足 edit 与对应版本可重试条件，候选刷新走独立确认。文档级 canDownload 等标记不保证所选未发布版本可读，实际操作仍重新鉴权，拒绝后更新页面事实。

#### Scenario: 可查看但不可下载或编辑
- **WHEN** 用户可读取详情，但能力响应的 canDownload、canUploadVersion、canRetry 和 canDelete 均为 false
- **THEN** 页面保留查看行为，禁用或隐藏相应操作，不依据管理员名称或 ownerId 重新启用

#### Scenario: 版本可重试且能力允许
- **WHEN** 选中版本处于可重试失败状态且当前版本操作能力允许
- **THEN** 用户可以向该明确版本发起一次重试，并显示新返回的处理状态
- **AND** 提交期间防止重复点击，超时不自动重发

#### Scenario: 点击前授权已被撤销
- **WHEN** 页面曾取得 true 标记，但实际下载、上传版本或删除请求被新权限拒绝
- **THEN** 页面按最新拒绝更新操作状态，不继续依赖旧标记重试放行

#### Scenario: 父文档可下载但候选不可访问
- **WHEN** 文档级 canDownload=true，但所选新候选版本的访问未确认或被拒
- **THEN** 不按文档级标记启用该版本下载，清理失效的预览和入口

#### Scenario: 旧服务未返回删除能力
- **WHEN** 能力响应没有 canDelete 字段，或当前能力读取尚未成功
- **THEN** 删除操作保持禁用，不用 canUploadVersion、canRetry 或旧缓存推断删除能力

## ADDED Requirements

### Requirement: 详情页删除必须明确作用于整份文档

用户端 SHALL 在 `/documents/{documentId}` 详情页提供单文档删除入口。确认前 MUST 重新读取当前详情及删除能力；仅两者就绪且 canDelete=true 时允许确认。确认界面 SHALL 以安全文本展示当前标题，说明删除影响整份文档及全部版本、取消未完成处理和审核、当前不支持恢复；不得枚举隐藏版本或声称原件已彻底擦除。此入口不提供单版本删除、批量删除或恢复。

#### Scenario: 选中历史版本后删除
- **WHEN** 用户选中 V1，而文档当前发布版本是 V2，随后打开删除确认
- **THEN** 界面明确操作对象是整份文档及全部版本，不显示“删除 V1”或仅影响当前选择的含义
- **AND** 确认后仅向该文档的 `DELETE /api/documents/{documentId}` 提交，不携带 versionId 或版本筛选

#### Scenario: 首个版本尚未发布
- **WHEN** 文档当前没有发布版本，但当前详情可读取且 canDelete=true
- **THEN** 用户仍能确认删除整份文档，不要求存在可预览、已发布或可重试的版本

#### Scenario: 确认前事实变化
- **WHEN** 用户打开确认后，重新读取显示无删除资格、文档不可访问或读取失败
- **THEN** 确认提交保持禁用，不使用打开弹窗前的资格或标题继续操作
- **AND** 只有重新取得合法当前事实才能重新确认

#### Scenario: 取消确认或没有业务提交
- **WHEN** 用户取消尚未提交的删除确认，或确认前读取未完成
- **THEN** 不发送 DELETE 请求，不修改文档状态

### Requirement: 删除提交必须防止本页重复和冲突操作

删除 SHALL 使用既有认证会话及精确文档 ID，提交无请求体的 `DELETE /api/documents/{documentId}`，不虚构幂等回执能力。进入删除确认后，本页 SHALL 阻止新发起的上传、重试、审核、评论及收藏写入；已在途的同页写入必须结束或进入明确的结果未确认提示后才能提交删除。删除请求在途时 MUST 防止重复提交，关闭预览并暂停本页相关轮询；暂停或取消浏览器请求不得宣称服务端操作已撤销。

#### Scenario: 连续点击确认
- **WHEN** 同一文档的删除请求尚在途，用户连续点击或重复触发表单提交
- **THEN** 本页只发出一次删除请求，重复事件不创建第二个请求

#### Scenario: 其他写入仍在途
- **WHEN** 本页已有上传、重试、审核、评论或收藏写入尚在等待结果
- **THEN** 删除确认不得提交，也不得通过卸载其界面将其当作已取消成功
- **AND** 已知结果未确认的写入须向用户提示可能已执行，再由用户明确确认整文档删除

#### Scenario: 确认期间发起其他操作
- **WHEN** 删除确认、提交或结果核对尚未结束，用户尝试启动本页其他文档写操作
- **THEN** 新操作被阻止，不形成两个相互独立的可提交窗口

#### Scenario: ID 超出 JavaScript 安全整数
- **WHEN** 文档 ID 为合法的长整型大整数
- **THEN** 删除与核对请求均使用精确原 ID，不经浮点转换或截断

### Requirement: 删除成功必须以明确响应为依据并清理页面资源

客户端 SHALL 仅在当前会话、目标与请求仍有效且取得既有删除接口合法成功响应后显示删除成功。成功后 MUST 停止该详情页的轮询、文件读取及其他关联请求，释放预览临时资源，清理版本、审核、评论、收藏等本页旧状态，并返回重新读取的文档中心。成功提示 SHALL 只在当前会话内短暂显示，不将标题或删除状态保存到持久存储；不得以列表读取失败推翻已确认的删除成功。

#### Scenario: 明确成功后返回列表
- **WHEN** DELETE 返回合法成功响应
- **THEN** 详情页退出且文档中心重新请求当前可见列表，展示一次当前会话的删除成功提示
- **AND** 已打开的预览被关闭并释放，迟到的旧详情或版本响应不能恢复已退出的内容

#### Scenario: 删除成功但列表读取失败
- **WHEN** 删除已获确认，而返回文档中心后的列表查询失败
- **THEN** 页面保留已确认的删除结果，同时单独显示列表加载失败和重读入口
- **AND** 不因此重发 DELETE 或声称文档未删除

### Requirement: 删除结果未确认时必须只读核对当前事实

删除已发出后遇到网络中断、超时、无法可靠解析成功响应或可能发生在提交之后的服务错误，客户端 SHALL 标记结果未确认，提供用户主动触发的只读核对与返回列表入口，MUST NOT 自动重发 DELETE。核对 SHALL 重新读取当前详情与能力；404 仅表示当前不可访问，200 仅表示查询时仍可访问，均不得冒充原请求回执。核对失败保持未确认；再次删除必须取得新的有效事实并经过用户重新明确确认。

#### Scenario: 响应丢失而核对返回 404
- **WHEN** 删除响应丢失，后续详情或能力核对返回 404
- **THEN** 清除本页旧标题、版本、正文和文件入口，显示文档当前不可访问
- **AND** 不显示删除成功，不解释其原因是删除、归档或撤权

#### Scenario: 核对时文档仍可访问
- **WHEN** 结果未确认后的详情与能力查询成功，canDelete 仍为 true
- **THEN** 显示当前仍可访问且原删除结果未确认，不宣称原请求失败或回滚
- **AND** 重新删除须再次展示整文档影响并由用户确认，不自动重新提交；旧请求可能仍在服务端执行

#### Scenario: 仍可查看但不能再删除
- **WHEN** 核对成功且 canDelete=false
- **THEN** 保留当前可查看资料和未确认提示，禁止新的删除提交

#### Scenario: 核对再次失败
- **WHEN** 只读核对遇到网络或服务故障
- **THEN** 保持结果未确认及删除禁用，允许用户再次主动核对或返回列表，不启动无界轮询

### Requirement: 删除拒绝必须遵守当前身份与资源边界

明确拒绝删除时，客户端 SHALL 保留真实拒绝事实，按既有会话规则处理 401 和 403；资源 404 MUST 使用目标不存在或当前不可访问的统一表现，不作为成功。仍保持有效身份时 SHALL 重新核对详情与能力；重新读取前不得继续以旧 canDelete 提交，目标不可访问时清除其旧内容。

#### Scenario: 点击前 edit 被撤销
- **WHEN** 确认时拥有 canDelete=true，但 DELETE 随后因当前授权被拒绝
- **THEN** 页面展示拒绝并重新核对当前事实；新能力为 false 时删除保持禁用

#### Scenario: 删除请求直接返回 404
- **WHEN** DELETE 本身返回 404
- **THEN** 界面显示目标不存在或当前不可访问并清理旧内容，不显示删除成功

#### Scenario: 登录失效或必须改密
- **WHEN** 删除期间会话失效、主体停用或进入强制改密状态
- **THEN** 页面遵守既有身份门禁，停止保护请求，不把原会话的操作结果显示给后续身份

### Requirement: 删除交互必须隔离会话文档和请求代次

确认、提交、核对和成功提示 SHALL 绑定当前会话及文档。退出、身份变化、切换文档、页面隐藏或离开详情时 MUST 清理私有界面、停止本地活动请求并使旧回调失效；恢复时重新核对身份及当前资源，不自动恢复确认或重发删除。取消本地等待不证明服务端未执行，历史响应不得触发新页面跳转或把旧删除结果转为当前成功。

#### Scenario: 文档切换后删除响应迟到
- **WHEN** A 文档的删除尚未返回，用户已经进入 B 文档
- **THEN** A 的旧响应不能关闭 B、清除 B 的资料、显示 B 已删除或把页面带回列表

#### Scenario: 页面隐藏后恢复
- **WHEN** 删除确认或请求等待期间页面隐藏，随后用户恢复页面
- **THEN** 原确认界面失效，恢复先核对身份及资源，不重复发送删除或以读取结果重建成功提示

#### Scenario: 删除前读取在删除后返回
- **WHEN** 删除前发起的详情、能力、审核或评论读取在删除提交后才返回
- **THEN** 旧结果不能重新启用操作、覆盖核对结果或恢复已清理的私有内容
