# Proposal

## Why

项目已有权限受控的 BM25、向量、RRF 和 rerank
链路，但现有测试主要验证编排及接口契约，缺少统一的检索质量计算与方案比较工具。先建立可完全离线运行的评测能力，使人工标注和已有结果文件能够生成可复核的指标与退步用例，为后续真实环境评测提供统一口径。

## What Changes

- 新增 Java 21 命令行模块 `kb-eval`，纳入现有 Maven 构建，以本地文件为输入，不启动 Spring 应用或连接数据库、Redis、对象存储、HTTP
  服务及模型。
- 定义带版本的标注集、结果文件及运行清单；以 `caseId` 关联样本，以 `docId + versionId` 标注相关性，以完整三元组识别返回分块。
- 保留结果数组的原始顺序，先截取前 k 个分块，再按文档版本计算 Hit@k、Recall@k、MRR@k、nDCG@k 和文档版本重复率；默认 k 为
  5、10、20。
- 区分合法空结果、缺失用例和执行失败；无相关目标的样本单独计算空结果符合率，不混入相关性指标的平均值。
- 比较同一标注集与语料快照上的多个方案，输出总体、分类及逐用例指标，提供 JSON、CSV、Markdown 报告和可配置的回归门禁退出码。
- 提供可手算核对的合成样例、进程内组件单元测试及 PowerShell
  使用说明。本次实施不安排集成测试、外部组件验证或文档内容测试；文档及示例只作为交付物。报告默认只包含受控元数据、标识及指标，结果中的问题、标题、正文和凭据不进入日志或报告。
- 首版不采集真实检索结果、不实现检索算法或重排调用，不修改在线搜索
  API、SQL、权限或向量切换协议；不评测答案生成、精确分块相关性和实时权限正确性。已有记录的耗时仅作为附加统计，不将工具计算耗时当作检索延迟。

## Capabilities

### New Capabilities

- `retrieval-evaluation`：离线检索结果的输入校验、文档版本相关性计算、方案比较、报告与回归门禁。

### Modified Capabilities

无。复用现有版本身份和查询保密约束，不改变既有业务能力要求。

## Impact

- 实现阶段新增 `kb-eval/`，并在根 `pom.xml` 注册模块；使用独立评测 DTO，不依赖五个既有模块或引入 Spring 运行时。
- 新模块需要 JSON 解析及测试依赖，并生成可通过 `java -jar` 运行的 CLI 包；具体依赖沿用父 POM 管理的版本及现有
  JUnit/AssertJ 风格。
- 实现阶段新增合成样例及 `docs/retrieval-evaluation.md`，更新 README 中的评测入口与验证范围。
- 不需要数据库迁移、新 HTTP 端点、真实业务数据或中间件。离线计算正确性的验收与实际检索效果结论分开记录。
