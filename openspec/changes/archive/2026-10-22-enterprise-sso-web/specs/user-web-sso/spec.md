# Spec Delta

## Purpose

为已有知识库用户提供企业浏览器登录、本人外部身份绑定和固定结果页交接，消费现有钉钉、企业微信、飞书后端协议，并在一次性结果消费、会话变化及网络不确定时保持可解释且不串用身份的页面行为。

## ADDED Requirements

### Requirement: 企业登录入口必须由当前启用目录决定

登录页 SHALL 匿名读取 `/api/auth/sso/providers`，仅展示服务端当前启用且属于 dingtalk、wecom、feishu 的连接。目录加载、无连接与读取失败 MUST 有可区分的状态，且不阻止使用本地用户名密码登录。页面 MUST 不根据前端配置猜测连接已经启用。

#### Scenario: 部分连接启用
- **WHEN** 目录仅返回飞书
- **THEN** 页面只提供飞书企业登录入口，本地登录仍可独立提交

#### Scenario: 目录为空或不可用
- **WHEN** 目录返回空数组或读取失败
- **THEN** 前者不提供企业登录按钮，后者提供目录不可用及显式重读提示
- **AND** 二者均不禁用本地登录，也不自动重试登录操作

### Requirement: 授权发起必须使用受控的当前标签页导航

用户选择连接后，页面 SHALL 向对应 LOGIN 发起接口提交空 JSON 对象，携带同源浏览器 Cookie，并在验证返回地址属于该连接允许的 HTTPS 授权入口后在当前标签页顶层导航。提交期间 MUST 防止重复发起及本地登录与企业登录并发提交；前端不得拼装 state、授权码、企业身份或自定义回调地址。

#### Scenario: 正常发起企业登录
- **WHEN** 用户选择已启用的钉钉连接
- **THEN** 页面向 `/api/auth/sso/dingtalk/login` 提交 `{}`，并导航到服务端返回的合法钉钉授权地址
- **AND** 不使用弹窗、内嵌授权页或第三方前端 SDK

#### Scenario: 双击或不可信授权地址
- **WHEN** 用户重复点击，或返回地址为非 HTTPS、错误主机、错误授权路径或含用户信息的地址
- **THEN** 前者仅发起一次操作，后者停止导航并显示安全失败
- **AND** 不显示或记录原授权地址

### Requirement: 固定结果页必须独立处理浏览器交接

用户端 SHALL 提供固定 `/auth/sso/result`，使用原浏览器 Cookie 向 `/api/auth/sso/exchange` 提交空 JSON 对象，BIND 同时使用当前标签页中的原会话令牌。结果页 MUST 在普通身份加载、身份故障及登录重定向之前可达，不加载受保护业务内容，也不从页面查询参数读取令牌、意图、身份或回调材料。

#### Scenario: 匿名 LOGIN 返回结果页
- **WHEN** 用户完成平台授权并被后端重定向到固定结果页
- **THEN** 页面在无本平台令牌时仍能消费 LOGIN 结果，不先跳回登录页

#### Scenario: 保存的旧会话暂不可确认
- **WHEN** 结果页所在标签页保存的旧会话尚未核对或暂时无法核对
- **THEN** 页面仍可处理本次交接，而不展示旧账号业务内容或等待旧身份无限重试
- **AND** BIND 的原会话有效性仍由后端验证

### Requirement: 一次性结果不得因页面生命周期自动重复消费

同一标签页同一次授权发起 SHALL 至多主动发送一次结果交换。重复挂载、聚焦、恢复、历史前进后退及刷新 MUST 不自动重发已发出的交换；请求在途时重复进入页面复用该次处理状态。缺少有效的本标签页发起上下文、上下文损坏或已消费时，页面 SHALL 提示重新发起，不能依据 URL 构造授权上下文。

#### Scenario: 重复挂载与焦点事件
- **WHEN** 同一结果页重复挂载并连续收到页面恢复事件
- **THEN** 结果交换仍只发送一次，且不会仅因这些事件被中止后重新发送

#### Scenario: 交换发出后刷新
- **WHEN** 用户在交换发出后刷新，新的页面无法取得前一次请求的确定结果
- **THEN** 页面显示结果未确认或需要重新发起，不再次消费同一授权

#### Scenario: 直接访问结果页
- **WHEN** 标签页没有合法的本地发起上下文而直接访问结果页
- **THEN** 页面不发送交换请求，提供本地登录或返回账户的安全入口

### Requirement: LOGIN 结果必须统一进入当前会话生命周期

页面 SHALL 区分合法 LoginResult 与绑定结果，只有与本次 LOGIN 意图相符的有效登录结果才可替换当前凭据。接管时 MUST 清理旧受保护状态，仅在当前标签页保存令牌并重新核对 `me`，执行强制改密门禁。结果接管前发生退出或凭据替换时，旧结果 MUST 不覆盖新的身份。

#### Scenario: 正常登录与强制改密
- **WHEN** LOGIN 返回有效令牌，且登录结果或当前身份要求强制改密
- **THEN** 页面先进入改密流程，不预取文档、管理权限或会话数据
- **AND** 无改密要求且身份确认成功时恢复经过校验的站内地址，缺省进入文档中心

#### Scenario: 返回类型错误或旧结果晚到
- **WHEN** LOGIN 返回绑定类型或不合法令牌，或者退出后旧 LOGIN 结果才到达
- **THEN** 不接管该结果、不写入新凭据，也不展示其中身份数据

### Requirement: 账户页面必须如实显示本人绑定状态

当前身份确认且已完成改密后，账户页 SHALL 读取 `/api/auth/sso/bindings` 并展示三家连接的启用状态与本人绑定状态。连接关闭和未绑定 MUST 分别表达；读取失败不得显示为未绑定。仅当连接启用且当前未绑定时允许本人发起绑定，不提供自助解绑或输入外部主体标识的入口。

#### Scenario: 已绑定连接关闭
- **WHEN** 返回 connectionEnabled=false、bound=true
- **THEN** 页面显示连接已关闭且绑定仍存在，不显示可登录或需要重新绑定的结论

#### Scenario: 状态读取失败
- **WHEN** 绑定状态无法可靠读取
- **THEN** 页面显示失败及显式重读入口，不开放依赖未知状态的绑定操作

### Requirement: 本人绑定必须重新验证密码并保持原会话

绑定 SHALL 由已登录本人主动选择连接并输入当前密码，向该连接 BIND 发起接口仅提交 `{password}`；成功发起后在当前标签页继续平台授权。密码 MUST 在提交结束、关闭或身份变化时清除，不持久化。BIND 结果仅在当前原会话下确认；成功不得建立额外本地登录或把绑定结果当作登录结果替换凭据。

#### Scenario: 正常完成本人绑定
- **WHEN** 已改密用户通过当前密码验证和平台授权，交换返回匹配连接的 bound=true
- **THEN** 页面保留原本平台会话，核对当前身份和绑定状态后显示当前绑定事实

#### Scenario: 原会话被替换
- **WHEN** BIND 发起后当前令牌改变，即使新令牌属于同一个用户
- **THEN** 页面停止继续使用旧操作，不自动借新令牌完成或重试绑定
- **AND** 后端拒绝时不将其显示为绑定成功

#### Scenario: 密码验证失败
- **WHEN** 本人绑定发起因当前密码错误而返回 401
- **THEN** 页面提示验证未通过，并按当前会话核对结果处理，而不直接将密码错误解释为已退出

### Requirement: 未绑定登录必须引导重新进行本人绑定

LOGIN 返回 `409/SSO_BINDING_REQUIRED` 时，页面 SHALL 引导用户先登录已有本地账号、完成必要改密，再到账户页主动绑定。引导 MUST 不自动建号、不关联邮箱或手机号，也不将首次 LOGIN 中的授权材料用于 BIND。可保留的引导仅包含非敏感平台提示及经校验的站内目标。

#### Scenario: 首次企业登录尚未绑定
- **WHEN** 飞书 LOGIN 返回 SSO_BINDING_REQUIRED
- **THEN** 页面提供本地登录后前往账户绑定的路径，账户页只提示飞书而不自动提交绑定
- **AND** 用户再次输入当前密码并开始一轮新的平台授权

### Requirement: SSO 错误必须按端点和可信类别表达

页面 SHALL 结合当前操作、HTTP 状态和已知 SSO errorCode 显示安全提示。非成员、连接关闭、绑定冲突、事务失效、限流和依赖故障 MUST 不被混为本地密码错误或部门额度不足。仅消费有界、合法的错误数据；缺少类别、未知类别或非 JSON 错误使用对应操作的通用提示，不回显服务端 message、原始错误体或第三方错误。

#### Scenario: 常见拒绝类别
- **WHEN** 服务端分别返回 NOT_MEMBER、CONNECTION_UNAVAILABLE、BINDING_CONFLICT 或 RATE_LIMITED
- **THEN** 页面分别提示成员资格拒绝、连接不可用、联系管理员处理冲突或稍后重新发起
- **AND** 不显示对方身份，也不循环自动提交

#### Scenario: 网关旧错误包装
- **WHEN** 网关返回没有 SSO errorCode 的 401/403，或错误体损坏、超限
- **THEN** 页面仍安全处理实际状态，必要时核对当前身份，不假设存在错误字段或显示原始载荷

### Requirement: 网络不确定必须采用操作对应的恢复路径

授权发起及交换请求超时、连接中断或成功载荷不可读时，页面 SHALL 表达结果未确认，不自动重发写操作。LOGIN 未取得可用令牌时需要重新授权；已取得并保存令牌但 `me` 暂不可用时只重核身份。BIND 可显式读取当前绑定状态；该状态不得被描述为旧交换已重放成功。

#### Scenario: 登录响应丢失
- **WHEN** 交换可能已消费但没有收到可用的 LoginResult
- **THEN** 页面引导重新发起企业登录或使用本地登录，不伪造令牌或重复消费旧结果

#### Scenario: 绑定响应丢失
- **WHEN** BIND 结果不确定，当前原会话仍有效
- **THEN** 用户可读取本人当前绑定状态或重新发起授权
- **AND** 显示的是当前状态，不承诺前一次请求的提交结果

#### Scenario: 登录令牌已保存但身份核对故障
- **WHEN** 已接管合法登录令牌，随后 `me` 返回暂时故障
- **THEN** 页面提供重新确认身份及退出入口，后续只重试身份读取而不重发交换

### Requirement: 浏览器并发行为必须遵循单活动授权边界

页面 SHALL 说明同一浏览器新发起授权会替代先前授权，并按当前后端事务结果处理，不承诺多个标签页独立完成授权。前端流程提示仅用于导航和重复提交控制，MUST 不被当作企业身份、当前服务端 flow 或绑定资格的证明；意图或平台不符的结果不得被静默当成原操作成功。

#### Scenario: 另一标签页发起新授权
- **WHEN** 当前授权期间另一标签页发起了新授权，旧流程随后被后端拒绝
- **THEN** 页面显示流程失效并提供重新发起入口，不自动恢复旧 state 或旧结果

#### Scenario: 本地意图与结果不符
- **WHEN** 标签页等待 BIND，却收到 LoginResult，或收到另一平台的绑定结果
- **THEN** 不替换当前身份，也不显示本次绑定成功，要求重新核对或发起

### Requirement: SSO 页面必须最小化敏感材料存储与传播

SSO 请求 SHALL 使用同源固定路径并禁止缓存；认证 Cookie 由浏览器管理。页面 MUST 不读取 HttpOnly Cookie，不保存密码、授权码、state、完整授权 URL、平台令牌或结果证明，不把认证材料写入 URL、localStorage、日志或遥测。除既有会话令牌存储外，标签页存储只允许有界、短期、非敏感的流程及导航提示；结果页部署必须设置 no-store/no-referrer。

#### Scenario: 检查存储和请求内容
- **WHEN** 用户发起并完成 LOGIN 或 BIND
- **THEN** 标签页仅保留既有会话凭据及必要流程提示，不新增认证材料副本，提交体不含 requestId、returnUrl、userId 或自造证明

#### Scenario: 页面收到恶意文案或导航输入
- **WHEN** 错误内容包含可执行标记，或本地返回地址是外部地址
- **THEN** 页面只展示固定安全文案，导航回退到合法站内地址，不执行标记或向外传递令牌
