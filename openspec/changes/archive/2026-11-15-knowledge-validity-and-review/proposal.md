# Proposal

知识有效期与复审，对应[开发路线图 F-02](../../../../docs/development-roadmap.md)。本文记录探索阶段已确认的十项决定和首期边界。当前只有提案；设计、增量规格和任务待后续生成，实施须另行确认。

以上状态为提案阶段原文，后续实施、核验、主规格同步及归档结果见[归档记录](archive-record.md)。

## Why

制度和流程资料通常在正文中写明生效或截止日期，并需要有人定期确认内容仍然准确。系统目前只有文档资料、版本审核和发布状态，用户在阅读、搜索和问答时无法分辨资料是否仍然适用，也无法追踪由谁负责复审，容易误用过期制度。

## What Changes

### 已确认的决定

1. **两件独立的事**：适用期是内容本身声明的生效与截止日期，跟随文档版本；复审是责任人定期确认资料仍然准确，跟随整份文档。复审逾期不等于内容失效，过期也不等于归档、删除或未发布。
2. **首期只加标识**：不改变发布、当前版本切换和搜索、问答召回。新版本已发布但尚未生效的过渡期内，标识说明“尚未生效”，正在施行的旧版本通过版本历史查看。
3. **独立设置适用期**：通过按版本的独立接口设置和修改。单文件上传、新版本上传和批量导入接口不变；存量版本可以补填。
4. **适用期修改规则**：候选版本需要能访问该候选，并具有 view 和 edit，活动审核期间冻结。已发布版本在 AUTO 与 REVIEW_REQUIRED 空间都需要 view 和 edit，必须填写原因，保留不可删除的修改历史，标识显示“已更正”。
5. **只有当前责任人能确认**：只有当前合格的责任人能确认“仍然准确”。其他编辑者可以修改资料或发布新版本，但不能代为确认。
6. **由空间管理员指定**：当前空间 manage 或 `space:manage-all` 可以指定、改派或取消责任人，每份文档至多一名。候选只返回用户 ID 和显示名，不要求 `identity:user:read`，提交时重新核验。责任人失去资格时显示“需重新指定”，不说明原因，也不自动改派。不复用 `owner_id`，上线时所有文档均为“未指定”。
7. **以清单提醒**：提供本人负责资料清单、空间管理员的复审概况清单和导航实时数量；不推送站内通知或外部 IM。
8. **日期与时区**：只保存日期，全站按 `Asia/Shanghai` 判断“今天”，生效日与截止日均包含当天。截止日区分“未声明”“明确长期有效”和具体日期。状态在读取时计算，不由定时任务改写。
9. **复审周期**：固定为 3、6、12、24 个月，统一提前 30 天进入“即将到期”；版本适用期的“即将届满”同样提前 30 天。首次指定时开始计时，改派不重新计时；修改周期时按最近确认日（从未确认时为指定日）重算，确认时按确认日重算。
10. **问答引用标识**：前端按引用中的版本 ID 批量读取标识，kb-ai、SSE 事件、内部检索协议和模型提示词不变。模型不知道资料的适用状态，回答正文仍可能把已届满内容当作现行规定，只能依靠引用标识提醒。

### 首期范围

- 版本适用期的读取、设置、修改历史与状态计算；按版本批量读取标识，逐个按当前资格返回，不可见项不返回任何信息。
- 文档详情、版本历史、审核界面、搜索结果和问答引用（实时与历史）展示标识。搜索结果与问答引用共用同一批量读取，搜索接口不变。
- 文档责任人的最小候选、指定、改派、取消和复审确认；文档管理面板新增责任人区块。
- 本人清单同时列出复审即将到期或已逾期的资料，以及当前发布版本适用期即将届满或已届满的资料。空间管理员清单按文档 ID 列出未指定、需重新指定、即将到期和已逾期的资料。
- 新增数据库迁移和协调发布说明；既有文档默认为“未声明”和“未指定”。

### 首期非目标

不做以下内容：定时切换当前版本，或过渡期内新旧版本同时可检索；修改已发布版本的适用期需要审核批准；站内通知和外部 IM 推送；让模型感知适用状态（需要修改 `kb-chat-text-v1` 消息格式并重新适配严格预算策略）；上传或导入时直接填写适用期；1 个月复审档位；按空间设置时区；按状态过滤搜索和问答召回。这些是首期边界，不表示永久排除。

## Capabilities

### New Capabilities

- `document-applicability`：版本适用期的声明、修改规则与历史、按业务时区计算状态，以及按版本批量读取标识的授权边界。
- `document-stewardship`：文档责任人的指定与资格、复审周期与到期计算、责任人确认，以及本人与空间管理员的复审清单。
- `user-web-document-stewardship`：用户端本人负责资料清单、导航实时数量和复审确认交互。

### Modified Capabilities

- `user-web-documents`：文档详情、版本历史和搜索结果展示适用期标识；详情页提供版本适用期的设置与修改。
- `user-web-conversations`：实时与历史回答的引用展示适用期标识，不改变引用身份和生成流程。
- `user-web-document-review`：审核界面展示所审版本的适用期，并说明审核期间冻结。
- `admin-web-documents`：文档管理面板新增责任人区块，支持指定、改派、取消和设置周期。
- `admin-web-spaces`：空间详情新增复审概况清单，保持文档 ID 级投影。
- `audit-query`：适用期修改、责任人变更和复审确认进入既有审计范围，并只投影固定结构，不输出原因正文。

## Impact

- **后端**：`kb-app` 新增适用期与复审的持久化、受控读写、最小候选和清单查询，新增迁移（预计 V39）。沿用资料编辑的严格输入、请求标识、回执与审计模式，不新增功能权限。`kb-ai`、`kb-worker` 不变。
- **前端与入口**：`kb-web` 涉及文档详情、搜索、助手、审核、文档管理面板、空间详情和新的本人清单页；`kb-gateway` 需核对新增路径的路由及 `no-store` 边界。
- **保持不变的约束**：`document-review` 的固定版本与原子发布、`citation-provenance` 的引用身份、`search-filtering` 的召回与筛选协议、`chat-model-adapter` 的消息格式与预算绑定均不改变。责任人身份不授予文档阅读、编辑或审核资格。
- **待设计确认**：搬迁、删除和归档对责任人及清单的影响（如决定搬迁时清除责任人，需补充 `document-relocation` 增量规格）；已被取代的历史版本如何显示标识；批量读取的数量上限；app、gateway、web 的发布顺序与回退方式。
- **上线影响**：存量资料全部为“未声明”和“未指定”，需要空间管理员逐步指定责任人后，清单才会有内容。
