# Spec Delta

## Purpose

为文档责任人提供浏览器中的本人负责资料清单、导航提醒数量和复审确认交互，使责任人能看到需要处理的资料并明确确认，同时页面状态服从当前身份和服务端事实。

## ADDED Requirements

### Requirement: 本人负责资料页面必须读取服务端清单

用户端 SHALL 提供受保护路由 `/stewardship`（导航名称“我负责的资料”），支持直接访问、刷新及合法登录返回。页面分为“需要处理”和“全部”两个视图，分别对应服务端 attention 与 all，通过“加载更多”按服务端游标续读，不展示总数。每项显示已授权标题、复审状态、到期日、最近确认日、周期、提醒原因和当前版本适用期标识，并可进入文档详情。

#### Scenario: 没有需要处理的资料
- **WHEN** attention 视图成功返回空列表
- **THEN** 页面显示“暂无需要处理的资料”，并可切换到全部视图

#### Scenario: 读取失败
- **WHEN** 清单读取返回 503 或网络失败
- **THEN** 页面显示读取失败并提供重新读取，不显示为空清单，也不保留上一身份的旧列表

#### Scenario: 续页时文档已不再归属本人
- **WHEN** 加载更多时部分文档已改派他人
- **THEN** 只追加服务端本次返回的项，不为消失的项保留占位

### Requirement: 导航提醒数量必须按会话隔离且后台暂停

导航项 SHALL 在服务端数量大于 0 时显示该数量，超过 99 显示 99+；数量不可确认时显示“?”，为 0 时不显示角标。数量仅保存在内存中，同一会话共享一个订阅和至多一个在途请求，自动刷新间隔不短于 60 秒。页面隐藏、离线、退出或身份代次变化时取消请求并清除旧数，恢复时先核对身份；确认成功后立即重新读取。

#### Scenario: 切换账号
- **WHEN** 用户退出并以另一账号登录
- **THEN** 旧账号的数量立即清除，新账号的数量重新读取后才显示

#### Scenario: 页面进入后台
- **WHEN** 标签页被隐藏
- **THEN** 停止自动刷新并清除当前数量，回到前台后重新核对身份再读取

### Requirement: 确认必须显式提交并核对不确定结果

确认 SHALL 由用户在确认对话框中明确提交，对话框说明“确认此资料内容仍然准确”以及确认后的新到期日按今天计算。提交携带 X-Request-Id 与当前 stewardshipVersion；响应未确认时只提供以原标识重试、重新读取核对或放弃，不自动重发。403、404 或 409 时重新读取该项，不显示为确认成功。

#### Scenario: 响应超时
- **WHEN** 确认请求超时，结果未知
- **THEN** 页面提示结果待确认，提供以原标识重试或重新读取，不自动重发新请求

#### Scenario: 提交前已被改派
- **WHEN** 用户提交确认时已不是当前责任人
- **THEN** 页面显示无法确认并重新读取清单，该项从“需要处理”中消失

### Requirement: 本人负责资料页面必须隔离身份与迟到结果

页面 SHALL 在身份代次变化、强制改密、退出或离开页面时取消在途请求，并清除列表、游标和对话框状态。迟到的读取或确认响应 MUST NOT 覆盖当前视图或其他身份的页面；切换视图时丢弃另一视图的在途结果。

#### Scenario: 切换视图时旧请求返回
- **WHEN** 用户从“需要处理”切换到“全部”后，前一视图的请求才返回
- **THEN** 迟到结果被丢弃，页面只显示“全部”视图的结果
