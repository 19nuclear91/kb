# Proposal

## Why

Worker 的普通解析、向量重建和就绪探测共用远程 Embedding 客户端，目前缺少请求及响应字节限制、贯穿完整调用的截止时间和失租取消传播。超时后的逻辑结束也未与底层实际退出关联，可能继续领取任务、占用资源或保留供应商错误正文，需要补齐完整调用生命周期的资源约束。

## What Changes

- 为 Worker 三条调用路径提供统一的有界传输：请求默认 1 MiB、响应默认 4 MiB、JSON 深度默认 64，拒绝重复字段和尾随 JSON，非成功响应不读取供应商错误正文。
- 在发送前按现有 `batch-size` 与实际 JSON UTF-8 字节双限制拆批，保留原输入及向量对应关系；单条仍超限时明确失败，HTTP 子批不改变原有数据库提交单元。
- 使用单调时钟截止时间：普通解析沿用现有默认 900 秒流水线预算；重建生成阶段默认 300 秒；每个 profile 探测默认 10 秒。HTTP 子批进一步受连接配置和执行剩余时间约束。
- 每实例固定一个普通解析／重建共用业务槽位和一个独立探测槽位，无执行等待队列。先取得业务槽位再领取数据库任务，取消后保留容量至实际工作退出。
- 将超时、失租、续租结果不可确认及进程关闭传递到在途调用，停止后续子批并拒绝迟到结果；取消与截止调度独立于业务和探测工作线程。
- 明确有限错误分类：网络故障、超时、408、429、5xx 使用现有任务级退避；请求或响应超限、协议错误及认证拒绝使普通解析进入死信、重建进入 `BLOCKED`；探测失败记录不就绪。
- **BREAKING（运维行为）**：非法远程响应在普通解析中由可能的未知错误自动重试改为永久错误；新增默认限界会拒绝原来可能被接受的超大或超时调用。调整运行限额不改变向量 profile 指纹。
- 增加能够区分逻辑终结与实际退出的低基数观测，并以受控响应流、单调时钟和执行屏障覆盖限界、竞争、取消及恢复行为。

## Capabilities

### New Capabilities

- `worker-embedding-resilience`：Worker 外部 Embedding 的载荷、分批、期限、执行容量、取消、错误分类与探测约束。

### Modified Capabilities

- `document-parsing`：普通解析领取前准入、流水线预算传播、取消后实际退出，以及 Embedding 永久／暂时故障的恢复语义。
- `embedding-rebuild`：重建生成阶段截止、共享业务容量、失租取消、迟到提交隔离及受控失败恢复。

## Impact

- 主要涉及 `kb-worker` 的 Embedding 传输与装配、普通解析和重建 Runner、探测调度、失败分类及指标；`kb-common` 提供必要的纯 JDK 执行契约和分批扩展。
- 保留查询侧现有调用预算及模型语义；实现和测试需覆盖公共接口扩展对 `kb-app` 查询路径的兼容性。
- 继续使用既有 profile、任务租约、执行代次、原子发布和重建提交协议。错误诊断以固定类别、受控摘要及指标提供，不新增模型地址或正文外发入口。
- 更新 Worker 配置及 Embedding／解析运维说明，明确限额调优、死信重放、重建恢复和取消后仍占用容量的排障方式。
- 交付通过离线可控组件回归验证实现行为；真实供应商延迟与目标环境联调另行记录，不将初始限额解释为性能承诺。
