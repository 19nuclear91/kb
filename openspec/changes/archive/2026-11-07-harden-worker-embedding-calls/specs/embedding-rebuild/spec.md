# Spec Delta

## MODIFIED Requirements

### Requirement: 批次提交与进度必须原子且可续建

系统 MUST 原子提交批次向量、profile 身份和对应进度，防止成功计数与实际数据脱节。一次领取批次拆成多个 HTTP 子批时，全部生成和校验完成前 MUST 不提交其中任何子批的向量或成功进度。执行资格失效的旧实例 MUST 不能写回；接管后 SHALL 只处理未提交的目标。已提交成功批次不得因重启或恢复再次调用模型；提交前崩溃或失败的调用不承诺避免上游重复计费。

#### Scenario: 写入向量后进度更新失败

- **WHEN** 批次事务在向量更新后、进度提交前失败
- **THEN** 整批数据库修改回滚，重试不会面对向量已成功但进度丢失的状态

#### Scenario: 成功批次后进程退出

- **WHEN** 部分批次已提交成功后 Worker 退出并被接管
- **THEN** 成功批次保留且不重复生成，仅续建未提交部分

#### Scenario: 租约接管后旧实例返回

- **WHEN** 新执行者取得资格后旧执行者提交迟到结果或失败状态
- **THEN** 旧提交无效，不覆盖新执行者的向量或进度

#### Scenario: 后续 HTTP 子批失败

- **WHEN** 当前领取批次中部分 HTTP 子批成功，但后续子批失败
- **THEN** 当前领取批次没有部分向量或成功进度提交；此前已提交的其他批次保持有效

### Requirement: 重建失败必须保留进度且只能受控恢复

系统 SHALL 对网络故障、生成超时、HTTP 408／429／5xx 等临时故障有界退避；请求或响应超限、协议或向量错误、认证拒绝等永久故障及重试耗尽 MUST 进入 BLOCKED，保留成功进度、目标和恢复阶段。`POST /api/admin/embedding/rebuilds/{runId}/resume` MUST 重新鉴权、检查 expectedVersion、目标可用性和请求幂等后恢复原作业。失败不得自动恢复混合检索或将普通解析标为死信；已失去执行资格的实例不得写入新的失败状态。

#### Scenario: 模型持续限流直至耗尽

- **WHEN** 目标服务持续返回可重试错误并达到上限
- **THEN** 作业进入 BLOCKED，BM25 保持可用，新内容继续等待，错误原因可查询

#### Scenario: 管理员修复后恢复

- **WHEN** 合格操作者以正确版本恢复 BLOCKED 作业且目标预检通过
- **THEN** 返回 202，沿原目标和成功进度继续，不新建全量作业

#### Scenario: 恢复预检仍失败

- **WHEN** 目标服务仍不可用时提交恢复
- **THEN** 返回 503，作业保持 BLOCKED，不丢失成功进度

#### Scenario: 载荷超限立即阻塞

- **WHEN** 本次生成发现单条请求仍超限或模型响应越限
- **THEN** 作业直接 BLOCKED，不自动拆小重发已发送的请求，保留原分块及成功进度供修正后恢复

#### Scenario: 生成超时仍持有资格

- **WHEN** 生成阶段到期而本次数据库执行资格仍有效
- **THEN** 以一次可重试故障处理，并受既有尝试上限约束，不因租约可以续期而继续无限等待

#### Scenario: 故障写回前已失租

- **WHEN** 模型失败或超时准备写回时原资格已过期或被接管
- **THEN** 旧失败写回无效，不将新执行者的作业改为退避或 BLOCKED

## ADDED Requirements

### Requirement: 重建必须在共享业务容量内领取和执行

Worker SHALL 与普通解析共享单实例一个业务槽位，并在领取重建 run 与 item 前取得该槽位。一个槽位只承载一个领取批次，HTTP 子批顺序执行。无槽位时 MUST 不领取、不消耗 item 尝试次数；已逻辑结束但底层或取消收尾尚未退出时 MUST 保留槽位。无目标、空批次和领取异常均须在本次实际工作退出后释放容量。

#### Scenario: 普通解析正在退出
- **WHEN** 全局已进入重建，但本机旧普通解析仍未实际退出
- **THEN** 本机不领取重建批次，其他具有空闲槽位和合法资格的实例可继续处理

#### Scenario: 超时后下次调度到达
- **WHEN** 一个重建批次已逻辑超时，但旧网络工作或取消动作仍在执行
- **THEN** 调度不领取下一个批次，不以取消句柄完成作为槽位空闲依据

#### Scenario: 没有待处理条目
- **WHEN** 已取得槽位而领取返回空批次
- **THEN** 按原资格规则完成释放后归还本地槽位，不启动模型调用

### Requirement: 重建生成必须具有独立截止并响应失租取消

每个领取批次的生成阶段 SHALL 使用可配置的默认 300 秒单调截止，覆盖读取分块、编码、全部 HTTP 子批及结果校验。续租 MUST NOT 延长该截止。续租失败或结果不可确认时 MUST 停止后续子批并取消在途调用；取消与超时后的迟到结果不得发起提交。生成在截止前成功交接后 SHALL 由既有短事务再次验证资格并提交，旧生成计时器不得中断新的执行或已合法交接的阶段。

#### Scenario: 租约持续续期但生成未结束
- **WHEN** 心跳持续成功而生成耗时达到总预算
- **THEN** 本次仍按生成超时终结，不以租约有效替代时间预算

#### Scenario: 多子批共用剩余时间
- **WHEN** 第一个 HTTP 子批已耗去部分生成预算
- **THEN** 后续子批只能使用剩余时间，预算不足时不发送新请求

#### Scenario: 心跳返回失败或抛出异常
- **WHEN** 本次续租返回失败，或数据库故障使续租结果不可确认
- **THEN** 停止本次生成并请求取消当前调用；迟到向量不得发起提交，失败收尾仍受数据库原资格约束

#### Scenario: 生成完成后合法提交
- **WHEN** 全部结果在截止前通过校验且本次执行仍可交接提交
- **THEN** 在原事务中再次核对 run、item、epoch、profile 与正文一致性，生成计时器随后迟到也不取消其他阶段

#### Scenario: 关闭期间仍有生成
- **WHEN** Worker 开始关闭且一个重建生成仍在运行
- **THEN** 停止准入与后续子批，请求取消在途工作，保留原持久进度及租约恢复机制
