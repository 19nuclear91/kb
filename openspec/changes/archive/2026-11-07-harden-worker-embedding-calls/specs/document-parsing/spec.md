# Spec Delta

## MODIFIED Requirements

### Requirement: 失败分类必须决定重试或死信

系统 SHALL 将解析失败分类为永久错误、可重试错误或未知错误；永久错误 MUST 立即进入死信，可重试和未知错误 MUST 受最大尝试次数约束。外部 Embedding 的请求或响应超限、协议或向量校验失败及认证拒绝 MUST 明确归为永久错误；网络故障、调用超时、HTTP 408／429／5xx SHALL 归为可重试错误。Embedding 诊断 MUST 使用固定类别和受控摘要，不保存供应商错误正文。

#### Scenario: 永久错误立即死信

- **WHEN** 输入无效、格式不支持、内容不可索引或解析器明确返回错误
- **THEN** 任务不再重复消耗自动尝试次数并进入死信
- **AND** 文档版本不得进入可检索状态

#### Scenario: 暂时性错误退避重试

- **WHEN** 对象存储、embedding 或数据库返回超时、限流或暂时性服务错误
- **THEN** 任务按退避策略重新排队
- **AND** 达到最大尝试次数后进入死信并标记文档版本失败

#### Scenario: 租约失守不伪造失败

- **WHEN** 当前 Worker 发现自己已经失去任务租约
- **THEN** 当前 Worker 放弃写回结果和失败记录
- **AND** 该事件由后续租约恢复路径处理而不是生成重复失败

#### Scenario: Embedding 载荷或协议永久错误

- **WHEN** 单条输入连同包络无法满足请求上限，响应越限，或响应及向量协议校验失败
- **THEN** 任务直接进入死信并保留原文和固定错误诊断，不作为未知异常重复调用模型

#### Scenario: 模型返回认证拒绝或请求超时状态

- **WHEN** 模型返回 HTTP 401／403，或返回 HTTP 408
- **THEN** 前者直接进入死信，后者按现有退避机制重试，均不读取和保存供应商错误正文

### Requirement: 在途普通解析必须无伪失败地安全收敛

系统 MUST 在重建覆盖开始前完成或失效所有在途普通发布资格。仅因维护被中止的尝试 SHALL 幂等回到待处理，不新增解析失败或死信、不净消耗重试预算；此前真实失败记录 MUST 保留。维护或失租被本实例确认后 MUST 停止新增 Embedding 子批并请求取消在途调用；本实例业务槽位保留至实际工作退出。迟到心跳、失败写回和旧结果 MUST 不改变新状态，手工重试和巡检不得绕过维护暂停。

#### Scenario: 在途任务因维护中止

- **WHEN** 任务正在调用模型时进入维护并中止该次执行
- **THEN** 该次执行被记录为维护延期并回到等待，历史真实失败次数保留，不产生新的业务失败

#### Scenario: 巡检与维护收敛并发

- **WHEN** 多个实例同时巡检或尝试收敛同一被维护中止的执行
- **THEN** 维护延期只生效一次，既不重复补偿次数，也不将该次中止记入死信

#### Scenario: 手工重试处于维护期间

- **WHEN** 合格用户重试一个真实失败版本
- **THEN** 依既有规则入队和保留历史，但仍等待维护结束才领取

#### Scenario: 维护失效后模型仍未退出

- **WHEN** 普通解析的发布资格已经失效，而本机模型调用仍在退出中
- **THEN** 旧结果不能发布，本机不领取新的解析任务或重建批次，其他合格实例可依既有维护与租约规则继续工作

#### Scenario: 维护与调用超时竞争

- **WHEN** 模型调用超时准备记录失败，但维护已使该执行资格失效
- **THEN** 失败写回按原执行代次复核后无效，不覆盖维护延期、不再次扣减或补偿尝试次数

## ADDED Requirements

### Requirement: 普通解析领取前必须取得实际业务容量

Worker SHALL 与向量重建共享单实例一个业务槽位，先准入再领取解析任务。一次空闲槽位只允许领取一份立即可执行的解析任务；配置的领取数量不得产生本地等待队列。无槽位时 MUST 不调用任务领取、不增加 attempts 或改变版本状态。空领取、领取异常及执行终结 SHALL 在本次相关工作实际退出后恰好释放一次槽位。

#### Scenario: 调度时槽位仍被占用
- **WHEN** 上一次解析或重建尚未实际退出，解析轮询再次触发
- **THEN** 本轮不领取任务，不改变任务与版本状态，等待后续调度

#### Scenario: 配置一次领取多条
- **WHEN** 领取数量配置大于一，但实例只有一个可用业务槽位
- **THEN** 本轮最多领取一份解析任务，不将其余任务提前置为运行中等待

#### Scenario: 数据库领取返回空或异常
- **WHEN** 已取得槽位后领取返回空集合或抛出异常
- **THEN** 领取调用实际退出后释放本次槽位；结果未知的数据库操作继续按原持久租约规则恢复

### Requirement: 普通解析必须传播流水线剩余预算并隔离迟到结果

普通解析 SHALL 从流水线开始建立现有默认 900 秒的单调截止，并将剩余预算和本次执行停止信号传播至全部 Embedding 子批。到期或取消后 MUST 不启动下一子批、不交付迟到成功；若仍持有数据库执行资格，真实超时 SHALL 按可重试失败处理。正常生成在截止前完成后 SHALL 进入原原子发布门禁，已结束生成的计时器不得取消后续合法提交或其他执行。

#### Scenario: 前置解析耗时
- **WHEN** 原件读取与解析已消耗大部分流水线预算
- **THEN** 后续向量生成使用原截止的剩余时间，编码和全部子批共同受限

#### Scenario: 超时但仍有数据库资格
- **WHEN** 流水线到期而原任务执行资格仍有效
- **THEN** 选择一次超时失败并执行受资格约束的退避写回，不仅因本地计算已被取消就误判为失租

#### Scenario: 超时后底层忽略中断
- **WHEN** 解析已逻辑超时，底层解析或 Embedding 工作仍不退出
- **THEN** 保留业务槽位，不领取替代任务；迟到结果不得写入分块或推进版本

#### Scenario: 旧心跳迟到
- **WHEN** 第一份任务的心跳在第二份任务开始后才返回失租
- **THEN** 只作用于第一份执行，不取消第二份的网络调用、预算或槽位

#### Scenario: HTTP 子批部分成功
- **WHEN** 一份文档的前几个子批成功而后续子批失败
- **THEN** 本次不发布部分分块或向量，旧已发布版本仍按原规则可用
