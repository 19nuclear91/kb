# chat-model-adapter Spec Delta

## RENAMED Requirements

- FROM: `### Requirement: 通用协议就绪不得替代可信多轮预算能力`
- TO: `### Requirement: 通用协议就绪必须配合显式多轮预算策略`

## MODIFIED Requirements

### Requirement: 通用协议就绪必须配合显式多轮预算策略

系统 MUST 将协议接入与多轮预算策略分开判断。默认 verified 模式 SHALL 仅接受绑定实际部署及消息格式、提供核验窗口与完整输入上界的严格扩展；显式 estimated 模式 SHALL 使用服务端配置窗口及本地估算规则，并明确其不证明真实上界。协议配置完整本身不得开启多轮。缺少当前模式所需能力时，新生成 MUST 在创建轮次、领取配额、检索或调用模型前返回 503；已有匹配重放保留原状态核对。严格模式的缺失、异常及身份不匹配 MUST NOT 自动降级为估算。

#### Scenario: 只有通用配置
- **WHEN** 模型地址、密钥和名称有效，未设置预算模式且没有匹配的严格预算扩展
- **THEN** 默认 verified；旧单轮可使用真实协议适配，多轮新生成返回 503，不创建轮次、不检索、不调用模型、不领取配额

#### Scenario: 模型身份与预算不匹配
- **WHEN** verified 模式中的模型或消息格式改变，而预算扩展仍绑定旧身份
- **THEN** 不能复用旧预算声明启用多轮，也不能仅填写窗口使其被视为已核验；不自动改用估算

#### Scenario: 扩展契约的离线验证
- **WHEN** 测试注入匹配身份的确定性严格预算替身
- **THEN** 可以验证消息、预算裁剪和事件桥接，但替身不进入生产装配，也不构成真实模型预算已核验的证明

#### Scenario: 显式选择通用估算
- **WHEN** 部署方显式选择 estimated，模型协议及预算参数均有效，且内置多轮适配为当前实现
- **THEN** 不要求供应商 tokenizer 或严格预算扩展即可启用估算能力，并按 ESTIMATED 处理；其本地估算允许与真实 token 不一致

#### Scenario: 严格策略计算失败
- **WHEN** verified 策略计算抛出异常、返回非法值或多个策略同时匹配同一身份
- **THEN** 按既有运行时拒绝或配置错误处理，不调用估算器、不切换模型、不向上游发送本次生成请求

#### Scenario: 显式估算与已有自定义模型
- **WHEN** 部署已有自定义单轮或多轮模型，并配置了 estimated
- **THEN** 各自定义模型的既有优先级保持不变；估算配置仅选择内置多轮预算策略，不覆盖自定义模型或将其缺失的预算能力视为具备
- **AND** 已显式启用的通用模型配置仍须通过校验

## ADDED Requirements

### Requirement: 估算模式必须使用显式有界的服务端配置

预算配置 SHALL 只由服务端提供；mode 只接受 verified、estimated，默认 verified。启用 estimated 时，窗口 MUST 显式配置且为正整数；换算比例、每消息开销、请求开销和安全余量 SHALL 使用有界整数及明确单位。窗口与预留的较小值 MUST 严格大于多轮输出上限加余量。配置缺失、类型错误、未知模式、数值越界或容量无效 MUST 在建立业务连接前以固定安全错误拒绝，不回显原始值。

#### Scenario: 默认估算参数
- **WHEN** 部署启用 estimated 并提供合法窗口，但没有覆盖估算参数
- **THEN** 每 1024 UTF-8 字节估算 1024 token，每消息额外 16 token，请求额外 64 token，安全余量 512 token
- **AND** 这些默认值只定义启发式行为，不声明任何供应商已核验或默认窗口

#### Scenario: 窗口缺失或容量被余量占满
- **WHEN** estimated 未提供窗口，窗口不在 1–2147483647，或 min(窗口, 单轮预留) 小于等于输出上限加余量
- **THEN** 启动配置校验失败，不把缺失窗口替换为供应商猜测值，也不在运行时强行放行

#### Scenario: 比例和开销越界
- **WHEN** 每 1024 字节的 token 系数不在 1–65536、每消息或请求开销不在 0–65536、余量不在 0–2147483647，或字段不是整数
- **THEN** 拒绝配置；浮点、溢出或不可解析值不得被截断为可用配置

#### Scenario: 单轮输出配置与多轮配置独立
- **WHEN** 部署修改旧单轮输出上限，而多轮输出与预留未变
- **THEN** 多轮预算继续使用其原多轮输出值与预留；估算参数不另行创建或修改账本预留额度

#### Scenario: 未启用模型适配
- **WHEN** 通用模型适配保持关闭
- **THEN** 预算配置本身不启用内置模型调用，不创建远程计数或模型探测请求

### Requirement: 通用估算必须完整覆盖实际消息并保持确定性

estimated SHALL 对最终消息列表中全部 role 与 content 的 UTF-8 字节数之和 B 计算 `ceil(B * P / 1024) + N * M + F`，其中 N 为消息数、P 为每 1024 字节 token 系数、M 为每消息开销、F 为请求开销。系统 MUST 只对总字节数做一次向上取整，包含指令、历史、材料包装及原问题；不将 HTTP 外层传输转义或凭据作为模型消息计数。计算 SHALL 本地、有界、确定性且不修改消息；非法输入或溢出 MUST 拒绝。

#### Scenario: 混合语言及角色参与计数
- **WHEN** 消息为 role=user、content=A 和 role=assistant、content=中😀，P=512、M=2、F=3
- **THEN** B=21、N=2，估算结果为 18，完整包含角色与多字节正文

#### Scenario: 只对全部消息取整一次
- **WHEN** 两条消息均为 role=user、content=A，P=512、M=2、F=3
- **THEN** B=10、N=2，估算结果为 12，不得逐消息向上取整而得到 13

#### Scenario: 材料包装参与计数
- **WHEN** 发送的材料消息包含固定说明、文档/版本/分块/页码字段及 JSON 转义内容
- **THEN** 这些实际消息字符全部参与 UTF-8 字节计数，不能只统计原分块正文
- **AND** 不额外计算 HTTP 外层序列化为同一字符串引入的传输转义，也不读取认证头

#### Scenario: 重复计算不触发副作用
- **WHEN** 对相同消息和冻结参数连续计算或因裁剪重新计算
- **THEN** 相同输入得到相同结果，原消息不变，不发出网络、模型或在线计数请求，也不保存正文

#### Scenario: 数值或编码非法
- **WHEN** 计数运算溢出、出现非法 Unicode/NUL、负数计数或不一致的预算类型
- **THEN** 以固定安全错误拒绝，不按零值或已知上界继续，不泄露问题、材料或原始异常

### Requirement: 估算能力必须与严格能力隔离且兼容既有扩展

系统 SHALL 明确区分 ESTIMATED、VERIFIED 与不可用能力；能力窗口、余量及计数结果 MUST 使用同一类型和冻结配置。既有只提供严格上界的部署方扩展 SHALL 继续按 VERIFIED 使用，不能因新增模式被要求实现估算。估算策略 MUST NOT 通过旧严格上界能力或计数接口声称已核验。配置变更经重启生效，不在一次生成中热切换；严格与估算之间不存在自动失败回退。

#### Scenario: 旧严格扩展保持兼容
- **WHEN** 既有严格多轮扩展只提供原有的预算能力、窗口和上界计数
- **THEN** 新编排仍将其作为 VERIFIED 使用，额外余量为零，不要求新增估算实现

#### Scenario: 旧上界调用方访问估算实现
- **WHEN** estimated 实现被旧严格上界调用方查询能力或直接要求上界值
- **THEN** 其严格上界能力为不支持，上界计数请求被拒绝；只有明确识别 ESTIMATED 的新编排可使用估算值

#### Scenario: 发送前预算复核
- **WHEN** 已选择的消息准备发送给模型
- **THEN** 系统按相同冻结策略复核实际待发送消息；不匹配或超限时不发送，不在复核之后增加未计入的内容

#### Scenario: 选择 estimated 时存在严格策略
- **WHEN** 部署显式选定 estimated，同时存在可匹配的严格预算扩展
- **THEN** 内置多轮按所选估算策略计算，不调用严格策略来隐式覆盖选择或混合两个结果

### Requirement: 估算值不得成为实际用量或费用上限证明

估算计数 SHALL 仅用于输入准入和裁剪，不写入实际 prompt/completion usage，也不替代额度预留。正常确认的实际 usage MUST 完整保存与结算，包括超过估算或预留的值；已有模型调用意图但没有最终统计继续为 UNKNOWN 并按既有预留规则结算，无调用意图时为 NOT_INVOKED 和零 token 结算。上游拒绝、截断或估算不足 MUST 沿用既有失败收尾，不自动重新生成。

#### Scenario: 真实用量超过预留
- **WHEN** 本地估算允许调用，而模型最终确认的输入加输出 usage 超过本轮预留
- **THEN** 完整保留真实统计并按既有 KNOWN 规则结算，不裁成估算值或预留上限，不把预算通过解释为费用硬上限

#### Scenario: 缺少最终统计
- **WHEN** estimated 模式下已有模型调用意图但没有可确认的最终 usage
- **THEN** 真实用量仍为 UNKNOWN、token 字段为空，扣除额度按原预留处理，不以估算值补齐

#### Scenario: 意图保存后发送复核失败
- **WHEN** 模型调用意图已持久化，发送前最后复核失败且本地没有发送 HTTP 请求
- **THEN** 不发送模型请求，但仍按既有意图及缺少确认 usage 的 UNKNOWN 规则收尾，不凭本地计数重写意图或伪造 NOT_INVOKED

#### Scenario: 上游因上下文拒绝
- **WHEN** 本地估算通过但上游因实际窗口不足拒绝，或返回非正常截断结束
- **THEN** 本次生成失败并按原规则收尾，不自动改窗口、删参数、切模式、重新裁剪后再次调用或伪造成功 done
