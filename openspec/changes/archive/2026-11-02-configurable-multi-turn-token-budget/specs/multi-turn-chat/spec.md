# multi-turn-chat Spec Delta

## MODIFIED Requirements

### Requirement: 上下文与输出必须受明确预算约束

系统 SHALL 为当前问题、指令、完整历史、新材料及输出设置有界预算。输入计数 MUST 明确为 VERIFIED 上界或显式启用的 ESTIMATED 估算，计数加输出上限及适用安全余量不得超过窗口与单请求预留的较小值；估算通过不证明真实 token 一定落入该范围。超限 SHALL 先排除最旧完整历史问答，再按 Unicode 安全规则裁剪材料，每次裁剪重新计数；原问题不得静默截断。来源、字符和字节限制继续生效，必需输入或有效材料仍无法容纳时不得调用模型。

#### Scenario: 历史超过预算
- **WHEN** 多轮历史和新材料超过当前模式的上下文预算
- **THEN** 最近的完整轮次优先保留，最旧轮次成对排除，材料裁剪不破坏 Unicode 字符，并在裁剪后按完整发送消息重新计数
- **AND** 保存的来源依赖只覆盖实际输入，SSE 引用与本轮实际新材料一致

#### Scenario: 问题本身无法容纳
- **WHEN** 当前原问题与必需指令无法在窗口、预留及适用余量内容纳
- **THEN** 流开始前返回 400，或流开始后以安全 error 终止，并携带固定 code=INPUT_BUDGET_EXCEEDED；不调用模型
- **AND** 不把问题截断后当成原问题回答，也不虚构 token usage

#### Scenario: 估算余量只计一次
- **WHEN** 窗口至少 12000、单轮预留 12000、多轮输出上限 2048、安全余量 512
- **THEN** 在其他门禁均满足时，估算输入 9440 可通过，9441 必须裁剪或拒绝；选择阶段与发送前复核采用相同边界

#### Scenario: 配置更大的模型窗口
- **WHEN** 部署提高模型窗口，但单轮预留与输出上限不变
- **THEN** 预算仍受单轮预留限制，不因此扩大部门账本预留或绕过输出限制

#### Scenario: 窗口小于单轮预留
- **WHEN** 配置窗口小于单轮预留但仍能容纳输出和余量
- **THEN** 使用窗口减输出及余量后的输入容量，不能以较大的预留放行超窗输入

#### Scenario: 字符或请求字节限制更紧
- **WHEN** token 估算通过，但现有字符或请求字节保护不允许该输入
- **THEN** 继续按对应保护裁剪或安全拒绝，不因估算模式跳过硬资源边界

#### Scenario: 类型不匹配或计数无效
- **WHEN** 计数类型与本轮能力不一致、计数为负或计算溢出
- **THEN** 拒绝本次生成，不按空输入、零预算或另一种模式继续，不发布成功 done

### Requirement: 多轮模型契约必须显式支持历史

模型适配边界 SHALL 接受有序角色消息、当前新材料和输出上限，返回增量文本及 usage；预算能力 MUST 明确区分不可用、VERIFIED、ESTIMATED，不得把估算声明为已验证上界。只有实际具备历史与当前模式预算能力的适配器才能接受新生成，否则 SHALL 在创建轮次及领取配额前返回 503；不得保存占位回答、静默忽略历史或提升客户端角色。既有严格预算自定义实现 SHALL 保持兼容，具体供应商接入不是能力完成的替代证明。

#### Scenario: 仅有旧单轮适配器
- **WHEN** 系统只装配旧单轮适配器或没有支持多轮和当前模式预算的适配器
- **THEN** 新生成入口返回安全 503，不创建轮次、领取配额或生成占位回答
- **AND** 既有单轮接口仍遵循原有行为

#### Scenario: 适配器收到多轮输入
- **WHEN** 完整历史、当前问题与新材料已经选入当前预算
- **THEN** 适配器按服务端确定的角色和顺序接收同一输入，增量和累计 usage 可被消费

#### Scenario: 原严格扩展升级后使用
- **WHEN** 部署方已有严格预算多轮适配器且未新增估算功能
- **THEN** 新编排按其原窗口和上界以 VERIFIED 运行，额外余量为零，不要求修改原扩展才能保持可用

#### Scenario: 预算关闭或缺失后的匹配重放
- **WHEN** 当前新生成能力不可用，但请求与已有轮次的用户、会话、请求标识、原问题及预期序号匹配
- **THEN** 仍返回原轮次的 JSON 状态核对，不受新生成预算门禁阻断，不重新检索、领取配额或调用模型

## ADDED Requirements

### Requirement: 预算耗尽不得伪装成无检索结果

当初始有效版本材料非空，随后因 token 预算或字符保护裁到没有可用材料时，系统 MUST 以 INPUT_BUDGET_EXCEEDED 拒绝生成，不能封存 NO_RESULTS、成功回答或保留被裁掉材料的引用。已建立流时 SHALL 发送固定安全 error 并按既有 FAILED 与 NOT_INVOKED/零 token 结算收尾；未建立流时返回 400。合法空检索与检索协议失败 SHALL 保留各自既有语义。

#### Scenario: 非空材料被预算裁空
- **WHEN** 检索返回可用版本材料，但在保留原问题及必要包装后，材料全部因预算耗尽被移除
- **THEN** 本轮发送或返回 code=INPUT_BUDGET_EXCEEDED，不调用模型，不追加“未找到与问题相关的内容”正文，不返回成功 done
- **AND** 不通过旧历史答案或额外检索绕过本次材料预算

#### Scenario: 字符保护导致材料清空
- **WHEN** token 计数满足限制，但原问题与指令占用字符容量，使所有有效材料被字符保护移除
- **THEN** 同样报告 INPUT_BUDGET_EXCEEDED，不把资源限制解释为成功空检索

#### Scenario: 授权检索真实为空
- **WHEN** 检索成功返回合法空列表
- **THEN** 沿用固定 NO_RESULTS 成功处理及 NOT_INVOKED/零 token 结算，不误报预算耗尽

#### Scenario: 检索材料缺少版本身份
- **WHEN** 非空检索响应中的材料全部缺少有效版本身份
- **THEN** 继续以 SEARCH_UNAVAILABLE 失败，不改为预算错误或 NO_RESULTS

#### Scenario: 预算失败的终态与结算
- **WHEN** 轮次及配额已创建，预算耗尽发生在输入选择阶段、尚未形成模型调用意图，且持久化和结算依赖可用
- **THEN** 保存 FAILED、NOT_INVOKED、真实 token 为零及扣除额度为零，并释放并发资格；既有请求次数窗口不额外返还
- **AND** 不保存预算错误文案为助手正文，不将失败轮次纳入后续完整历史

#### Scenario: 预算失败收尾暂不可确认
- **WHEN** 预算耗尽后保存 FAILED 或提交结算暂时不可用，或者取消与失败竞争
- **THEN** 沿用持久资格过期、固定结算意图重试及终态竞争规则，流有界结束，不伪造已确认状态、不覆盖已提交终态

#### Scenario: 预算失败后匹配重试
- **WHEN** 客户端对预算失败轮次提交匹配重放
- **THEN** 返回该轮次当前状态，不再次裁剪并生成、不重新检索或领取配额；用户主动以新标识重发才形成新的执行

### Requirement: 预算判断不得改变来源与用量事实

估算及严格模式 SHALL 使用最终实际保留的历史和材料确认来源，不因增加安全余量改变引用所属版本或省略历史依赖。输入计数 MUST 与实际 usage 和预留额度分开；预算错误或上游失败不能制造 KNOWN 用量、成功终态或重复调用。既有真实累计用量、UNKNOWN 保守结算及超预留用量完整保留规则继续适用。

#### Scenario: 历史淘汰时来源同步
- **WHEN** 旧历史问答因预算被整对移除
- **THEN** 只保留最终输入实际需要的历史来源依赖，本轮 SSE 引用仅列实际新材料，不保留没有正文对应的假输入声明

#### Scenario: 有效 usage 大于估算
- **WHEN** 模型确认的最终 usage 大于预算估算，且流满足既有正常终结条件
- **THEN** 保存真实 usage 并按既有结算规则处理，不改成估算值、不因低估而隐藏用量或重新生成

#### Scenario: 供应商没有给出最终 usage
- **WHEN** 本轮采用估算预算且模型调用意图已保存，但最终实际统计不可确认
- **THEN** 仍以 UNKNOWN 表示真实用量，按原预留结算，不将估算作为最终统计
