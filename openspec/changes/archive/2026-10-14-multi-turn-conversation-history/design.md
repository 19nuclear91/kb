# Design

## Context

动机和范围见 `proposal.md`，对外行为见 `specs/conversation-history/spec.md` 与 `specs/multi-turn-chat/spec.md`
。本设计适用于这些已确认规则：个人私有、按当前权限屏蔽历史、断连取消、保留已保存的部分回答并标记未完成。

- `kb-ai` 使用 WebFlux，`ChatRequest` 只有问题，`ChatModelClient` 只有单轮问题/引用输入；没有具体模型供应商实现，未注入时返回占位回答。
- `ChatController` 保证单次订阅、四类 SSE 事件、心跳及取消传播，先结算再发送 done；当前失败/取消释放按零 usage
  处理，不能直接作为新多轮持久化账本的事实。
- `kb-app` 是持久化和细粒度授权的唯一入口。`PermissionService` 只允许请求内主体复用，不能把权限句柄或范围存入会话字段跨请求使用。
- 固定引用已有 `docId + versionId + chunkId`。版本是否当前、分块是否存在与用户是否仍可查看是不同问题；现有指定版本读取不要求当前版本。
- 现有迁移至 V17。网关没有 `/api/conversations/**` 路由；旧单轮链路和数据库依赖边界必须继续受回归保护。

## Goals / Non-Goals

**Goals:**

- 将会话归属、资源授权、生成执行资格和配额关联分别建模，避免一种资格代替另一种。
- 在短事务中决定顺序和写入资格，模型及网络调用在事务外运行；以持久状态处理并发、响应丢失与崩溃。
- 让来源依赖在第一段回答保存前封闭，历史读取和下一轮输入使用同一授权规则。

**Non-Goals:**

- 不恢复旧单轮请求的历史，不保存检索片段或完整 prompt 快照，不把引用或依赖当作逐句证据。
- 不通过本变更选择云模型、增加知识图谱、构建前端或实现后台生成和 SSE 事件回放。
- 不追溯擦除已送达客户端或由用户自行复制的内容；本设计约束系统新的读取和模型输入。
- 按用户确认的验收范围，不创建或执行集成、端到端、真实数据库或 Redis 验证，不启动业务服务、HTTP
  测试服务器及外部组件；不新增针对文档、示例、注释或源码文件文本内容的断言测试。功能代码和生产依赖保持原设计，验收限于进程内行为、mock/stub、编译与静态检查。

## Decisions

### D1. 会话存储与授权留在 kb-app

新增 `kb-app.conversation`，保持 `web -> service -> mapper`。历史授权通过 document 服务新增的批量“文档版本当前可查看”入口完成；conversation
不直接访问 document mapper。AI 使用 WebClient 和本模块本地协议 DTO，不引入 JDBC/MyBatis，不把服务 Web DTO 放入 kb-common。

内部调用的通用签名计算可放在只依赖 JDK 的公共安全包，装配和配置仍在各服务。个人业务接口不新增管理员 bypass 权限，也不把空间
manage 当作会话正文权限。

**备选：** 将历史存 Redis 会引入另一套持久性和按版本授权查询；给 kb-ai 加数据库则拆掉既有边界。采用已有 PostgreSQL 与
kb-app 服务入口。

### D2. 以会话和轮次为主模型，正文与账本分开

计划新增下一条未占用 Flyway 迁移（目前候选 V18，实施时重新核对最高版本），不修改 V1–V17。

| 数据对象                         | 关键事实与约束                                                                                                                                                      |
|------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `kb_conversation`            | 稳定 owner_user_id、用户显式标题/固定默认标题、create_request_id、创建绑定摘要、last_turn_seq、active_turn_id、execution_epoch、deleted_at；本人创建标识唯一                                     |
| `kb_conversation_turn`       | conversation_id、turn_seq、request_id、原问题、绑定摘要、assistant_text、生成状态、answer_kind、source_sealed、预期来源数量/摘要、保存位置、执行资格摘要和过期时间、模型调度事实、usage_status、时间；会话序号和会话请求标识分别唯一 |
| `kb_conversation_source`     | 每轮有效 `doc_id + version_id` 并集，包含被输入历史回答的传递依赖；每个身份唯一，不保存正文                                                                                                    |
| `kb_conversation_citation`   | 仅本轮实际新材料的引用身份、展示和来源提示、contextTruncated；不保存检索正文或签名直链                                                                                                          |
| `kb_conversation_batch`      | 已提交 batch_seq、内容摘要及长度，用于保存响应丢失后的去重；正文只在 turn 保存一份                                                                                                            |
| `kb_conversation_settlement` | 固定 turn_id、部门、配额租约/事件关联身份、预留、已知或未知 usage、保守结算额、意图摘要、状态、重试次数/时间；每轮唯一                                                                                          |

状态、非负序号、资格期限及活动位置有数据库约束。会话行提供单飞串行化；活动轮次另用唯一约束防御漏锁。来源身份不使用会因文档物理删除而级联清空的外键，避免“来源被删后集合变空”误变成无来源放行；保存声明的数量和摘要并在读取时核对完整性。

正文是受保护的产品数据，审计只包含安全标识、状态和用量。数据库不保存 Sa-Token、内部服务密钥、明文写入票据、检索原文或完整模型请求。
`answer_kind` 区分模型回答与服务端固定无结果模板；模型回答不能凭空来源集合当作已验证无来源内容。

**备选：** 松散消息行难以保证问答成对裁剪和请求幂等；复用身份审计存正文违反现有摘要边界。采用轮次聚合，保留角色化模型输入作为运行时契约。

### D3. 公共接口显式区分首次执行、状态读取和重放

| 接口                                           | 约定                                                                                                                                    |
|----------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| `POST /api/conversations`                    | title 可选；requestId 或 X-Request-Id 必需且一致；首次 201，匹配重放 200，缺省标题为“新会话”                                                                    |
| `GET /api/conversations`                     | 创建序固定分页，按 created_at/id 倒序；limit 默认 20、最大 100；只返回本人未删除会话及安全元数据                                                                        |
| `GET /api/conversations/{id}`                | 本人摘要、lastTurnSeq 与活动状态；不返回助手预览或来源名称                                                                                                   |
| `GET /api/conversations/{id}/turns`          | 按 turn_seq 正序游标分页；返回原问题、生成状态、incomplete、visibility、当前可展示的回答/引用和独立结算状态                                                                 |
| `GET /api/conversations/{id}/turns/{turnId}` | 同一历史授权规则下查询单轮，用于请求响应丢失后的核对                                                                                                            |
| `DELETE /api/conversations/{id}`             | 本人删除及重复删除均 204，其他目标统一 404                                                                                                             |
| `POST /api/ai/conversations/{id}/turns`      | question、requestId、expectedLastTurnSeq；首次接受 SSE，匹配重放返回 200 JSON `{conversationId, turnId, turnSeq, status, replayed:true}`，不返回正文或执行票据 |

明确缺省及上限，拒绝未知身份、角色、历史和来源字段。问题原文与预期序号参与精确请求绑定，不仅按 requestId
查存在。匹配重放在检查本人及未删除状态后先于过期序号校验；重复请求不重新运行检索或配额流程。

新 SSE 使用同样四类事件名和新的本地事件 DTO，允许新增会话/轮次身份与诚实的 usage 状态；旧 DTO 和旧 `/api/ai/chat`
行为不变。初始响应提供 `X-Conversation-Id`、`X-Turn-Id`，网关精确暴露这两个 CORS 响应头。客户端按 Content-Type 区分 SSE 与
JSON 重放；新接口文档明确这一点。

身份、归属、参数、预期序号、适配能力及配额的可提前拒绝在响应提交前完成，分别使用 401/403/404/400/409/503/429。流开始后故障使用安全
error 帧，不回显上游原始错误。会话、历史和新 SSE 使用 no-store。

**备选：** 重试重新附着原流需要持久事件日志和回放协议；本期用轮次状态查询完成核对，不引入第二个生成订阅。

### D4. 使用短事务、稳定序号和执行票据串行化

begin 在短事务内锁会话行，先判本人/未删除，再检查请求重放；新请求要求没有活动轮次且 expectedLastTurnSeq 匹配。分配下一序号，插入
RUNNING 轮次并占用活动位置，同事务生成至少 256 bit 随机写入票据，只保存摘要并绑定会话 epoch、轮次及持有者。票据只给首次接受的可信
AI，不在重放或公共响应中返回。

所有 source seal、批次、续期和终态事务使用一致锁顺序：会话行、轮次行、派生行。写入要求未删除、活动位置匹配、RUNNING、epoch/票据一致且租约未过期；数据条件和影响行数构成执行栅栏，不依赖进程内
Map。

执行租约建议默认 120 秒、每 30 秒续期，配置验证续期间隔小于期限，并覆盖实际网络预算。心跳是该 SSE
执行的一部分，断连时停止；续期失败停止模型。有界关闭失败后，kb-app 周期恢复已过期轮次为 INTERRUPTED
并释放活动位置。恢复器和正常结束竞争同一栅栏，不启动模型或夺取旧轮次继续生成。

**备选：** 部门并发配额不能保证会话内串行；把行锁持到模型结束会占满连接池。采用短事务和持久租约。

### D5. 内部调用采用独立签名与执行绑定

`/internal/conversations/**` 不进入公开网关路由，但路由隐藏只是额外防御。app/AI 使用外部注入的共享密钥进行 HMAC-SHA256
服务签名；签名覆盖调用方、方法、实际路径、时间戳、nonce、实际请求体摘要及相关用户令牌摘要，采用恒定时间比较。时间窗与 nonce
去重阻止重放；Redis 去重不可用则拒绝内部调用。敏感头不得写日志。

历史准备和 source seal 还要求有效
Sa-Token，并从服务端解析本人及启用事实。已接受执行的批次、续期和终态必须以服务身份和票据证明绑定的所属用户/轮次；终态清理不因令牌自然过期而阻塞，且不能取得额外历史正文。未删除和执行栅栏始终复查。

纯结算接口使用双向服务签名与固定结算意图，允许会话过期或主体停用后的账本清理；它不能读正文、领取新的生成资格或调用模型。内部输入由本地协议
DTO 限定，不能以 public owner token 独立写 assistant/system 内容。

多轮功能默认关闭；显式开启时 app/AI 必须具备匹配的服务密钥、Redis 和合法预算/租约配置。prod 缺配置拒绝开启，dev 测试密钥不得进入
prod。签名工具只用 JDK 密码学能力，不增加认证厂商依赖。

**备选：** 单用调用者 Sa-Token 会让用户可伪造助手输出；单信来源 IP 依赖部署拓扑。采用服务签名和按轮票据两层绑定。

### D6. 将历史依赖与当前引用分开封闭

`effectiveSources(turn) = newModelSources(turn) UNION effectiveSources(selectedCompletedParentTurns)`
，按文档版本去重。历史候选必须属于同一会话、完整、当前可见且来源声明完整。AI 完成预算选择后调用 source
seal，提交实际选择的父轮次和新检索引用；app 重查父轮归属/完整状态、当前版本可见性及新身份归属，服务端重算并集、保存当前引用和声明摘要，一次性封闭。

seal 先于 citation、模型调度和任何回答批次；相同 seal 重试按绑定摘要幂等，不同内容冲突。模型调用的历史和材料必须与已确认
seal 完全一致。旧上游的 UNVERSIONED 材料在新持久化入口排除，不能补最新版本；旧单轮兼容分支不变。

对每次历史页和上下文准备，先读取本人轮次元数据与来源声明，批量调用 document 的版本可见性服务。该服务一次请求铸造主体句柄并使用既有
view 谓词，不要求 current_version、published 或 chunk 存在；既有未删除和空间归档规则照常执行。任一版本不匹配或不可见，整条
assistant 和 citations 屏蔽。查询故障返回无正文 503，不把它写成永久权限结论。

依赖数量/摘要不符或 MODEL 回答丢失来源声明时默认屏蔽；已确认 NO_RESULTS 模板可以合法为空依赖。被屏蔽响应保留本人的问题、轮次身份及状态，返回
answer=null、citations=[] 和固定提示，不输出来源 ID、名称、数量或具体理由。

源文档新版本发布或 chunk 被重建不改变保存引用的身份；仍有原版本 view 时允许保存回答展示，点击旧 chunk 使用现有
CHUNK_UNAVAILABLE 降级。依赖集合只用于访问控制，不在 SSE 中伪装成本轮新引用或逐句证据。

**备选：** 只检查当前引用遗漏跨轮 A→B 依赖；逐句删改无法可靠确定模型归因；检查全会话全部来源又会屏蔽未使用来源的独立回答。采用实际输入的传递并集及整条屏蔽。

### D7. 有界历史窗口和追问检索先于多轮输入

候选历史仅来自当前可见 COMPLETED 轮次。首期不生成长期摘要，使用最近完整问答对；建议最多 8 对、有效来源最多 256
个。超过来源上限时整对排除，不能保留文本却裁掉其访问依赖。

默认追问查询使用最近至多两条合格历史的用户问题与当前问题进行有界主题组合，不读取被屏蔽回答，不增加额外改写模型调用。本轮原问题始终单独保存和传给模型；构造结果只是检索
query。查询长度遵守 SearchRequest 上限并保持 Unicode 安全，当前问题无法容纳时明确拒绝，历史主题可缩减。接口保留未来语义改写扩展点，其新增模型消耗必须另行纳入配额。

无结果、拒绝或召回不可用继续使用当前安全的固定无结果行为，不将旧回答作为空召回的旁路。该模板不调模型；来源声明为空且明确标记
NO_RESULTS。

新多轮模型契约接收服务端构造的角色消息、新材料和 maxOutputTokens，同时声明多轮能力、上下文上限与可验证的 token
估算上界。适配器没有这些能力时新入口 503；不靠默认方法静默丢弃历史，也不把旧占位回答伪装成多轮成功。验证使用实现该契约的确定性测试适配器，真实供应商接入仍是独立部署前提。

预算先为当前问题、服务端指令和输出预留，再选择历史和新材料：排除最旧完整问答对，必要时裁剪新材料正文，重新计算最终实际依赖。沿用
code point 上限作为额外资源护栏，token 上界则由已声明能力的适配器提供；不能把字符数冒充实际 usage。建议输出上限默认 2048
token，输入上界与输出之和不超过每轮预留及模型窗口；所选供应商没有可靠上界估算就不能启用新生成入口。

**备选：** 直接拼所有历史会扩大成本及来源链；直接用当前追问容易丢失主语；强制增加一次云改写调用会使本变更绑定供应商。采用有界主题组合与可扩展模型契约。

### D8. 单次订阅的增量保存与终态竞争

新编排只有一个上游订阅，禁止用另一次 body.then() 订阅驱动历史保存。模型增量经 Unicode 安全、有界缓冲分批保存，建议阈值 1024
code point 或 1 秒；持续增量最多缓存有限批次，保存串行执行并传递反压。回答总长度另有上限，建议 64000 code point。

每批绑定 turn、epoch、batch_seq、内容摘要。app 在同一短事务校验下一批位置、追加 assistant_text、记录 batch
摘要及保存位置；完全相同批次重试不重复追加，冲突和跳号返回 409。已经关闭的执行不能借重试追加新文本；终态请求的完全相同重试只确认已提交状态。

保存或续期出现未确认故障时有界重试，耗尽立即取消模型。调用方不知道是否提交的批次只允许同标识重试，不把它当作下一批继续发送。历史以最后确认的持久前缀为准，不能承诺所有网络已送达字节都被保存。

正常模型完成后，app 原子写完整回答、最终保存位置、COMPLETED、usage 与固定结算意图，并清除活动位置。结算确认后 AI 发送
done。若结算暂不可确认，发送安全 error 提示核对历史，已持久化状态仍为 COMPLETED，settlementStatus 独立为
PENDING/REVIEW。该已完整保存回答仍可在授权及预算满足时用于下一轮。

取消关闭还在 RUNNING 的轮次为 CANCELLED；尽力在有界时间内保存剩余缓冲和关闭，但失败时不持续后台生成，由租约过期恢复
INTERRUPTED。FAILED/CANCELLED/INTERRUPTED 均 incomplete=true 并排除上下文；已完成结果不被取消回调改写。

```text
RUNNING --> COMPLETED
        --> FAILED
        --> CANCELLED
        --> INTERRUPTED

settlement: PENDING --> SETTLED
                   --> REVIEW
```

**备选：** 每字符写库放大事务开销；只在 done 保存会丢失全部中断输出；把结算失败改成模型失败会与已保存内容不一致。采用有界前缀和两个独立状态。

### D9. 用固定结算意图处理重试和未知费用

新执行沿用部门请求窗口、并发租约和 token 预留，并将领取成功的租约/审计关联
ID、当前部门与预留量绑定轮次。只有首次接受的执行可领取，重放不领取。领取响应不确定时不启动模型，相关 Redis
租约由原有期限回收，不用另一个标识再领取。

模型调度意图在调用前记录。有提供方明确确认的最终累计 usage 时记 KNOWN，取累计值而非事件求和；未调度记 NOT_INVOKED、实际
usage 为零；已调度但无法确定完整 usage 时记 UNKNOWN，公共字段为 null，保守结算额单独记录为预留上限。保存过的观测值只能解释为观测值，不能冒充确认的最终
usage；提供方真实统计超过预留时如实记录并结算，不能截断以掩盖超额。

轮次关闭与结算意图同事务提交。AI 即时尝试处理，kb-app 的有界调度器也可投递相同意图至 AI 的签名内部结算接口；后者只根据可信固定账本信息操作
Redis，不取历史正文、不重新调用模型。Redis 结算脚本按固定租约/意图摘要去重，将并发释放、预留转结算和账本标记原子执行；同 ID
不同意图拒绝。审计使用同一 eventId 去重，失败分别重试，不制造新事件身份。

重试窗口必须短于 Redis 结算去重保留期；超过安全窗口或无法核对已执行事实时转 REVIEW 并停止自动重试，不能在标记过期后重新扣费。Redis
灾难性数据丢失后的账本重建属于单独运维处置，不能宣称跨这种故障已证明恰好一次。调度工作只处理持久化和结算，不继续生成。

**备选：** 直接沿用 failAsync()/cancelAsync() 的零 usage 会把未知消耗变成免费；只靠 AI 进程内缓存无法跨崩溃重试。采用固定意图、诚实
usage 状态与受期限保护的结算去重。

### D10. 删除在同一写入栅栏上清除正文

本人删除事务先锁会话，再锁活动轮次，设置 deleted_at、推进 execution_epoch、关闭尚未完成的活动位置，并清空
title、question、assistant_text、引用和来源内容。保留删除墓碑、请求绑定摘要、序号和结算必需元数据，以保证重放不复活且费用仍能清理。

已结束轮次的生成终态不改写；删除是独立会话可达性事实。未结束轮次记录取消原因码但不含正文。旧 holder
在下一次保存/续期收到拒绝后停止上游；删除接口不承诺跨进程瞬时撤回已经开始的输出，也不等待模型结束才提交。后续日志和审计不保存被清理文本。

**备选：** 立即级联硬删所有轮次会丢失费用关联和幂等事实；只软删除而永久保留正文不符合此次删除契约。采用清除敏感文本加最小墓碑。

### D11. 离线行为验证与证据边界

- 进程内单元测试：直接调用 service/controller/配置校验器，使用 standalone MockMvc、mock ServerWebExchange
  与真实序列化器，覆盖身份门禁、权限屏蔽、A→B 依赖、分块缺失、Unicode 预算和敏感输出；不启动完整业务应用。
- 持久化协作：加载生产映射并使用 mock JDBC 结果集检查字段转换；用 mock mapper 的返回状态和影响行数覆盖重放、批次冲突、终态先后顺序、删除拒绝及过期恢复编排。不连接
  PostgreSQL/ParadeDB 或 H2，不执行 SQL、迁移、数据库并发、锁或回滚测试。
- 配额协作：mock 主体、Redis、审计及意图存储的返回值和异常，覆盖固定关联身份、UNKNOWN/NOT_INVOKED、部门变化、重试期限与拒绝分支；不启动
  Redis 或执行 Lua。Lua 与数据库约束交付后人工审查，不能以 mock 结果宣称已验证真实原子性。
- 流式与内部客户端：用 Reactor 虚拟时间、确定性适配器、mock ExchangeFunction 和客户端协作验证单次订阅、取消传播、批次缓冲、请求签名与错误处理；不监听端口、发送真实
  HTTP 请求、运行多服务联调或调用外部模型。
- 模块与兼容：使用明确的进程内测试白名单保护既有单轮、引用、日志保密、请求内权限复用及 kb-ai 无数据库能力，结合编译、打包和
  OpenSpec 结构校验。白名单不包含已有真实数据库烟测或集成测试。
- 文档交付：说明、使用示例和运维文档仅人工核对，不创建针对
  README、Markdown、注释、示例或源码/SQL/XML/配置文件文字的断言测试。接口序列化和实际控制器行为仍由功能单元测试验证。

本变更不安排集成环境、第三方组件运行任务或真实效果验收。证据只覆盖被执行的离线行为；真实迁移、数据库约束、事务并发、Redis
脚本、供应商语义质量及多服务链路保持未验证状态，不能作为本次任务的隐含完成门槛，也不能标记为已验证。

## Risks / Trade-offs

- [来源依赖随多轮增加] -> 按实际输入继承，限制历史对数和来源数量；超限整对排除，不能削减依赖后保留正文。
- [保守整条屏蔽损失部分仍可看的内容] -> 接受该取舍，恢复权限后可重新展示；不承诺模型逐句归因。
- [权限在生成期间变化] -> 每次新历史请求和上下文准备重新鉴权；沿用既有请求处理边界，不声称收回已开始响应，下一次历史读取必按新事实屏蔽。
- [部分输出的最后一批未保存] -> 明确只恢复已保存前缀；小批缓冲、有界关闭、持久过期恢复防止伪完成。
- [生成与账本无法跨 PG/Redis 原子提交] -> 正文终态与固定意图同事务，账本脚本幂等，独立结算状态及安全重试窗口，不用错误状态掩盖真实已完成回答。
- [未知费用保守结算可能高于实际消耗] -> usage 与 chargedTokens 分开展示；真实供应商具备可靠尾部统计后减少未知情况，不编造真实
  token 数。
- [用户自己输入可能包含复制的受限内容] -> 按私人原始输入处理，明确权限屏蔽针对系统派生回答，不承诺语义擦除用户文本。
- [真实模型仍未接入] -> 新入口拒绝不具多轮/预算能力的适配器，先用确定性实现验证协议，供应商上线验证独立进行。
- [本次只有离线验证证据] -> 明确记录真实迁移、锁、回滚、Lua 原子性和多服务效果未验证，保留功能契约，不把 mock 编排通过解释为真实环境可用。

## Migration Plan

以下仅说明生产部署依赖和兼容顺序，不属于本变更 tasks.md 的组件运行或验收任务，本次不执行部署、真实迁移或运行演练。

1. 实施前核对迁移最高版本，新增独立迁移及约束；由 kb-app 执行，Worker 不参与。
2. 保持多轮功能关闭，先部署 app 的存储、内部授权、恢复和结算投递能力；生产环境配置内部密钥与网络/TLS，迁移仍由 kb-app 负责。
3. 部署支持新契约的 AI 与网关公开会话路由，配置匹配签名密钥、预算和支持多轮的适配器；新功能配置缺失时明确拒绝开启，旧单轮仍可用。
4. 新入口受显式开关控制；本次离线证据不能替代真实运行效果，不把启动生产服务或运行演练加入开发任务完成条件。
5. 回滚先关闭新接受，取消或排空已接受生成并完成已持久化结算意图；保留新表和最小墓碑，禁止把旧单轮服务用于恢复新轮次或直接删除账本意图。数据读取与执行能力升级完成前不重新开启。
