# Spec Delta

## Purpose

在现有管理端提供空间分类树和全局标签字典的维护交互，使不同管理资格、分层分页、并发版本及不确定写入结果都能被明确呈现，并让用户在同一会话生命周期内完成目录整理。

## ADDED Requirements

### Requirement: 分类管理必须位于目标空间上下文

空间详情 /admin/spaces/:spaceId SHALL 提供分类管理区块，只有当前空间管理资格确认后才能读取完整管理目录和执行写入。区块展示名称、层级、排序、treeVersion 及加载/失败状态；归档空间呈现只读目录。空间身份变化、管理资格拒绝或页面恢复时必须重新读取当前事实。

#### Scenario: 普通空间读者打开管理详情
- **WHEN** 用户可以阅读空间文档但无空间管理资格
- **THEN** 分类管理区块不读取管理目录或提供目录写入，不从阅读资格推断管理资格

#### Scenario: 归档空间目录
- **WHEN** 管理者打开已归档空间
- **THEN** 可读取分类树并看到只读状态，创建、改名、移动、排序及删除不可提交

### Requirement: 分类树必须按需分层加载

分类树 SHALL 按服务端同级分页逐层加载，显示继续加载、空分支和读取失败，不将失败当作叶节点。一次目录操作后重新取得 treeVersion；续页返回树变化冲突时废弃对应旧目录并重新加载。父节点选择只采用服务返回的合法分类身份，不手填 ID 或拼接跨空间节点。

#### Scenario: 子节点读取失败
- **WHEN** 展开分类时子节点请求失败
- **THEN** 显示失败及重读入口，不显示“无子分类”或据此允许删除

#### Scenario: 分页过程中其他人调整树
- **WHEN** 继续加载返回 treeVersion 冲突
- **THEN** 提示目录已变化并重新读取，不将新旧页面继续拼接

### Requirement: 分类维护必须使用明确目标和版本

页面 SHALL 提供根/子分类创建、改名、同空间移动、排序和删除，提交规范化字段、expectedTreeVersion 及请求标识。根位置明确使用 null。客户端可预先排除自身及已知后代，但服务端决定合法性；引用冲突、重名、深度或版本冲突必须显示固定类别并提供重读，不自动改成其他目标或重试。

#### Scenario: 删除存在引用
- **WHEN** 服务端拒绝删除仍有子节点或文档引用的分类
- **THEN** 页面保留分类，说明需要先处理引用，不显示被引用文档名称或猜测数量

#### Scenario: 基于旧目录提交
- **WHEN** 用户确认时目录版本已被他人更新
- **THEN** 提示冲突并重新加载，下一次主动提交基于新事实使用新请求标识

### Requirement: 全局标签管理必须有独立入口及权限

管理端 SHALL 提供 /admin/document-tags，导航、直接访问和刷新均要求当前 document:tag:read；创建、改名及启停另需 document:tag:write。页面呈现名称、启用状态和版本，支持名称字面筛选、状态过滤及有界续页。缺少写资格时可按读取资格浏览，不能创建或更新词条。

#### Scenario: 只持标签读取资格
- **WHEN** 用户有 document:tag:read 但没有 document:tag:write
- **THEN** 标签列表可用，维护动作禁用或隐藏，空间 manage 不能补足写资格

#### Scenario: 只持写资格
- **WHEN** 用户有标签写资格但没有读取资格
- **THEN** 页面和导航不开放，不能通过进入页面自动取得管理目录

### Requirement: 标签维护必须准确呈现停用含义

页面 SHALL 提供新建、改名、停用及重新启用，已存在标签使用当前 expectedVersion。停用确认应说明已有文档关联保留、新关联不可建立；成功以服务端回执为准并重新读取词条。编辑界面不提供直接删除标签身份、改写 tagId 或查看关联文档清单的能力。

#### Scenario: 停用成功
- **WHEN** 管理者停用标签并得到合法成功响应
- **THEN** 词条显示停用并刷新版本，页面不声称已经从所有文档移除该标签

#### Scenario: 标签重名或版本冲突
- **WHEN** 创建或改名返回重名冲突，或更新返回版本冲突
- **THEN** 分别提示名称已占用或资料已变化，不将两者统一当作保存成功

### Requirement: 管理写入必须保留固定意图和不确定结果

分类及标签写入 SHALL 在提交期间互斥，绑定规范化载荷、目标、版本和请求标识。网络结果不确定时保留原意图供用户匹配重试或只读核对，不自动重发；读取当前状态不冒充原请求回执。改变载荷、版本或目标必须创建新意图，重复确认不能产生第二次写入。

#### Scenario: 创建标签响应丢失
- **WHEN** 标签创建已发出但响应丢失，用户选择匹配重试
- **THEN** 重用原请求标识和规范化名称，按服务器首次回执处理，不换标识重复创建

### Requirement: 目录页面状态必须隔离身份和迟到响应

管理页面 SHALL 保持 ID 与版本精确，名称作为安全文本展示，筛选和目录只保存在当前页面内存。退出、强制改密、切换身份/空间、页面隐藏或离开使旧读取和写入回调失效；恢复先核对当前身份及资格，再读取目录，不自动恢复旧确认或提交。

#### Scenario: 切换空间后旧响应返回
- **WHEN** A 空间的目录或保存响应在页面进入 B 空间后到达
- **THEN** 不填充 B 的分类树、版本或成功提示，也不触发 B 页面跳转

#### Scenario: 大整数与恶意名称
- **WHEN** 分类或标签 ID 超出 JavaScript 安全整数范围，名称包含 HTML 标记
- **THEN** 请求保留精确身份，名称按文本展示，不执行标记或写入浏览器持久存储
