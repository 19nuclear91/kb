# Proposal

## Why

现有文档中心只能按空间分页，标题仅在上传时设置；文档逐渐增多后，缺少持续整理资料和组合条件定位文档的完整入口。增加空间分类树、统一标签和即时生效的文档元数据编辑，使现有文档管理形成可维护、可筛选的组织体系。

## What Changes

- 增加文档级标题、人工摘要、单分类和多标签编辑，使用独立 `metadataVersion`、当前 `view + edit`、请求绑定与同事务审计；即使空间采用文件版本审核，元数据保存后也立即生效。
- 每个空间独立维护分类树，由当前空间管理员维护；每篇文档至多属于本空间的一个分类，允许未分类。
- 建立全局标签字典，由具有独立功能权限的人员统一维护；文档编辑者选用已有标签，多选标签筛选采用全部匹配。
- 文档中心提供标题字面匹配、空间、分类及后代、未分类、标签、当前发布版本文件类型和更新时间范围组合筛选，继续采用当前文档可见性与候选版本隔离规则。
- 增加空间分类管理、全局标签管理、文档详情编辑和文档中心筛选交互；元数据写入参与既有详情页删除协调。
- **BREAKING**：文档搬迁使用严格新协议，必须显式提交目标分类（`null` 表示未分类）及元数据并发版本；缺少字段的旧请求返回 400，前后端同步升级。搬迁在同一事务切换空间与分类、推进 `metadataVersion`，并保留全局标签。
- 扩展功能权限目录、资源能力和安全审计投影，提供管理者无需正文读取资格即可取得的最小搬迁上下文。

## Capabilities

### New Capabilities

- `document-metadata`：文档级元数据读取、即时编辑、严格幂等、并发版本和授权组合筛选。
- `document-categories`：空间内分类树维护、层级与引用完整性、管理和使用候选的上下文范围。
- `document-tags`：全局标签字典治理、文档关联、停用语义和全部匹配筛选。
- `admin-web-document-taxonomy`：空间分类管理与全局标签管理页面的权限、交互和请求生命周期。

### Modified Capabilities

- `user-web-documents`：文档中心组合筛选、元数据展示与编辑，以及与删除、版本选择和会话生命周期的协调。
- `user-resource-capabilities`：在当前可查看父文档的能力响应中增加独立 `canEditMetadata`。
- `document-relocation`：最小搬迁上下文、显式目标分类、元数据版本前置条件、严格请求重放及原子分类切换。
- `admin-web-documents`：搬迁时取得最新上下文并显式选择目标分类或未分类，处理新冲突和旧协议不兼容。
- `functional-authorization`：增加独立标签目录管理读写权限及一次性初始化规则。
- `audit-query`：增加分类、标签、元数据和新版搬迁事件的安全摘要投影。
- `admin-web-audits`：消费有界标签 ID 集合和固定字段集合，保留大整数、显式空值及历史未知值。

## Impact

- `kb-app`：文档查询与写入、空间管理和搬迁、权限目录、审计投影、MyBatis SQL 及正式增量迁移；当前迁移至 V26，新迁移承接现有历史。
- `kb-common`：文档搬迁回执等共享契约；`kb-web`：文档中心与详情、空间详情、管理导航、标签页面、搬迁弹窗及 API 类型。
- `kb-gateway`：新端点的提前拒绝缓存策略与既有路由契约回归。
- 新增元数据、分类、标签与筛选接口；扩展文档摘要和能力响应，严格升级 `PATCH /api/admin/documents/{id}/space`。
- 持久层增加分类树、全局标签及文档关联、元数据版本和有界命令回执；使用现有 PostgreSQL、认证和角色权限基础。
- 迁移脚本与发布说明交付旧搬迁客户端拒绝、未知权限目录兼容、历史文档默认未分类及后续撤权不被重启恢复的设计；本次不执行迁移或部署。
- 验证限定为明确白名单的纯内存单元/组件测试、编译、类型检查和静态打包，覆盖输入、树结构、权限分支、请求绑定、投影及前端生命周期；数据库实现作静态代码审查，不宣称已验证真实 SQL、约束、隔离、回滚或并发。
- 不编写或执行集成、端到端、外部组件及嵌入式数据库/缓存测试；README、Markdown、说明文案、注释和示例只作交付，不进行内容断言测试或执行示例。OpenSpec 结构校验单独执行。
