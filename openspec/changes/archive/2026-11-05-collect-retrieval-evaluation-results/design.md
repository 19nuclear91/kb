# Design

## Context

动机与范围见 `proposal.md`。本设计基于以下现有行为：

- `SearchController` 仅接受 `POST /api/search`，从 Sa-Token 取得用户身份；成功为 `R` 包装的有序分块数组。组合筛选成功响应包含 `X-Search-Filter-Version: 1`。
- `SearchService` 可以跳过向量或回退重排前顺序，降级事实仅进入受控观测，不在成功数组中声明。`ChunkHit.score` 不是可据以重建最终排名的统一算法分数。
- `GET /api/auth/me` 返回服务端确认的内部用户及强制改密状态，可核对令牌是否属于预期用户；它没有覆盖空间 ACL、部门树及语料的整体版本号。
- `kb-eval` 的 `InputReader` 要求数据集、标注摘要和场景完整匹配；运行清单拒绝额外字段，结果三元组必须是精确正整数，`ERROR` 会使整个评测拒绝。现有 CLI 不接触网络。

新增采集器涉及凭据、网络限界及两个工具的文件兼容，需要独立设计。前述源文件及 `docs/retrieval-evaluation.md`、`docs/search-filtering-api.md` 是实现时的接入依据。

## Goals / Non-Goals

**Goals:**

- 让一个完整批次的真实最终响应直接成为现有评测输入，并可核对该批次使用的用例、身份绑定和数量参数。
- 在发送任何网络请求前发现可本地判定的输入错误；任何失败都不发布可误用的部分运行。
- 保持采集行为有界且可测试，查询、正文和凭据不进入输出或诊断。

**Non-Goals:**

- 不读取数据库、不修改搜索后端，不提供算法分支切换、阶段采样、自动登录、并发压测、断点续采或自动重试。
- 不自动冻结语料或权限，不把 `/me` 核对等同于完整 ACL 快照验证，不执行模型答案质量评测。
- 不改变现有 `kb-eval` 的文件 schema、指标、退出码或离线运行边界。

## Decisions

### 1. 独立模块，以文件协议连接现有评测器

新增 `kb-eval-collector`，纳入根 Maven reactor，采用 Java 21、JDK HTTP 客户端及 Jackson，生成独立可运行 JAR。运行时不依赖 `kb-app`、`kb-ai`、`kb-worker`、Spring 或数据库客户端。

采集器有界解析现有 v1 数据集、标注及新增配置，只实现采集所需的校验和转换；标注校验遵循现有等级、身份、重复项及空结果规则。使用测试范围的 `kb-eval` 依赖，以现有 `InputReader` 验证成功产物和共享输入语义，避免复制指标或让离线工具引入网络依赖。无需为本次新增工具拆分公共模块。

建议职责分为 CLI、输入与身份绑定、HTTP 传输、响应转换、批次编排和输出发布。HTTP 传输、令牌来源、单调时钟和输出发布分别可替换，便于故障与边界测试。

考虑过给 `kb-eval` 增加在线模式；其既有规格明确要求完全离线，独立可执行包可以直接保持该边界。也考虑过 PowerShell 脚本；统一 Java 工具更便于严格 JSON、64 位整数及跨平台打包验证。

### 2. 固定四个必需 CLI 参数，配置与用例分离

CLI 使用 `--dataset <dataset.json> --cases <cases.jsonl> --config <collection-config.json> --output <新目录>`，另支持 `--help`。其他参数、重复参数或缺失值拒绝；帮助不读文件、不发请求、不写目录。

- `dataset.json`、标签格式和相对路径规则沿用现有 v1 契约；标签中的非必要顶层附加内容按既有语义忽略，不进入任何输出。
- `cases.jsonl` 每行只接受 `caseId`、`identity`、`request`。`request` 包含 `query` 和现有搜索筛选字段，数量由运行配置统一注入，不接受用户、角色、向量或算法模式声明。
- 用例 ID 必须与标注完整一一对应。相同查询在不同身份或筛选下使用不同 `caseId`；输入顺序即采集及结果写出顺序，不按返回 score 重排。
- 配置接受 `schemaVersion=1`、`runId`、`configurationId`、`endpointId`、`baseUrl`、`identities`、数量与网络限制。三个逻辑标识沿用评测标识的字符规则；配置、用例和请求拒绝未知或重复字段，时间及 ID 精度遵守现有搜索契约。

合成用例形态：

```json
{"caseId":"q001-staff","identity":"staff","request":{"query":"示例问题","fileType":"PDF"}}
```

配置中的身份绑定形态：

```json
{"staff":{"tokenEnv":"KB_EVAL_TOKEN_STAFF","expectedUserId":7}}
```

`tokenEnv` 仅为环境变量名，禁止直接配置令牌值。`expectedUserId` 是精确的 1 至 Long.MAX_VALUE 整数，仅供本地比对，不转发给搜索接口。

默认 `candidates=50`、`topK=20`，各为 1–200；保留 API 允许 topK 大于 candidates 的行为，并记录实际参数。评测者需要选择与请求返回上限相符的 k，不因为返回少于 k 就将合法成功改为错误。

本地文件只读。配置及数据集清单各限 1 MiB，用例和标注各限 32 MiB，JSONL 单行限 128 KiB，每批最多 10,000 个场景，JSON 最大深度 32。全部输入、格式、配对、身份引用和输出路径在网络前校验；按有界字节副本冻结输入，摘要与后续执行使用同一份内容，文件被外部修改不会拼接成混合批次。

这些首版限界为实现默认值，不是在线服务容量承诺。输入文件不接受 URI、UNC 网络共享或通配扫描，输出位置不覆盖输入或既有目录。

### 3. 一个批次使用一个受控端点，逐身份预检

`baseUrl` 是服务根地址，保留合法路径前缀并追加固定 `/api/auth/me`、`/api/search`。拒绝用户信息、query、fragment 和路径回退。默认要求 HTTPS；仅当 `allowHttpLoopback=true` 时允许 host 精确为 `localhost`、`127.0.0.1` 或 `[::1]` 的 HTTP，用于本地受控部署。不允许用此开关访问任意 HTTP 主机；该运行能力不要求本次开发验证启动本地服务。

批次开始时读取所有被用例引用的环境变量并冻结令牌，缺失或空白直接失败。所有引用身份在首次搜索前依次通过 `/me` 检查：HTTP 200、code=200、用户 ID 匹配、用户启用、`mustChangePassword=false`。每个请求仅带对应身份的 `satoken`，不发送身份声明、不混用账号，也不负责注销既有会话。未引用的身份配置不触发网络调用。

随后按输入顺序逐条搜索。每次搜索由服务端重新鉴权；采集器的预检只排除接错账号等错误，不缓存授权结果。会话中途失效按请求失败处理。

考虑过直接接受一个全局 token；身份别名可支持同一批次的权限场景，且显式预期用户能防止错把管理员结果记入普通员工样本。也考虑过自动密码登录，但这会扩大凭据和账号生命周期范围。

### 4. 请求有绝对期限，首版只允许串行且不重试

`connectTimeoutMs` 默认 5,000，范围 1–60,000；`requestTimeoutMs` 默认 15,000，范围 1–300,000，且不小于连接超时；`maxResponseBytes` 默认 4 MiB，范围 1 byte–64 MiB。限制覆盖身份与搜索请求。

整次期限从发送前开始，覆盖连接、响应头、实际正文读取与解析。不能只设置响应头等待时间后无限读取 body；采用可取消、逐块计数的响应消费，并在解析期间核对同一截止时间。拒绝不支持的内容编码；正常请求只接受 UTF-8 JSON，正文没有 Content-Length 时仍按实际字节限制。

每个请求最多发送一次；禁止自动重定向、认证挑战重放、失败重试、身份切换或取消筛选后重查。429/503 的 Retry-After 只作为拒绝事实，不安排自动等待重发。中断或超时取消本地请求、关闭响应并停止后续用例，不宣称服务端或供应商工作立即停止。

搜索请求编码后最多 128 KiB，query 最多 8,000 个 Unicode code point，保留原文且拒绝非法 Unicode/NUL。实际后端若配置更小上限，以其拒绝结果终止批次。

`latencyMs` 用单调时钟测量，从搜索发送前至整个合法响应读取和验证结束，不包含 `/me`、输入加载、输出写盘或评测计算。它是客户端观测耗时，不能作为数据库阶段耗时或吞吐指标。

### 5. 严格接受整条响应，完整保留排名

成功必须同时满足 HTTP 200、合法 JSON 成功包装 code=200 和数组 data。拒绝重复 JSON 属性、尾随内容、空 HTTP 正文、204、null data 或错误包装；message 和远程错误体不进入诊断。

对带有效筛选的请求，要求 `X-Search-Filter-Version` 仅有一个值且精确为 `1`；缺失、冲突或未知版本失败，不撤掉条件重新请求。无筛选请求沿用旧接口兼容行为，不强制版本头。

逐项读取 `docId`、`versionId`、`chunkId`：必须是精确的正整数且不超过 Long.MAX_VALUE，拒绝字符串、小数、null、缺失和溢出。一个坏项使本次采集失败，不能过滤后继续。完整三元组重复视为损坏；同文档版本下不同分块正常保留。标题、正文和 score 等非必要字段有界跳过，不保存为领域结果。

结果顺序就是最终排名，不按 score 排序、不将版本合并、不补齐缺失版本。HTTP 200 且 data=[] 是正常空结果，与权限不可见或无匹配的内部原因保持同一边界。

### 6. 兼容输出与可核对的元数据分别存放

完整成功批次在一个新目录中发布：

| 文件 | 内容 |
| --- | --- |
| `run.json` | 只使用既有 v1 字段：schemaVersion、runId、datasetId、datasetVersion、corpusSnapshotId、configurationId、sourceType、labelsSha256、resultsFile；sourceType 固定 RECORDED，resultsFile 固定 results.jsonl |
| `results.jsonl` | 每个 caseId 一条 status=OK、完整有序三元组数组和 latencyMs，恰好覆盖所有标注 |
| `collection.json` | 独立 schemaVersion=1；记录运行/端点逻辑标识、工具版本、开始结束 UTC 时间、数量/时间/大小设置、场景数、身份别名及核对结果、文件摘要和观测边界 |

`collection.json` 至少记录 dataset、labels、cases、results 的实际 SHA-256，以及不含令牌的场景绑定摘要。绑定摘要按 caseId 排序，对每条的 caseId、规范化后的完整请求（含原 query）及 expectedUserId 编码后计算；对象键按字典序，数组保持顺序，字符串按 UTF-8 JSON 编码，ID 保持十进制整数。摘要不包含环境变量名、令牌、端点或运行标识，因此换 token 不改变场景含义；查询、筛选或预期用户变化会改变摘要。数量设置作为比较配置单独记录。

元数据标记 `resultSemantics=FINAL_RESPONSE`、`degradationStatus=UNOBSERVED`、`snapshotVerification=DECLARED_ONLY`。`configurationId` 和 `corpusSnapshotId` 是操作者声明，工具不把它们当作后端执行或冻结证明；开始结束时间也不能证明中间没有 ACL 变更。只输出端点逻辑别名，不输出 base URL、用户名、部门、角色、查询、筛选明文、令牌或原始响应。

输出保留原运行清单的精确字段集合；不把新增元数据塞进 `run.json`，也不要求修改评测器读取逻辑。评测器不会自动读取旁路元数据，因此跨运行的场景摘要和环境一致性需在比较前核对，不宣称工具已自动阻止全部不公平比较。

### 7. 失败停止与完整发布

网络前拒绝已有输出目标。实际输出先写同父目录中本次独有的暂存目录，三个文件写入完整且内部一致后发布为新目标；发布时再次检查竞争创建，采用不覆盖目标的移动方式。不能仅写出 run.json 就认为批次完成。

首个身份、传输或响应错误立即停止；不续采、不恢复旧部分结果、不发布目标目录。清理仅限本次创建的暂存目录，必须验证其父目录与固定命名前缀；不能清理已有目标、输入或其他批次。中断、权限不足或崩溃若留下暂存目录，不得把它当作完成结果，后续运行不自动恢复或覆盖。

采集器独立退出语义：0 为完整成功；2 为参数、输入、配置、输出或本地处理失败；3 为身份校验、HTTP、超时或响应协议失败。stdout 成功仅输出 `COLLECT_COMPLETE`；错误使用 `COLLECT_ERROR <固定类别> role=<安全别名> line=<行号> field=<固定字段>`，不回显值、绝对路径、环境变量内容、远程 message 或异常 cause。收尾错误可使退出类别变为本地输出错误，但不得掩盖失败为成功。

考虑过保留部分成功并用 status=ERROR 补齐；现有评测器会拒绝该运行，而部分产物更容易被误用。首版选择失败即停止、重跑使用新目录，接受重复采集成本。

### 8. 验证限定为进程内测试与构建检查

- 输入与配置测试覆盖重复/未知字段、标签配对、身份引用、冻结字节摘要、非法 Unicode、64 位精度、文件/行/场景限界和网络前零调用。
- 使用进程内传输接口、响应流替身及可控时钟，覆盖 `/me`、POST 请求构造、凭据隔离、筛选头、200 失败包装、合法空数组、损坏命中、重定向拒绝、429、慢响应正文、无长度超限、中断、无重试与 fail-fast；测试不监听端口、不建立网络连接。
- 输出与兼容测试将生成文件交给未修改的 `kb-eval.InputReader`，核对样本覆盖、顺序、Long.MAX_VALUE、摘要及数据集身份；用缺少一个用例或损坏一条命中证明失败不能发布运行。
- 不安排启动前端、业务应用、本地 HTTP 服务、数据库、Redis、MinIO、Docker 或其他第三方组件的集成测试，也不运行真实采集。
- 按明确的进程内单元/组件测试类白名单执行 Maven `test`，使用跳过测试的 `package` 检查独立 JAR，并仅执行无需服务的 `--help` 进程烟测；不使用未限定范围的 `verify` 带入集成测试。
- 替身测试仅证明已覆盖的本地编排、转换及边界处理，不能证明真实网络、客户端底层行为、部署兼容性或模型效果；实际服务验收不作为本变更的编码完成任务。
- 不为 README、Markdown、注释或文档措辞编写内容断言测试。

## Risks / Trade-offs

- [采集期间语料、发布版本或 ACL 变化] -> 使用受控评测环境固定这些条件，元数据保留时间、场景摘要和声明边界；不增加跨请求事务或权限快照协议。
- [可选检索阶段降级不可从响应识别] -> 输出明确为最终交付结果，降级状态保持 UNOBSERVED；算法阶段对比留给独立后续变更。
- [多个部署的相同逻辑配置名称不代表相同实际配置] -> configurationId 由运行方版本化管理，元数据记录工具请求设置，不声称已核验远程模型或索引配置。
- [令牌失效或一条失败导致重采] -> 首版 fail-fast，终止后不继续消耗调用；运维为批次提供足够有效期的会话，重新运行显式使用新目录。
- [输入校验与评测器可能漂移] -> 使用既有读取器做契约测试，并覆盖其允许的附加标签字段与严格运行清单；避免改动现有 schema。
- [耗时受网络、连接复用与服务状态影响] -> 只报告客户端观测耗时，串行采集不承担压测或阶段性能结论。
- [未执行真实 HTTP 或外部组件集成测试] -> 保留可替换传输与时钟的进程内测试，交付记录明确网络和部署行为尚未验证，不将替身结果宣称为端到端验收。
- [最终结果 ID 仍是受控业务信息] -> 仅保留评测必需字段，交付目录按评测环境的访问规则管理，不记录正文或凭据。

## Migration Plan

1. 实现并注册新模块，完成进程内组件、传输替身、文件兼容测试与独立打包；既有服务不需要发布或迁移。
2. 交付不含真实账号、令牌或业务正文的合成配置和 PowerShell 用法；配置完整后由运行方显式启动采集。
3. 运行方实际使用时，对固定语料和权限条件分别采集 baseline 与 candidate，核对元数据后将两个 run.json 交给现有 kb-eval 比较及质量门禁；这是使用说明，不是本次开发验证任务。
4. 回退只需停止使用新 CLI 或回退新增模块；不修改业务数据、既有服务配置或现有评测输入。已生成目录保持只读留存，不自动删除。
