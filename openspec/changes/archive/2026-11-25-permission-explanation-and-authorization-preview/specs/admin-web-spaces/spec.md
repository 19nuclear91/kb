# Spec Delta

## ADDED Requirements

### Requirement: 空间诊断区块必须同时受功能与资源资格控制

空间详情 SHALL 仅在当前 authorization:diagnose 及该空间 manageable 均确认后显示权限诊断入口并加载最小用户候选。只显示已选择用户的授权来源与条件，不创建全局人员权限清单。可从最小用户候选或当前空间 USER 授权行选择目标，不通过手填内部用户 ID 或全量身份目录补全。没有诊断资格时，原授权列表和写操作继续按原规则可用。

#### Scenario: 普通空间管理员获得诊断资格
- **WHEN** 用户可管理该空间且有 authorization:diagnose，但没有身份目录读取资格
- **THEN** 可选择最小用户候选并主动诊断，不请求完整身份、角色或部门目录

#### Scenario: 资格尚未确认
- **WHEN** 功能权限或资源管理资格仍在加载或读取失败
- **THEN** 不发送诊断、预演及其候选请求，不借旧资格显示来源

#### Scenario: 从已有用户授权发起
- **WHEN** 管理者点击当前 USER 授权行的诊断入口
- **THEN** 使用该行用户标识重新请求诊断，显示当前事实，不把旧授权名称或行存在当成有效身份

### Requirement: 空间诊断必须区分授权来源与资源条件

空间区块 SHALL 分别展示 view、download、edit、review、comment、manage 的授权命中、来源和空间条件。归档时保留来源但提示资源访问暂停，manage 单独显示。只选空间时不显示文档可读总数或全空间访问承诺；主动选择同空间一份可管理文档后，才展示该文档的授权及当前发布版本访问层，并按服务端声明范围解释结果。

#### Scenario: 多条来源共同生效
- **WHEN** 用户同时经个人和祖先部门获得 view
- **THEN** 展示两条本资源授权来源，不把其中一条当作唯一原因

#### Scenario: 归档空间管理
- **WHEN** 已归档空间中的诊断成功
- **THEN** 展示归档阻断及 manage 结果，不提示取消归档或授权已实际发生

#### Scenario: 选择不可阅读的文档
- **WHEN** 管理者可管理文档但不能阅读其标题
- **THEN** 文档选择及诊断按 ID 展示，不为补充标题枚举文档详情；版本信息使用受控条件结果

### Requirement: 空间授权预演必须绑定既有表单的完整草稿

单条和批量空间授权表单 SHALL 为有诊断资格者提供可选“预演影响”，要求明确选择一个目标用户。授予按表单全部主体与权限位，撤销按显式选中条目提交一次只读预演；单条操作可映射为单项意图。用户、空间、观察文档、动作或任一草稿字段变化后旧结果立即失效。含 manage 的草稿在缺少 space:grant-manage 时不得预演。

#### Scenario: 修改预演后的草稿
- **WHEN** 完成预演后改变权限位、主体或待撤销条目
- **THEN** 清除可用的旧前后结果，标明需重新预演，不把旧结果附在新确认摘要下

#### Scenario: 切换诊断用户
- **WHEN** 对用户 A 的预演仍在途，用户改选 B
- **THEN** A 的请求被本地取消且迟到响应被丢弃，B 仅在主动预演后显示自己的结果

#### Scenario: 批次影响未展开
- **WHEN** 草稿包含部门或角色授权
- **THEN** 页面明确本次仅评估所选用户，不把条目数量或结果变化解释为影响人数

### Requirement: 预演结果必须展示前后差异及仍有效的来源

页面 SHALL 分别展示拟议条目变化、所选用户的授权前后变化和可评估的访问变化，并展示 evaluatedAt 及仅代表本次读取的说明。重复授予和不存在的撤销标为无变化。身份阻断、密级阻断、无当前发布版本、故障和未评估须分别呈现，不以红绿布尔值代替全部状态。

#### Scenario: 撤销仍可访问
- **WHEN** 撤销个人 view 后仍命中部门 view
- **THEN** 展示直接来源拟移除、部门来源保留和访问结果不变，不提示权限已收回

#### Scenario: 新授权仍受密级阻断
- **WHEN** 对选定文档预演增加 view，服务端报告授权命中变化而访问仍被密级阻断
- **THEN** 分别说明这两层变化，不显示用户已可阅读，也不提供密级调整捷径

#### Scenario: 目标账号条件未通过
- **WHEN** 诊断返回通用身份阻断
- **THEN** 只显示账号当前不满足访问条件，其他未评估项不显示为无授权或密级不足

### Requirement: 可选预演必须与实际授权写入相互独立

页面 MUST 允许具备既有写资格的用户在未预演、预演不可用或无诊断资格时，按原确认流程主动提交。预演不能提交授权、自动采用其他草稿或解除未知写入绑定。正式写入在途或结果待核对时，按原流程恢复，不通过新预演推断旧写入是否成功；开始正式提交或确认写入结果后清理旧预演。

#### Scenario: 无预演仍能提交
- **WHEN** 管理者未选择诊断用户便确认合法批量授予
- **THEN** 仍只调用原批量写接口，不要求先生成预演结果

#### Scenario: 预演返回不支持或故障
- **WHEN** 新端点返回 404／405、503 或无法确认完整契约
- **THEN** 区块显示不可用，不自动改调旧能力接口或提交授权，原写资格有效时仍可主动走原流程

#### Scenario: 结果待核对时再次查看
- **WHEN** 正式授权响应未知，用户关闭后重新打开表单
- **THEN** 恢复原写入请求标识及精确载荷，禁用新的预演意图，不能用当前诊断结果结清原请求

### Requirement: 空间诊断的私有状态必须随上下文失效

目标选择、搜索词、授权草稿副本和诊断结果 SHALL 仅保存在当前身份的内存。隐藏、离页、换号、强制改密、诊断资格失效或资源不可管理时清理诊断状态并作废所有在途回调；恢复先重新核对身份和资源，诊断需主动重发。诊断清理 MUST NOT 错误清除同一身份下原授权流程仍待核对的写入绑定。

#### Scenario: 失去诊断资格但仍可授权
- **WHEN** 诊断请求返回 403，重核后仅 authorization:diagnose 被撤销
- **THEN** 清除诊断用户、候选和结果，保留按原资格可用的授权功能及未决写入核对

#### Scenario: 失去资源管理资格
- **WHEN** 诊断返回 404 且资源管理重核失败
- **THEN** 按既有空间详情规则清除整个资源私有数据，迟到成功不能恢复旧来源

#### Scenario: 页面恢复与持久化
- **WHEN** 页面隐藏后恢复或浏览器刷新
- **THEN** 不从 URL、localStorage、sessionStorage 或 IndexedDB 恢复诊断载荷，不自动重新预演或重放写入
