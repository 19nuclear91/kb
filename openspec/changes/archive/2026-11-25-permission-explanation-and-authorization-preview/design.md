# Design

## Context

动机及确认范围见 [proposal.md](proposal.md)。本变更涉及跨层权限解释、私有投影和新权限迁移，满足生成设计产物的条件。

当前代码提供以下基础：

- `PermissionService` 在一次调用栈内从可信用户解析用户／角色／祖先部门主体和精确功能权限；句柄不能伪造或跨请求保存。现有生产入口的 userId 代表真实调用者，不能直接把请求体目标当作登录身份传进去。
- `PermissionMapper.findVisibleSpaceIds` 根据权限位查空间 ACL，除 manage 外排除归档空间。`DocumentMapper.xml` 的 `documentAccessPredicate`、`currentViewGrant`、`versionInteractivePredicate` 负责文档例外、当前 view 及具体版本门禁；SQL 和 `VersionAccessRules` 有需要保持一致的规则。
- `DocumentCapabilitiesService` 只提供当前用户、先 view 后 download/edit 的最小能力。它故意把不可见与不存在合并，不能为管理员诊断他人复用为外部接口。
- `PrincipalQueryService` 和 `IdentityQueryMapper.principals` 已有资源上下文最小候选，但用户候选过滤停用账号与无效主部门。`DocumentAdminQueryService` 只提供管理范围内的文档 ID、空间 ID 和归档状态，不返回内容或版本。
- `SpaceAclService` 已支持 50 主体 × 6 权限位批量授予、300 显式条目撤销；`DocumentAclService` 仍是单主体单权限位。原写接口对 manage 的资格分支与本次诊断要求不完全相同，本变更不修改原写资格。
- `AclPanelContent.vue`、空间详情及文档管理面板已处理确认、未知写入、父级绑定及生命周期；新增只读状态须与这些写入绑定分开。

规格边界见本变更的四份 delta：新增 `authorization-diagnostics`，以及 `functional-authorization`、`admin-web-spaces`、`admin-web-documents` 的附加要求。既有授权、资源能力和文档审核规格是被复用的行为基线，不在此改变。

## Goals / Non-Goals

**Goals:**

- 用同源规则返回来源证据和判定，两次解释的不同及一次预演的 before/after 都有明确的事实范围。
- 在单资源、单用户下有界读取与计算，不展开角色／部门成员或枚举所有受影响文档。
- 将服务器内部判定事实、可披露诊断投影、普通用户执行资格分离，复用不等于开放原始数据。
- 预演对业务只读，前端可选接入，发布时保持已有授权交互可用。

**Non-Goals:**

- 任何历史／待审版本、具体审核轮次、自审判定、评论可执行性、解析任务可重试性或文件实际可用性检查。
- 模拟用户启停、角色绑定、部门树、密级、空间归档、文档搬迁或发布指针；合并空间和文档改动为新的原子写命令。
- AI 解释、自动修复授权、全库影响报表、永久诊断历史、预演票据或强制预演门禁。
- 实施只交付本地代码、迁移文件、独立离线测试和说明，不同步主规格或部署。

## Decisions

### D1. 一项功能资格与当前资源管理资格共同准入

新权限定为 `authorization:diagnose`，诊断目标搜索、解释和预演共用。准入顺序固定为真实操作者会话／认证门禁 → 精确诊断权限 → 路径资源当前管理资格 → 请求对应的额外写资格 → 目标用户及诊断事实。请求体 target userId 永远是被分析者。

文档必须先通过当前所属空间的管理范围；空间内附选文档也要验证仍属于该路径空间。已归档空间仍可诊断。不存在、已删除、越管理范围或附选文档不属于本空间统一 404，且不带目标或归属信息。真实操作者须改密、停用或无诊断权限为 403；缺少有效会话为 401。

含 manage 的预演须在上述全部门禁之后额外具有 `space:grant-manage`。`space:grant-manage` 单独不能扩展诊断管理范围，拟议给自己授出的 manage 不能用于本次准入。诊断普通 view/download 时，不要求操作者也具有这些正文权限。

考虑过直接用 manage 开放诊断；未采用，因为原管理员看见授权行并不等于已获准查询某人与该行的命中关系。也不拆分解释／预演两个功能 code：本期二者披露的事实范围一致，且预演另受实际授权动作资格约束。

### D2. 最小目标选择复用现有范围，不扩展身份目录

新增诊断专用 POST 用户搜索包装现有最小投影规则。候选仅含用户和主部门启用者，返回 userId／label；q 字面匹配显示名，最多 128 个 code point；limit 默认 20、最大 100，按 userId 升序，以 lookahead 表达 hasMore，不返回总人数。

此外，在已授权读取的 USER ACL 行提供“诊断此用户”。解释接口在完成操作者和资源鉴权后允许精确查询一个已存在的目标用户，即使其后来停用；UI 不提供任意用户 ID 输入。选择之后失效或来自已有授权行的失效用户可得到通用身份阻断，不需要新增可枚举全部停用人员的目录。用户不存在为安全 404，不把不存在与停用合并为假身份记录。

目标搜索游标使用现有有界分页机制，绑定查询种类、真实操作者／认证代次、资源和规范化 q。游标不是准入票据，每次重新鉴权；名称不进入 URL。既有 ACL 主体候选接口、身份目录及其权限保持原义。

空间诊断可选择同空间一份文档以观察具体访问结果。选项使用现有 ID 级管理清单，不新增标题检索或按标题补全；文档面板固定路径文档。

### D3. 读取事实与目标身份类型明确隔离

新建 app 内部诊断服务，先持有已验证的操作者资源上下文，再加载一个目标用户的服务器事实。提取或复用 `IdentityService` 的只读主体解析部分，使在线权限解析和诊断共用用户启用、主部门、角色、祖先链及有效身份语义；强制改密条件另使用现有认证事实。不要让新的诊断 DTO 或客户端 roleIds 铸造 `PermissionService.PrincipalHandle`。

目标身份不合格时只返回 `subjectCondition=BLOCKED`；所有授权命中／来源和文档密级检查都为未评估，不继续读取角色和祖先链，不能以空数组证明“没有授权”。该通用条件覆盖现有有效 enabled（含生命周期限制）、有效主部门及必要改密门禁，不暴露具体原因。数据库异常是 503，不包装成身份受阻。

目标合格时，使用服务器角色和祖先链匹配当前空间 ACL，以及指定文档的例外 ACL。仅对 manage 检查目标是否有 `space:manage-all`，公开结果使用固定全局来源，不公开授予该功能权限的角色清单。操作者身份与目标身份采用不同类型／参数位置，并在测试中以高权限目标、低权限操作者覆盖身份混淆。

### D4. 提取共用授权谓词，不建立第二套生产访问规则

实施时将相关 SQL 中可复用的主体匹配、空间／文档授权并集、归档及版本条件整理为共享片段，保持现有业务入口行为。线上读取使用真实 ACL 行集，诊断使用当前事实行集，after 使用叠加单次意图后的行集；三者引用同样的权限组合规则。

共享片段的表别名／来源选择只能由固定 Mapper 语句选择，客户端不能指定表、SQL 片段或规则版本。不能为“有解释”新写一套近似 Java 判定并假定与 SQL 等价，也不能把预演的合成行集交给普通业务接口作为授权上下文。

对文档当前发布版本查看／下载的判定，复用 `DocumentMapper.documentAccessPredicate`、`currentViewGrant`、发布兼容条件和现有 file 入口的授权组合，新增只返回条件事实的最小查询；不调用会带出文件元数据的 `findFile` 获取诊断响应。不改变既有对文档状态的各入口差异，尤其不把评论或审核专有条件无差别套给普通文件读取。

SQL 布尔结果为本资源权限判定依据；解释使用同次查询的匹配来源和条件事实生成。before、after 都由同一套查询／规则入口求值。共享谓词和调用关系以人工代码审阅核对，只执行现有权限、文件读取及版本用例中符合 D10 离线边界的明确白名单。Mapper 参数／结果替身只能验证应用处理分支，真实 SQL 授权等价性保持未验证；本变更不新增或执行测试库差异比对。

### D5. 一次只读一致快照产生完整前后结果

解释和预演使用有界的 PostgreSQL `REPEATABLE READ`、read-only 事务，避免沿用已在其他隔离级别开启的业务写事务。操作者的诊断及资源准入、目标状态、角色／部门、ACL、资源归属、密级和发布指针均在这次一致读取内获取；游标请求是新的读取，不冻结整个交互会话。

事务内获取数据库时间作为 evaluatedAt，然后读取有限事实，计算 before 与 after 并形成不可变结果。after 只叠加该请求的授权意图；不能把前端上次显示的结果作为 before。并发变化发生在快照之后时，本次结果仍注明仅代表该次读取，下一次请求采用新事实。不承诺计算结束与发送之间没有变化，也不让时间戳成为有效期凭据。

不执行 DML、`SELECT FOR UPDATE`、授权写服务、临时业务表、成功审计、持久回执或模型／存储调用。只读查询超时或取消后释放资源；不通过实际授予再回滚的方式实现模拟。

### D6. 单次预演对应一种现有写入意图

采用带类型的封闭 intent 联合，资源种类限制可用类型：

| intent.type | 载荷 | 语义 |
| --- | --- | --- |
| SPACE_GRANT | principals、permissions | 沿用原批量授予的完整集合、去重和 50×6 上限 |
| SPACE_REVOKE | items | 仅移除显式 1–300 条主体／权限组合，不作笛卡尔积 |
| DOCUMENT_GRANT | principalType、principalId、permission | 指定路径文档的一条例外 |
| DOCUMENT_REVOKE | principalType、principalId、permission | 指定路径文档的一条例外 |

原单条空间操作映射到一项空间意图即可，实际提交仍走原选定接口。每个请求只能包含一种意图；不支持同请求先撤销再授予、跨空间、同时改空间与文档，避免提供没有对应原子写接口的虚假提交预期。

提取既有写入的纯输入校验及只读引用检查供预演使用，保持权限位、角色有效引用、重复授予、撤销缺失条目的语义。写事务专用锁和回执读取留在原服务，不调用其事务性校验入口。对授予的新增角色检查存在；对撤销残留行不要求角色仍存在。USER／DEPT 引用校验沿用对应原写接口，不能在预演中悄悄声称它比实际写入更宽或更窄。

假设行集为当前集合加／减精确条目，原角色及部门归属不变。只选一个观察用户，不展开所有拟授权主体的成员。结果中的 `changes` 表示 ADDED／REMOVED／UNCHANGED；不复用正式回执字段 `grantedCount`、`removedCount`、`replayed`，不输出“已授权”。草稿对观察用户无影响时明确结果不变，不能省略其他条目然后宣称对全体无影响。

### D7. 结果契约区分三个层次，最小字段固定

响应使用现有 R 封装，data 内包含固定 `contract=AUTHORIZATION_DIAGNOSTICS_V1`。所有 ID 为精确十进制字符串；前端严格校验枚举、ID、数组上限、资源／目标／模式与本次请求一致。

| 字段 | 约定 |
| --- | --- |
| mode | EXPLAIN 或 PREVIEW |
| user | userId、label，不附身份详情 |
| resource | kind、spaceId，以及已选择时的 documentId |
| evaluatedAt | 同次数据库读取时间，带偏移的 ISO 时间 |
| assumptions | 固定声明：仅所选用户／资源、事实读取时点、只模拟所列 ACL、未检验文件可用性 |
| before | 当前事实的分层结果 |
| after | PREVIEW 必填；EXPLAIN 为 null |
| changes | PREVIEW 的完整规范化意图条目及拟议变化，每项带 sourceKind、主体类型／ID、权限位、GRANT／REVOKE 动作与 ADDED／REMOVED／UNCHANGED 结果；EXPLAIN 为空 |

before／after 的内部结构：

1. `subjectCondition`：PASSED／BLOCKED。失败依赖不进入成功响应。
2. `spacePermissions`：固定六项；分别包含 `grantMatch`（MATCHED／NOT_MATCHED／NOT_EVALUATED）、`scopeCondition`（PASSED／BLOCKED／NOT_EVALUATED）、固定 reasonCodes 和来源引用。manage 可带 GLOBAL_MANAGEMENT 来源，归档不阻断 manage。空间 view 命中只说明空间授权，不代替文档密级。
3. `documentPermissions`：仅已选文档时提供 view／download／edit／review／comment 五项；前三类及 comment 可合并例外，review 只有空间来源。授权和通用门槛分别说明，这些不是 canEdit/canReview/canComment 的业务动作承诺。manage 展示取自 spacePermissions，不另制造文档权限位。
4. `currentVersionAccess`：无文档为 NOT_APPLICABLE；有文档而目标身份受阻为 NOT_EVALUATED；身份有效且文档当前指针为空为 NO_CURRENT_PUBLISHED_VERSION；否则为 ASSESSED，分别返回查看／下载 ALLOWED 或 DENIED 及固定原因。已选文档时标明 scope=CURRENT_PUBLISHED，其他状态下查看／下载均为 null，不能以 false 代替未评估。缺失／不合法的非空发布指针为 503；不输出版本 ID、号、上传者、时间或版本数。

状态优先级：未选文档时当前版本层固定 NOT_APPLICABLE；已选文档而目标身份受阻时不查询／披露版本及密级，当前版本层为 NOT_EVALUATED；身份有效且无当前发布指针为 NO_CURRENT_PUBLISHED_VERSION，授权层仍计算；其余按当前发布事实求值。SPACE_ARCHIVED、CLEARANCE_BLOCKED、VIEW_NOT_GRANTED、DOWNLOAD_NOT_GRANTED 是可披露的资源阻断类别；不输出原始异常或额外人事原因。空间归档、密级比较等非 ACL 事实在 before/after 中必须一致；客户端验证 changes 与所提交意图的精确条目集合一致，条目换序不改变含义。

来源只包含当前资源已有授权行的 sourceKind（SPACE／DOCUMENT）、principalType、principalId、label、permission，以及 EXISTING／PROPOSED；拟议新行没有数据库 ACL id。GLOBAL_MANAGEMENT 是固定类别，不带角色成员关系。每个 before／after 有一份去重 sources，权限行使用 sourceKeys 引用；来源键由范围、主体类型／ID、权限位构成，两个结果可使用相同键表示保留来源。同一 sources 内重复或悬空引用视为契约损坏；空间来源被空间层和文档层同时引用是合法的。changes 对未命中目标的主体只回传输入中的条目标识及拟议变化，不补查其他成员、身份详情或显示名。

当前发布层沿用发布证据与 LEGACY_COMPAT 的既有规则：使用真实 current_version_id，绝不选择最大的 versionNo 或最近 indexed 版本。新版本未发布不进入计算；当前版本能下载只表示权限条件，后续真实下载仍检查身份、资源和原件。

### D8. 接口与限界

新增以下只读 POST API，不改变既有 GET 能力接口或正式写端点：

| 路径 | 正文 |
| --- | --- |
| `/api/admin/spaces/{spaceId}/authorization-diagnostics/users/search` | q、limit、cursor |
| `/api/admin/spaces/{spaceId}/authorization-diagnostics/explain` | userId、可选 documentId |
| `/api/admin/spaces/{spaceId}/authorization-diagnostics/preview` | userId、可选 documentId、intent |
| `/api/admin/documents/{documentId}/authorization-diagnostics/users/search` | q、limit、cursor |
| `/api/admin/documents/{documentId}/authorization-diagnostics/explain` | userId |
| `/api/admin/documents/{documentId}/authorization-diagnostics/preview` | userId、intent |

不接受 URL 查询参数、重复 JSON 字段、未知属性、浮点／负数／溢出 ID、sourceVersionId、身份或密级覆盖。正文中的业务 ID 按现有精确整数编码，响应使用字符串。候选另用固定版本的分页投影。

首期服务端默认限额：请求实际 UTF-8 字节不超过 64 KiB；目标主体键最多 4096 个；before/after 命中来源并集最多 1000 条；完整 JSON 响应最多 512 KiB；一次查询总预算 5 秒。源行查询读取至上限加一判断超限，不先载入全库；意图条目最多 300，不受可见用户总数影响。限额在受控服务配置中校验为正值，前端只依赖公开契约上限和服务端拒绝，不自动截断或拆批。

错误使用安全 R 错误封装与固定 reasonCode：INVALID_INPUT（400）、DIAGNOSTIC_LIMIT_EXCEEDED（400，主体键／来源规模）、PAYLOAD_TOO_LARGE（413）、UNAUTHORIZED（401）、FORBIDDEN（403）、NOT_FOUND（404）、DIAGNOSTIC_UNAVAILABLE（503）。部分结果不发送；不把 unknown 伪造成 DENIED。数据库 timeout 受剩余预算约束，结果编码也检查预算和大小，不引入无限等待队列或服务器后台诊断任务。

app 在路径级标记全部成功／错误 no-store，gateway 保持既有身份头净化、认证代次检查和 no-store 兜底。新路径应走现有业务管理路由；无新版本头或跨域配置要求，契约版本在响应体内。日志与追踪只保留固定端点模板、阶段和结果类别，不把 userId／documentId／q／草稿／来源或原因明细作为标签或请求日志。内部 SQL 敏感日志继续服从已有限制。

### D9. 可选 UI、草稿绑定和未知写入隔离

在现有空间／文档详情中懒加载诊断区块，不新建全局诊断路由。组件提供最小用户选择、主动“查看权限解释”、来源与条件结果。在授权弹窗中显示“预演影响”，必须先选用户；既有授权确认按钮不因尚未预演、预演不可用或缺少诊断权限而增加禁用条件。

每次诊断请求捕获真实会话 epoch、资源种类／ID、观察文档、目标用户、规范化意图和本地 generation。任一字段改变立即 abort 并增加 generation；响应到达同时校验身份、可见性、资格、generation、请求绑定和完整契约。仅 aborted 不足以处理不可取消的传输，迟到成功仍须丢弃。

空间授予直接读取现有完整 BatchDraft，单条／批量撤销读取精确条目。文档例外使用一项意图。结果展示“当前／若提交后”与拟议来源变化，不能使用成功授权回执的视觉或措辞。增加匹配项的表达允许与仍被密级／归档阻断的结果并存。

开始正式写入立即清理旧诊断。正式写入在途或未知时停止新增预演，保留原 write binding；重读权限、关闭只读区块、返回成功的诊断都不能结清原写入。原绑定只能按已有回执／明确拒绝／显式放弃规则结束；恢复后需主动重新诊断。文档删除确认、搬迁和密级写入的父级互斥同样传入诊断区块。

隐藏、离页、退出、换号、强制改密或关闭诊断区块清理诊断状态，原正式写入绑定仍按其已有作用域规则保留或清理。诊断 403 先清理并有界核对功能与资源资格；如果只是额外 manage 授出权限不足，重新核对后仍可诊断普通权限。404 清理并重新读取资源管理范围；不自动改目标、发新预演、降级为身份目录查询或重发正式写入。

预演触发 403／404 重核前，ACL 面板将待恢复的正式表单动作、主体和权限交给所属资源详情页的内存作用域；同一身份及归属下重新确认管理资格和 ACL 读取成功后，恢复一次原表单。只保存正式草稿，诊断目标、候选及结果仍清理；身份变化、确认失权、归属改变或详情页销毁时清除待恢复状态。固定失败提示按身份／资源共享，恢复后由弹窗内区块显示，关闭弹窗后由外部区块显示；仅失去诊断资格时仍可见固定提示，但不能重新发起诊断。405 保留当前表单并显示不可用。空间批次继续使用已有草稿，文档单主体选择允许恢复到候选首页之外，正式提交仍由原接口实时校验。

### D10. 独立离线验证与证据边界

本变更仅编写和执行不需要联调或外部组件的独立单元／组件测试。后端使用 Mock／Stub、内存仓储、进程内事务代理、连接／结果集替身及受控时钟；前端使用 jsdom、内存 Session／传输与可控 Promise。分别直接调用被测控制器、过滤器、服务、路由及前端 API 模块，不启动前端或后端应用、HTTP 监听服务器、真实浏览器、数据库、Redis、对象存储、容器或第三方服务。集成测试文件、真实环境准备及执行均不属于本次任务，即使环境可用也不自动加入。

离线回归围绕可观察的组件行为，至少覆盖：

- 操作者／目标身份混淆，精确新权限、真实资源资格与 manage 授出资格组合；用保留内存绑定后重新构造组件验证不恢复撤权，独立目录检查对未知 code 拒绝，不实际启动或重启应用。
- 直接／多角色／祖先部门／文档例外并集，撤销仍有其他来源、全局 manage 不授阅读、归档保留 manage、身份阻断与依赖故障区分。
- 没有当前发布版本、V1 当前而 V2 待审、兼容版本、非法非空指针，download 需要 view，低密级仅显示受控原因。
- 原批量授予／撤销边界和文档单项，重复与不存在条目的 no-op、撤销已删除角色残留行、不相关主体草稿不展开成员。
- 内存事实交错下 before／after 复用同次读取，事务／连接替身捕获只读和隔离级别请求，客户端 before 不被信任；实际 SQL 求值、数据库隔离及并发可见性不由这些用例证明。
- 输入字节、主体键、来源及输出大小限制；超时和部分失败不输出伪结果；不执行 DML、写服务、审计成功或原件／模型调用。
- 客户端完整解码、相同草稿不同请求代次、用户切换、编辑草稿、关闭／隐藏／重挂载、403／404 资格恢复与迟到成功、未知写入不能被只读结果解除。

真实 SQL 授权等价性、数据库约束／锁／隔离、迁移执行、实际网络与跨实例、真实浏览器及前后端联调继续标为未验证。该边界属于本次明确排除的验证层次，不新增为待办或本变更完成／归档的前置条件，也不把替身通过或未运行用例计作真实环境验证。

不编写或执行文档存在性、关键词／段落包含、文本快照，或针对 Markdown、说明文案、注释、SQL 字符串的内容断言测试。迁移、SQL、说明文档按人工审阅交付，不用文件存在或文本匹配冒充业务验证。类型检查、生产静态构建、包体隔离、相关 Java 模块编译和 OpenSpec 格式校验按各自用途执行。回归前审阅明确白名单及其依赖，排除超出上述边界的用例；已选用例失败应修复或明确报告，不能临时跳过失败来获得通过。

## Risks / Trade-offs

- [SQL 与解释语义漂移] → 提取公共谓词并人工审阅原读路径与新查询的调用关系，离线回归只核对应用分支和映射；不以平行 Java 规则代替生产规则，真实 SQL 等价性保持未验证。
- [来源披露引入新的成员关系可见性] → 独立诊断权限加当前资源管理范围，只返回本资源命中行；身份无效时停止解析私人关系，精确等级和人事原因从不公开。
- [一致快照仍会随时间过期] → evaluatedAt 只标读取时点；草稿和上下文变化清除结果，提交实时重核，不声称预演锁定未来效果。
- [超大角色／部门或 ACL 集合] → 只读单目标，来源与主体键独立上限、SQL 时间预算及完整响应大小限制，超限整体拒绝而非截断并宣称唯一原因。
- [无法从启用候选搜索到已停用用户] → 可从当前可见的 USER ACL 行发起精确诊断；已有选择失效时返回通用阻断。本期不新增全量停用人员目录。
- [预演仅覆盖一份文档而批量授权影响更广] → UI 明示观察范围，changes 是授权条目数而非影响人数，不输出全空间影响承诺。
- [可选预演与未知写入相互干扰] → 分离只读 generation 与写入 binding，未知时禁用新预演，读结果永不结清写入。
- [新功能权限导致旧 app 不兼容] → 一次性迁移前排空旧实例，回退保留目录识别及新绑定，不更改未知权限拒绝启动规则。

## Migration Plan

1. 实现前重新核对最高 Flyway 版本；当前基线最高为 V42，新权限迁移计划使用下一个未占用版本，不修改历史迁移。不建立诊断历史或预演结果表。
2. 新增服务端权限 code、空库引导及一次性 ROLE_ADMIN 绑定迁移，并补充显式授予普通诊断角色的说明；不会给所有空间管理员自动补权。
3. 升级先排空不认识新 code 的全部旧 app，再由 app 执行迁移并发布新接口／共享规则；Worker 不运行迁移。按现有网关路由交付保护检查，最后发布 web 哈希资产及原子切换 HTML。
4. 功能回退先撤回前端新入口或撤销新诊断资格；保留能够识别新 code 的 app、绑定和审计。不得直接回退到不认识新 code 的旧 app，或通过删除新权限绑定、忽略目录校验恢复旧实例。
5. 本节交付发布与回退方案，不将实际部署、迁移执行、SQL／隔离或浏览器联调作为本变更测试任务；实施记录只报告真正执行的独立离线检查，外部环境行为保持未验证。实施与离线证据见 verification.md、traceability.md；新 Java 代码按当前 AGENTS.md 放入 auth 的 controller／service／mapper／model 层及 config，并提供完整 Swagger 描述。
