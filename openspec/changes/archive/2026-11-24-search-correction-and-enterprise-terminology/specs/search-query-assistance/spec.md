# Spec Delta

## Purpose

为知识搜索提供可解释的企业术语扩展和人工登记错词建议，使用户能够了解当前查询实际采用的表达、选择歧义含义并恢复原词搜索。将建议与原查询、完整筛选和一致词典修订绑定，避免词条更新、输入变化或旧响应造成未经确认的查询改写。

## ADDED Requirements

### Requirement: 增强搜索必须显式进入并保留原始查询

系统 SHALL 提供 `POST /api/search/assisted`，接受 ASSISTED 或 ORIGINAL 模式，省略模式为 ASSISTED。query 始终保存本次搜索链的用户原始输入；effectiveQuery 只反映用户已确认的错词或歧义替换，自动同义扩展另以 appliedTerms 表达。每次成功响应同时交付本次 hits 与 assistance，不要求客户端另查词典推测执行方式。旧 `POST /api/search` 不自动启用词典。

#### Scenario: 原查询包含简称
- **WHEN** 用户以 ASSISTED 提交“OA 使用说明”
- **THEN** 响应保留该原始 query，effectiveQuery 仍为“OA 使用说明”，实际采用的同义表达列入 appliedTerms

#### Scenario: AI 使用既有搜索入口
- **WHEN** AI 或其他旧客户端只向 `/api/search` 提交原有合法请求
- **THEN** 不执行词典扩展，不返回新的 assistance 对象，保持原有数组和查询行为

### Requirement: 词条匹配必须字面确定且保留原文位置

匹配 SHALL 使用词典的 NFC 与 ASCII 大小写比较规则，保留原查询文本及可映射回原文的 Unicode code point 起止位置。中文允许字面子串匹配；表达首尾若为 ASCII 字母、数字或下划线，对应相邻字符不得属于同一类。标点按字面处理，不执行正则、通配、拼音或语义猜测。重复出现的同一表达具有独立位置。

#### Scenario: 英文缩写边界
- **WHEN** 已登记 OA，查询分别为“oa流程”、“OA-流程”和“LOAD流程”
- **THEN** 前两者可以匹配 OA，第三者不能从 LOAD 内部命中 OA

#### Scenario: Unicode 原始位置
- **WHEN** 查询含补充字符或规范等价的组合字符，后续出现已登记术语
- **THEN** 建议定位和替换对应原文完整片段，位置不按 UTF-16 半个字符计数，也不改变未选中的文本

#### Scenario: 未登记近似词
- **WHEN** 查询与某术语仅拼音或字形相似，但不存在对应字面词条或人工错词映射
- **THEN** 不猜测纠错建议，不调用模型生成新表达

### Requirement: 重叠匹配必须采用固定优先级

匹配 SHALL 按原查询从左到右选择不重叠片段，同一起点优先最长匹配，再继续处理该片段之后的内容。相同片段所属的全部启用组共同参与唯一性判定；选择最长表达不得隐式选择某个含义。生成的替换文本与扩展词不再次参与递归匹配，同一次查询不得沿别名关系跨组传递。

#### Scenario: 长短术语重叠
- **WHEN** 词典同时有“报销”和“差旅报销”，查询为“差旅报销流程”
- **THEN** 在该位置采用“差旅报销”这一完整匹配，不叠加其中“报销”的另一组扩展

#### Scenario: 相同片段有多个组
- **WHEN** 同一最长匹配“PM”关联两个启用术语组
- **THEN** 保留一个歧义片段及两个含义候选，不按 termId 或维护时间选定其中一组

#### Scenario: 扩展包含另一术语
- **WHEN** 已采用的一个别名包含其他组的表达
- **THEN** 不继续触发另一轮扩展或组合生成更多查询

### Requirement: 唯一术语关系必须自动扩展且避免歧义传播

ASSISTED 模式中，一个匹配表达仅对应一个启用组时 SHALL 自动纳入该组标准名称及当前无跨组歧义的别名；规范化等价表达去重，原输入不被自动替换。组内有歧义的其他别名不因组已唯一选定而加入扩展。每项 appliedTerms 须说明命中片段、组身份与版本、实际采用的表达；停用词、错词及无关组不得出现在扩展中。

#### Scenario: 搜索简称与搜索正式名称
- **WHEN** “OA”和“办公自动化”属于同一唯一启用组，用户分别搜索其中一个
- **THEN** 两次查询都可通过词典纳入另一表达，并展示本次真正采用的扩展

#### Scenario: 组内别名在其他组有歧义
- **WHEN** “项目管理”唯一匹配自身组，但该组别名“PM”也属于“产品经理”
- **THEN** 不自动把 PM 加入“项目管理”的扩展，不经该共享别名传播到“产品经理”

#### Scenario: 同一组重复匹配
- **WHEN** 原查询多次出现同一组的表达
- **THEN** 保留原查询各位置，扩展表达去重，不因重复位置倍增召回工作

### Requirement: 歧义提示必须等待明确选择

未确认的歧义片段 SHALL 保持原词搜索，并返回当前启用组的稳定身份、标准名称及释义作为候选，按 termId 升序展示。用户选择后只将该位置替换为所选组标准名称，并按该组形成后续扩展；其他歧义位置仍等待选择。提示不附带资料数量，不承诺选择能作为文档语义的硬过滤条件。

#### Scenario: 尚未选择 PM 的含义
- **WHEN** 用户搜索 PM，存在“项目管理”和“产品经理”两个候选
- **THEN** 当次搜索保留 PM，不自动扩展两组，响应给出两个待选择含义

#### Scenario: 选择其中一种含义
- **WHEN** 用户在仍有效的上下文中选择“项目管理”
- **THEN** 新请求使用该选择生成 effectiveQuery 和扩展，原始 query 仍可供原词模式恢复

### Requirement: 人工错词建议不得自动应用或反向扩展

只有当前启用且目标组有效的人工错词映射 SHALL 产生 CORRECTION 建议，包含原片段、位置和目标标准名称。未采用前保留原错词搜索；用户确认后只替换对应位置，再纳入目标组的合法同义扩展。已确认位置不再次给出同一纠错建议，其他位置继续独立处理。系统 MUST 不把无结果本身作为纠错依据。

#### Scenario: 错词已有搜索结果
- **WHEN** “报消流程”能命中文档，词典同时登记“报消”到“报销”
- **THEN** 返回当前结果及纠错建议，不因存在结果隐藏建议，也不自动改搜报销

#### Scenario: 同一查询既有简称又有错词
- **WHEN** 用户提交“OA 报消流程”且尚未确认纠错
- **THEN** 唯一的 OA 关系可自动扩展，报消仍保持原样并给出待确认建议，两种处理分别说明

#### Scenario: 仅采用一个位置
- **WHEN** 原查询含两个错词位置，用户仅确认其中一个
- **THEN** effectiveQuery 只替换选中位置，另一位置保留原文及待确认建议

### Requirement: 建议采用必须绑定查询条件和当前身份

有待确认建议的响应 SHALL 提供至多 4096 字符的服务端可验证不透明 selectionContext，有效期 10 分钟，绑定当前用户与认证代次、原始 query、规范化完整筛选、candidates、topK 和 dictionaryRevision。采用请求携带该上下文及累计 selections，每项定位原文片段、建议种类和目标稳定身份。服务端 MUST 重新计算合法匹配并验证选择，拒绝伪造、重复、重叠或不属于该查询的选择；上下文不是资源授权凭据。

#### Scenario: 更改草稿筛选后点击旧建议
- **WHEN** 页面当前草稿已变化，但用户点击上一结果的建议
- **THEN** 采用请求继续携带上一结果的已提交条件；若实际提交了不同条件，服务端返回 400

#### Scenario: 跨用户或认证代次采用
- **WHEN** 另一用户或重新认证后的代次使用旧 selectionContext
- **THEN** 当前身份门禁通过后仍拒绝该上下文，不借旧建议延续前一会话

#### Scenario: 累积选择
- **WHEN** 用户已确认一个纠错位置，再选择另一歧义位置
- **THEN** 请求携带原始 query 和累计明确选择，服务端验证所有位置，响应保留已确认替换并处理剩余建议

### Requirement: 过期建议必须明确拒绝并要求重新取得

采用时 SHALL 在同一一致读取中核对 selectionContext 及当前完整词典修订；修订变化或有效期届满返回 409 与固定类别 ASSISTANCE_STALE，不执行该次召回或自动替换目标。任一组、别名或纠错映射维护均可使旧建议失效，包括修改后又恢复原值。仅重新搜索并取得新上下文后，用户才能重新确认，客户端不得自动采用更新后的建议。

#### Scenario: 目标已改名或停用
- **WHEN** 用户点击旧建议前，目标组已改名或停用
- **THEN** 返回 ASSISTANCE_STALE，不使用旧名称、不切换其他组，也不将已停用关系当作有效

#### Scenario: 无关词条更新
- **WHEN** 建议生成后另一词条修改推进全局修订
- **THEN** 旧上下文同样失效，界面提示词典已更新，可由用户重新搜索

#### Scenario: 读取后再次并发修改
- **WHEN** 采用请求已在修订 R 下完成一致核验，随后维护提交为 R+1
- **THEN** 本请求可以按 R 完成并标示 R，不能混用 R+1 的说明或词条，也不声称词典锁定至响应送达

### Requirement: 原词模式必须明确绕过词典处理

ORIGINAL 模式 SHALL 使用完整原始 query 及同一已提交筛选执行现有授权检索，effectiveQuery 等于 query，appliedTerms、suggestions、selections 为空，dictionaryRevision 与 selectionContext 为 null。携带非空选择或上下文返回 400。该模式不依赖词典读取、匹配或可用性；切回它须用户主动发起，不由增强失败自动触发。

#### Scenario: 采用纠错后恢复原词
- **WHEN** 用户从已采用“报销”的结果点击“仅搜原词”
- **THEN** 使用最初的“报消流程”及原已提交筛选重新搜索，清除纠错和同义扩展

#### Scenario: 词典不可用但用户选择原词
- **WHEN** 词典依赖故障，用户明确发起 ORIGINAL 请求且普通检索依赖可用
- **THEN** 可以完成原词检索，不读取旧词典缓存或伪造“无匹配词条”状态

### Requirement: 扩展必须形成有界且可解释的检索表达

系统 SHALL 在一次授权检索中使用 effectiveQuery 与本次实际采纳的同义关系，响应须可区分原文替换和补充表达。关键词召回须支持所采用的等价表达，向量及重排采用的表达必须与这份计划一致且保留未替换上下文；不得为每个别名递归发起完整搜索。候选按固定分块身份去重，不保证任何表达的结果必然位于 topK。具体分值和融合策略可在保持这些行为时调整。

#### Scenario: 文档只包含正式名称
- **WHEN** 查询含唯一简称，已采用其标准名称，而一篇符合权限与筛选的文档只包含标准名称
- **THEN** 该文档可以通过等价表达参与关键词召回，不被要求同时包含原简称；是否进入 topK 仍由相关性和数量决定

#### Scenario: 降级到关键词召回
- **WHEN** 已生成查询计划后 Embedding 不可用
- **THEN** BM25 继续采用本次已确认的术语关系与完整筛选，响应说明与实际降级执行一致

#### Scenario: 无词典匹配
- **WHEN** 合法查询在当前词典没有匹配
- **THEN** 使用原表达执行搜索，返回空扩展和空建议，不能据此判断企业不存在相关知识

### Requirement: 一次响应必须准确表达采用和待确认状态

assistance SHALL 包含 mode、originalQuery、effectiveQuery、dictionaryRevision、appliedTerms、suggestions、selections 和 selectionContext。ASSISTED 下前三类词典数据须来自同一修订；没有建议时 selectionContext 为 null。原文片段使用 code point 半开区间，建议种类仅为 CORRECTION 或 DISAMBIGUATION。实际未采用的表达不得进入 appliedTerms；真实空 hits 可与非空公开建议并存。

#### Scenario: 空命中仍有建议
- **WHEN** 公开词典命中，但当前权限与筛选下没有资料结果
- **THEN** 返回 hits=[] 及对应建议，不把建议当成文档命中或隐藏资料证明

#### Scenario: 响应结果与说明来自不同版本
- **WHEN** 服务端无法取得一致修订下的结果计划和词条说明
- **THEN** 请求明确失败，不拼装一份表面成功但互相矛盾的响应
