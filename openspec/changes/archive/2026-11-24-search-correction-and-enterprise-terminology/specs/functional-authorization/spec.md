# Spec Delta

## ADDED Requirements

### Requirement: 企业术语管理必须具有独立精确读写资格

服务端固定权限目录 SHALL 定义 `search:term:read` 和 `search:term:write`，分别保护术语组与错词管理目录读取，以及新建、编辑和启停。两项按当前有效主体全部持久角色权限的并集精确匹配，彼此不蕴含；标签管理、空间 manage、space:manage-all、文档 edit、身份权限或 ROLE_ADMIN 名称不能代替。管理资格不授予文档正文、搜索历史或私有会话读取权。

#### Scenario: 目录显示新资格
- **WHEN** 合格角色读取者查询权限目录
- **THEN** 返回两项精确 code 及用途，可通过既有角色权限维护分别授予

#### Scenario: 只有词典读取资格
- **WHEN** 用户持有 search:term:read 但没有 search:term:write
- **THEN** 可以读取管理目录，维护操作返回 403

#### Scenario: 其他管理者尝试维护词典
- **WHEN** 用户只有 document:tag:write、空间管理或管理员角色名称
- **THEN** 未命中对应词典权限时拒绝管理请求，不因相似管理用途放行

### Requirement: 公开搜索辅助与词典管理必须使用不同资格边界

公开搜索辅助 SHALL 使用既有有效会话、主体启用和强制改密门禁，不要求词典管理权限；词条为全公司公开内容，文档结果继续按每次当前资源权限过滤。管理接口须先核对对应精确资格再查询目标、回执和冲突事实。匹配重放重新鉴权，客户端权限声明、旧建议、游标及先前成功均不能延续资格。

#### Scenario: 无管理资格的普通用户
- **WHEN** 普通用户身份有效且已完成必要改密，但没有任何词典管理权限
- **THEN** 可以使用相关公开词条建议，不能枚举管理目录或写入词条

#### Scenario: 写资格撤销后重放
- **WHEN** 用户首次维护成功后全部角色中的 search:term:write 被撤销，再提交原标识
- **THEN** 返回 403，不查询并回显原成功回执以延续写资格

#### Scenario: 无资格者猜测目标
- **WHEN** 无词典读取或写入资格者分别访问存在和不存在的管理目标
- **THEN** 均在目标查询前按缺少相应资格拒绝，不通过响应差异暴露管理事实

#### Scenario: 管理资格与资料授权分开
- **WHEN** 用户可以维护词典但没有任何文档可检索范围
- **THEN** 可以执行合法词典管理及取得公开建议，搜索文档命中仍为空

### Requirement: 术语权限初始化必须保留撤权及目录兼容边界

首次迁移 SHALL 仅向当时存在的 ROLE_ADMIN 一次性绑定两项术语权限，其他角色不隐式获得；空库正式引导新管理员角色时纳入完整目录。后续启动或重复引导不得恢复已撤销绑定。新增权限入库前排空不认识它们的旧 app，保留未知 code 拒绝启动规则，不以忽略权限或删除绑定实现回退；词典授权不修改既有资源 ACL。

#### Scenario: 存量系统升级
- **WHEN** 首次应用包含术语管理权限的迁移
- **THEN** 当时已有 ROLE_ADMIN 获得一次性绑定，其他角色及全部资源授权保持原事实

#### Scenario: 撤销后重启
- **WHEN** 管理者撤销词典写权限后重启或重复运行引导
- **THEN** 权限保持撤销，不因角色名称重新补授

#### Scenario: 空库首次引导
- **WHEN** 迁移时无管理员角色，之后正式创建首个管理员
- **THEN** 新角色纳入完整权限目录，不依赖开发种子

#### Scenario: 旧实例回退
- **WHEN** 不认识术语权限的旧 app 在新绑定存在时启动
- **THEN** 按既有目录检查拒绝启动，发布方案须明确这不是兼容混部或直接回退
