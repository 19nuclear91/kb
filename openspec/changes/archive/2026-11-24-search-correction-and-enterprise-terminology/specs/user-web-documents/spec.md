# Spec Delta

## MODIFIED Requirements

### Requirement: 搜索必须只消费现有授权检索能力

搜索页 SHALL 通过 POST JSON 提交 query、有界数量参数及 search-filtering 定义的可选组合条件，展示服务器返回的有序片段、标题和版本信息；本期使用 `/api/search/assisted` 的明确模式及结果对象。不选条件时搜索全部当前可见已发布内容，选择条件时取其交集；失败不能伪装为空结果，空结果不得推断存在不可见文档。页面须按 8000 个 Unicode code point 的默认上限校验查询，不静默截断；服务端是最终判定。400、409、413、429 和 503 SHALL 按搜索上下文呈现，容量拒绝不得误报为部门 AI 额度不足，Retry-After 不触发自动重发。结果继续最多展示 20 条片段。

#### Scenario: 提交搜索
- **WHEN** 用户输入关键词并提交，可附带合法组合条件
- **THEN** 请求发往不含关键词或筛选参数的固定 POST 路径，页面按实际响应顺序展示结果
- **AND** 页面地址、持久存储和日志不保存该关键词或筛选草稿

#### Scenario: 未命中和依赖故障
- **WHEN** 检索成功返回空 hits，或接口返回 503
- **THEN** 前者显示当前条件下未找到可用结果，后者显示检索暂不可用，两种状态可区分

#### Scenario: 查询超过字符上限
- **WHEN** 用户输入超过 8000 个 code point 的查询，或输入包含 NUL 或孤立代理项
- **THEN** 页面提示修正输入并阻止提交，不截断后发送；补充字符按一个 code point 计算

#### Scenario: 服务端拒绝输入
- **WHEN** 搜索返回 400 或 413
- **THEN** 页面分别显示查询输入不符合要求或搜索请求过大，不把搜索正文超限描述为上传文件过大；固定类别 ASSISTANCE_LIMIT_EXCEEDED 另提示辅助处理超限，可主动缩短输入或选择原词搜索
- **AND** 只在当前页面保留输入，不显示被拒请求的成功结果

#### Scenario: 搜索用户并发超限
- **WHEN** 搜索返回 429，可选带有 Retry-After
- **THEN** 页面提示搜索请求过于频繁、稍后重试，不提示部门 AI 额度不足
- **AND** 不自动再次搜索、不循环倒计时发请求；用户可以在条件允许时主动重新提交

#### Scenario: 合法的降级结果
- **WHEN** 搜索通过 BM25 或原候选排序回退返回合法成功结果，且通过增强及必要筛选协议确认
- **THEN** 页面按响应原顺序显示片段，不自行重排、补取、移除条件或自动重复请求以追求非降级结果

#### Scenario: 新请求发出后旧请求才返回
- **WHEN** 用户重新提交搜索、离开页面或切换身份，旧请求随后才返回
- **THEN** 旧成功、错误及 Retry-After 信息不得覆盖新页面状态，取消本地等待不被解释为服务端工作已经退出

## ADDED Requirements

### Requirement: 搜索页必须展示实际采用的表达与待确认建议

搜索页 SHALL 在提交新查询时默认选择 ASSISTED，并提供可见的原词模式入口。页面根据同一次响应展示 originalQuery、已确认替换后的 effectiveQuery、实际 appliedTerms 及待确认建议，避免把建议显示为已经生效。错词提示使用“是否搜索”语义，歧义候选显示标准名称与释义；普通用户无需词典管理读取资格。

#### Scenario: 自动同义扩展成功
- **WHEN** OA 被唯一映射至办公自动化并完成搜索
- **THEN** 显示原输入及已包含的同义表达，并提供“仅搜原词”，不偷偷改写输入草稿

#### Scenario: 同时有纠错建议和结果
- **WHEN** 查询报消流程返回结果及报销流程建议
- **THEN** 当前结果仍标明原查询处理方式，用户点击之前不显示“已按报销搜索”

#### Scenario: 公开提示与空结果并存
- **WHEN** hits 为空但返回公开词典建议
- **THEN** 展示当前条件下无结果及独立建议，不宣称全库无知识、存在隐藏文档或采用建议必然有结果

### Requirement: 采用建议必须保持已提交条件与累计选择

纠错或歧义选择 SHALL 作为用户主动的新搜索，以原始 query、原已提交的完整筛选及数量、服务端 selectionContext 和累计明确选择提交。当前输入草稿不能替代这些条件。提交期间停用当前建议按钮，清理旧结果与引用，并隔离旧响应；不同位置可逐次采用，未经选择的位置不得一并确认。

#### Scenario: 草稿与结果筛选不同
- **WHEN** 用户在结果显示后修改空间草稿但尚未提交，再点击旧结果的纠错建议
- **THEN** 采用请求仍使用旧结果所属的已提交空间和其他条件，页面明确显示该次已提交条件

#### Scenario: 逐次处理两个位置
- **WHEN** 用户先采用一个错词建议，再选择另一处简称含义
- **THEN** 第二次请求保留已明确确认的第一项选择，其他建议仍待确认

#### Scenario: 重复点击和迟到响应
- **WHEN** 建议请求仍在途时连续点击，或前一次普通搜索随后返回
- **THEN** 不重复提交同一采用动作，旧响应不能覆盖新查询的结果、说明或建议

### Requirement: 原词搜索必须恢复最初输入并保留完整筛选

“仅搜原词” SHALL 主动提交 ORIGINAL 模式，使用该搜索链最初的 query 与已提交筛选、数量，移除全部选择和上下文。页面把该结果明确标为原词搜索；再次启用术语辅助须主动提交 ASSISTED，不恢复先前纠错决定。原词模式为本页状态，不保存跨登录偏好。

#### Scenario: 已纠错后切回原词
- **WHEN** 用户从已按报销流程搜索的结果点击仅搜原词，最初输入是报消流程
- **THEN** 重新提交报消流程并保持原筛选，不把当前 effectiveQuery 当作最初输入

#### Scenario: 从原词重新启用辅助
- **WHEN** 用户主动重新选择术语辅助并搜索
- **THEN** 使用当前提交的输入取得新建议，先前选择不自动应用

### Requirement: 过期或不可用的辅助必须有明确恢复入口

ASSISTANCE_STALE SHALL 清理可采用的旧建议及其上下文，提示词典已变化或建议已过期，由用户重新搜索。ASSISTANCE_LIMIT_EXCEEDED、词典不可用及协议不支持须分别呈现固定安全提示；不自动重发、不自动放宽筛选或切换原词。不认识的错误类别使用通用安全提示，不能回显远程 message。保留仍在当前有效页面内的输入供主动处理。

#### Scenario: 点击前词典修改
- **WHEN** 采用返回 409 ASSISTANCE_STALE
- **THEN** 停止使用原建议，提供重新搜索入口，不用新 revision 自动重发旧选择

#### Scenario: 增强入口不存在
- **WHEN** 新页面请求收到 404、405 或不满足增强协议的响应
- **THEN** 提示当前服务无法确认辅助搜索支持，不将旧结果数组或空响应解释为成功

#### Scenario: 词典故障时继续原词
- **WHEN** 辅助请求失败后用户明确选择仅搜原词
- **THEN** 可以发起新的 ORIGINAL 请求，页面不会把前次失败标为已完成辅助

### Requirement: 搜索辅助状态必须与身份和请求代次一起清理

原始输入、有效表达、采用关系、词典修订、建议上下文和累计选择 SHALL 与既有草稿、已提交条件、hits 及引用共同保存在当前页面内存。离页、隐藏、退出、强制改密和身份变化清理这些内容并使旧回调失效；恢复不自动搜索或采用旧建议。所有词条按安全文本展示，大整数及 code point 位置保持精确。

#### Scenario: 身份切换后旧建议到达
- **WHEN** A 用户请求的建议在 B 用户身份建立后返回
- **THEN** 不展示 A 的输入、结果、建议或上下文，不为 B 发起采用请求

#### Scenario: 隐藏后恢复
- **WHEN** 页面隐藏后重新可见
- **THEN** 先遵守现有身份恢复规则，辅助状态保持已清理，由用户重新输入并搜索
