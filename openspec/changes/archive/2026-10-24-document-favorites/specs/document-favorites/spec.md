# Spec Delta

## Purpose

为用户提供跨登录保留的个人文档收藏，通过稳定文档身份快速返回当前可查看的资料，并明确收藏关系的私人归属、重复操作、实时授权过滤、分页和权限变化后的表现，避免收藏成为过期内容或他人资料的访问入口。

## ADDED Requirements

### Requirement: 收藏操作必须绑定当前可信用户

收藏、取消、列表和批量状态查询 SHALL 仅操作服务端会话对应用户的收藏。所有入口 MUST 检查当前用户及主部门有效性和强制改密状态；无有效会话返回 401，主体停用或要求改密返回 403。管理员资格 MUST NOT 授予读取或修改他人收藏的能力。

#### Scenario: 普通用户跨登录使用收藏
- **WHEN** 普通用户重新登录或更换设备后查询收藏
- **THEN** 返回该稳定内部用户身份下的当前可见收藏，不要求管理功能权限

#### Scenario: 管理员访问收藏
- **WHEN** 管理员调用收藏列表或取消接口
- **THEN** 只处理该管理员本人的收藏，不能指定其他用户

#### Scenario: 旧会话对应账号失效
- **WHEN** 会话令牌仍存在，但用户或主部门已停用，或账号已被要求改密
- **THEN** 四类入口均返回 403，包括取消收藏，不继续操作收藏关系

### Requirement: 收藏必须以当前文档查看资格建立唯一关系

`PUT /api/documents/{documentId}/favorite` SHALL 将本人对目标文档的状态设为已收藏。当前 view、密级、未删除和空间未归档检查通过后返回 HTTP 200，R.data 为 `documentId`、`favorited=true`；不可见、已删除或不存在统一返回 404。同一用户与文档 MUST 至多一条关系，重复收藏保持原收藏时间和位置。

#### Scenario: 文档例外授权允许收藏
- **WHEN** 用户仅通过文档例外取得 view 且满足密级要求
- **THEN** 可以收藏该文档，不要求对整个空间有 view、edit 或 manage

#### Scenario: 已有关系但查看资格已撤销
- **WHEN** 先前收藏过文档的用户失去 view 后再次提交 PUT
- **THEN** 返回 404，不通过已有收藏关系跳过当前查看检查

#### Scenario: 文档尚无发布版本
- **WHEN** 文档当前可查看，但首个版本尚未发布
- **THEN** 可以收藏该文档，返回成功不表示已有可检索或可预览内容

### Requirement: 取消收藏必须只删除本人关系并支持重复操作

`DELETE /api/documents/{documentId}/favorite` SHALL 将本人对目标文档的状态设为未收藏，成功返回 HTTP 200，R.data 为请求的 `documentId`、`favorited=false`。完成身份门禁后，即使文档当前不可见、已删除、不存在或本人从未收藏，也 MUST 返回相同成功结构；不得返回文档内容或是否曾有关系。

#### Scenario: 撤权后取消本人收藏
- **WHEN** 用户保留原文档 ID，在失去该文档查看资格后取消收藏
- **THEN** 本人关系被删除，不要求恢复 view，不读取或返回原文档标题

#### Scenario: 重复取消或他人存在收藏
- **WHEN** 用户取消自己未收藏的文档，而另一个用户存在同文档收藏
- **THEN** 返回 `favorited=false`，另一个用户的关系保持不变

### Requirement: 收藏读取必须按当前权限过滤

列表与批量状态 SHALL 每次重新检查当前文档 view、密级、删除与空间归档事实；收藏关系不构成授权依据。不可见文档 MUST 不出现在列表、状态项或分页统计中，也不得以失效占位展示其旧标题、版本或数量。权限变化仅影响可达性，未被本人取消的关系 SHALL 在权限恢复后重新可见。

#### Scenario: 归档、升密或撤权
- **WHEN** 收藏后文档因空间归档、密级提高或授权撤销变得不可查看
- **THEN** 下一次列表和状态查询均不返回该文档，不要求退出登录才生效

#### Scenario: 权限恢复
- **WHEN** 原文档重新可查看，且用户未取消该收藏
- **THEN** 从首页重新查询时可见原收藏，保留其原收藏时间和位置

### Requirement: 收藏列表必须有界且按稳定创建顺序分页

`GET /api/documents/favorites` SHALL 仅接受 limit、cursor，limit 默认 20、范围 1–100，按收藏关系固定创建顺序倒序返回 R.data 的 `items`、`hasMore`、`nextCursor`。每项仅含 `documentId`、`title`、`spaceId`、`securityLevel`、`currentVersionId`、`currentVersionNo`、`favoritedAt`；无当前版本时版本字段为 null。权限过滤 MUST 先于分页；响应不提供全局或隐藏关系总数。

#### Scenario: 权限稀疏时翻页
- **WHEN** 较新的若干收藏已不可见，较旧收藏仍可见
- **THEN** 按可见关系填充本页并计算 hasMore，不先截取原始关系后返回虚假的空页或结束标记

#### Scenario: 新增收藏或文档更新发生在两页之间
- **WHEN** 用户读取首页后新增收藏，或者某文档发布新版本，再使用原游标续页
- **THEN** 新建的较新关系不会把已遍历位置挤入续页，文档更新不改变收藏排序
- **AND** 分页不承诺冻结快照，撤权、恢复和取消按当次事实处理

#### Scenario: 复用不匹配的游标
- **WHEN** 用户提交其他查询种类、另一用户范围或损坏的 cursor
- **THEN** 返回 400，不将 cursor 当作身份或文档权限凭据

### Requirement: 批量状态查询必须有界并省略不可见目标

`POST /api/documents/favorites/status` SHALL 接受仅含 `documentIds` 的 JSON 对象，数组含 1–100 个互不重复的正整数文档 ID。响应 R.data 的 `items` SHALL 按请求顺序仅返回当前可查看目标的 `documentId`、`favorited`。不可见与不存在均省略；可见但未收藏返回 false。请求不得逐个回显拒绝原因、隐藏关系或他人收藏数量。

#### Scenario: 同页混合目标
- **WHEN** 输入包含可见已收藏、可见未收藏、不可见和不存在文档
- **THEN** 只返回前两类，分别标记 true 和 false；后两类无区别地省略

#### Scenario: 读取单个文档状态
- **WHEN** 文档详情以仅含该文档 ID 的合法数组查询状态
- **THEN** 使用与列表批量查询相同的权限与响应规则

### Requirement: 收藏必须跟随文档身份及当前版本

收藏 SHALL 关联文档而非版本、分块或标题快照。版本发布、文档改名或合法搬迁 MUST NOT 复制收藏、改变收藏归属或原收藏顺序；列表使用当前授权文档信息，打开收藏进入文档详情并按其当前版本规则读取。收藏行为 MUST NOT 改写既有搜索或问答引用的固定版本身份。

#### Scenario: 收藏后发布新版本
- **WHEN** 用户收藏时文档当前版本为 V1，之后发布 V2
- **THEN** 收藏仍只有一条，列表显示当前 V2，打开文档时按现有详情规则选择当前版本
- **AND** 已有 V1 搜索或问答引用仍指向 V1

#### Scenario: 文档搬迁
- **WHEN** 文档搬迁至另一空间
- **THEN** 收藏关系保留原文档身份，用户在新空间仍有查看资格时继续可见，否则按不可见规则隐藏

### Requirement: 并发与重复收藏操作必须收敛为明确目标状态

相同用户和文档的重复 PUT MUST 不创建重复关系或刷新收藏时间；重复 DELETE MUST 不产生第二种结果。PUT 与 DELETE 均表达显式目标状态，不能实现为反转状态。相反指令并发时 SHALL 以实际服务端执行结果为准；取消后重新收藏产生新的创建位置。每次 PUT 仍需重新鉴权，不承诺跨相反指令重放原回执。

#### Scenario: 两个相同收藏同时到达
- **WHEN** 两个通过查看检查的同用户 PUT 并发提交
- **THEN** 最终只有一条收藏，两次均可得到已收藏成功结果，不以唯一约束竞争返回 500

#### Scenario: 取消后主动重新收藏
- **WHEN** 用户成功取消后再次主动 PUT，且当前文档仍可查看
- **THEN** 建立新的收藏时间和位置，首页按新的创建顺序展示

#### Scenario: 相反操作竞争
- **WHEN** 两个客户端并发提交收藏和取消
- **THEN** 最终至多一条关系，后续查询返回服务端当前状态，不根据客户端点击时间虚构顺序

### Requirement: 收藏参数必须严格校验且保持资源身份精确

所有文档 ID MUST 为 `1..Long.MAX_VALUE` 的整数；路径 ID 非法、列表参数重复或未知、非法 limit/cursor、批量空数组、重复/超限 ID、JSON 重复或未知字段、字符串或小数 ID 均返回 400。PUT/DELETE 不接受非空请求体或查询参数；批量查询不接受查询参数。错误 MUST 不回显原始输入。

#### Scenario: 浏览器安全整数范围之外的文档
- **WHEN** 请求携带合法且超过 JavaScript 安全整数范围的文档 ID
- **THEN** 服务端按该精确身份处理，成功响应保留原整数值

#### Scenario: 客户端夹带用户或版本
- **WHEN** 请求在参数或 JSON 中夹带 userId、versionId、正文或其他未声明字段
- **THEN** 返回 400，不据其建立归属或版本级收藏

### Requirement: 收藏故障必须明确失败且响应控制内容输出

收藏入口 SHALL 对自身身份解析、权限或持久化依赖故障返回安全 503，不伪装为空列表、未收藏、404 或成功写入。响应 MUST 标记 `Cache-Control: no-store`；日志与错误不得包含标题、正文、令牌或原始 SQL/异常内容。收藏操作仅影响个人关系，不修改文档更新时间、ACL、密级、版本、解析任务或模型用量。

#### Scenario: 状态查询依赖故障
- **WHEN** 当前身份、授权事实或收藏状态无法可靠读取
- **THEN** 返回 503，不将整页状态默认为 false，也不删除已有关系

#### Scenario: 写入失败
- **WHEN** 收藏或取消的数据库事务未能提交
- **THEN** 不返回已确认成功；客户端可通过后续读取核对当前状态

#### Scenario: 收藏与文档更新时间
- **WHEN** 用户收藏、重复收藏或取消一篇文档
- **THEN** 文档内容、updatedAt、权限、版本及处理任务均不改变，只有个人关系发生相应变化
