# Spec Delta

## ADDED Requirements

### Requirement: 采用整理建议须在资料写入时核对固定来源

系统 SHALL 为包含已采用建议的表单提供受控保存入口。首次写入必须在同一提交边界核对请求属于当前操作者和目标文档、已完成且建议仍有效、固定来源可读且仍为当前发布版本、当前 view/edit、资料版本及分类上下文有效。按当前资料规则一次提交用户确认的完整表单，推进一次资料版本并写入回执及无正文审计。

#### Scenario: 发布指针变更但资料版本相同
- **WHEN** 用户采用源自 V1 的摘要，首次保存前 V2 已发布，metadataVersion 仍匹配
- **THEN** 返回来源冲突且不修改任何字段，编辑者可基于 V2 重新生成。

#### Scenario: 等待写入期间改名、搬迁或撤权
- **WHEN** 另一编辑者先提交资料更新，或等待期间文档搬迁、升密、被删除，或操作者失去资格
- **THEN** 按锁后事实返回版本冲突或既有权限拒绝，不能用生成时的权限覆盖新资料。

#### Scenario: 只采用摘要并手工修改其他字段
- **WHEN** 编辑者采用摘要、修改其措辞并手工修改标题，以原表单基线提交
- **THEN** 整体保存经确认的最终表单，保留未修改的分类及标签，资料立即生效，文件发布和审核状态不受影响。

#### Scenario: 分类路径变化或请求不属于本人
- **WHEN** 建议生成后分类目录已变，或用户提交另一人的整理请求标识
- **THEN** 前者要求重读分类后重新选择或生成，后者拒绝；均无部分修改。

### Requirement: 辅助保存须有独立请求绑定并兼容人工保存

系统 MUST 区分生成标识与保存标识。保存标识绑定辅助保存操作、操作者、目标、来源建议、采用字段、资料基线及规范化完整表单。匹配重放在重新核对操作者对文档的当前 view/edit 和对固定来源的可读资格后返回首次最小回执。首次提交的来源新鲜度检查不应造成已提交写入再次执行。普通手工保存沿用现有五字段契约。

#### Scenario: 保存响应丢失后资料或发布指针再次变化
- **WHEN** 原操作者仍具上述资格，以同一保存标识和完全相同的载荷重试已提交的写入
- **THEN** 返回原回执及重放标记，无建议正文，不再次写入、审计或计费；绑定不匹配返回冲突。

#### Scenario: 已撤权后重放
- **WHEN** 已提交的同一保存请求在失去文档编辑或来源阅读资格后再次到达
- **THEN** 拒绝重放并保护原回执。

#### Scenario: 原有客户端或仅手工编辑
- **WHEN** 客户端按原接口提交标题、摘要、分类、标签和 expectedMetadataVersion
- **THEN** 沿用原输入校验、无实际变更处理及幂等规则，不要求提供来源建议或运行模型。
