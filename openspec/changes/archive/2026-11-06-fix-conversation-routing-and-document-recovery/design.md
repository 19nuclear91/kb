# Design

## Context

动机与范围见 `proposal.md`。本变更跨网关配置和前端权限状态，保留单独设计以约束安全恢复和回归范围。

- 开发配置整体覆盖网关 routes，`application-dev.yml` 的 kb-app 谓词漏掉 `/api/conversations/**`。基础配置已有；`ConversationRouteTest` 仅加载 prod。
- `Documents.tsx` 将下载的 `onDenied` 连接到 `loseVersion`，后者向 `deniedVersions` 加入版本并持续过滤，重新读取不能消除仅由下载拒绝造成的排除。
- `UploadDialog` 的异常分支只显示错误，新版本提交未消费父页实时 `canUploadVersion`，能力查询失败也没有独立重读入口。
- `useResource` 已提供 revision、AbortController 和迟到读取保护；`DocumentDetailPage` 按文档及身份作用域重新挂载。`VersionReviewPanel` 通过 `onStatus` 提供所选版本资格。`DocumentOperations` 持有独立于子组件挂载的在途/未确认写入事实。

## Goals / Non-Goals

**Goals:**

- 在原路由及 API 契约上修复三处行为，不增加另一套授权来源。
- 区分“拒绝事实”“正在重核”“核对失败”“当前资格允许/不允许”，避免旧 true 或旧读取回调恢复已暂停的入口。
- 能力失败不会冒充阅读拒绝；明确的阅读拒绝仍及时清理对应私有内容。

**Non-Goals:**

- 不重构全局 Session、通用读取缓存、审核流程或文档删除控制器。
- 不修改后端业务代码、资源授权、会话默认开关和模型配置。
- 不新增自动上传重试、后台无限重核或浏览器持久状态。
- 不建设真实浏览器 E2E、数据库环境或外部服务验收工程。

## Decisions

### 1. 最小补齐路由，测试实际 profile 绑定

仅在开发 kb-app 路由补入会话路径。扩展现有测试，加载真实 dev/prod 配置后执行 Path 谓词，验证根路径、子路径、AI 多轮生成路径与内部路径隔离；保留 CORS 暴露会话/轮次头和 no-store 回归，并核对 AI 路由流式 metadata 与禁缓冲过滤器。

不把开发和生产全部配置合并重构，也不扩大为 `/api/**` 通配业务路由。原因是问题仅为一个路径遗漏，配置重构会扩大无关风险。

### 2. 下载拒绝触发重核，不直接失去阅读版本

文档详情为下载拒绝建立独立处理入口，不再直接调用“阅读版本被拒”的排除逻辑。处理开始即清除旧版本资格、关闭预览、使依赖旧能力的按钮不可用，同时重读文档、文档能力及所选版本审核/访问状态。

重核保持原显式选择的精确 versionId；若当前详情仍包含该版本且新的 canRead=true，恢复阅读入口，下载仍要求文档和版本各自的最新下载资格。版本不再返回或读权限被拒时只展示当前授权投影；故障提示与空集合区分。失败后提供主动重核，不对失败自动循环。

复用 `useResource` 的读取代次和版本面板 revision；父页消费版本状态时同时约束文档、版本与重核代次，不能只比较 versionId。若调整回调，需要保持稳定引用并拒绝旧面板回调，避免 effect 自触发循环。只有下载拒绝不建立持续的阅读黑名单；已有真实阅读拒绝保护不能简单删除。

不采用“下载失败后直接重新启用原按钮”或“每次详情成功无条件清空所有拒绝状态”。两者都会在独立授权或交错读取下复活旧资格。

### 3. 上传弹窗消费当前资格，并在拒绝后失效

父页向新版本上传弹窗传入明确的可提交状态、拒绝回调和主动重核入口。新版本模式不把缺少资格参数默认当作 true。按钮和表单处理函数均检查资格、本地暂停、busy 及删除独占，防止只禁用按钮却仍可通过提交事件发送请求。

明确 403/404 后先暂停并使旧资格失效，再触发文档与能力只读重核。重核成功且仍可上传，允许用户主动再次提交；false 或读取失败维持禁用，文档不可访问关闭目标交互并清理旧内容。重核入口在详情能力失败及上传暂停时均可达，加载期间防止重复触发。

复用同一个详情重核协调入口，必要时为文档/能力设置本轮完成条件，不能以一项查询成功代替全部相关事实。普通新文档上传仍采用可上传空间和真实密级字典，不扩展其后端协议。上传网络不确定分支保持原有语义，不自动提交或声称原请求未执行。

只读重核不得把已在途上传当作取消成功，不得丢失 `DocumentOperations` 的在途或未确认登记。当前文件只允许保留在当前有效弹窗内存，身份/文档变化及离开后清理。

### 4. 目标与代次隔离放在本次恢复入口

读取沿用 AbortController 与 revision；下载和上传回调还需检查其原目标及当前生命周期。文件组件取消后不得继续通知父级旧拒绝；V1 的旧响应不能隐藏 V2。重核不能覆盖新一轮能力结果，也不能在文档或身份切换后恢复旧窗口。

不新增全局权限缓存或通用请求框架。局部辅助函数/Hook 可以在实现时提取，但仅服务于本次文档详情恢复，不修改其他页面授权语义。

### 5. 验证以可重复的针对性测试为主

先增加能够复现原问题的测试，再修复并运行回归：

- 网关：`ConversationRouteTest` 覆盖 dev/prod；相关 Search/Review/Notification 路由测试保持通过，不启动监听服务器。
- 前端：文档详情组件使用真实状态流和受控 Session 替身，覆盖独立下载/阅读资格、历史版本选择、403/404、读取故障、主动恢复及延迟响应。
- 上传：断言暂停期间再次点击及表单提交均不产生额外 POST；重核成功不自动上传，网络不确定和删除协调回归不改变。
- 生命周期：以受控 Promise 交错核验新旧重核、版本切换、文档/身份切换及页面隐藏，旧回调不能恢复资格。
- 执行前端 typecheck、相关组件测试、完整 Vitest 回归与 build；后端只运行相邻网关配置测试。测试日志与临时产物放会话 scratch，项目仅保留必要工具链输出。

上述验证不代表真实网关网络、浏览器下载/Office 或外部服务已验收，不扩大为全后端与数据库集成测试。

## Risks / Trade-offs

- [独立下载拒绝被误当作阅读拒绝] → 下载入口分离，恢复依赖真实 canRead，增加“下载否/阅读是”用例。
- [重核交错或组件卸载后旧回调恢复权限] → 同时绑定身份、文档、版本和读取代次，测试晚到成功及晚到拒绝。
- [刷新全部详情导致在途写入或删除协调失真] → 保留现有写入登记，重核仅改变读取资格，不将浏览器取消当作业务撤销。
- [权限在重核之后再次改变] → 所有真实请求继续由后端鉴权，前端能力仍只是提示，不宣称授权快照。
- [没有真实浏览器或外部服务验收] → 最终报告明确模拟 DOM、进程内配置验证与未执行范围，不将测试通过等同部署验收。

## Migration Plan

无需数据库迁移、依赖升级或新环境变量。完成回归后按原流程发布网关与前端静态产物，继续使用原会话功能开关。更新 README 中“需手动补开发会话路由”的旧说明，以及前端资格恢复行为说明。

回退采用原网关和前端产物，不改动服务器数据；回退后这三处原缺陷可能重新出现。此变更不归档或同步主规格，交由后续实现与验收流程处理。
