## MODIFIED Requirements

### Requirement: 版本详情必须准确跟踪选中版本的处理状态

详情页 SHALL 展示服务端允许的元数据与版本列表，按选中 versionId 查询状态，区分当前发布版本、索引处理及审核状态。页面 SHALL 展示排队、处理中、退避、维护等待、待送审、审核中、驳回、撤回、索引待刷新、已发布及真实解析问题，不编造百分比或把 indexed 当作已发布；非终态轮询 MUST 有间隔和失败上限并随页面离开暂停。隐藏版本不补猜 ID 或数量。

#### Scenario: 新版本尚未替换旧版本
- **WHEN** 当前版本 V1 已发布，新上传的 V2 仍在解析或审核
- **THEN** 页面分别显示 V1 为当前版本、V2 为当前允许读取的处理／审核状态，不以 V1 成功或 V2 indexed 冒充 V2 已发布

#### Scenario: 向量维护或解析截断
- **WHEN** 进度返回 EMBEDDING_MAINTENANCE，或版本返回解析截断/问题摘要
- **THEN** 页面分别显示维护等待或相应解析提示，不把维护等待标成失败，不伪造缺失正文

#### Scenario: 页面离开或权限拒绝
- **WHEN** 用户离开详情页、页面隐藏，或轮询返回 401、403、404
- **THEN** 该轮询停止，恢复页面时先重新读取当前事实，不继续无界后台请求

#### Scenario: 普通读者看不到候选版本
- **WHEN** 普通读者只能取得 V1，V2 为未发布候选
- **THEN** 列表不展示 V2 占位、状态、文件名或隐藏数量，不尝试按连续版本号补查

### Requirement: 文档操作按钮必须结合独立能力和版本状态

详情页 SHALL 依据当前独立操作能力、所选版本的访问及审核状态控制下载、新版本上传、失败重试和审核相关操作；能力读取失败不默认启用。重试 MUST 满足 edit 与对应版本可重试条件，候选刷新走独立确认。文档级 canDownload 等标记不保证所选未发布版本可读，实际操作仍重新鉴权，拒绝后更新页面事实。

#### Scenario: 可查看但不可下载或编辑
- **WHEN** 用户可读取详情，但能力响应的 canDownload、canUploadVersion 和 canRetry 均为 false
- **THEN** 页面保留查看行为，禁用或隐藏相应操作，不依据管理员名称或 ownerId 重新启用

#### Scenario: 版本可重试且能力允许
- **WHEN** 选中版本处于可重试失败状态且当前版本操作能力允许
- **THEN** 用户可以向该明确版本发起一次重试，并显示新返回的处理状态
- **AND** 提交期间防止重复点击，超时不自动重发

#### Scenario: 点击前授权已被撤销
- **WHEN** 页面曾取得 true 标记，但实际下载或上传版本请求被新权限拒绝
- **THEN** 页面按最新拒绝更新操作状态，不继续依赖旧标记重试放行

#### Scenario: 父文档可下载但候选不可访问
- **WHEN** 文档级 canDownload=true，但所选新候选版本的访问未确认或被拒
- **THEN** 不按文档级标记启用该版本下载，清理失效的预览和入口

## ADDED Requirements

### Requirement: 审核私有内容不得进入普通版本摘要

文档中心及普通版本列表 SHALL 只消费当次授权投影，不展示待审意见或未经当前候选资格检查的新版文件资料。上传受理可使用返回的版本 ID 跟踪本人最小状态；没有 view 时仍不能读取正文、意见或文件。默认文件入口继续指向当前发布版本，不自动切到最高版本号。

#### Scenario: 版本号最高但尚未通过
- **WHEN** 当前已发布 V1 而 V2 为最高版本号且仍待审
- **THEN** 默认阅读与文件入口仍为 V1；只有明确选择且有资格时才打开 V2 的候选界面
