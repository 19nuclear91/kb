# Spec Delta

## MODIFIED Requirements

### Requirement: 登录尝试必须被节流

系统 MUST 对登录尝试施加节流；针对同一账户的连续失败达到阈值后，MUST 在窗口期内延迟或拒绝后续尝试，且节流 MUST 自动过期，不得造成需要人工干预的持久锁定。用户名密码登录 SHALL 同时按来源计数：同一来源在窗口内的凭据失败达到独立阈值后，MUST 拒绝该来源的后续登录尝试，无论尝试哪个用户名。来源检查 MUST 先于账户查询与凭据校验；登录成功 MUST NOT 清除来源计数。来源未知时只按账户节流。节流拒绝 MUST 与凭据失败使用相同的响应。

#### Scenario: 连续失败触发节流

- **WHEN** 同一账户在窗口内连续失败达到阈值
- **THEN** 后续登录尝试被拒绝或延迟，且不建立会话

#### Scenario: 节流自动过期

- **WHEN** 节流窗口过去后凭据正确的用户再次登录
- **THEN** 登录成功，无需人工解锁

#### Scenario: 对他人用户名的失败尝试

- **WHEN** 攻击者以某用户名为目标持续制造失败
- **THEN** 该用户在该窗口过后仍能以正确密码登录，无需人工干预

#### Scenario: 同一来源轮换用户名

- **WHEN** 同一来源在窗口内对多个不同用户名累计凭据失败达到来源阈值，且每个用户名各自未达到账户阈值
- **THEN** 该来源的后续登录尝试被拒绝，不建立会话，包括凭据正确的尝试

#### Scenario: 来源节流拒绝先于凭据校验

- **WHEN** 已达到来源阈值的来源再次提交登录
- **THEN** 返回与凭据失败相同的拒绝，不查询账户、不校验密码、不增加账户计数，也不写入审计

#### Scenario: 登录成功不清除来源计数

- **WHEN** 某来源已有凭据失败计数，随后从该来源以正确凭据成功登录任一账户
- **THEN** 该账户的失败计数被清除，该来源的失败计数保持不变，并继续计入后续失败

#### Scenario: 来源节流自动过期

- **WHEN** 来源节流窗口过去后，从该来源以正确凭据登录
- **THEN** 登录成功，无需人工解锁

#### Scenario: 来源未知时只按账户节流

- **WHEN** 登录请求的来源未知
- **THEN** 该请求不读取、也不增加任何来源计数，仍受账户节流约束

### Requirement: 登录成败必须可审计

系统 MUST 记录登录成功事件；登录失败尝试 MUST 可追溯，允许按来源与用户名聚合。来源已知时，失败记录 MUST 保留该来源；来源未知时 MUST NOT 补造来源。审计与日志 MUST NOT 包含密码或会话令牌。

#### Scenario: 登录成功留下事件

- **WHEN** 登录成功
- **THEN** 产生可按时间与目标检索的审计事件

#### Scenario: 失败尝试可追溯

- **WHEN** 登录失败反复发生
- **THEN** 系统保留可查询的失败记录，逐条或聚合
- **AND** 记录中不出现密码或令牌

#### Scenario: 失败记录保留来源

- **WHEN** 来源已知的登录请求因凭据失败或账户停用而被拒绝
- **THEN** 失败记录同时包含尝试的用户名与规范化后的来源，可按两者聚合

#### Scenario: 来源未知的失败记录

- **WHEN** 来源未知的登录请求失败
- **THEN** 失败记录只包含尝试的用户名，不出现来源字段或占位值

## ADDED Requirements

### Requirement: 登录来源必须取自入口代理写入的客户端地址

系统 SHALL 只采用 `X-Real-IP` 请求头中的单个 IPv4 或 IPv6 字面量作为登录来源，并将同一地址的不同写法规范化为同一来源。该头缺失、为空、包含多个值或不是 IP 字面量时，来源 MUST 视为未知，且 MUST NOT 为判断来源而发起域名解析。系统 MUST NOT 把 `X-Forwarded-For`、`Forwarded` 或请求的连接地址当作登录来源。

#### Scenario: 合法地址成为来源

- **WHEN** 登录请求携带单个合法的 `X-Real-IP`
- **THEN** 该地址规范化后用于来源节流与失败审计

#### Scenario: 同一地址的不同写法

- **WHEN** 两次登录请求的 `X-Real-IP` 是同一 IPv6 地址的不同写法（大小写不同，或零段压缩方式不同）
- **THEN** 两次请求计入同一来源

#### Scenario: 非法或多值视为未知

- **WHEN** `X-Real-IP` 为空、包含逗号分隔的多个值、带端口或方括号、是主机名，或出现多个同名头
- **THEN** 来源视为未知，不发起域名解析，登录按来源未知处理

#### Scenario: 不采信其他转发头

- **WHEN** 请求没有 `X-Real-IP`，但携带 `X-Forwarded-For` 或 `Forwarded`
- **THEN** 来源视为未知，不从这些头或连接地址推断来源
