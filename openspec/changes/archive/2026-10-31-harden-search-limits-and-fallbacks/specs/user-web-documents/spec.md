# Spec Delta

## MODIFIED Requirements

### Requirement: 搜索必须只消费现有授权检索能力

搜索页 SHALL 通过 POST JSON 提交 query 及有界数量参数，展示服务器返回的有序片段、标题和版本信息。首期 SHALL 搜索全部当前可见内容，不发送未支持的空间筛选或使用旧 GET 检索；失败不能伪装为空结果，空结果不得推断存在不可见文档。页面须按 8000 个 Unicode code point 的默认上限校验查询，不静默截断；服务端是最终判定。400、413、429 和 503 SHALL 按搜索上下文呈现，容量拒绝不得误报为部门 AI 额度不足，Retry-After 不触发自动重发。

#### Scenario: 提交搜索
- **WHEN** 用户输入关键词并提交
- **THEN** 请求发往不含关键词的固定 POST 路径，页面按实际响应顺序展示结果
- **AND** 页面地址、持久存储和日志不保存该关键词

#### Scenario: 未命中和依赖故障
- **WHEN** 检索成功返回空列表，或接口返回 503
- **THEN** 前者显示未找到可用结果，后者显示检索暂不可用，两种状态可区分

#### Scenario: 查询超过字符上限
- **WHEN** 用户输入超过 8000 个 code point 的查询，或输入包含 NUL 或孤立代理项
- **THEN** 页面提示修正输入并阻止提交，不截断后发送；补充字符按一个 code point 计算

#### Scenario: 服务端拒绝输入
- **WHEN** 搜索返回 400 或 413
- **THEN** 页面分别显示查询输入不符合要求或搜索请求过大，不把搜索正文超限描述为上传文件过大
- **AND** 只在当前页面保留输入，不显示被拒请求的成功结果

#### Scenario: 搜索用户并发超限
- **WHEN** 搜索返回 429，可选带有 Retry-After
- **THEN** 页面提示搜索请求过于频繁、稍后重试，不提示部门 AI 额度不足
- **AND** 不自动再次搜索、不循环倒计时发请求；用户可以在条件允许时主动重新提交

#### Scenario: 合法的降级结果
- **WHEN** 搜索通过 BM25 或原候选排序回退返回合法成功结果
- **THEN** 页面按响应原顺序显示片段，不自行重排、补取或自动重复请求以追求非降级结果

#### Scenario: 新请求发出后旧请求才返回
- **WHEN** 用户重新提交搜索、离开页面或切换身份，旧请求随后才返回
- **THEN** 旧成功、错误及 Retry-After 信息不得覆盖新页面状态，取消本地等待不被解释为服务端工作已经退出
