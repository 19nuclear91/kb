# Spec Delta

## MODIFIED Requirements

### Requirement: 检索仅通过 POST 请求体接收查询

系统 SHALL 仅通过 `POST /api/search` 的 JSON 请求体接收检索词 `query`、候选数 `candidates` 和结果数 `topK`。成功响应 SHALL 保持既有 JSON 字段、授权过滤和排序语义；缺省数量与现有接口一致。URL 查询参数 MUST NOT 成为检索输入。请求须遵守 search-resilience 的字符、正文、数量、时间及容量限制；输入或容量被拒时不得以成功空列表替代错误。

#### Scenario: 合法检索请求
- **WHEN** 已登录且完成必需改密的用户以 POST JSON 提交非空 `query` 和合法数量
- **THEN** 系统按该用户当前服务端身份执行授权检索，并以既有响应结构返回结果
- **AND** 请求 URL 不含检索词或数量参数

#### Scenario: 缺省数量
- **WHEN** POST 请求体只包含合法的 `query`
- **THEN** 每路候选数默认为 50，`topK` 默认为候选数

#### Scenario: 无效请求体或 URL 参数
- **WHEN** POST 请求体缺少或提供空白 `query`、数量超出现有 1–200 范围，或 `/api/search` 的 URL 携带查询参数
- **THEN** 系统返回固定且不回显输入值的 HTTP 400 响应，不执行检索

#### Scenario: 调用方伪造身份或向量
- **WHEN** 请求体包含 `userId`、角色、密级、`queryVector` 或 profile 声明
- **THEN** 系统不将这些值作为身份、授权范围或查询向量，仍只使用服务端解析的主体与既有查询配置

#### Scenario: 请求触发新增限界
- **WHEN** 查询字符、实际请求体或搜索并发超过配置上限
- **THEN** 分别返回约定的 400、413、429 或 503，不回显输入，不执行被拒请求的召回

### Requirement: AI 召回使用相同的保密检索入口

AI 服务 SHALL 通过 `POST /api/search` 的 JSON 请求体发送用户问题与召回数量，MUST NOT 把问题放入 URI；它 SHALL 透传调用者会话并继续使用同一授权检索响应与引用契约。仅 HTTP 200、code=200、data 为合法数组的成功响应可提供材料或真实空结果；检索拒绝、超时、依赖故障、空 HTTP 响应及损坏协议 MUST 显式失败，不转换为正常空集合，也不以服务账号、旧材料或放宽权限重试。

#### Scenario: 问答召回成功
- **WHEN** 用户提交 AI 问题并具有可见文档
- **THEN** AI 到业务应用的检索请求使用不含问题的固定路径及 JSON 请求体，携带原调用者会话
- **AND** 引用身份、来源字段及 SSE 事件语义与现有契约一致

#### Scenario: 召回被拒或上游不可用
- **WHEN** 业务应用拒绝召回或检索上游不可用
- **THEN** AI 明确结束为检索错误，不产生正常无结果回答，不以服务账号或无权限条件重试
- **AND** 对外信号不披露目标文档是否存在，原始 HTTP 状态和固定失败类别仅用于受控处理

#### Scenario: 合法的真实空结果
- **WHEN** 授权检索返回 HTTP 200 且响应为 code=200、data=[]
- **THEN** AI 使用既有固定无结果回答且不调用模型，不区分未命中与无可见范围

#### Scenario: 空响应或业务失败包装
- **WHEN** 上游返回 204、HTTP 200 空正文、null 根、缺少成功 code 或数组 data，或 HTTP 200 包装业务失败
- **THEN** AI 将其作为协议失败，触发安全错误收尾，不直接空完成或仅保留心跳

#### Scenario: 非空数组没有合法引用
- **WHEN** 非空成功数组中的记录经既有身份校验后全部无效
- **THEN** AI 将其作为协议失败，不把损坏材料误报为真实零命中
- **AND** 混合数组仍按已有引用规则保留合法项、丢弃损坏身份项，缺失的可选来源不伪造

#### Scenario: 检索取消或等待超时
- **WHEN** 独立检索预算到期或所属生成请求被取消
- **THEN** 停止上游读取，不自动重发；超时进入错误收尾，用户取消继续使用既有取消语义
