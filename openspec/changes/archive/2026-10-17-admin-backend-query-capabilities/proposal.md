# 后端管理查询能力提案

## Why

项目已有用户、部门、角色、空间授权和文档管理写接口，但管理侧缺少独立于正文阅读权限的文档清单、完整的身份授权查询以及可跨目标检索的审计接口。补齐这三类后端查询，可以让现有管理操作具备可靠的查找和追溯能力，并保持管理资格与内容读取资格分离。

## What Changes

- 新增管理侧文档分页清单，仅按当前空间 `manage` 或 `space:manage-all` 返回文档 ID、空间 ID
  和空间归档标记；包含归档空间中的未删除文档，不返回标题、文件名或正文。
- 补齐用户分页检索、指定用户角色绑定、脱敏外部身份绑定、当前用户有效功能权限和密级字典查询；保留原用户列表与会话响应的结构。
- 新增绑定具体空间或文档管理资格的最小授权主体检索，允许空间管理员选择用户、角色和部门，不开放完整身份目录。
- 新增全局审计分页检索，支持操作者、操作域、目标、结果、时间、请求标识与登录用户名条件，能够查到目标 ID 为空的登录失败事件。首期数据源明确限定为
  `sys_identity_audit`，不宣称覆盖 Redis AI 审计或独立的 Embedding 操作记录。
- 新增独立的 `audit:read`、`identity:external:read` 功能权限，设计一次性迁移、撤权不恢复和权限目录兼容规则。
- 为新查询约定有界分页、稳定排序、当前请求鉴权和最小响应投影；仅安排离线单元测试、内存映射检查、SQL
  人工审阅和构建校验，移除集成测试、外部组件运行及文档内容/示例测试任务。

## Capabilities

### New Capabilities

- `document-administration`: 文档最小管理清单、管理范围过滤和归档内容的管理可达性。
- `audit-query`: 现有管理与登录审计的跨目标检索、稳定分页、独立授权和安全投影。

### Modified Capabilities

- `identity-department`: 增加有界身份检索、用户绑定关系查询和服务端密级字典读取。
- `functional-authorization`: 增加两个独立读取权限、当前用户有效权限查询及新权限初始化规则。
- `space-authorization`: 增加按具体资源管理资格授权的最小主体检索，保持完整身份目录与内容读取边界。

## Impact

- 主要修改范围为 `kb-app` 的 `auth`、`document`、`space`，新增独立 `audit` 查询包；沿用 MyBatis、Sa-Token、既有主体句柄和
  PostgreSQL。
- 新 API 统一位于网关已覆盖的 `/api/admin/**`、`/api/auth/**`；无需新增网关路由。新增 DTO 留在业务主应用，`kb-common`
  不增加运行时依赖。
- 增量 Flyway 迁移以实施时最新版本为准，当前预期 V19；加入新权限的一次性初始化与查询索引，不修改 V1–V18 历史迁移。
- 采用新增查询路径保持既有 API 兼容；新权限入库后不得与不认识权限目录的旧 app 二进制混部或直接回退。
- 本变更只规划后端查询能力，不含前端、上传幂等、文档改名、部门配额、人工结算、OCR、存储处置或对既有写操作的改造。
- 验证期间不启动应用或监听端口，不连接 DB、Redis、MinIO、Docker、模型或嵌入式替代服务；迁移 SQL 仅作为文件交付，不在本变更内执行。离线检查不构成实际
  SQL、迁移、索引性能或跨服务行为的运行证明。
