# Proposal

## Why

聊天审计目前分散在 Redis 有界列表和 PostgreSQL 多轮结算记录中，缺少可长期追溯的统一查询；旧单轮记录还无法可靠区分零消耗和缺失 usage。需要为独立授权的管理人员提供跨部门聊天用量与审计查询，并落实已确认的 180 天可配置保留策略。

## What Changes

- 统一记录单轮、多轮聊天的调用元数据、真实用量状态、额度结算状态和追加式审计事件，由 kb-app 持久化到 PostgreSQL；kb-ai 通过独立服务鉴权接口提交，不获得数据库访问能力。
- 提供聊天用量汇总、按日/部门/用户分组、调用事件筛选和安全详情；真实 token、计划扣除额度、已确认结算额度分别展示，未知用量不补零。沿用单轮、多轮各自的额度计算规则。
- 新增 `ai:usage:read`、`ai:audit:read`，分别保护用量统计与调用审计；管理人员按精确权限跨部门读取，权限不隐含正文或私有会话读取资格。
- 增加独立管理页面 `/admin/ai/usage`、`/admin/ai/audits`，复用现有会话、权限生命周期、精确整数和故障恢复约定。
- 默认保留 180 天，可配置；有界自动清理仅处理已经终结且不再需要结算或核查的记录，待结算、待核查和执行中记录继续保留。
- 采集从明确启用的时间开始，标明覆盖范围；不把已裁剪的 Redis 历史或未记录的字段伪造为完整历史。不纳入 Embedding、rerank、第三方解析、金额核算、导出和人工改账。
- 部署兼容性：新增权限迁移前须排空不识别新权限的旧 app；启用持久采集后，登记/调度意图无法确认的调用不得开始模型调用。该可用性变化须在升级说明中明确。

## Capabilities

### New Capabilities

- `ai-usage-audit`: 聊天调用与审计持久化、真实用量和结算口径、内部采集鉴权、统计与审计查询、保留清理及历史覆盖边界。
- `admin-web-ai-usage`: AI 用量与审计管理页面的筛选、汇总、事件详情、精确数值和当前身份/权限生命周期。

### Modified Capabilities

- `functional-authorization`: 增加独立 AI 用量和审计读取权限及一次性初始化、撤权和升级兼容要求。
- `admin-web-access`: 注册两个 AI 管理页面、独立读取门禁、管理导航与合法登录返回路径。

## Impact

- kb-app：新增独立 AI 观测模块、Flyway 迁移、权限目录、内部元数据接收接口、查询 API 和保留清理任务；多轮创建/终结/结算确认事务同步更新观测记录。
- kb-ai、kb-common：服务签名与元数据 DTO、单轮调用生命周期与 usage 标记、幂等元数据投递；继续复用现有 Redis 配额和多轮固定结算意图，不扫描 Redis 列表生成报表。
- kb-web、kb-gateway：新增管理页面及导航、API 适配、路由与 no-store 策略；原 `/admin/audits` 与 `/api/admin/audits` 保持原管理和登录事件范围。
- 文档与验证：交付采集启停、数据覆盖、保留策略与升级回退说明；验证仅采用离线进程内单元/架构测试、无连接映射、类型检查、静态构建和 OpenSpec 结构校验。不执行集成测试、端到端测试、数据库/Redis 等外部环境运行任务或文档内容断言测试；真实事务、锁与清理竞态不声明已验证。当前只修改规划文件，不实施或部署。
