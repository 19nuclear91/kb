# Spec Delta

## Purpose

为个人私有会话提供浏览器管理和多轮问答交互，约束会话分页、当前权限下的历史展示、流式增量、幂等重试及取消后的状态核对，使用户看见的回答与后端已经保存的轮次事实一致，并能理解模型或功能尚不可用的情况。

## ADDED Requirements

### Requirement: 助手入口必须区分功能关闭与运行时不可用

用户端 SHALL 通过显式公开部署配置控制会话功能，缺省关闭，关闭时展示未启用且不发起会话或生成请求。开启后 SHALL 按真实响应处理不可用，503 展示暂不可用且不阻断文档/搜索。用户端 MUST NOT 回退旧单轮占位接口或伪造正常多轮回答；404 不作为全局功能开关判断。

#### Scenario: 会话功能关闭
- **WHEN** 前端会话配置为关闭
- **THEN** 助手页面展示未启用状态，不请求会话列表、新建或生成入口

#### Scenario: 功能开启但模型未配置
- **WHEN** 会话配置开启而生成返回 503
- **THEN** 页面显示问答暂不可用，保留用户本次输入，不增加伪造的已完成回答
- **AND** 文档中心和搜索仍可独立使用

#### Scenario: 某会话不可访问
- **WHEN** 指定会话接口返回 404
- **THEN** 页面清除该会话的旧正文并提示不可访问，不据此关闭全部助手功能

### Requirement: 会话侧栏必须遵循服务器的创建和分页事实

用户端 SHALL 展示本人会话并支持新建和删除，按服务器固定创建顺序使用不透明游标加载。标题只采用显式输入或服务器默认值，不从问题、回答或来源自动生成。创建的一次提交和匹配重试 SHALL 使用相同请求标识及标题，不把创建视为已经生成回答。

#### Scenario: 新建和创建重试
- **WHEN** 用户创建会话且响应丢失后重试同一次提交
- **THEN** 页面复用相同请求标识和规范化标题，采用服务器返回的同一会话
- **AND** 没有成功生成轮次时不显示助手回答

#### Scenario: 会话活动更新
- **WHEN** 较早创建的会话完成一轮回答后继续加载侧栏下一页
- **THEN** 页面保持服务器创建顺序和游标，不将活动更新时间作为新的分页位置

### Requirement: 历史展示必须服从当前可见性和保存状态

用户端 SHALL 按轮次序号加载历史，以服务端返回的 answer、visibility 和 status 展示内容。BLOCKED MUST 清除整条旧助手正文和全部引用，使用通用提示，不披露受限来源；FAILED、CANCELLED、INTERRUPTED 等未完成状态 SHALL 明确标识，不能伪装完整成功，不要求响应额外提供 incomplete 字段。

#### Scenario: 旧回答的来源被撤权
- **WHEN** 页面曾展示回答，再读取该轮得到 visibility=BLOCKED、answer=null 和空引用
- **THEN** 旧助手正文和引用均被清除，只展示通用不可查看提示及响应允许保留的本人原问题

#### Scenario: 打开保存了部分前缀的轮次
- **WHEN** 服务端返回 FAILED、CANCELLED 或 INTERRUPTED 的部分回答
- **THEN** 页面只展示当前允许读取的已保存前缀并标记未完成，不补回客户端曾见但服务器未保存的尾部

#### Scenario: 历史分页期间新增轮次
- **WHEN** 用户加载历史下一页时会话已有新轮次
- **THEN** 页面按服务端序号合并，不重复显示已加载轮次或改变其顺序

### Requirement: 生成请求必须只提交本轮输入并遵守串行约束

用户端 SHALL 只提交 question、requestId、expectedLastTurnSeq 及当前认证头，问题非空且最多 8,000 个 Unicode code point，不静默截断，不提交历史、角色、来源或助手正文。同一会话活动轮次尚未关闭时 SHALL 限制新提交；多标签页冲突的最终判定服从服务器 409，页面不得用覆盖历史的方式消除冲突。

#### Scenario: 正常发送问题
- **WHEN** 用户在可提交会话输入问题并发送
- **THEN** 请求只包含原问题、该次请求标识和服务器最新序号，不把本地聊天记录作为 history 一并提交

#### Scenario: 两个标签页并发
- **WHEN** 本页提交因其他标签页已创建轮次而返回 409
- **THEN** 页面刷新会话元数据和历史，保留尚未确认提交的输入，并等待用户决定是否重新发送
- **AND** 不自动以新标识循环提交

### Requirement: 流式响应与匹配重试必须按不同协议处理

用户端 SHALL 根据响应 Content-Type 消费首次 SSE 或匹配重放 JSON，正确处理 citation、delta、done、error 及保活注释。网络分块 MUST 不导致字符或事件丢失，畸形或超限流 SHALL 停止并进入状态核对。匹配重试 MUST 保留原请求标识、原问题和原预期序号，收到 replay 后读取持久轮次，不重放或重新启动 SSE。

#### Scenario: 中文字符和事件跨网络块
- **WHEN** SSE 的 UTF-8 字符、事件边界或 CRLF 被拆分到多个网络块，或出现多行 data 与注释帧
- **THEN** 页面按完整事件连续展示增量，保活不被显示为正文或重复事件

#### Scenario: 首次响应丢失后匹配重试
- **WHEN** 用户重试内容相同且状态未知的原请求，接口返回 application/json 且 replayed=true
- **THEN** 页面使用返回的会话/轮次身份查询历史，不把 JSON 当成流文本或触发第二次生成

#### Scenario: 流中发生错误或畸形数据
- **WHEN** SSE 返回 error、畸形帧或超过既定上限
- **THEN** 页面停止消费，将该次结果转入状态核对，不显示成功 done

### Requirement: 停止和断流后必须核对服务器持久轮次

用户停止生成、离开当前会话或退出时，用户端 SHALL 关闭本页持有的生成连接。身份仍有效且页面活跃时，停止、异常、未收到 done 的流结束及完成通知后 SHALL 读取持久轮次；离开后在再次打开时核对，退出后不继续保护查询。仍在处理时只允许有上限查询，不宣称续传、补全未保存文本或凭本地取消覆盖服务器终态。

#### Scenario: 用户停止生成
- **WHEN** 用户在输出期间点击停止
- **THEN** 连接被关闭，页面显示正在核对，并以之后读到的已保存前缀和状态更新结果
- **AND** 查询仍为 RUNNING 时不会立即伪造 CANCELLED；到达核对上限时提示稍后刷新

#### Scenario: 停止与完成同时发生
- **WHEN** 本地停止之后服务器读取结果已经为 COMPLETED
- **THEN** 页面保留完成结果，不因本地停止覆盖为取消

#### Scenario: 流结束但没有完成事件
- **WHEN** 连接出现 EOF 而未收到 done
- **THEN** 页面将状态视为未确认并查询持久结果，不把 EOF 自动作成功回答

### Requirement: 生成状态和用量结算必须分别显示

用户端 SHALL 分别处理生成状态、真实 usage 状态和结算状态。COMPLETED 且结算待确认 SHALL 仍显示生成成功；UNKNOWN 的真实 token 数 MUST 不显示成零，chargedTokens 不得冒充真实消耗。引用 SHALL 标为本轮参考材料，不宣称逐句证明模型回答。

#### Scenario: 回答完成但结算待确认
- **WHEN** 历史返回 COMPLETED 而 settlementState 尚未确认
- **THEN** 页面保留完整可见正文，独立提示用量确认中，不引导用户重复生成以“修复”结算

#### Scenario: 真实用量未知
- **WHEN** usageStatus=UNKNOWN、真实 token 字段为空而 chargedTokens 有值
- **THEN** 页面显示真实用量未知，并将额度扣除值作为独立信息，不把空值转成零

### Requirement: 删除会话必须清理当前客户端可达内容

用户端 SHALL 支持本人会话删除，在提交前让用户确认目标。删除成功后 SHALL 从侧栏移除会话，清除该会话的正文、引用和临时流状态；删除当前生成会话时先关闭本页持有连接。重复删除的 204 SHALL 视为成功，旧流或在途历史响应 MUST 不恢复已删除页面内容。

#### Scenario: 删除正在生成的会话
- **WHEN** 用户确认删除当前会话且后端返回 204
- **THEN** 本页生成连接关闭，页面返回可用会话入口，正文与引用被清理
- **AND** 晚到的增量或历史读取不能重新插入侧栏或恢复该会话

#### Scenario: 删除拒绝或结果不确定
- **WHEN** 删除返回拒绝或网络结果不确定
- **THEN** 页面显示对应失败/待确认状态，不声称正文已经从服务器删除；后续读取继续服从服务器事实
