# Design

## Context

动机与功能范围见 [proposal.md](proposal.md)。当前项目只有六个 Maven 模块，没有前端工程。与本变更直接相关的实现事实如下：

- `AuthController` 返回 `R<LoginResult>`，以 `satoken` 请求头传递会话；强制改密状态只允许 me、改密和退出等既有必要操作。普通错误没有统一的结构化业务错误码，不能解析中文消息来判断身份状态。
- `DocumentController` 已提供上传、列表、详情、版本、进度、新版本上传、重试、指定版本预览/下载。列表只有 spaceId/page/size 过滤；进度是状态事实，没有可靠解析百分比。
- `SpaceSummary` 仅含 viewable/manageable，列表不包含只有空间 edit 的主体；`DocumentSummary` 不含下载或编辑能力。现有功能权限查询不返回资源 ACL，不能解决这两个缺口。
- `SearchController` 只接受 POST JSON query/candidates/topK，没有空间筛选。检索片段与引用已包含版本身份；来源位置只是解析提示。
- 会话 API 直接返回 DTO，不套 `R<T>`；生成首次为 SSE，匹配重试为 JSON。app 和 AI 的会话控制器都由 `kb.conversation.enabled` 控制，默认关闭；没有具体多轮模型时，开启后的生成入口返回 503。
- 后端会对每次历史读取重新核对全部来源，返回 BLOCKED 时正文为空。既有测试大量使用 Mockito、standalone MockMvc 和受控流，不能据此宣称真实多服务链路已验证。

## Goals / Non-Goals

**Goals:**

- 形成普通用户可操作的浏览器闭环，页面状态、权限提示和恢复行为与服务端事实一致。
- 通过新增只读查询解决上传候选和操作按钮问题，不改既有上传、阅读、搜索及生成契约。
- 让模型缺失、功能关闭和依赖故障成为可理解的产品状态，前端构建与进程内单元测试可独立运行。

**Non-Goals:**

- 不新增模型供应商、认证机制、数据库迁移或管理员功能；不把现有管理权限解释为内容读写权限。
- 不提供离线阅读、回答持久缓存、SSE 续传或新的后端幂等保证。其他功能排除项沿用 proposal。
- 本变更不编写或执行集成、端到端、真实浏览器测试，不启动完整应用或 HTTP 监听，不运行/连接数据库、Redis、对象存储、容器、嵌入式替代组件及真实模型服务；说明文档、配置示例和 Javadoc 文案不作为测试对象。

## Decisions

### 1. 独立前端工程与稳定的页面边界

采用 `kb-web/`，使用 React、TypeScript、Vite、Ant Design 和客户端路由，npm 与提交的 `package-lock.json` 固定依赖。实施时选择互相兼容的明确版本并记录 Node 要求，不使用依赖版本 `latest`，不将 Node 构建挂入父 POM。

| 路由 | 页面及主要交互 |
|---|---|
| `/login` | 用户名密码登录，凭据失败使用统一提示 |
| `/change-password` | 强制改密，可退出；成功后重新读取 me |
| `/documents` | 默认登录落点、空间筛选、分页、上传弹窗 |
| `/documents/:documentId` | 元数据、版本列表、选中版本状态、预览/下载、新版本上传、失败重试 |
| `/search` | 站内授权搜索、结果片段和版本引用抽屉 |
| `/assistant`、`/assistant/:conversationId` | 会话侧栏、历史、输入区和参考来源抽屉 |
| `/account` | 当前身份信息及自助改密 |

桌面采用导航侧栏加内容区，长表格与长正文支持滚动，保留加载、空结果、失败、不可用状态。首期交付面向 PC 浏览器的界面，本次验证采用模拟 DOM 中的单组件测试；基础窄屏可用性不扩展为移动端专项交付。上传和引用使用弹窗/抽屉，不增加独立页面。

选择独立 SPA 是因为项目没有可复用的前端基础，且现有网关已经提供所有调用路径；服务端模板页面和嵌入 Maven 构建会增加前后端耦合。首期不引入额外全局状态框架或持久化查询缓存，按会话、页面和请求维护有界内存状态。

### 2. 明确四类传输协议与凭据边界

所有受保护请求显式带登录结果中的 tokenName/tokenValue；会话调用落实为现有 `satoken` 头。本地登录令牌放在当前标签页的 sessionStorage，页面刷新后通过 me 重新确认主体；不建立长期“记住我”机制。密码仅存在于提交期间的表单内，令牌不进入 localStorage、URL、日志或遥测。

前端 API 层分别适配：

1. 登录、文档、搜索及新增查询的 `R<T>`：同时核对 HTTP 状态与成功封装。
2. 会话直接 DTO：不统一解包 `.data`；204 不解析 JSON。
3. 首次 SSE 与幂等重放 JSON：依据 Content-Type 分派，处理 chunk 边界、UTF-8 跨块、CRLF、注释保活及多行 data；设置事件帧和累计输出上限，畸形或超限时中断并核对服务端状态。
4. 文件流：先检查 HTTP 状态与实际媒体类型，再消费文件；错误 JSON 不作为文件下载。

流解析默认每个事件最多 1 MiB、累计回答最多 64,000 个 Unicode code point、参考材料最多 256 项；后两项与既有会话默认上限对齐，部署调高后端限额时须同步配置客户端界限。问题按 Unicode code point 校验至多 8,000，客户端不静默截断原问题。

Java long 身份字段在 API 层无损解码，页面内部按十进制字符串保存 ID；UUID 保持原字符串。数值序号按协议范围校验，并以无损 JSON 序列化提交 expectedLastTurnSeq 等数值字段，避免先经 JavaScript number 舍入。该策略不修改后端原有 JSON 数字类型。

401 时取消当前请求、清理令牌与页面内容并回登录页。业务 403 时至多重新读取一次 me：若仍要求改密则进入改密页；若主体被拒或身份无法确认则遮蔽受保护内容并显示相应拒绝/不可用状态；若身份正常则保留业务拒绝提示，不循环重试。404 清除对应资源内容；503 不能伪装成空集合。

不引入 BFF、Cookie-only 认证或长期“记住我”，原因是 AI 与内部会话路径明确使用请求头凭据；未来接企业扫码时另行设计其专用结果页与绑定交接。

### 3. 新增上传候选查询，不扩展管理空间清单

新增 `GET /api/auth/upload-spaces`，由 space 包的 controller/service 提供，路由沿用现有网关。成功为 `R<QueryPage<UploadSpaceCandidate>>`，每项只含 `spaceId`、`name`；仅接受 limit/cursor，按 spaceId 升序，默认 20、上限 100，使用 limit+1 生成 hasMore，不返回全局总数。

服务端从当前会话铸造一次主体句柄并先 requireEnabled，再按空间 edit 解析范围，查询未归档空间。只有文档例外 edit 的用户不获得向整个空间创建新文档的资格；只有 manage、space:manage-all 或 view 也不推导 edit。通过新的、独立授权的候选投影允许 edit-only 空间被选中，不改变既有 `/api/admin/spaces` 的 view/manage 契约。

复用现有参数和游标设施，游标种类为 upload-spaces，仅表示位置，不代表授权；每页重新解析资格。未知/重复参数、非法 limit 和错误种类游标返回 400。无会话 401，停用/强制改密 403，无候选成功空页，依赖不可确认安全 503；成功 no-store。新增只读调用不写审计、不连接对象存储。

不采用扩展旧 SpaceSummary 的方案，因为单加 editable 仍无法覆盖旧清单排除的 edit-only 空间，并会混淆管理清单与上传候选的边界。

### 4. 新增可查看文档的独立操作能力

新增 `GET /api/documents/{documentId}/capabilities`，不接受查询参数，成功为 `R<DocumentCapabilities>`，只含 `documentId`、`canDownload`、`canUploadVersion`、`canRetry`。由 document 包 service 在同一只读请求中复用当前主体句柄，先按既有文档 view 谓词确认父文档当前可查看，再独立按 download、edit 查询该文档；canUploadVersion 和 canRetry 都取实际 edit 资格。

这些值表示权限资格，不表示文件存在、格式可预览、指定版本可重试或提交时仍有资格。版本是否存在、是否已发布及是否有失败任务，由版本/进度数据与实际操作响应决定。manage、功能权限、ownerId、上传成功和角色名称都不作为推导条件。

父文档不存在、不可见、已归档、超密级或已删除统一 404；无会话 401，调用者停用/强制改密 403，路径/参数非法 400，依赖故障安全 503。响应 no-store，无正文、ACL、底层对象键和拒绝原因明细。旧 DTO 和写入入口不变，不通过这个接口授予新权限。

页面只对当前打开的文档详情按需查询能力，避免列表逐项请求；列表只提供“查看详情”。失败时禁用相关操作，不把未知能力当成 true；点击操作仍处理最新服务端拒绝。

### 5. 文档、搜索与文件的实际行为

- 文档空间过滤复用既有空间目录，排除 archived，并依据实际文档列表呈现内容；不把其 manageable 或目录可见性当成内容授权。文档例外可见但空间目录不可见的内容仍由“全部文档”展示，不额外枚举空间名称。
- 上传先读取新候选和真实密级字典。字典按服务端实际数值展示，不写死 0–3 或猜测级别名称；文件大小/类型的前端提示与后端约束对齐，但实际检验仍以服务端为准。上传、新版本上传和重试解析都没有新增幂等协议，提交期间防重复，超时不自动重发。
- 成功上传记录返回的 documentId/versionId，并按该 versionId 查询进度；新版本未发布时继续展示旧当前版本，不拿旧版本成功状态冒充本次解析完成。只有 edit 或密级不足导致后续 view 被拒时，提示提交成功但当前无法查看处理状态，不持续轮询 404。
- 进度以排队、处理、退避等待、维护等待、成功或失败展示。详情活跃且有非终态版本时进行有界间隔轮询，页面隐藏/离开时停止；错误采用有上限退避，401/403/404 停止。维护等待不显示为失败，解析截断和问题摘要沿用服务端事实。
- 搜索只在 POST JSON 中提交关键词，不写入路由 query、浏览器持久历史或遥测。首期不加入未支持的空间筛选、标题检索和服务端分页；界面只对明确 topK 的已返回片段展示结果。
- 引用共享一个抽屉，按 docId/versionId/chunkId 请求核对。AVAILABLE 展示完整片段及来源提示；CHUNK_UNAVAILABLE 提示片段当前不可用，并保留服务端提供的原版本文件入口；404 清除旧正文和入口。缺失版本不得补当前版本。
- 预览/下载通过带 satoken 的请求读取受保护业务路径，不在链接中拼接令牌。PDF 使用受控 Blob 预览，文本按纯文本呈现；415 显示格式不支持，下载入口由独立权限决定。文件路径必须为预期的同源业务路径，Blob URL 在关闭、切换、撤权结果或退出后释放，不承诺撤回用户已经取得的文件。

### 6. 会话配置与流状态机

公开前端配置 `VITE_CONVERSATION_ENABLED` 缺省 false，与部署的 app/AI 开关保持一致；它不包含密钥，也不表示授权或模型就绪。关闭时助手页展示未启用并停止会话请求；开启后按现有接口请求，503 展示暂不可用，404 只表示目标不可访问，不用于推断全局开关。前端不探测旧单轮占位接口来伪造成功。

会话侧栏按后端固定创建顺序分页，使用服务端返回标题，不从问题/答案自动生成或改写标题；新建时可显式输入标题，未输入使用服务端默认。历史轮次按后端正序游标加载，追加数据不会改变已存序号。

```text
IDLE --> SUBMITTING --> STREAMING --> RECONCILING --> IDLE
          |               |              |
          v               v              v
       HTTP_ERROR      ABORT/ERROR     SAVED_STATE
```

一次提交绑定 question/requestId/expectedLastTurnSeq。内容相同的网络不确定重试必须保留三者；收到 JSON replay 后查询对应轮次，不重启流。409 刷新会话元数据和历史，保留输入供用户确认，主动再次生成才使用新 requestId 和最新序号。页面和同会话活动轮次共同限制重复提交，跨标签竞争最终由后端 409 判定。

停止按钮、离开助手会话、退出或卸载组件使用 AbortController 关闭本页持有的生成连接，不后台保持生成。身份仍有效且对应页面仍活跃时，停止、异常、未收到 done 的 EOF，以及 done 后状态核对都重新读取持久轮次；采用有上限轮询核对仍 RUNNING 的记录，到限后提示稍后刷新。离开后在再次打开该会话时核对；退出后不继续发受保护查询。模型调用前返回的拒绝可能没有 turnId，此时不虚构轮次身份。

STREAMING 文本明确为正在生成；历史中的 COMPLETED、FAILED、CANCELLED、INTERRUPTED 依服务端显示。COMPLETED 且结算待确认保留成功正文，独立显示用量状态，未知真实 usage 不显示为零。任何历史/引用请求返回 BLOCKED 或拒绝时，丢弃已有相应助手正文和引用，不回退内存旧值；本人的原问题按返回结果保留。客户端不发送 history、roles、来源或助手正文。

现有 `TurnView` 没有独立的 incomplete 字段，客户端从 status 派生未完成展示标记，不为此扩展既有 DTO；这对应历史规格中的未完成语义。

### 7. 内容安全、状态隔离与可验证性

首期问题、答案和片段按文本与代码块安全展示，不执行原始 HTML，不自动加载正文里的远程图片/嵌入资源；普通外链限制协议且不携带认证信息。路由只保存页面和资源 ID；会话列表、文档正文、问题、答案及引用不持久化到 localStorage、sessionStorage、IndexedDB 或 service worker 缓存。

登录身份变更、退出、401 或强制改密切换时中止请求并递增客户端请求世代；旧身份和旧资源的迟到响应不得更新新页面。页面重新进入及从后台恢复时重新读取受保护事实，加载期间遮蔽旧敏感正文；失败不能使用旧正文充当授权后的成功结果。该设计不承诺跨进程即时撤回已经送达客户端的内容。

前端仅采用 Vitest 的纯函数、状态机和模拟 DOM 单组件测试，使用内存路由、请求替身、可控 Promise 和虚拟时间覆盖行为，不引入 Playwright、真实浏览器或端到端脚本。HTTP/SSE 响应均在内存构造，不建立真实网络连接。

后端 service 与 controller 分别作为被测单元，其依赖使用 Mock/Stub；controller 可使用 standalone MockMvc，但不组装 controller-service-mapper 完整链路或启动完整 Spring 应用。MyBatis 只在内存构建映射、绑定参数和消费 Mock ResultSet，不获取连接、不执行 SQL，也不使用 H2、Testcontainers、Docker 或真实 PG/Redis/MinIO。既有检查只保留明确白名单中的纯架构检查，排除数据库烟测、全量旧测试与 JavaSourceConventionTest 等文案检查。

README、Markdown、配置示例和 Javadoc 文案只作为编写交付物，不编写内容断言、快照或“按说明启动服务”的测试。构建、类型检查和单测结果仅记录各自实际覆盖的进程内行为，不以真实环境联调作为本变更的执行任务或完成门槛。既有规格的场景继续描述产品行为，不因此扩展测试执行范围。

## Risks / Trade-offs

- [资源能力在点击前变化] → 能力仅作按钮提示，每次实际操作仍受服务端当前鉴权，拒绝后清除对应结果并刷新。
- [标签页会话令牌可被同源脚本读取] → sessionStorage 只保留最小令牌，安全文本渲染、禁止敏感遥测，部署收紧 CSP；不宣称具备 HttpOnly 的防护性质。
- [编辑主体未获得查看资格] → 上传候选按 edit 独立提供，成功后明确后续不可查看，不扩大 view 或进度权限。
- [模型缺失或会话开关部署不一致] → 显式配置与状态提示，文档/搜索独立可用，测试不以假回答验收模型接入。
- [断流后本地已见文本多于持久化前缀] → 以再次读取的服务端状态替换临时显示，保留未完成标记，不宣称续传。
- [Blob 预览需要完整读取文件] → 首期遵循已有上传大小上限并及时释放；大文件 Range 与流式预览另行规划。
- [既有响应和错误结构不统一] → 按端点适配并以 HTTP/me 事实处理，不扩大本次为全后端协议重构。

## Migration Plan

以下仅为运维说明的设计内容，不是本变更实际执行的部署、联调或测试任务。

1. 本变更没有新 DDL、角色权限或历史数据迁移。后续部署时先提供两个新增只读后端入口，再发布依赖它们的前端；旧客户端不受影响。
2. 前端交付可独立构建的静态产物。同源托管设计为 `/api/**` 转发至现有网关，SPA 回退仅作用于页面路径；开发期提供 Vite 代理配置。本次不启动代理或网关验证链路。
3. 部署说明记录 Node/npm 要求、安装/构建/单测命令、网关代理、文件约束和公开会话开关。app/AI 未启用会话时前端保持关闭；503 提示通过内存响应单测覆盖，不运行缺模型环境验收。
4. 本次只执行类型检查、静态构建和限定白名单的单元/架构检查，记录实际命令和结果，不执行浏览器验收或真实 PG/Redis/MinIO/模型联调。
5. 回退说明描述恢复旧静态产物或撤下入口，新增只读后端可保留；如回退后端，先撤下依赖新接口的前端。本变更不实际执行发布或回退，也不删除文档、会话和凭据。
