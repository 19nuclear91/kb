# Proposal

## Why

知识库已经提供账号、部门和角色管理接口，但现有 `kb-web` 只有普通用户页面，管理操作仍依赖接口工具。需要在同一应用中交付按实际功能权限开放的管理区，让管理员能够完成账号生命周期、组织结构和角色授权操作，并明确处理冲突与网络结果不确定的情况。

## What Changes

- 在现有 `kb-web` 增加 `/admin/users`、`/admin/departments`、`/admin/roles`，复用登录、强制改密门禁、会话隔离、中文视觉风格和同源部署。
- 根据 `/api/auth/permissions` 的当前权限分别控制菜单、页面、选择器和操作；读取与写入独立，权限不可确认时保留可重试的失败状态。
- 账号页提供有界搜索、精确主部门及状态筛选、新建账号、详情、启停、重置密码、调整主部门及独立密级调整，以及用户角色的逐项分配和解除。
- 部门页提供部门树和详情、新建、改名、移动及启停，保留父子约束、版本冲突和停用前置条件。
- 角色页提供目录和权限详情、新建、改名、无引用角色删除，以及基于服务端完整目录的逐项权限授予和撤销。
- 增加管理表单的提交互斥、请求标识重试、版本核对、敏感输入清理及权限变更后的界面更新。
- 为指定身份管理写接口增加可选的有限错误分类，保留 HTTP 状态和既有 `code/message/data` 字段；前端按白名单分类展示固定中文提示，兼容未提供分类的后端。
- 首期范围为已有账号、部门和功能角色能力；账号通用资料编辑、用户/部门删除、批量授权保存、批量导入导出、外部身份管理和全局审计页面另行规划。

## Capabilities

### New Capabilities

- `admin-web-access`：同一用户端中的管理导航、按当前权限开放的页面和选择器，以及管理写操作的生命周期。
- `admin-web-users`：账号搜索、创建、详情、部门/状态/密码/密级调整及角色分配界面。
- `admin-web-departments`：部门树浏览和创建、改名、移动、启停界面。
- `admin-web-roles`：角色目录、角色生命周期和逐项功能权限配置界面。
- `identity-management-feedback`：身份管理写操作的兼容错误分类及安全的客户端提示契约。

### Modified Capabilities

无。复用 `user-web-session`、`user-authentication`、`identity-department` 和 `functional-authorization` 的既有会话、授权、审计、幂等及业务约束；新增管理页面和可选错误投影，不改变既有资格、数据模型、成功响应或业务状态码语义。

## Impact

- `kb-web`：新增管理页面、权限上下文及操作状态逻辑；调整路由、合法站内返回地址、导航、DTO、错误消费和组件测试，继续使用现有 React/TypeScript/Vite/Ant Design 工程及依赖。
- `kb-app` / `kb-common`：在已知身份管理冲突产生处补有限原因元数据，为精确匹配的 `/api/admin/identity` 管理写入口提供增量错误投影；保留公共 `R` 和旧 `/api/identity` 别名契约，不回传任意异常消息或底层错误体。
- 复用现有 `/api/admin/**` 和 `/api/auth/**` 网关路由，无新增数据库迁移、权限 code、后台服务或基础设施依赖。
- 验证仅采用内存业务单元测试、模拟 DOM、standalone MockMvc、ArchUnit、前端类型检查及静态构建。执行任务不包含集成测试、端到端测试、完整应用/HTTP 服务启动或数据库、Redis、MinIO、容器、嵌入式数据库、真实浏览器及供应商服务；不编写或运行文档内容、配置示例、Javadoc 或 OpenAPI 文档注解测试。既有测试混有文档断言时仅选择业务方法，不整类执行。部署、旧后端兼容和回退说明作为文档交付，不列文档/规格校验测试任务。
