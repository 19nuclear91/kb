# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本变更涉及首屏性能、异步渲染及身份清理，适用设计文档。

- `kb-web` 使用 React 19.3.1、React Router 7.18.4 的 `BrowserRouter/Routes`、Vite 8.3.4 和 Ant Design 6.6.6。`App.tsx` 静态导入全部页面，当前没有页面资源加载边界。
- `pages/Documents.tsx` 导出列表、详情、上传和进度组件，并导入评论、版本审核、删除协调和 Office 预览。`pages/AuthPages.tsx` 同时导入企业登录和账户绑定面板。仅将同一模块的不同导出包装为懒加载不能保证分离下载。
- `SessionProvider` 管理聚焦、后台恢复与身份订阅；`ProtectedLayout` 中的 `AdminAccessProvider` 同时供导航和普通文档页使用。管理详情仍需页面内部资源级核对，不能把所有鉴权前移为一个新的全局权限门禁。运营报表保留不加载空间目录的特殊行为。
- 已有测试直接导入聚合页面或模拟其模块，如 `admin/access.test.tsx`、`admin/operations-routing.test.tsx`、`sso/route.test.tsx`，拆分需同步测试入口。
- 探索时读取的 `dist` 生成于 2026-11-05：单 JS 为 1,316,042 bytes，离线 gzip 408,261 bytes、Brotli 331,538 bytes；CSS 为 4,645 bytes。此旧产物不是当前源码的正式对比基线，也不证明服务器启用了压缩。本次规划不运行构建或性能测试。

## Goals / Non-Goals

**Goals:**

- 让模块边界与路由实际使用范围一致，保证页面资源等待期间的身份门禁、导航和退出持续工作。
- 用构建依赖图及受控的延迟/失败测试证明按需加载，而非仅以分包数量或单文件大小判定成功。
- 将模块下载状态与业务接口状态分别处理，保持现有写操作绑定、取消和结果核对行为。

**Non-Goals:**

- 不调整页面数据获取策略、权限查询时机、业务表单交互或功能开关；不通过提前请求业务数据来掩盖加载耗时。
- 不引入运行时依赖、不迁移路由模式、不添加通用预加载器，也不把普通弹窗和面板进一步变成异步组件。
- 不把浏览器静态代码可下载性当作授权边界。业务 API 授权继续由服务端负责。

## Decisions

### 1. 沿用声明式路由，使用顶层懒加载声明

保留 `BrowserRouter`、`AppRoutes` 及公开路径，以 `React.lazy` 和静态字面量 `import()` 定义业务页面。声明集中于独立的 `src/routing/lazyPages.ts` 或同等专用模块，不在渲染期间创建组件类型，不在模块初始化时调用加载器，也不通过遍历目录批量导入页面。

认证入口 `LoginPage`、`ChangePasswordPage`、`SsoResultPage` 继续直接导入；后者仍在 `AppRoutes` 的普通身份分支之前处理。其他用户页面及管理页面按现有路由分别懒加载。同一助手模块复用两个助手路径，`AiUsagePages.tsx` 的两个薄入口允许共用一个异步模块，分别保留既有资格与状态隔离。

不采用数据路由器的路由懒加载接口：它要求迁移现有路由组织，收益与此次页面拆分目标不匹配。不以手动打包全部 `node_modules` 或 Ant Design 为首轮方案；先观察自动共享分包结果，避免把只在业务页使用的组件重新放入入口依赖。

### 2. 拆开两组聚合模块，维护单向依赖

建议落点如下，实施时允许在同一职责范围内调整文件名：

| 现有模块 | 拆分落点 | 共享部分 |
| --- | --- | --- |
| `pages/AuthPages.tsx` | `pages/LoginPage.tsx`、`pages/ChangePasswordPage.tsx`、`pages/AccountPage.tsx` | `auth/PasswordForm.tsx`；仅账户页导入 `sso/BindingPanel` |
| `pages/Documents.tsx` | `pages/DocumentsPage.tsx`、`pages/DocumentDetailPage.tsx` | `documents/UploadDialog.tsx`、`documents/ProgressCard.tsx` 及必要进度 hook |

页面导入共享组件，共享组件不导入页面。同步入口不得再经过同时导出懒加载页面的聚合文件。所有生产引用和受影响测试改为明确模块入口，不依靠保留旧聚合入口证明拆分。

文档列表需要的上传、处理进度、筛选与收藏保持当前实现；评论、版本审核操作、Office 预览、整文档删除协调和详情元数据编辑由详情入口按需带入。保留详情原有 `DocumentOperations`、删除控制器、固定版本、资格重核、请求代次和清理时机。共享模块拆分不能新建一套操作状态或让控制器跨文档复用。

仅增加两个指向原聚合文件的动态导入是被排除的替代方案，因为构建器仍可能交付同一个大模块。

### 3. 身份及权限守卫外置，页面区域承载等待与失败

```text
SessionProvider
+-- AppRoutes
    +-- Login / ChangePassword / SsoResult
    +-- ProtectedLayout + AdminAccessProvider
        +-- Navigation + UnreadBadge + Logout
        +-- SelectedRoute
            +-- ExistingGuard (where applicable)
                +-- PageLoadBoundary
                    +-- Suspense
                        +-- LazyPage
```

新增 `src/routing/PageLoadBoundary.tsx`，包含页面错误边界、可访问的加载提示和固定安全文案。每个路由在现有门禁之后包装，管理路由的既有 `AdminGuard` 在边界之外，因此加载中或失败后仍能按新权限卸载页面。保留资源详情在页面内部核对的流程，不要求先取得尚未加载页面负责读取的资源事实。

外壳及 `SessionProvider` 不被页面 Suspense 包围，也不随切页重建。页面边界按当前规范化路径和身份 epoch 复位，继续保留页面内部的资源 key；不要以普通渲染次数或随机数作为 key。必要权限变化由既有守卫和页面资源作用域处理，不统一按全部权限集合变化重建所有普通页面。

React 的导航过渡可能保留已展示内容，不能据此推断旧页面已清理。在 jsdom 中通过内存路由切换与可控延迟模块验证新路径显示自身加载状态、旧资源卸载，以及退出、改密和身份故障即时接管。页面 A 的迟到 Promise 不能修改 B 的边界；代码缓存只复用静态模块，不保存身份或资源数据。

### 4. 失败恢复使用显式刷新

模块加载失败展示“页面加载失败”，提供“刷新页面”及现有导航、退出，并在刷新按钮附近说明未保存输入会丢失。刷新仅由用户主动触发并保留当前站内路径；重新加载后由原会话流程核对身份，不恢复业务草稿或自动重放写入。页面组件本身的渲染异常使用通用界面失败说明，不冒充资源下载失败或业务成功。

React 会缓存 `lazy` 的 Promise 和失败结果，单纯重置错误边界不能保证重新导入；本轮不提供声称必然重新下载的同页“重试”。也不注册自动 `location.reload()` 的全局 `vite:preloadError` 处理，不吞掉错误使页面永久停留在加载状态。错误展示及诊断不包含原始异常、资源 URL、身份资料或业务正文。

加载失败与 401/403、业务 503 和结果不确定的写操作使用不同处理链路。显式刷新可能失去当前内存中的请求绑定，文案不能承诺原服务端写入已撤销；后续仍通过既有读取核对结果。

参考行为依据：[React lazy](https://react.dev/reference/react/lazy)、[Suspense 导航边界](https://react.dev/reference/react/Suspense#resetting-suspense-boundaries-on-navigation)、[Vite 资源加载失败](https://vite.dev/guide/build.html#load-error-handling)。这些是设计依据，最终兼容性以仓库锁定版本及其测试为准。

### 5. 以构建图度量入口与路由成本

新增 `kb-web/scripts/bundle-report.mjs` 及配套构建分析输出，复用 Node.js 文件、哈希和压缩能力。Vite 输出 manifest，并在构建阶段收集 chunk 的有效源模块归属，供结构检查使用；分析清单使用项目相对模块标识，保留在验证产物中，不随公开站点发布、不启用公开 source map。

报告至少覆盖入口、登录、文档列表、文档详情，其他动态页面列出独立块和共享依赖。统计规则：

- 入口集合包含 HTML 引用的脚本、样式及入口 JS 递归静态依赖；动态导入目标不默认计入入口。
- 路由冷启动集合为入口集合与目标页面入口及其递归静态依赖的并集；同时报告相对入口的增量。样式及真正预加载的资源计入实际需要的集合，不能只统计路由文件。
- 按最终产物路径去重，分别汇总 JS、CSS 的 raw、gzip、Brotli 与请求文件数；压缩参数固定并记录，逐文件压缩后求和，不把文件拼接压缩成不真实的传输大小。
- 根据有效源模块归属检查：入口不含受保护页面专用实现；登录不带入 `BindingPanel`；列表不带入详情专用评论、版本审核操作和 Office 预览。共享的权限工具、类型及 UI 组件不按目录名整体判违规。
- 缺失入口、资源、模块映射或不一致的依赖图视为报告失败，不填零、不跳过失败分支。依赖环使用访问集合终止，菱形共享依赖只计一次。

正式基线在实施页面改动前，以当前源码重新构建。先加入不改变运行时代码的分析能力，保存基线；再用相同锁文件、Node/npm 版本、构建模式和公开功能开关构建候选。记录 git 修订与工作区状态、锁文件摘要、工具版本和公开配置白名单，不导出全部环境变量。旧单包基线中路由代码若已包含于入口，其冷启动集合仍按入口计算，不能因没有动态条目而漏算。

验收同时要求结构隔离检查通过，并且相同条件下入口/登录及文档列表的累计 gzip 大小小于正式基线；文档详情及其他路由报告完整差异和请求数。本轮不预设下降百分比、不用提高 `chunkSizeWarningLimit` 代替优化，也不把本地压缩结果或分包数量当作浏览器性能结论。

### 6. 测试覆盖异步行为及原有生命周期

验证限定为本地离线检查：不启动前端开发/预览服务、真实浏览器、后端服务或数据库、Redis、MinIO 等外部组件，不连接真实 SSO、模型及 Office 服务。不对 README、设计说明、运维说明等文档文本编写或执行内容断言测试；文档更新属于交付工作。

- 在 Vitest/jsdom 中使用内存路由、API 替身、可控 Promise 和应用路由外壳覆盖加载等待、成功、拒绝、快速切页、退出、强制改密、身份不可确认、换号及管理撤权，检查懒加载器调用与模拟请求，而非仅断言出现占位文本。
- 验证未授权路由不触发其页面加载器；缓存命中仍经过门禁。已选中的共享模块允许由另一合法路由使用，不能将共享代码等同于资料访问。
- 回归 `sso/route.test.tsx` 和结果页流程：交接仍先于普通身份分支，同一次交换不因挂载或刷新处理而重发。保留原文档操作、后台恢复、文件清理及管理写入测试。
- 为构建报告提供包含共享依赖、循环、动态路由及缺失产物的最小图 fixture，验证去重、错误退出和统计口径；再检查真实生产构建输出。
- 执行前端类型检查、受影响单元测试和本地生产构建，构建与报告脚本不启动应用服务。慢加载、缺块和刷新恢复以可控 Promise、失败替身及刷新函数替身验证；不安排真实浏览器网络抽查或部署联调，也不将它们作为任务完成条件。

## Risks / Trade-offs

- [首次进入懒加载页面多一次网络等待] → 保留外壳、明确等待状态，并报告冷启动总字节和文件数；首轮不通过全站预取抵消拆分。
- [共享组件或 vendor 分组把页面代码重新拉进入口] → 依据实际输出模块归属和递归依赖做结构检查，优先修正导入方向。
- [拆分文档模块改变控制器或 effect 生命周期] → 主要执行机械拆分，保留当前 key、实例所有权与清理逻辑，回归上传、删除、预览和迟到响应。
- [权限变化发生在代码下载途中] → 守卫持续工作，迟到模块仅作为静态代码缓存；不得自行触发资源读取。
- [旧标签页引用已删除的 chunk] → 至少保留上一版完整哈希资源，HTML 使用既有 no-store 或重新验证策略；仍失败时允许用户显式刷新，不承诺无限期兼容旧标签页。
- [只有入口文件变小或压缩口径不一致造成虚假收益] → 冻结基线配置，比较去重后的完整冷启动集合，记录各路由及请求数。
- [静态产物缓存被误用为业务数据缓存] → 只对公开带哈希资产采用长期缓存，认证、文档、搜索和会话响应继续 no-store，不新增 Service Worker。

## Migration Plan

1. 实施时先生成当前源码基线，再完成拆分和边界；运行类型检查、相关回归、构建及报告比较，保留可复核证据。
2. 更新 `kb-web/README.md` 与 `docs/user-web-operations.md`：记录加载状态、刷新后果、报告命令、HTML 与资产缓存规则及旧资产保留要求。
3. 部署先上传新哈希资源及保留旧版本资源，再原子切换入口 HTML；静态资源缺失返回真实 404，不能回退 SPA HTML；只有页面地址使用 SPA 回退。SSO 结果页继续 no-store/no-referrer。
4. 回退时恢复前一版入口及其完整资产集合，同时保留候选版资产供已打开标签页使用，按部署平台的保留策略清理。无需后端、数据库或功能开关迁移。
5. 上述迁移步骤仅为发布与回退说明。本变更不执行实际发布、服务器缓存验证、真实浏览器测试或外部组件联调，也不将这些操作作为任务完成条件；本地离线检查不构成生产验收。
