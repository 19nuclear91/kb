# Proposal

## Why

当前前端入口静态导入全部用户端和管理端页面，登录及普通文档浏览也需要下载不使用的页面代码；文档列表与详情、认证入口与账户页面共用模块，进一步放大首次加载成本。本变更落实已确认的首屏与路由拆分范围，同时为新增的异步页面加载提供明确的状态与恢复行为。

## What Changes

- 保留登录、强制改密、SSO 结果页和会话、导航、权限控制的直接加载；普通业务页及管理页按路由加载，不主动预取未进入的业务页面。
- 拆开文档列表与详情，以及认证入口与账户页面；上传、进度和密码表单等按实际复用关系抽为共享模块，避免共享模块反向带入完整页面。
- 在页面区域提供加载占位和错误边界，保持导航、退出及权限守卫可用；资源加载失败提供用户主动刷新和离开入口，不自动刷新或重放业务写入。
- 异步加载继续遵守当前身份、路由及资源作用域，退出、强制改密、撤权和切页后的迟到结果不得恢复旧页面或业务请求；SSO 交接保持既有一次性消费规则。
- 增加构建产物及依赖图报告，比较登录、文档列表和文档详情冷启动所需的全部 JS/CSS，并检查入口和路由依赖隔离；记录 raw、gzip、Brotli 大小，不预先承诺压缩比例。
- 使用模拟 DOM、内存路由和 API 替身补齐延迟加载、失败恢复和权限生命周期单元回归，并更新静态资源缓存、旧版本资源保留及发布回退说明。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `user-web-session`：增加业务页面按需加载、认证入口独立可达、页面加载状态及显式恢复、异步页面与身份及导航隔离的要求。
- `admin-web-access`：增加管理页面加载受当前路由守卫约束、加载期间继续响应权限变化、局部失败不阻断导航的要求。

## Impact

- 前端：`kb-web/src/App.tsx`、`pages/AuthPages.tsx`、`pages/Documents.tsx`、新的独立页面与共享模块、页面加载边界及相关测试；复用现有 `SessionProvider`、`AdminAccessProvider` 和业务清理逻辑。
- 构建：`kb-web/vite.config.ts`、`package.json` 及新增构建报告脚本。沿用当前 React、React Router、Vite、Ant Design 和 Node.js 工具链，不新增运行时依赖。
- 文档：`kb-web/README.md`、`docs/user-web-operations.md`，以及实施后的构建对比和验证记录。
- 保持公开页面路径、登录返回规则、后端 API、功能开关和业务写入协议兼容，不修改后端或数据库。
- 验证仅含本地类型检查、单元测试、静态构建与产物分析；不启动前端服务、真实浏览器、后端或外部组件，不执行说明文档内容断言测试，文档更新仍保留。
- 范围不含弹窗和复杂面板的进一步懒加载、路由框架迁移、全站预加载、SSR、Service Worker、UI 库替换、需要运行服务的集成测试、浏览器 E2E 或实际生产部署。当前阶段只交付规划文档。
