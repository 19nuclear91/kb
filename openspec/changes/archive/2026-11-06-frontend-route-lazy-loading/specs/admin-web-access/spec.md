# Spec Delta

## ADDED Requirements

### Requirement: 管理页面按需加载必须服从现有路由资格

管理页面专用代码 SHALL 在目标路由被选中且当前身份与该路由既有资格门禁通过后才触发加载；菜单展示不得主动预取各管理页面。具有独立功能读取资格的路由 MUST 保持各自资格判定，空间目录故障不得阻断不依赖该目录的入口。需在页面内核对具体资源的路由 SHALL 保持既有资源读取和授权流程，不把模块加载或缓存命中视为资源授权，也不新增更宽的读取接口。

#### Scenario: 功能资格未确认或被拒绝
- **WHEN** 用户直接访问账号管理页，但当前身份或 `identity:user:read` 资格尚未确认、读取故障或明确不存在
- **THEN** 显示对应身份或权限状态，不触发账号管理页面专用代码加载及账号资料请求
- **AND** 若代码此前已缓存，仍不得挂载受拒绝的页面或读取其资料

#### Scenario: 普通用户只访问文档列表
- **WHEN** 无管理权限的正常用户进入文档列表
- **THEN** 不加载管理页面专用代码，文档列表及普通导航继续可用
- **AND** 应用外壳现有的本人权限核对不被当作管理实体数据预取

#### Scenario: 独立报表资格与空间目录
- **WHEN** 当前用户拥有 `operations:reports:read` 并进入运营报表，而空间目录不可用
- **THEN** 报表仍按独立资格加载，不为判断其资格新增空间、账号或角色目录请求

#### Scenario: 资源详情需要自身核对
- **WHEN** 用户进入合法空间详情或文档管理目标，现有路由门禁允许继续
- **THEN** 页面代码加载后仍按原资源接口核对当前管理资格，仅展示实际允许的区块
- **AND** 不因拥有全局菜单入口或模块已下载而获得该空间、文档的管理或阅读权限

### Requirement: 管理页面加载期间必须继续响应资格变化和局部故障

管理页面资源等待或加载失败 MUST 不中断应用外壳的身份及权限核对，不阻断导航和退出。资格撤销、身份失效、目标变化或离开页面时，迟到的代码完成或失败 MUST 不挂载旧管理页面、不发起旧目标请求、不恢复原资料。失败恢复 SHALL 沿用用户端的显式刷新与导航规则，不能自动重放管理写入；其他仍具资格的页面应能独立使用。

#### Scenario: 资源下载期间撤销权限
- **WHEN** 账号管理页面代码仍在下载，最新权限核对已确认用户失去读取资格
- **THEN** 当前区域显示无资格，迟到的模块不能挂载账号页面或请求账号资料

#### Scenario: 管理页面下载失败后继续导航
- **WHEN** 某管理页面代码加载失败，用户转到仍具资格的搜索或其他管理页面
- **THEN** 新目标按自身状态加载，旧页面错误不覆盖新目标，原会话和退出入口继续可用

#### Scenario: 目标切换及旧结果晚到
- **WHEN** 用户从管理目标 A 切换到 B，而 A 对应的页面加载随后才完成或失败
- **THEN** 只有 B 的当前目标及资格参与渲染和读取，不启动 A 的数据请求，也不显示 A 的错误状态

#### Scenario: 资源失败恢复不重放写入
- **WHEN** 用户通过失败页主动刷新，刷新前曾存在结果未确认的管理写入
- **THEN** 刷新后按当前事实重新读取，不自动重传原写入或声称原服务端操作已取消
