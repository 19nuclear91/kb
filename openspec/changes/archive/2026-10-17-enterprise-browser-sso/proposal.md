# Proposal

## Why

知识库已具备本地账号、外部身份绑定表和共享 Sa-Token 会话，但缺少钉钉、企业微信、飞书的浏览器登录实现，普通用户也无法自行验证并绑定外部账号。本变更补齐三家平台的扫码／授权登录，让已有用户复用内部身份、权限与历史，并按指定企业范围控制外部登录。

## What Changes

- 提供钉钉、企业微信、飞书三个独立的浏览器认证适配器，共用连接配置、授权事务、企业成员核验、账号映射与会话交接服务；三家均需交付，允许逐个配置和启用。
- 仅允许管理员已创建的本地账号：用户验证本地密码、完成强制改密后，明确发起本人绑定并授权三方账号；未绑定的外部登录不建号、不自动合并、不授予业务会话。
- 在每次绑定及新扫码登录时核验指定企业的成员身份，身份作用域绑定平台、企业和应用；未知、非成员或无法可靠核验均拒绝。
- 使用绑定发起浏览器和操作意图的一次性 state、防重放与短时会话交接凭证；令牌不进入跳转 URL，回调不能由客户端指定内部用户或外部 subject。
- 外部登录复用现有 Sa-Token、内部账号启停、有效主部门、强制改密和实时权限规则；外部身份不更新内部部门、角色、密级或 ACL。
- 增加本人绑定状态查询与成功／失败审计，保留现有管理员绑定、解绑和读取资格；为新增登录与绑定事件提供现有全局审计中的安全投影。
- 明确离职处理：本轮不订阅人员变更或同步通讯录；企业成员条件仅在绑定和新外部登录时核验，本平台管理员负责停用内部账号。离开 IM 企业不会自动终止已有本平台会话，也不会自动关闭本地密码登录。

## Capabilities

### New Capabilities

- `enterprise-sso`: 三家平台的浏览器扫码／授权登录、企业成员核验、连接作用域、授权事务和安全会话交接。

### Modified Capabilities

- `identity-department`: 扩展外部身份唯一归属及管理边界，允许经过本地验证的用户绑定本人账号，新增本人最小绑定状态读取。
- `user-authentication`: 明确外部认证建立已有内部用户会话及强制改密兼容规则，不改变本地密码登录契约。
- `audit-query`: 覆盖新增企业登录与本人绑定事件，定义有限平台与结果码的安全摘要，保持原分页及读取资格。

## Impact

- 代码范围主要为 `kb-app` 的 `auth`、`config`、`audit` 与相关 Mapper，以及 `kb-gateway` 的精确认证放行规则和响应头；`kb-ai`、Worker、资源授权 SQL 不新增平台认证逻辑。
- 复用 PostgreSQL `sys_user_identity`、`sys_identity_audit` 及共享 Redis；采用服务端 HTTP 客户端与明确的供应商接口，不引入统一身份代理或绑定特定 OIDC SDK。`kb-common` 不增加供应商或 Web 运行时依赖。
- 新增 `/api/auth/sso/**` 和本人绑定接口，交付浏览器对接协议、失败语义、配置及运维说明。当前没有业务前端工程，本轮以后端及可联调浏览器协议为交付边界，不新建完整前端应用。
- 新连接使用独立命名空间，复用现有字段与唯一约束，不新增 DDL、不猜测迁移旧 provider/subject，也不改变历史迁移。
- 不包含 IM 工作台内免登、自动注册、自动账号合并、通讯录或离职同步、角色同步、纯 SSO 建号、用户自助解绑、通用 OIDC 提供方或业务前端建设。
- 本变更验证仅包含不依赖外部服务和真实凭据的离线单元测试、人工代码／SQL 审阅、编译打包与 OpenSpec 结构校验；不安排集成测试、真实数据库／Redis／供应商联调、浏览器或部署环境验证，不启动服务或嵌入式替代组件。文档仅作交付和人工审阅，不新增文档内容、注释、文案或示例测试，也不执行示例。真实环境和凭据不作为实施或完成前置，离线结果不宣称真实运行效果已验证。
