# Spec Delta

## ADDED Requirements

### Requirement: 第一轮评测登记只能关联服务端确认的执行

已登记测试用例 SHALL 沿用本人会话与原第一轮生成接口，实际用户、认证代次、会话和轮次从服务端确认的执行取得；本地登记只允许匹配，不允许覆盖这些事实。公开请求仍不接受额外历史、角色、来源或评测身份字段。登记过期、问题不符、非第一轮或匹配重放不得创建另一份新生成证据，不改变原幂等、预算和配额门禁。

#### Scenario: 客户端在请求体中夹带评测参数
- **WHEN** 生成请求增加任意 evaluation、history 或 system 字段
- **THEN** 继续按原严格请求契约拒绝，不因测试模式放宽角色或身份输入

#### Scenario: 用同一标识核对已存在轮次
- **WHEN** 已登记用例命中原轮次的匹配重放
- **THEN** 只返回原 JSON 状态，不再次采集为新运行、不重启检索或模型

#### Scenario: 可信执行与登记用户不同
- **WHEN** 登记声明的用户或问题摘要不匹配实际受理执行
- **THEN** 原授权规则保持不变，该执行不能进入所声明用例的证据集合

### Requirement: 评测证据必须区分业务结果与模型结果

测试执行 SHALL 为登记轮次记录来源封存类型、实际新材料身份、模型是否进入生成路径及已确认的业务终态，供运行器与原公开响应核对。合法 NO_RESULTS 须明确未调用模型；业务完成、结算状态和客户端成功交付分别表达。证据收集不得读取不合格历史、保存未授权额外来源，或为核对重新生成、补查最新版本。

#### Scenario: 合法空检索完成
- **WHEN** 受理第一轮后授权检索成功为空并按既有流程完成
- **THEN** 证据记为 NO_RESULTS 及未调用模型，不伪造消息快照、模型正文或实际 token

#### Scenario: 模型完成而结算待确认
- **WHEN** 回答已保存为 COMPLETED，但结算未确认且未发送 done
- **THEN** 业务完成和结算待确认分别记录，不能将其报作完整端到端成功

#### Scenario: 采集失败与账号撤销同时发生
- **WHEN** 测试证据写入失败且原账号输出许可被撤销
- **THEN** 按既有机制有界停止输出和取消上游，不等待采集完成，不利用采集资格读取或输出更多正文
