# Design

## Context

动机和已确认范围见 [proposal.md](proposal.md)。本变更同时影响独立工具和 AI 执行边界，并增加受控内容采集、外部裁判调用和文件复核协议，因此需要设计文档。

- `kb-eval` 的输入只保留文档版本与分块身份，运行时完全离线；`kb-eval-collector` 只调用身份和搜索接口。不能把回答正文和在线裁判塞入这两份现有契约。
- `ConversationBudget` 先选择历史、裁剪新材料；`OpenAiMultiTurnModel.generate` 再渲染 `PreparedChatRequest`、复核预算，随后运输层编码并发送。预算循环产生的中间视图不能充当实际输入。
- 当前引用与持久化引用只保存来源身份、定位提示和裁剪标记。引用查询返回完整存储分块，不保存当轮 prompt，也没有结论与证据的语义对应。
- 多轮接口接受 question/requestId/expectedLastTurnSeq，第一轮使用序号 0。服务端返回会话和轮次身份；SSE 的 done 晚于完整保存与结算确认。模型完成、业务完成和客户端交付不是同一时刻。
- 当前提示词由服务端代码提供；比较提示词时比较明确部署的制品及实际消息摘要，不增加任意客户端 system 输入。第三方解析适配器尚未交付，不能将新上传原件视为已可检索。

## Goals / Non-Goals

**Goals:**

- 为完整执行的同一用例形成可核对的输入、输出、初评和复核链；同时保留所有未执行、失败和未知项。
- 在当前业务接口与权限规则之内自动执行第一轮，限定测试采集用途，使离线报告可重复生成。
- 固定评测语义、格式和有限资源预算；让外部模型选择与业务阈值成为显式运行配置。

**Non-Goals:**

- 不为评分改变业务 prompt、召回、当前版本、授权、会话账本或模型重试规则。
- 不新增业务管理页面、线上长期正文日志、网络 prompt 导出接口、生产会话抽取、模型权重真实性认证或自动脱敏。
- 不在本变更实现解析供应商接入或全套部署平台，也不安排需要启动服务或外部组件的集成验收；真实部署与实际运行仍须满足产品自身的依赖条件。

## Decisions

### D1 独立工具与受控采集组件

新增 `kb-answer-eval` Java 21 CLI，运行时仅依赖 JSON 与有界 HTTP/文件处理能力，不依赖业务 Spring 容器或数据库。`kb-ai` 新增默认关闭的 `evaluation` 组件，完成登记匹配、执行关联及采集。业务 app、Worker 和 web 不新增接口、表或页面；现有本人会话读取与创建继续负责授权。

文件契约、摘要和本地路径校验由 AI 采集组件复用新模块的普通 Java JAR；可执行工具通过独立 `cli` classifier 打包，避免将 shaded 依赖重复装入 AI 服务。依赖方向为 AI 到纯 Java 评测模块，CLI 不依赖业务模块。

命令分为 `validate-dataset`、`collect`、`judge`、`review-template`、`review-import`、`report`。前两类在线阶段分别明确调用目标；模板、复核导入和报告完全本地。`validate-dataset` 也完全离线。各命令提供独立 `--help`，未知或重复参数拒绝。不依赖 shell 串联掩盖阶段退出码。

选择独立模块是因为原检索工具有明确的不联网、不保存正文及严格 v1 格式；在原工具中添加可选字段会模糊既有保证。新模块首期复用格式与算法设计，不为复用少量代码抽取大范围公共框架。

```text
Dataset + cases + labels --> Runner --> Existing authenticated APIs
                               |                    |
                               |                    v
                               |              kb-ai execution
                               |                    |
                               v                    v
                        Registration <--> Private capture directory
                               |
                               v
                      Bound collection bundle
                               |
                               v
                     Rules + isolated judge calls
                               |
                               v
                       Local review revisions
                               |
                               v
                     Offline baseline report
```

### D2 版本化数据契约

新格式统一 `schemaVersion: 1`，不兼容复用旧检索清单。建议文件及职责如下：

| 文件 | 关键内容 |
| --- | --- |
| `dataset.json` | datasetId、datasetVersion、corpusSnapshotId、来源、用例与标注文件、文件摘要、审定标识、允许的被测/裁判目标逻辑标识 |
| `cases.jsonl` | caseId、身份别名、原问题、分类、可选注入测试标识；无客户端角色/历史/来源注入字段 |
| `labels.jsonl` | caseId、ANSWER/ABSTAIN、带 factId 的必需要点、禁止断言、注入目标行为和标记、关键错误判据 |
| `corpus.jsonl` | 人工审定的固定文档/版本/分块身份、正文摘要及相应受控文本，供实际材料范围核对；不作为补查或送入模型的额外材料 |
| `collection.json` | runId、工具/制品版本、完整用例集合、身份绑定摘要、已确认配置、阶段覆盖与内容文件摘要 |
| `answers.jsonl` | 每例状态、会话/轮次身份、客户端答案、可见持久答案摘要、来源、执行/结算状态及 usage |
| `inputs/` | 按生成的内部键保存最终消息、实际材料身份与裁剪信息、阶段和摘要；路径不使用用户问题或外部文件名 |
| `judgments.jsonl` | 规则结果、两种视图的结构化初评、逐项证据、裁判身份和请求摘要 |
| `reviews.jsonl` | 复核标识、绑定摘要、修订链、复核人逻辑标识、逐项结论、理由 |
| `summary.json`、`cases.csv`、`report.md` | 不含正文的汇总、逐例指标与基线差异；受控复核模板另含所需文本 |

标识采用受控字符集与长度；业务 ID 精确保留正 64 位整数，UUID 不经浮点转换。重复属性、未知契约字段、非法 Unicode/NUL、身份溢出、重复 caseId 和不完整用例覆盖在联网前失败。ANSWER 必须至少有一个必需要点；ABSTAIN 的必需要点为空，拒答条件及禁止断言另列。

SYNTHETIC 基准随仓库交付。HUMAN_APPROVED_DEIDENTIFIED 必须附审定逻辑标识、审定版本、各内容文件摘要及允许目标；工具校验声明绑定，不声称识别了全部敏感信息。审定数据和真实产物置于仓库之外或实现时新增的忽略目录；不要在仓库中提交业务语料。

语料快照和 ACL 默认 `DECLARED_ONLY`。数据集含人工准备的固定语料/版本/分块清单及受控文本。原件经既有解析发布后，由有权限的测试操作者准备并审定该清单；本工具不自动全库导出。采集和 judge 都逐项验证实际材料属于该清单：未裁剪内容必须完全一致，裁剪内容必须是审定文本的真实前缀，正文摘要绑定同一字节内容。范围外或不匹配时不保存本例正文评测包、不调用裁判；运行器只能留下安全状态。该核对证明本次材料匹配审定清单，不证明全库或 ACL 冻结。重新解析改变分块身份或内容后应重新审定数据集，不补猜继任分块。

### D3 本地登记与实例边界

首期部署形态为一个专用 AI 测试实例、一个串行运行器，以及二者可访问的受控本地目录；可以是容器挂载的同一目录，但不允许 CLI 通过 UNC/任意网络 URI 发现内容。分布式采集服务与跨节点归并不在首期。

采集配置需要同时提供显式 enable、测试部署逻辑标识、允许用户 ID 和受控目录；缺任一项拒绝启用，prod profile 强制拒绝。该检查不能证明基础设施隔离，部署手册须要求测试网关、app、数据库、模型配置及语料均为专用资源。

`collect` 先验证所有输入与用户，再创建独立会话；得到真实会话 ID 后原子写本例登记，随后发起第一轮。登记含 runId、caseId、不可重用 attemptId、expectedUserId、conversationId、expectedLastTurnSeq=0、规范化前原问题 UTF-8 摘要、到期时间和生成的产物键。问题不进行隐式归一化或裁剪。

AI 从已有服务端执行取得 userId/authEpoch/conversationId/turnId，并匹配本地登记。首次绑定原子持有该登记，其他轮次拒绝采集；重放不新建绑定。通过专用请求上下文把不可变执行身份送到采集组件，不暴露执行票据、令牌或输出许可内部对象。登记索引只缓存本地测试登记，不缓存业务授权通过结果。

目录结构区分 runner 写入的登记与 AI 写入的快照。共享目录权限限定这两个服务账号，登记文件的持有者属于可信测试操作者；这不是抵御拥有该目录写权限的攻击者的签名系统。路径在预检和发布时检查解析后根边界、目录链接及目标竞争；普通请求无匹配登记时不读取或记录其正文。

### D4 最终输入捕获与完成标记

在最终预算通过、`PreparedChatRequest.encode()` 成功后，从同一发送视图取得消息与材料映射，先按 D2 核对审定语料范围，再异步提交给有界采集组件。不得在预算反复计数时记录中间视图。材料映射必须与消息中实际编码的材料一致，含固定三元组、真实文本和裁剪标志；原分块页码等只作来源提示，证据偏移相对实际文本。语料核对失败只使评测不完整，不改变既有业务调用规则；测试部署须事先将测试账号的可读范围限定为审定语料。

采集阶段为 INPUT_READY、REQUEST_SUBSCRIBED、MODEL_COMPLETED 或 MODEL_FAILED/CANCELLED；INPUT_READY/REQUEST_SUBSCRIBED 不是供应商接受证明。捕获模型解码正文的 UTF-8 摘要和 code point 数，正常结束时固定；不额外保存一份无须复核的原始模型正文。失效或中断不补成功。

业务编排另产生关联的 answerKind、来源封存身份与已确认终态标记。NO_RESULTS 记录未调用模型，不生成假 prompt。全部文件先写独有临时目标，最后以只读完成清单及文件摘要提交；目录存在或阶段缺少不能视为完成。服务崩溃后不从零散文件猜测完整快照。

采集队列和写入线程独立有界，不阻塞 Netty 或输出许可到期处理。失败将此次证据标记为不完整；即使失败标记也无法落盘，运行器最终等不到完整标记仍判缺失。业务继续按原流程处理，采集不引入额外模型订阅、重试、正文日志或数据库连接。关闭组件后不扫描采集根目录。

备选方案是事后读取引用全文，无法证明模型当时收到的裁剪内容；反向代理抓完整 HTTP 会扩大凭据暴露面且缺少业务轮次关联，首期不采用。

### D5 用例执行和结果核对

`collect` 先用 `/api/auth/me` 核对全部身份，然后逐例调用现有 `POST /api/conversations` 与 `POST /api/ai/conversations/{id}/turns`。每例新会话、固定新请求 ID、期望序号 0。不发送标签、答案、system、历史、检索参数或管理员声明。检索配置变化通过外部部署配置实现。

首个执行/采集失败后停止新生成，剩余用例填 NOT_RUN。语义回答错误不影响后续执行。已发送生成不自动重试；只读轮次核对允许在既定期限内轮询，不能用新请求标识再生成。若创建会话的响应丢失且无法确定目标，记录未知并停止，不遍历其他会话猜测归属。

成功 MODEL 用例需同时满足：响应绑定正确；SSE 单一合法成功终止；客户端正文摘要与本人可见 COMPLETED 持久回答一致；来源元数据与实际材料匹配；模型解码正文摘要一致；最终输入和模型完成标记完整。NO_RESULTS 则核对固定安全回答、业务 answerKind 与未调用模型的声明。只读核对故障、屏蔽、结算未确认、EOF/error、部分正文均不能当作完整成功。保留已经确认的业务完成事实，不因评测失败改写业务状态。

采集阶段禁止用引用读取接口补正文；权限发生变化时不会以磁盘快照替代被拒绝的业务核对。运行器对 SSE 文本仅有界暂存，确认材料属于审定范围后才写本例正文文件；核对失败时不落原文。产物本身是人工批准测试资料的独立副本，不声称能随线上撤权自动回收。

会话和测试原件由操作者按产物中的明确目标清理；本工具首期不自动删除会话、用户、空间或原件。回归起点是已准备、已发布且可检索的固定测试语料。合成原件及现有导入/发布操作说明随工具交付，新上传依然需要 E-01。

### D6 初评协议与两种输入视图

每个证据完整的 MODEL 用例最多发送两次裁判请求：

1. **correctness**：问题、人工必需要点、禁止断言、答案；逐要点判断，识别额外关键错误，并给出 ANSWER/ABSTAIN/UNCERTAIN。
2. **grounding**：问题、答案、实际材料及预设注入目标；列出全部可核验关键结论、结论在答案中的区间、材料相关性和每结论的支持判断。此视图不含标准答案或原分块全文。

所有业务文本放在明确数据消息中，裁判系统指令固定，禁止工具执行、额外检索、URL 访问和按材料改变评分规则。候选名称不进入评分内容，评分所需语义资料保持完整。安全性仍靠无工具调用、固定出站目标、结构与证据校验及人工复核，不把提示词隔离视为注入免疫。

使用独立配置的 OpenAI-compatible 文本请求，首期采用 `POST /chat/completions`、`stream=false`、单候选；输出 token 字段明确选择 max_tokens 或 max_completion_tokens。要求正常 stop 和一条普通文本 content，其正文必须能严格解析成评分 JSON。不得自动删参、添加供应商专用开关或转换工具/思考输出。未知协议、拒绝载荷、多个候选、截断、错误 JSON 均为初评失败。本次进程内替身测试不证明真实供应商兼容性，该兼容性保持未验证。

JSON 字段包括固定枚举、要点 ID、结论 ID、回答区间、证据三元组及区间、短引文、理由和关键错误；禁止直接接受总分、置信度作为门禁。引文及偏移以 Unicode code point 的 `[start,end)` 表示；所有定位先做严格子串匹配，再保留模型的语义关系判断。不进行模糊纠错来救活伪造引用。

NO_RESULTS 成功样本无需调用裁判：按预期确定拒答符合值、答案要点覆盖为零或不适用，证据与材料指标不适用。注入测试另核对攻击暴露情况；未实际传入预设攻击材料只表示未覆盖该攻击，不能算模型抵抗成功。

裁判与被测模型可由运行方显式选择相同模型，但报告记录这种关联；推荐独立配置不等于强制不同供应商。裁判不复用业务部门额度账本，使用 CLI 的独立运行预算与实际 usage 记录。未知 usage 保持未知。

### D7 指标口径和状态

初版指标口径命名 `answer-quality-v1`。每例分别计算，之后按适用且已判定用例宏平均；同时保留完整、适用、已判定与未知数量。标签重叠时分类可重复计入，总体只计一次。

| 指标 | 逐例定义 | 不适用/未知 |
| --- | --- | --- |
| factCoverage | COVERED 必需要点数 / 全部必需要点数 | ABSTAIN 无要点为 N/A；任一 UNCERTAIN 为未知 |
| claimSupport | SUPPORTED 关键结论数 / 全部可核验关键结论数 | 无结论为 N/A；任一 UNCERTAIN 为未知 |
| materialRelevance | RELEVANT 实际材料数 / 实际材料数 | 无材料为 N/A；任一 UNCERTAIN 为未知 |
| abstentionAccuracy | 实际 ANSWER/ABSTAIN 与预期一致为 1，否则 0 | 执行失败不评分；行为 UNCERTAIN 为未知 |
| injectionCompliance | 暴露了预设攻击且全部目标行为成立为 1，否则 0 | 普通用例 N/A；应暴露却未暴露为 NOT_EXERCISED，阻止完整验收 |

额外关键错误独立列出，不能被覆盖率或平均分抵消。模型列举结论不是客观完整性证明，人工必须能补漏和改写语义判断；复核后分母随明确的修订变化，初评分母仍保留。UNKNOWN 与 N/A 不混用。局部已知均值可以展示，但覆盖不足时不进入完整质量通过计算。

不声称 claimSupport 为模型真正利用证据的因果证明，也不将当前来源列表称为逐句引用准确率。引用三元组是否与实际材料一致属于规则校验，不由裁判凭语义批准。

### D8 复核协议与确定性抽查

`review-template` 输出受控 JSONL 模板及必要文本的本地说明；`review-import` 验证后生成新的只读复核产物，不修改原始初评。每项绑定 case/run/answer/context/rubric/judgment 摘要、逻辑复核人、reviewId、revision 和 previousRevisionSha256。首次修订前驱为空；同 ID 同内容幂等，同 ID 异内容或分叉冲突拒绝。保留全部修订，不能以时间戳决定冲突胜者。

人工可以补遗漏的结论，修改枚举、关键错误及证据，定位仍须严格校验。任何改判都要原因。签署标识是操作记录，不做企业认证承诺；本地文件权限由运行方管理。数据集标注错误须新版本，不能当作普通评分修订。

必需集合基于不可变初评计算：所有未知、未符合预期、关键错误及规则/语义矛盾项，加上通过样本的分类抽查。抽查比例 p 显式设置在 `(0,1]`；每类取 `max(1,ceil(p*n))`，按 `SHA-256(datasetDigest | rubricVersion | caseId)` 再按 caseId 排序，标签重复取并集。抽查策略及集合摘要进入报告。初评改判后集合不缩小；新增人工关键错误必须反映最终门禁。未抽中的通过项保留 MODEL 来源。

初评协议错误或证据缺失不能靠人工填“通过”补齐，必须补完整输入或新建评审运行。模型正常返回 UNCERTAIN 则可经人工解决；人工仍未知时保持待复核。

### D9 比较、门禁和发布

正式比较需相同数据集/标注摘要、用例问题与身份绑定、语料快照声明、裁判配置、评分规则和复核策略；完整样本集合一致。被测制品、提示词和检索配置可不同，实际材料也允许不同。无法核验语料/ACL 不变时保留 DECLARED_ONLY，不能凭相同字符串声称环境冻结。

有效指标采用有效人工修订，否则使用模型原判，同时输出来源覆盖；模型初评指标并列保留。每个质量规则可选全局或标签范围，指定 min 和/或 maxRegression。所有指标越高越好，退步量为 baseline-candidate，使用固定 `1e-12` 容差；阈值范围 `[0,1]`，重复规则、未知指标、无适用样本或缺基线拒绝。质量阈值须由运行方显式提供，示例不是生产承诺。

最终判定顺序：输入/配置无效 INVALID；执行/采集/初评或必需攻击暴露不完整 INCOMPLETE；必需复核或可解决的语义未知未完成 REVIEW_REQUIRED；关键错误或质量规则未通过 FAIL；未配质量规则且无前述问题 NOT_CONFIGURED；其余 PASS。退出码分别 2、3、4、1、0、0。INCOMPLETE/REVIEW_REQUIRED 仍显示已知失败，但最终不冒充已完成质量判定。输入结构损坏只返回安全诊断；完整合法但不足的证据可生成明确不完整报告。

报告保留所有用例，不取交集或自动删失败。JSON/CSV/Markdown 汇总不带正文，受控复核包保存必要文本与短引文。三种格式均保留数据集逻辑标识、版本及来源，执行范围分别记录授权检索、被测模型和裁判：TEST_DOUBLE、HTTP_UNVERIFIED、NOT_CALLED 或 UNKNOWN。采集/初评清单记录 invocationOrigin；HTTP 不证明目标内部真实后端，旧清单缺字段按 UNKNOWN 处理。正式比较拒绝测试替身与 HTTP/未知范围混用，但合法 NO_RESULTS 无需模型或裁判调用的 NOT_CALLED 不阻止同配置比较。旧报告需由原冻结输入离线重新生成。

目录发布采用同父独有暂存目标、完整清单与不覆盖发布，失败只清理本次文件。部分写入失败使暂存会话不可再提交，即使调用方捕获异常也不能发布残留文件。报告不联网，相同输入与选项排序及字节输出稳定；生成过程中当前时间和路径不写入确定性汇总。

### D10 资源与费用边界

以下为首期工程上限，不代表供应商或生产质量门槛。配置只能在支持区间内调整，所有限制按实际读取字节和单调期限执行，超限不静默截断。

| 边界 | 首期值 |
| --- | --- |
| 单批用例 | 最多 1,000；串行执行 |
| 单清单/配置 | 1 MiB；JSON 深度 32 |
| 用例、标注或审定语料文件 | 各 64 MiB；JSONL 单行 512 KiB |
| 原问题 | 8,000 code point，继续受业务更紧限制 |
| 单例采集文件总量 | 8 MiB；单运行内容总量 2 GiB |
| 采集队列 | 最多 4 份有界待写记录，总排队字节最多 32 MiB；独立线程执行文件 I/O |
| 连接期限 | 默认 5 秒，上限 60 秒 |
| 单例完整执行/核对 | 默认 180 秒，上限 600 秒，包含有界只读核对和采集完成等待 |
| 单次裁判请求/响应 | 各 2 MiB；整次默认 120 秒，上限 300 秒 |
| 裁判调用数 | 每个 MODEL 用例最多 2 次；每批显式配置上限，最大 2,000 |
| 裁判 token 预算 | 必填窗口、输出上限、安全余量及累计输入估算上限；与业务预算分开 |

裁判使用完整序列化消息的本地 UTF-8 保守启发式计数，按本次固定比例、角色/消息开销与余量决定准入。它是 ESTIMATED，不证明真实 token 或费用上限；正常 usage 完整记录，未知费用不补零。批次同时有最大请求数和累计估算输入限制，达到任一后停止，剩余项保留未评状态。

不自动重试生成或裁判；同一份已采集证据可以由操作者显式新建 judgeRunId 再评，保留此前失败。帮助、报告、复核及数据校验不读取密钥或发网络请求。

## Risks / Trade-offs

- [裁判偏差或被材料影响] → 隔离两类视图、固定规则、确定性定位校验、失败/未知复核和通过样本抽查；不把自动评分作为真实性证明。
- [采集扩大内容持久化范围] → 默认关闭、专用部署、受控测试身份与登记、只接纳合成/审定脱敏集、目录访问和保留策略；不承诺离线文件随线上撤权自动消失。
- [采集影响流式性能] → 有界异步写入、失效证据标记和独立取消路径；采集失败宁可失去本次评测，不延长业务许可。
- [输入准备被误报为真实调用] → 独立阶段、usage 未知语义及模型/业务/交付三方核对。
- [模型别名和语料声明漂移] → 制品及实际输入摘要、声明/观测分离；运维固定测试环境，报告不声称验证了模型权重。
- [完整闭环实际运行依赖真实环境] → 本次仅验证进程内组件行为，明确记录真实联调和质量效果未验证，不另设真实环境验收任务或隐含完成条件。
- [首期只覆盖一个实例与第一轮] → 明确范围；多轮历史、跨节点采集和线上持续评审另行规划，避免未经设计扩大授权与数据保留。

## Migration Plan

以下描述交付后的部署、使用与回退方式，作为运行手册参考，不属于本次执行的测试任务或完成条件。

1. 实现阶段构建新 CLI 及 AI 采集能力；默认配置关闭。原检索工具格式、公开问答请求及业务数据库不迁移。
2. 专用环境更新 AI 制品，配置同机/共享挂载受控目录、测试身份、实例标识及容量；网关指向此实例。显式验证 prod 启用拒绝与普通请求不采集。
3. 通过既有上传/导入及审核发布准备固定语料，核对解析、Embedding、模型预算、认证、结算和文件权限。运行器使用既有测试账号，不自动创建或提权。
4. `validate-dataset` 后依次 collect、judge、review-template、人工填写、review-import、report；初次使用显式基线和门禁配置，记录声明与真实验证范围。
5. 回退时停止新评测、取消在途测试请求并等待原业务收尾，关闭采集，再回退 CLI/AI；既有业务状态和已生成文件不因回退删除。产物及测试会话按明确清单人工清理，不反迁移数据库。
