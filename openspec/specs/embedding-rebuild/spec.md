# embedding-rebuild Specification

## Purpose

为已发布知识内容提供受控的模型更换和向量修复能力，在保持全文检索与原有访问控制的前提下，管理当前版本分块的重算、暂停、进度、故障恢复与完成切换，避免半成品向量进入在线混合检索。

## Requirements

### Requirement: 重建必须由显式请求发起且先验证目标可用

系统 SHALL 提供 `POST /api/admin/embedding/rebuilds`，接收 profileId、非负
expectedEpoch、原因及请求标识，通过输入、资格、目标查询/文档客户端可用性检查后返回 202 和 runId。未知 profile 或夹带覆盖配置
MUST 返回 400；预检失败 MUST 返回 503 且不改变原服务模式。相同 profile SHALL 允许用于修复性重建。

#### Scenario: 目标只有查询侧可用

- **WHEN** 目标查询客户端可用，但没有就绪文档客户端能使用同一目标身份
- **THEN** 发起被拒绝，原 ACTIVE 或未初始化状态保持不变

#### Scenario: 正常开始重建

- **WHEN** 合格操作者以当前 epoch 提交合法且预检通过的目标
- **THEN** 系统返回 runId 并进入维护准备阶段，客户端无需等待全库重算完成

### Requirement: 重建管理必须幂等并防止并发覆盖

系统 MUST 按操作域和请求标识绑定操作者、目标、预期版本及规范化原因；匹配重放重新鉴权后返回首次回执，不创建第二次操作。输入不匹配或非重放请求版本过期
MUST 返回 409。requestId SHALL 为 1-128 字符，原因去空白后为 1-500 字符；请求体与头同时提供标识时必须一致。

#### Scenario: 同一开始请求并发重试

- **WHEN** 同一操作者并发提交相同请求标识和内容
- **THEN** 最多创建一个 run，一条成功操作审计；后续返回首次回执并标记 replayed

#### Scenario: 他人复用请求标识

- **WHEN** 另一名已获资格的操作者使用已有标识提交请求
- **THEN** 返回 409，不返回原回执也不修改作业

#### Scenario: 头和请求体标识不一致

- **WHEN** requestId 与 X-Request-Id 不同，或原因/预期版本不合法
- **THEN** 返回 400，维护状态和成功审计不改变

### Requirement: 同一系统只允许一个未完成重建

系统 MUST 在持久状态中只允许一个未完成全局作业，BLOCKED 也占用该位置。开始后目标 profile MUST 固定；首期 MUST NOT
提供半途换目标、取消后立即恢复向量或强制激活接口。完成后重新选旧 profile SHALL 通过另一轮完整重建执行，而非切换配置回滚。

#### Scenario: 并发选择不同模型

- **WHEN** 两个合法请求并发选择不同目标
- **THEN** 至多一个作业建立，另一个返回 409，不形成两套同时覆盖的写入

#### Scenario: 部分重建后请求改回旧模型

- **WHEN** 作业未完成且已有部分新向量，操作者请求新建旧模型作业或修改目标
- **THEN** 系统拒绝，保留原目标和成功进度，不恢复旧向量服务

### Requirement: 维护状态必须持久化并控制服务行为

系统 SHALL 持久化未初始化、准备收敛、重建、校验、阻塞与 ACTIVE 状态，并记录当前/目标 profile 和单调执行代次。除 ACTIVE 外 MUST
关闭向量召回和普通解析发布，但保持授权 BM25、上传及既有预览下载。实例重启、执行者失联或部分失败 MUST NOT 自动退出维护状态。

#### Scenario: 重建中服务重启

- **WHEN** 重建中 app 或 Worker 重启
- **THEN** 系统仍仅 BM25，普通解析继续等待，作业从持久进度恢复

#### Scenario: 旧向量查询尚未安全结束

- **WHEN** 维护准备阶段仍有可以读取旧向量的数据库查询
- **THEN** 系统不开始原地覆盖，直至查询结束或被安全终止

### Requirement: 重建范围必须限定于未删除文档的当前版本

系统 SHALL 在普通发布安全收敛后确定当前版本分块范围，包括文档或空间归档内容；历史版本及尚无当前版本的新上传 MUST 不重算。并发删除
MUST 使对应内容退出范围。历史分块原 profile 或未知身份 MUST 保留，不得通过全表改标冒充已重建。

#### Scenario: 文档有历史版本且空间已归档

- **WHEN** 该文档进入重建范围
- **THEN** 仅当前版本已有分块被重算，归档状态不变，历史向量和身份不变

#### Scenario: 重建期间新上传文档

- **WHEN** 新文档已上传但尚无当前发布版本
- **THEN** 不将其算作缺失向量，待恢复普通解析后再建立向量

#### Scenario: 模型调用期间删除文档

- **WHEN** 文档在其分块向量生成期间被删除
- **THEN** 提交跳过该文档，不恢复文档或版本指针，并可查询跳过计数

### Requirement: 重建不得改变正文或权限事实

系统 MUST 基于已有分块正文原地更新向量相关字段，保留分块 ID、正文、来源、解析元数据、内容版本、空间、密级及 ACL。重建与搬迁/升密并发时
MUST 保留各自合法结果；正文或版本不再匹配时不得写入基于旧文本的向量。重建 MUST NOT 重跑解析器或切块器。

#### Scenario: 重建与搬迁及升密重叠

- **WHEN** 向量生成期间文档完成合法搬迁和密级调整
- **THEN** 重建完成后向量属于目标 profile，空间与密级仍是最新值，ACL 仅按既有搬迁语义处理

#### Scenario: 分块内容意外改变

- **WHEN** 提交时发现分块正文与本次生成输入不一致
- **THEN** 拒绝该结果并记录可诊断阻塞，不将旧文本向量写入新正文

### Requirement: 批次提交与进度必须原子且可续建

系统 MUST 原子提交批次向量、profile 身份和对应进度，防止成功计数与实际数据脱节。执行资格失效的旧实例 MUST 不能写回；接管后
SHALL 只处理未提交的目标。已提交成功批次不得因重启或恢复再次调用模型；提交前崩溃的调用不承诺避免上游重复计费。

#### Scenario: 写入向量后进度更新失败

- **WHEN** 批次事务在向量更新后、进度提交前失败
- **THEN** 整批数据库修改回滚，重试不会面对向量已成功但进度丢失的状态

#### Scenario: 成功批次后进程退出

- **WHEN** 部分批次已提交成功后 Worker 退出并被接管
- **THEN** 成功批次保留且不重复生成，仅续建未提交部分

#### Scenario: 租约接管后旧实例返回

- **WHEN** 新执行者取得资格后旧执行者提交迟到结果或失败状态
- **THEN** 旧提交无效，不覆盖新执行者的向量或进度

### Requirement: 重建失败必须保留进度且只能受控恢复

系统 SHALL 对临时故障有界退避，永久故障或重试耗尽进入 BLOCKED，保留成功进度、目标和恢复阶段。
`POST /api/admin/embedding/rebuilds/{runId}/resume` MUST 重新鉴权、检查
expectedVersion、目标可用性和请求幂等后恢复原作业。失败不得自动恢复混合检索或将普通解析标为死信。

#### Scenario: 模型持续限流直至耗尽

- **WHEN** 目标服务持续返回可重试错误并达到上限
- **THEN** 作业进入 BLOCKED，BM25 保持可用，新内容继续等待，错误原因可查询

#### Scenario: 管理员修复后恢复

- **WHEN** 合格操作者以正确版本恢复 BLOCKED 作业且目标预检通过
- **THEN** 返回 202，沿原目标和成功进度继续，不新建全量作业

#### Scenario: 恢复预检仍失败

- **WHEN** 目标服务仍不可用时提交恢复
- **THEN** 返回 503，作业保持 BLOCKED，不丢失成功进度

### Requirement: 完成必须验证实际范围和目标服务能力

系统 MUST 在激活前核验实际范围全部分块具有目标 profile、合法 1024
维有限非零向量，没有漏项、未完成工作或可提交旧结果的资格，且目标查询和文档客户端已通过新鲜可用性检查。通过后才原子启用目标
profile、完成作业并恢复普通解析；任何失败 MUST 保持维护模式。

#### Scenario: 计数完成但有分块未覆盖

- **WHEN** 进度显示完成但实际当前版本仍有旧 profile、未知身份或非法向量
- **THEN** 校验失败并记录阻塞，不进入 ACTIVE

#### Scenario: 当前版本记录存在却无分块

- **WHEN** 校验发现已有当前版本的文档缺失全部分块
- **THEN** 报告数据完整性阻塞，不以空集合伪装重建成功；尚无当前版本的新上传不触发此错误

#### Scenario: 校验通过后恢复

- **WHEN** 数据覆盖、执行资格与目标可用性全部通过
- **THEN** active profile、服务模式和作业成功状态一起提交，新解析任务统一使用目标 profile

#### Scenario: 激活后有实例配置落后

- **WHEN** 一台实例没有目标 profile 的兼容客户端
- **THEN** 该实例不使用旧模型进行向量查询或普通发布，不影响其他就绪实例正确服务

### Requirement: 管理状态和审计必须可追踪且不泄露内容

系统 SHALL 提供 `GET /api/admin/embedding/status` 与 `GET /api/admin/embedding/rebuilds/{runId}`，返回模式、profile
身份、版本、分块进度、退避及脱敏阻塞原因；未知作业返回 404。发起、恢复、阻塞和完成 MUST 留下可关联且去重的事件。日志、响应和指标
MUST 不包含正文、查询词、凭据或远程错误体。

#### Scenario: 查询阻塞任务

- **WHEN** 有读取资格的操作者查询 BLOCKED 作业
- **THEN** 可见成功、未完成和跳过计数以及受限错误码，不返回其他文档正文或存储路径

#### Scenario: 审计写入失败

- **WHEN** 发起、恢复或激活的成功审计无法与状态一起提交
- **THEN** 对应状态变更回滚，不产生没有审计的成功操作

#### Scenario: 多次巡检同一阻塞

- **WHEN** 多实例重复观察同一次状态转移
- **THEN** 不产生重复转移事件，指标标签不按作业或分块 ID 无界增长
