# document-administration Specification

## Purpose

为文档授权和搬迁提供独立于正文阅读权限的最小管理查询，使具有当前空间管理资格的操作者能够定位文档，同时保持标题、文件名、正文、版本内容和存储地址的既有访问边界。

## Requirements

### Requirement: 管理文档清单必须按当前管理范围过滤

系统 SHALL 提供 `GET /api/admin/documents`，仅返回调用者当前拥有所属空间 manage 资格或 `space:manage-all` 资格的未删除文档。查询
MUST 不以 view、edit、文档例外授权、文档所有者或角色名称替代管理资格。最小清单不因正文 ACL 或操作者密级不足而隐式授予正文读取能力。

#### Scenario: 只有空间管理资格

- **WHEN** 启用用户能够管理空间 A，但没有 A 中文档的 view 权限
- **THEN** 清单返回 A 中未删除文档的最小管理记录
- **AND** 该用户通过内容接口读取标题、版本或正文仍按原有规则被拒绝

#### Scenario: 只有正文读取资格

- **WHEN** 用户能够阅读某文档，但不具备其所属空间的 manage 或跨空间管理资格
- **THEN** 管理清单不包含该文档，即使用户是上传者或拥有文档例外授权

#### Scenario: 跨空间管理资格

- **WHEN** 用户当前持有 `space:manage-all`
- **THEN** 清单可包含全部空间中的未删除文档，但不因此提供内容读取或密级调整资格

### Requirement: 管理清单必须使用固定的最小字段投影

每条管理记录 SHALL 仅包含 `documentId`、`spaceId`、`spaceArchived`。响应 MUST NOT
包含标题、文件名、文档密级、所有者、版本、解析错误、分块、存储键、外部地址或正文；即使调用者同时持有 view，也 MUST
使用相同的最小投影。正文信息只能通过既有受保护接口另行取得。

#### Scenario: 管理者同时可以阅读

- **WHEN** 同一用户同时持有管理和阅读权限并调用管理清单
- **THEN** 返回字段仍严格限定为三个管理字段，不自动合并普通文档摘要

#### Scenario: 文档包含敏感标题和文件名

- **WHEN** 查询命中的文档带有敏感标题、文件名、存储键和解析错误信息
- **THEN** 响应及查询错误信息不包含这些值

### Requirement: 归档内容必须保持管理可达而不恢复读取

管理清单 SHALL 默认包含归档空间中的未删除文档，支持显式 `spaceArchived` 布尔过滤；无当前发布版本的新文档也 SHALL
可被定位。软删除文档 MUST 始终排除。查询 MUST NOT 取消归档、激活版本、触发解析或改变既有读取与检索结果。

#### Scenario: 归档空间中的文档

- **WHEN** 空间已归档且用户仍有该空间管理资格
- **THEN** 管理清单仍返回文档 ID 并标记 `spaceArchived=true`
- **AND** 普通文档列表、详情、预览、下载和检索不因本查询恢复可见

#### Scenario: 首个版本尚未解析完成

- **WHEN** 新上传文档已有记录但尚无当前发布版本
- **THEN** 管理清单可按文档 ID 定位它，不把“没有当前版本”误认为文档不存在

#### Scenario: 文档被删除

- **WHEN** 管理者以精确 ID 查询已软删除的文档
- **THEN** 返回空集合，不返回历史标题、版本或对象信息

### Requirement: 管理清单必须支持有界且授权一致的分页过滤

清单 SHALL 支持可选的正整数 `spaceId`、`documentId`、布尔 `spaceArchived`、`limit` 和 `cursor`，按 `documentId` 倒序返回
`items`、`hasMore`、`nextCursor`。limit 默认 20、范围 1–100；非法参数、未知过滤字段和不匹配查询条件的游标 MUST 返回 400。过滤及分页
MUST 在当前可管理范围内完成，MUST NOT 返回未授权总数。

#### Scenario: 指定无权管理的空间或文档

- **WHEN** 合法用户使用无权管理或不存在的 spaceId/documentId 过滤
- **THEN** 两种情形均返回相同形状的空页，不泄露目标是否存在

#### Scenario: 翻页期间新增文档

- **WHEN** 第一页之后出现 ID 更大的新文档，调用者使用返回的游标继续查询
- **THEN** 继续按上一页末尾 ID 向后读取，不因新记录插入重复返回已遍历记录
- **AND** 不承诺跨请求的冻结快照；删除、搬迁和权限变化按当前事实过滤

#### Scenario: 使用正文相关过滤条件

- **WHEN** 请求试图以 title、fileName 或正文关键词过滤最小管理清单
- **THEN** 返回 400，不使用隐藏字段的匹配结果充当存在性探针

### Requirement: 管理查询必须在每次请求重新校验资格

新查询 SHALL 对无效或缺失会话返回 401，对用户或主部门停用、强制改密状态返回 403；正常身份无管理范围时返回空页。分页游标 MUST
NOT 充当授权凭据。管理授权变更完成后的下一次查询 SHALL 使用新权限范围，响应 MUST 标记 `Cache-Control: no-store`，依赖故障
MUST 不被伪装为空结果。

#### Scenario: 使用旧游标继续访问已撤权空间

- **WHEN** 第一页查询后该用户的空间 manage 被撤销，下一次请求继续使用原游标
- **THEN** 不再返回该空间的文档，也不要求退出并重新登录才生效

#### Scenario: 文档在两页之间搬迁

- **WHEN** 文档迁入调用者无权管理的空间，调用者随后精确查询或翻页
- **THEN** 文档不再出现在管理清单中，游标不能保留原空间管理资格

#### Scenario: 权限或数据库查询故障

- **WHEN** 当前请求不能可靠取得授权事实或执行查询
- **THEN** 返回安全的 503，不返回“没有文档”的成功空页，不暴露 SQL 或底层异常

### Requirement: 管理端删除必须按当前所属空间的管理资格判定

系统 SHALL 提供 `DELETE /api/admin/documents/{documentId}`，仅允许在该文档当前所属空间持有 manage 或持有 `space:manage-all` 的已认证操作者执行。资格 MUST NOT 由 view、edit、download、文档例外授权、上传者身份或角色名称替代，MUST 基于服务端解析的主体；已停用用户或主部门已停用的用户 MUST 被拒绝。已归档空间中的文档 SHALL 可以被删除。

#### Scenario: 空间管理员删除本空间文档

- **WHEN** 操作者在空间 S 持有 manage，但没有 S 中文档 D 的 view 或 edit
- **THEN** 对 D 的管理端删除被接受
- **AND** 操作者无需先为自己授予 edit

#### Scenario: 只有编辑资格

- **WHEN** 操作者持有文档 D 的 edit 或文档例外，但不在其所属空间持有 manage，也没有 `space:manage-all`
- **THEN** 管理端删除返回与目标不存在相同的 404
- **AND** 用户端按 edit 判定的删除接口不受影响

#### Scenario: 已归档空间中的文档

- **WHEN** 文档所属空间已归档，操作者仍持有该空间 manage
- **THEN** 管理端删除被接受
- **AND** 不要求先取消归档

#### Scenario: 已停用操作者

- **WHEN** 会话对应的用户已停用，或其主部门已停用
- **THEN** 系统拒绝该删除
- **AND** 不写入任何变更或审计事件

### Requirement: 管理端删除必须与用户端删除产生相同的文档效果

管理端删除 SHALL 软删除整份文档及其全部版本，在同一事务内取消该文档未完成的解析任务与审核轮次，事务提交后尽力清理全部版本原件。迟到的解析任务 MUST NOT 重新发布已删除文档的内容。删除后该文档 MUST 从检索、列表、详情、下载、预览、收藏、评论读取与管理文档清单中消失。系统 MUST NOT 提供恢复，原件清理失败 MUST NOT 回滚已提交的删除。

#### Scenario: 存在未完成解析任务

- **WHEN** 文档某版本仍在排队或解析中时被管理端删除
- **THEN** 该任务被取消，删除提交成功
- **AND** 此后 Worker 不得发布该版本的分块

#### Scenario: 存在进行中的审核

- **WHEN** 文档某版本处于审核轮次中时被管理端删除
- **THEN** 审核轮次被取消
- **AND** 相关审核待办不再可处理

#### Scenario: 原件清理失败

- **WHEN** 事务提交后对象存储删除失败
- **THEN** 文档保持已删除状态
- **AND** 残留原件由既有对象存储对账处理

### Requirement: 管理端删除必须对不可达目标统一返回 404 并在归属变化时拒绝

文档不存在、已删除或操作者无权管理其当前所属空间时，系统 MUST 返回同一 404，不区分三种情形。资格判定后、写入前文档归属发生变化时，系统 MUST 返回冲突错误且 MUST NOT 写入删除；调用方应重新读取归属后决定是否重试。路径参数不是正整数时返回 400。

#### Scenario: 不存在与无权管理

- **WHEN** 合格登录者分别删除不存在的文档和其无权管理空间中的文档
- **THEN** 两者返回相同形状的 404
- **AND** 响应不泄露目标是否存在或所属空间

#### Scenario: 已被用户端删除

- **WHEN** 文档已通过用户端删除，管理员随后以新的请求标识提交管理端删除
- **THEN** 返回 404
- **AND** 不产生新的审计事件

#### Scenario: 判定后被搬迁

- **WHEN** 资格按空间 S 判定通过后，文档在写入前被搬迁到操作者无权管理的空间 T
- **THEN** 删除返回冲突错误，文档保持未删除
- **AND** 不写入成功审计事件

### Requirement: 管理端删除必须幂等并产生最小披露的审计事件

删除 SHALL 要求请求标识，缺失返回 400。同一请求标识重复提交时，系统 SHALL 在重新核对操作者对首次删除时所属空间的管理资格后返回首次回执并标记 replayed，MUST NOT 再次写入。每次成功 SHALL 产生一条 `DOCUMENT_ADMIN_DELETE` 操作域的审计事件，记录操作者、文档 ID、所属空间、归档状态、时间与请求标识。回执与审计 MUST NOT 包含标题、文件名、正文、存储键或会话令牌。

#### Scenario: 相同请求标识重试

- **WHEN** 删除因超时被以相同请求标识重复提交
- **THEN** 系统返回首次回执且 replayed 为真
- **AND** 审计事件数量不变

#### Scenario: 回执与审计只含定位字段

- **WHEN** 被删除文档带有敏感标题、文件名和存储键
- **THEN** 回执仅包含文档 ID、所属空间 ID 与 replayed
- **AND** 审计摘要不包含上述敏感值

#### Scenario: 缺少请求标识

- **WHEN** 请求未携带 `X-Request-Id`
- **THEN** 返回 400
- **AND** 不执行删除

#### Scenario: 删除失败

- **WHEN** 资格、归属或持久化校验失败导致删除未提交
- **THEN** 系统不写入成功审计事件
- **AND** 失败信息不泄露操作者无权知悉的文档存在性
