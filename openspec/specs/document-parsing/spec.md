# document-parsing Specification

## Purpose

为文档解析、切块、检索引用和质量诊断提供稳定且可追踪的统一输出契约，使不同格式的文档都能保留结构、来源定位和解析质量信息。

## Requirements

### Requirement: 原件内容抽取必须通过第三方服务完成

系统 SHALL 将所有格式的原件内容抽取交给第三方服务，包括 PDF、Office、TXT 和 Markdown。Worker MUST 仅通过 `DocumentParser` 接入第三方服务，不内置文件解析引擎，也不提供本地解析回退。统一结果转换、分块、向量化和索引发布仍由本系统负责。

#### Scenario: 未接入第三方服务

- **WHEN** Worker 未装配第三方解析适配器，或适配器声明本地配置未就绪
- **THEN** 系统明确报告解析不可用，并在领取任务、增加尝试次数和改变版本状态前停止
- **AND** 待解析任务保持排队，不读取原件、不生成占位解析结果、不回退本地解析

#### Scenario: 接入第三方解析适配器

- **WHEN** Worker 装配已就绪的第三方 `DocumentParser` 实现
- **THEN** 原件内容抽取由该适配器调用外部服务完成，统一结果进入既有分块、向量化和发布流程
- **AND** 本系统不预设尚未确定的供应商协议，适配器须遵守既有质量、资源限制与失败契约

### Requirement: 解析结果必须保留文档结构与来源定位

系统 SHALL 将每个可索引内容单元表达为带类型、文本、层级上下文和来源定位的结构块；来源定位在可获得时 MUST 包含页码、行或字符范围，表格
MUST 保留行列单元格信息。

#### Scenario: 结构化文档成功解析

- **WHEN** 输入包含标题、正文、列表和表格的文档
- **THEN** 输出包含对应类型的结构块、标题路径和表格单元格
- **AND** 每个结构块保留可用的页码或源范围信息

#### Scenario: 无法确定来源坐标

- **WHEN** 解析器无法为某个结构块确定页码或精确范围
- **THEN** 该块仍可输出
- **AND** 未知坐标使用明确的未知值，不得伪造位置

### Requirement: 解析质量状态必须可追踪

系统 SHALL 在解析结果中记录截断、警告和错误问题及其代码、消息和来源位置；存在错误时文档版本 MUST 不得被发布为可检索状态，存在警告时
MUST 保留结果并保留问题信息供诊断。

#### Scenario: 抽取达到资源上限

- **WHEN** 文档内容达到配置的抽取上限
- **THEN** 结果标记为已截断
- **AND** 产生可识别的截断问题
- **AND** 版本不得被误报为完整解析

#### Scenario: 解析器报告错误

- **WHEN** 解析器返回错误级问题
- **THEN** 当前版本保持失败或待重试状态
- **AND** 不得写入可被检索的完整索引

### Requirement: 分块必须保留结构和引用溯源

系统 SHALL 为每个发布的分块保留其标题路径、页码和来源范围；切块 MUST 尽量在结构块、段落、句子或表格边界结束，且不得产生空分块或无界进度。

#### Scenario: 分块跨越多个结构块

- **WHEN** 一个分块包含多个相邻结构块
- **THEN** 分块保留首尾来源范围
- **AND** 标题路径和页码按照确定的继承规则输出
- **AND** 来源范围仍可用于定位原文

#### Scenario: 表格被切分

- **WHEN** 表格内容超过单个分块容量
- **THEN** 切分结果保留表格行列语义和来源范围
- **AND** 不得把表格单元格内容静默改写为无法解释的纯文本

### Requirement: 解析元数据与分块发布必须原子且可重试

系统 SHALL 将解析版本的质量元数据、解析器版本和分块来源信息与索引结果关联保存；索引结果必须在同一原子操作中完成，重复处理同一文档版本 MUST 得到一个一致的最终结果。索引完成 MUST 不等于业务发布：AUTO 版本满足发布门禁时自动推进，REVIEW_REQUIRED 版本仅完成候选索引，批准后才发布。写入分块 MUST 与文档当前空间一致，不因搬迁并发保留旧空间过滤归属。

#### Scenario: 解析成功并发布

- **WHEN** 解析、切块和向量化均成功且任务租约有效
- **THEN** 系统保存解析元数据和全部分块来源信息，版本进入 indexed
- **AND** 只有满足固定发布策略与发布门禁的版本才可成为当前可检索版本

#### Scenario: 发布过程中发生失败

- **WHEN** 元数据或分块写入中任一步失败
- **THEN** 该版本不得呈现为已索引
- **AND** 重试可以清理不完整结果并重新发布索引结果
- **AND** 不产生重复的同版本分块

#### Scenario: 同一版本重复处理

- **WHEN** 同一文档版本因重试或任务重投被再次处理
- **THEN** 最终只保留一套与最新成功结果一致的分块和元数据
- **AND** 不覆盖更新版本的当前版本指针，不借重试绕过审核

#### Scenario: 发布与文档所属空间变更并发

- **WHEN** 同一文档的分块发布与其所属空间变更在时间上重叠
- **THEN** 两者完成后全部已索引分块都按文档当前所属空间参与权限过滤
- **AND** 不残留按原空间参与过滤的分块

#### Scenario: 需审版本解析完成
- **WHEN** REVIEW_REQUIRED 的 V2 完成合法索引而 V1 已发布
- **THEN** V2 等待手动送审，不推进当前版本，V1 仍按原权限参与两路检索

### Requirement: 兼容旧解析器并明确不支持的输入

系统 SHALL 允许仅能返回纯文本的旧解析器继续工作，并将其包装为合法的统一结构结果；无法解析或不支持的输入 MUST
返回可诊断的问题，而不得返回空成功结果。

#### Scenario: 旧解析器返回纯文本

- **WHEN** 解析器未提供结构化输出
- **THEN** 系统将文本包装为至少一个合法内容块
- **AND** 现有分块与索引流程继续执行

#### Scenario: 输入无法解析

- **WHEN** 文件类型不受支持或解析器失败
- **THEN** 任务记录明确的失败问题代码和原因
- **AND** 版本不进入可检索状态

### Requirement: 解析任务恢复必须可收敛

系统 SHALL 区分租约恢复、可重试失败和终态失败；待重试任务 MUST 在下一次允许时间前保持不可领取，且文档版本状态 MUST
能反映任务正在等待重试或已失败。

#### Scenario: 暂时性依赖失败后退避

- **WHEN** 对象存储、embedding 或数据库发生可重试故障
- **THEN** 任务记录下一次可尝试时间并回到待重试状态
- **AND** 在该时间前的轮询不得重复领取该任务

#### Scenario: 租约过期恢复

- **WHEN** Worker 崩溃或失联导致运行中任务的租约过期
- **THEN** 其他 Worker 可以重新领取该任务并继续执行
- **AND** 原 Worker 即使恢复也不得写入结果或失败状态

#### Scenario: 自动重试期间的版本状态

- **WHEN** 任务失败但仍有自动重试机会
- **THEN** 文档版本对查询方显示为可识别的待重试状态
- **AND** 不得长期显示为仍在解析且没有下一步状态信息

### Requirement: 失败分类必须决定重试或死信

系统 SHALL 将解析失败分类为永久错误、可重试错误或未知错误；永久错误 MUST 立即进入死信，可重试和未知错误 MUST 受最大尝试次数约束。

#### Scenario: 永久错误立即死信

- **WHEN** 输入无效、格式不支持、内容不可索引或解析器明确返回错误
- **THEN** 任务不再重复消耗自动尝试次数并进入死信
- **AND** 文档版本不得进入可检索状态

#### Scenario: 暂时性错误退避重试

- **WHEN** 对象存储、embedding 或数据库返回超时、限流或暂时性服务错误
- **THEN** 任务按退避策略重新排队
- **AND** 达到最大尝试次数后进入死信并标记文档版本失败

#### Scenario: 租约失守不伪造失败

- **WHEN** 当前 Worker 发现自己已经失去任务租约
- **THEN** 当前 Worker 放弃写回结果和失败记录
- **AND** 该事件由后续租约恢复路径处理而不是生成重复失败

### Requirement: 死信必须保留执行历史并支持安全重放

系统 SHALL 保存每个执行周期的尝试、失败分类、脱敏错误摘要和死信处置结果；人工重放 MUST 开启新的执行周期并保留原死信历史。

#### Scenario: 任务进入死信

- **WHEN** 永久错误或自动重试耗尽导致任务终止
- **THEN** 系统保存可按任务、文档版本和时间查询的死信记录
- **AND** 记录包含最后一次尝试、失败分类、原因摘要和进入时间

#### Scenario: 管理员重放死信

- **WHEN** 管理员为未解决的死信提交带原因的重放请求
- **THEN** 原死信记录保持不变并创建新的待执行周期
- **AND** 重放请求与操作者、请求标识和原因关联保存

#### Scenario: 重放请求重复提交

- **WHEN** 同一请求标识因超时被重复提交
- **THEN** 系统最多创建一个新的执行周期
- **AND** 任务不会被并行重置或重复入队

### Requirement: 任务恢复操作必须按角色授权并可审计

系统 SHALL 允许有文档编辑权限的用户重试其可见版本。全局死信查询 MUST 要求启用主体当前持有 `parse:deadletter:read`，重放 MUST 要求 `parse:deadletter:replay`；两项资格独立，按角色绑定的功能权限精确判定，不因 ROLE_ADMIN 名称或文档编辑资格隐含授予。管理操作 MUST 产生不含敏感正文的审计摘要，并在检查目标或返回既有重放结果前重新验证当前操作资格。

#### Scenario: 用户重试自己的失败版本

- **WHEN** 已认证用户对拥有 edit 权限的失败版本发起重试
- **THEN** 任务进入新的待执行周期
- **AND** 历史失败与重试原因仍可查询

#### Scenario: 普通用户访问全局死信

- **WHEN** 当前用户没有全局死信查询或重放所需的功能权限
- **THEN** 对应请求返回禁止错误
- **AND** 不泄露其他文档、任务或失败原因是否存在

#### Scenario: 管理员处置死信留下审计

- **WHEN** 合格操作者查询、重放死信，或既有合法路径将死信标记已处理
- **THEN** 系统记录操作者、目标、操作、请求标识、时间和适用的脱敏原因
- **AND** 同一重放请求标识的匹配重试不得产生重复处置事件，本要求不新增手工标记解决接口

#### Scenario: 已撤销重放权限后再次重试
- **WHEN** 操作者先前成功重放，但当前角色权限已撤销该重放资格
- **THEN** 原请求标识的重试仍被拒绝，不通过读取既有回执绕过当前权限

### Requirement: 解析任务告警必须围绕状态事件发出

系统 SHALL 为死信转移、租约失守异常、队列老化和告警发送失败产生结构化事件；告警事件 MUST 支持去重，并不得包含会话令牌、完整对象路径或完整堆栈。

#### Scenario: 崩溃后最终失败告警

- **WHEN** 任务因租约过期和尝试耗尽由巡检落入死信
- **THEN** 系统发送与直接异常失败等价的死信告警事件
- **AND** 不因失败发生在巡检线程而静默遗漏告警

#### Scenario: 同一死信重复巡检

- **WHEN** 多个 Worker 同时发现同一任务已达到死信条件
- **THEN** 对外最多发送一条该执行周期的死信告警
- **AND** 数据库终态和告警事件保持一致

#### Scenario: 告警载荷脱敏

- **WHEN** 系统构造失败或死信告警载荷
- **THEN** 载荷包含任务、版本、分类、尝试次数和受限原因摘要
- **AND** 不包含会话凭据、完整对象内容或未截断堆栈

### Requirement: 解析任务指标必须支持健康观测

系统 SHALL 暴露低基数的任务处理、队列、租约、死信和告警指标；指标标签 MUST 不包含任务 ID、版本 ID、对象路径或用户输入。

#### Scenario: 队列积压观测

- **WHEN** 监控系统读取 Worker 指标
- **THEN** 可以获得待处理数量、死信数量和最老待处理任务年龄
- **AND** 指标能区分任务状态而不产生每任务一个时间序列

#### Scenario: 处理结果和耗时观测

- **WHEN** 任务完成、重试、死信或租约失守
- **THEN** 系统更新对应结果计数和处理耗时分布
- **AND** 可以按结果类型和失败分类观察趋势

#### Scenario: 外部阈值告警

- **WHEN** 外部监控规则根据积压年龄、死信深度或租约失守率超过阈值
- **THEN** 运维系统可以触发通知
- **AND** Worker 不要求绑定某个具体通知平台才能提供这些观测数据

### Requirement: embedding 维护期间上传必须排队而非伪发布

系统 SHALL 在 embedding 未初始化或维护期间继续受理合法上传与新版本创建，但暂停普通解析领取和发布，也不允许审批切换当前版本。版本仍固定创建时空间发布策略。新文档在满足索引与业务发布条件前 MUST 不可检索；新版本 MUST 不替换旧当前版本。等待状态 MUST 可与真实解析失败及待审区分，不得仅因维护等待消耗尝试次数。

#### Scenario: 维护期间上传新版本

- **WHEN** 有编辑资格的用户在重建期间上传既有文档的新版本
- **THEN** 原件、版本和持久任务正常创建并固定策略，旧当前版本仍可按权限检索和读取，新任务等待维护结束

#### Scenario: 用户查询等待进度

- **WHEN** 用户按既有权限查询处于维护等待中的解析版本
- **THEN** 返回可识别的 embedding 维护等待原因，而不是模型故障、待审完成或虚假的已发布状态

#### Scenario: 维护期间批准
- **WHEN** 合格审核人在非 ACTIVE 状态尝试批准候选版本
- **THEN** 不保存通过决定或切换当前版本，明确提示维护冲突

### Requirement: 在途普通解析必须无伪失败地安全收敛

系统 MUST 在重建覆盖开始前完成或失效所有在途普通发布资格。仅因维护被中止的尝试 SHALL 幂等回到待处理，不新增解析失败或死信、不净消耗重试预算；此前真实失败记录
MUST 保留。迟到心跳、失败写回和旧结果 MUST 不改变新状态，手工重试和巡检不得绕过维护暂停。

#### Scenario: 在途任务因维护中止

- **WHEN** 任务正在调用模型时进入维护并中止该次执行
- **THEN** 该次执行被记录为维护延期并回到等待，历史真实失败次数保留，不产生新的业务失败

#### Scenario: 巡检与维护收敛并发

- **WHEN** 多个实例同时巡检或尝试收敛同一被维护中止的执行
- **THEN** 维护延期只生效一次，既不重复补偿次数，也不将该次中止记入死信

#### Scenario: 手工重试处于维护期间

- **WHEN** 合格用户重试一个真实失败版本
- **THEN** 依既有规则入队和保留历史，但仍等待维护结束才领取

### Requirement: 普通发布必须验证生成时的 profile 与代次

系统 MUST 使普通解析结果携带生成时固定的 profile 和有效执行代次；只有系统仍允许普通索引提交且身份兼容、租约有效时才原子保存分块及索引状态，是否切换当前版本另受固定审核策略控制。维护结束后新任务 SHALL 使用新 active profile。审批发布仍须验证候选的索引身份兼容，不能将旧向量补标为新 profile。此约束 MUST 不削弱幂等、删除防复活、空间及密级同步。

#### Scenario: 旧任务在新 profile 激活后返回

- **WHEN** 旧代次普通解析结果在维护完成后才返回
- **THEN** 结果不得提交、不得把旧向量标成新 profile，也不得覆盖当前版本

#### Scenario: 新任务与升密或搬迁并发

- **WHEN** 恢复后的普通解析使用新 profile，期间文档完成升密或搬迁
- **THEN** 新分块使用新 profile 以及文档提交时的空间和密级，原发布一致性约束保持成立

#### Scenario: 待审索引未纳入全库重建
- **WHEN** 待审版本仍保留旧 profile，而仅当前版本的全库重建已经完成
- **THEN** 不因重建成功推断该候选就绪；发布拒绝并要求显式刷新候选索引和重新送审

### Requirement: 死信查询必须显式校验筛选和分页条件

`GET /api/admin/parse/dead-letters` SHALL 保留 page、size、status、failureClass、from、to 及分页成功结构。page MUST 为 1–2147483647，size 为 1–100；状态只接受 OPEN、REPLAYED、RESOLVED，分类只接受 PERMANENT、RETRYABLE、UNKNOWN，空值或省略表示不限制。时间须为带时区的合法时间，按含起点、不含终点筛选，双边存在时 from 必须早于 to。非法输入 MUST 返回 400，不查询目标资料。

#### Scenario: 未指定筛选条件
- **WHEN** 合格用户只提供合法分页和查询请求标识
- **THEN** 返回所有状态和分类中的对应页，按既有进入时间及 ID 倒序排列
- **AND** 保留查询审计，不因页面默认 OPEN 改变服务端省略条件的语义

#### Scenario: 未知枚举或反向时间
- **WHEN** status 或 failureClass 为未知非空值，或 from 大于等于 to
- **THEN** 返回 400，不将非法条件解释为空结果、全部数据或忽略条件

#### Scenario: 时间边界
- **WHEN** 某条记录进入时间等于 from 或 to
- **THEN** 等于 from 的记录可进入结果，等于 to 的记录不进入结果


### Requirement: 死信请求标识与原因必须独立校验且不得截断

死信查询及重放 SHALL 要求 X-Request-Id，去除首尾空白后长度为 1–256 个 Unicode code point；重放原因去除首尾空白后 MUST 为 1–2000 个 Unicode code point。空值、超长或包含 NUL 的输入 MUST 返回 400，不静默截断、替换或将不同输入规范化成同一个短标识。两类字段 SHALL 独立校验，原因不得复用标识的 256 字符限制。

#### Scenario: 长原因合法提交
- **WHEN** 合格操作者提供 300 个 Unicode code point 的合法原因及合法请求标识
- **THEN** 完整原因参与请求绑定与持久处置记录，不在第 256 个字符被截断

#### Scenario: 超长标识或原因
- **WHEN** 规范化标识超过 256，或规范化原因超过 2000 个 Unicode code point
- **THEN** 返回 400，不查询重放回执、不修改任务、不新增成功审计

#### Scenario: 原因包含需转义的文本
- **WHEN** 原因含引号、反斜杠、换行或制表符且仍满足输入约束
- **THEN** 合法文本完整参与绑定，审计摘要仍是有效结构，不通过拼接生成损坏或注入的字段


### Requirement: 死信重放必须绑定操作者目标和原因

`POST /api/admin/parse/dead-letters/{deadLetterId}/replay` MUST 将全局唯一请求标识绑定当前操作者、目标死信 ID 和规范化原因。当前已获资格的匹配重试 SHALL 返回首次已确认的死信重放结果，不新建周期或重复审计；任一绑定字段不同 MUST 返回 409，不返回原目标资料。未知或已被另一操作处置的目标继续返回 404。路径、请求体和成功 R 封装保持兼容。

#### Scenario: 同请求标识用于另一目标
- **WHEN** 合格操作者将已绑定请求标识用于另一条死信
- **THEN** 返回 409，不返回旧死信摘要，也不重放新目标

#### Scenario: 操作者或原因不匹配
- **WHEN** 另一名有重放资格的用户复用标识，或原操作者更改规范化原因
- **THEN** 返回 409，不把请求当作匹配重试或覆盖原处置记录

#### Scenario: 旧记录只能按持久事实核对
- **WHEN** 重试命中升级前已保存的重放记录
- **THEN** 按其已保存操作者、目标和原因核对；无法确认匹配时返回 409
- **AND** 不猜测被旧实现截断的原始长原因，不自动重建绑定或补写成功审计


### Requirement: 并发重放必须收敛并保持事务审计一致

系统 MUST 在并发请求下原子绑定请求标识、关闭原死信、创建至多一个新执行周期及写入一次成功审计。并发匹配请求在首次提交完成后 SHALL 返回同一已确认结果；并发内容冲突返回 409。事务失败 MUST 不留下部分处置或成功审计。维护期间合法重放只入队并遵守既有暂停，不能通过重放触发立即解析或激活向量。

#### Scenario: 同一请求并发到达
- **WHEN** 同一操作者对相同死信和原因使用同一标识并发重放
- **THEN** 至多创建一个新执行周期和一条成功审计，匹配请求取得相同已确认结果
- **AND** 不能把唯一约束冲突或第二次零行更新直接当作匹配重试的 500 或 404

#### Scenario: 不同请求标识争抢同一死信
- **WHEN** 两个合法不同标识并发重放同一 OPEN 死信
- **THEN** 至多一个成功关闭原死信，其他请求按已处置目标拒绝，不再递增执行周期

#### Scenario: 成功审计写入失败
- **WHEN** 原死信处置及任务重置已开始，但成功审计无法提交
- **THEN** 相关状态整体回滚，同一标识后续仍可按未成功请求重试

#### Scenario: Embedding 维护中重放
- **WHEN** 系统处于未初始化、维护或 BLOCKED 状态且合格用户重放真实失败任务
- **THEN** 新周期保持排队并保留历史，等待维护结束后才可被普通解析领取
