# worker-embedding-resilience Specification

## Purpose

为 Worker 的普通文档解析、向量重建和模型就绪探测建立一致的外部 Embedding 调用边界，使载荷、时间、并发占用和失败恢复均可核对，并在超时或执行资格失效后停止新增调用、隔离迟到结果和保留真实资源占用事实。

## Requirements

### Requirement: Worker 的全部 Embedding 入口必须使用统一运行限界

Worker SHALL 对普通解析、重建生成和每个 profile 的就绪探测使用统一载荷限界：每个 HTTP 请求默认最多 1048576 字节，每个响应正文默认最多 4194304 字节，JSON 最大深度默认 64。限界 SHALL 可配置，非法非正整数或无法安全处理的值 MUST 阻止启动。运行限额与槽位配置 MUST NOT 进入向量 profile 指纹或改变生成语义。

#### Scenario: 三条入口一致受限
- **WHEN** 同一远程 profile 分别用于普通解析、重建和就绪探测
- **THEN** 三条路径均执行请求、响应及 JSON 限界，不存在默认入口绕过限制

#### Scenario: 调整运行限额
- **WHEN** 部署只修改载荷限额或执行超时
- **THEN** profile 指纹保持一致，已存向量不因此要求重建

#### Scenario: 非法配置
- **WHEN** 任一限额为零、负数、小数、溢出值或非数值
- **THEN** Worker 拒绝启动，诊断只指明配置项，不回显凭据或原始配置内容

### Requirement: HTTP 子批必须同时满足条数与实际编码字节限制

Worker SHALL 在发送前按 profile 的 `batch-size` 与实际 JSON UTF-8 字节限额形成有序子批；字节计算 MUST 包含转换后的文本、转义、模型字段、维度与协议包络。恰好达到上限 SHALL 允许发送。任一单条输入连同包络仍超限时，整次生成 MUST 在首次发送前明确失败，不截断、改写或跳过文本。

#### Scenario: 条数允许但字节不足
- **WHEN** 条数上限为 16，而本组实际编码后一个请求只能容纳前 10 条
- **THEN** 系统顺序发送满足双限制的子批，并保留每条输入的原始对应位置

#### Scenario: 转义和前缀占用预算
- **WHEN** 文本含中文、补充字符、引号或换行，且 profile 要求文档前缀
- **THEN** 计算实际转换与转义后的 UTF-8 JSON 字节，不以字符数或未转换文本长度代替

#### Scenario: 最后一条输入单独超限
- **WHEN** 本次输入中较早条目均可发送，而最后一条连同包络仍超过上限
- **THEN** 在发送任何子批前返回请求超限错误，所有原文保持完整

#### Scenario: 请求恰好达到限额
- **WHEN** 子批编码后的字节数恰好等于限额
- **THEN** 该子批可以发送，再增加一个实际编码字节则拆批或明确失败

### Requirement: 子批结果必须保持输入对应关系与原子提交边界

系统 MUST 完整验证每个子批的结果数量、下标、模型身份、维度及向量有效性，再按原输入顺序组装整次结果。子批下标 SHALL 只在本次 HTTP 请求内解释。任一子批失败 MUST 使本次生成失败，不交付部分成功向量；普通文档索引和重建领取批次继续采用原有数据库原子提交单元。

#### Scenario: 各子批下标重新从零开始
- **WHEN** 两个合法 HTTP 子批均返回从零开始的下标
- **THEN** 系统分别校验各自范围，再按发送顺序映射回完整输入，不混用下标

#### Scenario: 后续子批失败
- **WHEN** 前两个子批成功而第三个超限、超时或返回非法向量
- **THEN** 本次生成不提交前两个子批的向量或成功进度；已有历史成功重建批次保持有效

### Requirement: 响应必须在完整读取和解析之前受字节限界

Worker MUST 按实际读取正文控制响应上限，未知字段同样计入；无长度头或长度声明不符不得绕过限制。声明已超限时 SHALL 提前拒绝，读取发现越限时 SHALL 停止并关闭响应资源，不先完整缓冲或反序列化。仅 HTTP 200 的合法结果可进入向量处理；其他状态不得读取供应商错误正文。

#### Scenario: 无长度头的大响应
- **WHEN** 上游持续发送无 Content-Length 的响应且正文越过上限
- **THEN** 在有限的越限探测后停止读取并发出响应超限错误，不继续读取剩余正文

#### Scenario: 响应边界
- **WHEN** 合法完整响应恰好达到上限，或在此基础上多一个字节
- **THEN** 前者可以继续协议校验，后者整批失败，不静默裁去尾部

#### Scenario: 错误正文包含敏感文本
- **WHEN** 上游返回 401、429 或 5xx，并附带任意正文
- **THEN** 系统根据状态分类且不读取正文，日志、异常摘要和持久状态均不包含该正文

### Requirement: 响应 JSON 必须完整且严格校验

Worker MUST 拒绝重复 JSON 属性、超出配置深度、尾随根值、损坏 JSON、空或非对象根及不完整响应。未知字段可以兼容，但其字节和结构 MUST 同样受限。只有完整通过 JSON 与既有 profile／向量校验的响应才可计为成功。

#### Scenario: 重复关键字段
- **WHEN** 响应重复提供 model、data 或结果项中的 index 等属性
- **THEN** 整个子批按协议错误失败，不按最后值覆盖后接受

#### Scenario: 深度与尾随内容
- **WHEN** 默认配置下响应超过 64 层，或合法根对象后还有另一个 JSON 根值
- **THEN** 响应按协议错误失败，不使用已解析的前缀

#### Scenario: 未知字段有界兼容
- **WHEN** 响应具有合法向量并带有未使用的附加字段
- **THEN** 附加字段仍受字节、深度和重复属性检查，完整响应合法时才可接受

### Requirement: 执行必须共享单调时钟截止时间

普通解析 SHALL 沿用默认 900 秒的流水线预算，重建生成阶段 SHALL 使用可配置的默认 300 秒预算，每个 profile 探测 SHALL 使用可配置的默认 10 秒预算。预算 MUST 使用单调时钟并覆盖所属阶段的准备、编码、全部 HTTP 子批、正文读取和结果校验；每次 HTTP 的剩余上限 MUST 不大于连接配置超时及父执行剩余时间。

#### Scenario: 解析已消耗部分时间
- **WHEN** 普通解析进入 Embedding 前已消耗流水线预算
- **THEN** 全部 Embedding 子批只能共享剩余时间，不重新取得 900 秒

#### Scenario: 多个 HTTP 子批
- **WHEN** 一个重建生成阶段拆成多个 HTTP 请求
- **THEN** 子批共享同一个生成截止，每次发送和返回后核对剩余时间

#### Scenario: 持续小块响应
- **WHEN** 远端持续发送字节但直到截止仍未完成有效结果
- **THEN** 到期触发取消，不因读取活动而延长预算

#### Scenario: 迟到的合法响应
- **WHEN** 响应内容合法但校验完成时已到截止
- **THEN** 不交付生成成功，不继续下一子批，也不记录探测成功

### Requirement: 业务与探测必须使用独立且有界的实际执行容量

每个 Worker 实例 MUST 提供一个普通解析与重建共用的业务槽位、一个独立探测槽位，且没有执行等待队列。业务槽位 MUST 在领取数据库任务前取得；没有槽位时不得领取、增加尝试次数或改变任务状态。一次业务执行只承载一份解析任务或一个重建批次，HTTP 子批顺序执行；探测按 profile 顺序执行。

#### Scenario: 旧解析仍在退出中
- **WHEN** 普通解析已终结但仍占用业务槽位，重建或解析调度再次到达
- **THEN** 新调度不领取任务、不创建排队执行、不消耗尝试次数

#### Scenario: 长业务与探测并行
- **WHEN** 一份合法文档正在耗时生成，探测调度到期
- **THEN** 探测可使用独立槽位，业务与探测各自最多一个实际执行

#### Scenario: 没有可领取任务
- **WHEN** 调度已取得业务槽位但数据库可靠返回无可领取任务
- **THEN** 本次实际领取调用退出后释放槽位，后续调度可再次竞争

### Requirement: 逻辑终结不得提前释放实际执行容量

超时、取消或结果选定只表示逻辑终结。系统 MUST 保留对应槽位，直至业务工作、网络响应资源处理及已调度的取消与收尾动作实际退出；取消句柄显示完成不得作为退出证明。执行线程、网络辅助工作、截止与取消调度 MUST 有固定容量，不得以无界线程、队列或替代执行逃避占用。槽位 MUST 恰好释放一次。

#### Scenario: 上游工作忽略中断
- **WHEN** 执行已超时而底层工作仍不退出
- **THEN** 槽位保持占用，迟到结果不可用，调度不启动替代业务工作

#### Scenario: 取消动作阻塞
- **WHEN** 关闭响应资源的动作暂时没有返回
- **THEN** 该动作受有限容量约束且不阻塞其他执行的截止判定，原槽位保持占用

#### Scenario: 完成与取消竞争
- **WHEN** 正常结束、超时与失租信号同时到达
- **THEN** 只产生一个逻辑终结，全部相关工作退出后只释放一次槽位

### Requirement: 取消必须绑定本次执行并阻止后续工作

到期、已确认失租、续租结果不可确认及进程关闭 MUST 使本次执行停止启动后续子批，并请求终止在途调用。最终结果交付前 MUST 再次核对预算与执行资格。截止和取消信号不得排在模型或数据库等待之后；旧执行的计时器、心跳与迟到响应 MUST NOT 取消新执行或恢复旧结果资格。

#### Scenario: 首个子批返回前失租
- **WHEN** 心跳确认本次执行失租或无法确认续租结果
- **THEN** 请求取消当前调用，后续子批不发送，旧结果与失败状态不得覆盖新持有者

#### Scenario: 旧计时器迟到执行
- **WHEN** 已结束执行的计时器在下一执行开始后才运行
- **THEN** 新执行的预算、资格和槽位不受影响

#### Scenario: 进程关闭
- **WHEN** Worker 开始关闭
- **THEN** 停止新准入并取消在途执行，持续未退出的工作保持实际占用事实，不通过新建执行器替代

### Requirement: 单次传输不得自动重试或重定向外发

每个已准备的 HTTP 子批 SHALL 只执行一次传输尝试，不在传输层自动重试、跟随重定向、等待 Retry-After 再发送，或在收到响应超限后拆小重发。任务级恢复可按既有持久机制重做未提交工作；既有成功重建批次 MUST 保留。系统 MUST NOT 将取消或本地失败解释为供应商未执行或未计费。

#### Scenario: 上游要求稍后重试
- **WHEN** 上游返回 429 和 Retry-After
- **THEN** 本次传输立即按暂时故障结束，由任务层决定退避，不立即再次发送

#### Scenario: 返回重定向
- **WHEN** 上游返回带 Location 的 3xx
- **THEN** 不向该地址发送原文或凭据，本次按不可自动重试的上游状态错误结束

#### Scenario: 响应太大
- **WHEN** 请求已发送而响应越限
- **THEN** 明确失败，不将原请求拆小后自动重新调用

### Requirement: 故障必须具有一致且有限的分类

网络故障、超时、HTTP 408／429／5xx SHALL 作为暂时故障进入已有有界任务退避。请求或响应超限、损坏协议、非法向量、认证拒绝及其他不可接受 HTTP 状态 MUST 作为永久故障，普通解析进入死信、重建进入 BLOCKED。已失效资格不得写入业务失败，维护中止沿用既有补偿规则；探测失败只影响就绪事实。

#### Scenario: 临时模型故障
- **WHEN** 普通解析或重建遇到连接故障、超时、408、429 或 5xx
- **THEN** 使用各自现有尝试次数和退避机制，耗尽后进入对应终态

#### Scenario: 输入或响应超限
- **WHEN** 单条请求无法容纳或响应越限
- **THEN** 普通解析立即进入死信，重建立即 BLOCKED，保留原文和此前已提交进度供人工修正后恢复

#### Scenario: 协议错误与认证拒绝
- **WHEN** 响应 JSON 或向量校验失败，或者模型返回 401／403
- **THEN** 不消耗多轮自动重试，持久诊断为固定类别和受控摘要

### Requirement: 探测必须独立限时且不得被迟到成功复活

Worker SHALL 对每个 profile 使用固定非敏感探测输入、独立截止和探测执行身份。只有在截止前完成全部校验的结果才可产生本次成功就绪事实；失败 SHALL 记录不就绪，持久化失败时保留原记录自然过期。探测已终结但实际工作未退出时 MUST 保留槽位，后续轮询不得排队或覆盖同次失败为成功。

#### Scenario: 探测超时后返回合法向量
- **WHEN** 本次探测超时已选定失败，之后上游才返回合法结果
- **THEN** 不更新为 ready，不延长旧成功记录的有效期

#### Scenario: 一个 profile 失败后继续
- **WHEN** 一个 profile 的失败调用及收尾已实际退出，且 Worker 仍运行
- **THEN** 后续 profile 可以取得自己的独立预算进行探测，不继承前一个 profile 的成功或截止

#### Scenario: 探测槽位仍占用
- **WHEN** 下一轮探测触发时旧探测还未实际退出
- **THEN** 不新增请求或排队工作，不生成虚假成功；其他记录按原有效期自然到期

### Requirement: 调用诊断必须反映实际占用且不包含敏感内容

系统 SHALL 提供固定用途和结果类别的调用耗时、故障、实际在途及逻辑结束后仍占用容量的低基数观测。日志、异常摘要和指标 MUST NOT 包含输入正文、供应商错误体、凭据或完整远程地址；指标不得按任务、文档、用户或任意 profile 身份扩张。供应商调用 MUST 继续隔离内部追踪头、baggage 和用户令牌。

#### Scenario: 逻辑失败后仍占用
- **WHEN** 调用超时但底层工作还没有退出
- **THEN** 可观察逻辑失败和仍占用容量两项事实，直到实际退出后占用归零

#### Scenario: 出站上下文隔离
- **WHEN** 当前内部任务存在追踪上下文或注入的客户端默认头
- **THEN** 供应商请求仅使用受控协议及模型认证信息，不传播内部上下文

#### Scenario: 可诊断的固定错误
- **WHEN** 请求超限、响应超限或认证失败被持久记录或观测
- **THEN** 操作者可通过固定类别、受控摘要或指标区分原因，不依赖供应商任意错误消息
