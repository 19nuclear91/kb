# chat-model-adapter Specification

## Purpose

为知识库提供不绑定具体供应商的 OpenAI-compatible 普通文本生成接入，明确服务端配置、授权材料与角色消息、流式完成和用量确认的可验证边界，使真实模型调用可以复用现有单轮和多轮编排，而不绕过权限、预算或结算约束。

## Requirements

### Requirement: 模型适配必须显式启用并兼容既有扩展

系统 SHALL 默认关闭通用模型适配，只有服务端显式启用且必要配置有效时才提供内置真实模型能力。启用但配置无效 MUST 在本地配置校验时拒绝启动，不静默关闭或回退占位。未启用时 SHALL 保留既有部署方模型扩展和旧单轮占位兼容；内置实现不得造成同类模型能力重复装配。

#### Scenario: 缺省未启用
- **WHEN** 部署方没有启用通用适配且没有提供自定义模型
- **THEN** 不发送任何模型请求，旧单轮保留既有占位行为，多轮新生成保持不可用

#### Scenario: 启用配置不完整
- **WHEN** 通用适配已启用但模型名称、地址或密钥缺失，或限制参数非法
- **THEN** 启动以不包含配置秘密的固定错误拒绝，不发送探测请求且不以缺省供应商继续启动

#### Scenario: 部署方已有自定义模型
- **WHEN** 部署方为单轮或多轮提供了自定义模型实现
- **THEN** 对应内置桥接不与该实现重复注册，未覆盖的另一类能力仍独立遵守自身装配与预算条件

### Requirement: 出站模型调用必须仅使用服务端受控地址与凭据

系统 MUST 仅从服务端配置取得模型 base URL、模型名称和 API Key，在保留 base URL 路径前缀的基础上调用 `POST /chat/completions`，使用 Bearer 认证。生产 MUST 使用 HTTPS，并拒绝地址中的用户信息、查询参数和片段。出站请求不得携带用户会话令牌、Cookie、内部服务签名、追踪传播头或 baggage，也不得自动跟随重定向。

#### Scenario: base URL 含版本路径
- **WHEN** 已配置的 base URL 路径为 `/v1/`
- **THEN** 请求路径为 `/v1/chat/completions`，不丢失版本前缀、不重复追加接口路径

#### Scenario: 上游要求重定向
- **WHEN** 配置地址返回重定向响应
- **THEN** 本次生成安全失败，不向重定向目标发送凭据或重发生成请求

#### Scenario: 身份凭据隔离
- **WHEN** 已认证用户经知识库触发模型生成
- **THEN** 模型请求只使用服务端模型密钥，不出现入站 satoken、Cookie 或内部签名

#### Scenario: 不安全生产地址
- **WHEN** 生产启用了 HTTP 地址或地址夹带凭据、查询参数、片段
- **THEN** 本地配置校验拒绝启动，不通过日志或异常回显原始地址与凭据

#### Scenario: 追踪上下文隔离
- **WHEN** 追踪已启用且一次生成触发模型调用
- **THEN** 模型请求不含 `traceparent`、`tracestate` 或 baggage
- **AND** 本地仍可记录该调用的耗时与结果类别

### Requirement: 模型消息必须保留可信角色与实际授权材料

系统 SHALL 仅使用编排层传入的历史、当前原问题和实际选入的授权材料构造消息。固定服务端指令单独作为 system 消息；历史 MUST 保持 user/assistant 角色及顺序，当前原问题只出现一次且不得静默截断。材料 MUST 作为明确标识的不可信数据输入，保留可用来源身份及未知值，不提升为 system 指令、不补成最新版本、不再从其他来源读取正文。

#### Scenario: 多轮消息与本轮材料
- **WHEN** 输入包含两对合格历史、本轮材料和原问题
- **THEN** 上游按原顺序收到两对历史、本轮材料和最后的原问题，系统指令来自服务端而非历史或材料
- **AND** 实际材料内容与编排层选入列表一致，不在协议层再次裁剪或补查

#### Scenario: 材料含伪造指令
- **WHEN** 授权材料或用户消息包含角色标记、分隔符或要求覆盖系统指令的内容
- **THEN** 内容保持在原有数据消息内，不被解释为额外 system 消息，不触发额外资源读取或模型工具

#### Scenario: 旧单轮来源缺少版本
- **WHEN** 旧单轮输入包含没有版本身份的材料
- **THEN** 来源仍明确为未知版本，不推断当前版本，也不改变原引用事件的来源状态

### Requirement: 请求参数必须采用显式文本协议而非自动试探

系统 SHALL 请求单个普通文本候选并开启流式输出，发送显式输出 token 上限。输出限制字段只接受服务端选择的 `max_tokens` 或 `max_completion_tokens`，每次只发一个。最终 usage 请求选项 SHALL 可显式开启或关闭，不支持时不得自动删参重试。请求不得包含工具、多模态、思考开关或任意供应商扩展参数。

#### Scenario: 标准文本请求
- **WHEN** 使用默认参数配置调用模型
- **THEN** 请求包含 model、messages、stream=true、n=1 和 max_tokens，按配置请求最终 usage，不携带工具或多模态内容

#### Scenario: 显式切换输出限制字段
- **WHEN** 服务端选择 max_completion_tokens
- **THEN** 请求仅使用该字段传递同一输出上限，不同时发送 max_tokens

#### Scenario: 上游不支持 usage 选项
- **WHEN** 上游因请求最终 usage 的选项拒绝调用
- **THEN** 本次调用安全失败且只发送一次，部署方可以另行显式关闭该选项，但本次不自动试探或重发

### Requirement: 流解码必须遵守 SSE 边界且逐步交付文本

系统 SHALL 接受成功的 UTF-8 `text/event-stream` 响应，按 SSE 事件而非网络分包解析数据，支持跨包 UTF-8、多行 data、合法换行与注释。文本只能来自唯一候选的普通文本增量；角色和空增量不产生虚假文字。系统 MUST 在收到合法文本事件后增量交付，不等待整条回答聚合。

#### Scenario: 网络分包不等于事件边界
- **WHEN** 一个汉字和一条 SSE JSON 事件被拆成多个网络分包，或一个分包包含多个事件
- **THEN** 输出的文本及顺序正确，不出现替代字符、丢字或重复增量

#### Scenario: 注释与元数据帧
- **WHEN** 上游先发送注释、assistant 角色和空内容，再发送正文
- **THEN** 只有正文形成文本增量，注释和角色不变成回答或用量

#### Scenario: 非流式成功响应
- **WHEN** 上游返回 200 但媒体类型为 JSON，或事件 JSON 存在重复键、尾随文档或非法结构
- **THEN** 以安全协议错误结束，不把原始响应转发成回答

### Requirement: 正常流完成必须经过明确终结确认

系统 MUST 仅在收到普通文本、唯一候选的 `finish_reason=stop` 以及后续 `[DONE]` 后正常完成模型流。EOF、单独 `[DONE]`、未知结束原因或截断不得替代成功确认。`length`、`content_filter` 等非正常结束 SHALL 安全失败，不向客户端发送成功 done，也不使多轮编排把部分回答封存为 COMPLETED。

#### Scenario: 正常结束
- **WHEN** 文本增量之后出现 stop、可选最终 usage 和 [DONE]
- **THEN** 按顺序交付文本，在终结确认后正常结束一次，已有编排再负责持久化、结算和客户端 done

#### Scenario: 达到输出上限
- **WHEN** 上游返回 finish_reason=length
- **THEN** 本次生成按未完整结束处理，不触发成功 done；多轮仅按既有失败收尾保留可确认前缀

#### Scenario: 异常 EOF 或错误结束标志
- **WHEN** 上游在 stop 或 [DONE] 之前断开，或没有 stop 就发送 [DONE]
- **THEN** 以协议未完成错误结束，不将网络连接关闭等同于完整回答

#### Scenario: stop 后继续发送正文
- **WHEN** 上游在 stop 与 [DONE] 之间再次发送非空正文
- **THEN** 以协议错误终止，不接受终态后的追加内容或提前确认累计用量

### Requirement: 首期必须拒绝不支持的生成形态

系统 SHALL 仅处理普通文本候选；非空工具或函数调用、非文本内容、拒绝载荷、思考过程字段以及多个候选 MUST 以安全的不支持或拒绝类别结束。不得执行模型建议的操作，不将思考、工具参数或供应商错误体作为正文、材料、历史或最终 usage 输出。无关的供应商元数据可忽略，但不得借此忽略有业务含义的不支持输出。

#### Scenario: 返回工具调用
- **WHEN** 上游返回非空 tool_calls 或 function_call
- **THEN** 终止本次生成，不执行工具、不构造新的检索，也不把工具参数显示为普通答案

#### Scenario: 返回思考过程或多模态
- **WHEN** 上游返回非空 reasoning_content、已识别的同类思考字段或非文本内容
- **THEN** 安全报告本期能力不支持，不向客户端和历史暴露该载荷

#### Scenario: 空回答或多个候选
- **WHEN** 上游在没有正文时宣布结束，或返回多个候选、非零候选索引
- **THEN** 不拼接候选或伪造成功空回答，以安全协议错误结束

### Requirement: 用量必须在流终结后作为最终累计值确认

系统 SHALL 仅将最后文本之后、经正常流终结确认的完整累计 prompt_tokens 与 completion_tokens 转换为最终 usage。两个值 MUST 为桥接接口可精确表达的非负整数，不能累加累计快照、截断溢出、按字符推算或用缺省零补齐。缺少最终统计 SHALL 不产生 usage 事件，由既有观测与多轮结算保持 UNKNOWN；显式零统计与未知必须区分。

#### Scenario: 多个累计快照
- **WHEN** 上游在最后文本之后先后给出完整累计用量 10/2 和 10/4，并正常终结
- **THEN** 仅发送一次最终 usage=10/4，不计算成 20/6，不在 [DONE] 确认前发布最终统计

#### Scenario: 缺失统计但正常结束
- **WHEN** 上游正常结束但没有给出完整最终 usage
- **THEN** 文本可以正常完成，但不合成零用量事件；观测的真实用量为 UNKNOWN，既有单轮响应与结算兼容行为不被改写

#### Scenario: 用量格式非法
- **WHEN** usage 含负数、小数、缺少一项或超出对应桥接的整数表示范围
- **THEN** 安全终止且不发布该统计，不将其截断或当作已知零值

#### Scenario: 显式零与中途统计
- **WHEN** 正常终结前收到完整最终 0/0，或只收到随后又有正文的中途统计
- **THEN** 前者产生一次已知零值事件，后者不能成为最终统计，必须等待新的完整尾部统计

### Requirement: 一次生成不得因重试订阅或收尾而重复调用上游

系统 MUST 在真正订阅生成流时才发送请求，每次编排执行只订阅上游一次，不因心跳、审计、预算核验、终态保存或元数据重试再次生成。任何上游 HTTP 错误、限流、超时或协议错误均不得自动重试、切换模型或切换供应商。下游取消 MUST 取消上游订阅并释放本地网络与缓冲资源，不承诺供应商已停止计算或停止计费。

#### Scenario: 尚未订阅或取消
- **WHEN** 生成流尚未订阅，或下游在输出过程中取消
- **THEN** 前者不发送请求，后者传播取消并清理资源，不启动后台继续生成或第二次请求

#### Scenario: 限流或连接故障
- **WHEN** 上游返回 429、5xx、连接故障或超时
- **THEN** 以安全失败结束，本次上游请求至多一次，不根据 Retry-After 自动重发

#### Scenario: 持久状态重放
- **WHEN** 多轮编排处理匹配重放，或重试已有终态及结算元数据
- **THEN** 不触发适配层的另一轮生成，沿用既有请求幂等与账本关联身份

### Requirement: 出站请求与流资源必须有界

系统 SHALL 限制序列化请求字节、单个 SSE 事件、累计响应字节、回答 code point、JSON 深度、连接等待、事件空闲和整次调用时长。边界 MUST 在读取和构造过程中执行，不能等无界聚合后检查；上游注释或无效小帧不能无限延长总期限。任何限额触发 SHALL 取消上游并安全失败，不静默截断后宣布成功。

以 CR 结束的事件分隔空行 SHALL 在发布该事件前，为可能随后到达的 LF 保守预留 1 字节；预留不足 MUST 立即失败，即使实际上是没有后续 LF 的单 CR 结尾。普通事件与 `[DONE]` 终结事件 MUST 使用相同规则；预留充足时不等待后续字节或 EOF，实际 LF 到达时只计入一次。

#### Scenario: 超大事件或持续小帧
- **WHEN** 单事件超限，或大量小事件和注释使累计响应超过上限
- **THEN** 在首个越限位置结束读取并释放持有缓冲，不继续收集完整响应

#### Scenario: 慢速持续输出
- **WHEN** 上游不断发送小事件而未触发空闲超时，但整次调用期限已到
- **THEN** 总期限仍然终止请求，不因持续活动而无限占用连接或配额租约

#### Scenario: CR 事件终结处保守预留 LF
- **WHEN** 事件分隔空行的 CR 已使当前事件恰好达到字节上限
- **THEN** 立即以限额错误终止，不发布该事件；若是 `[DONE]`，不得发布候选最终 usage 或成功终结
- **AND** 至少剩余 1 字节时可立即完成该事件，不等待 LF 或 EOF；即使实际不跟 LF，也按同一保守规则判定

#### Scenario: 输入或输出超过限制
- **WHEN** 序列化消息超过请求上限，或累计正文超过回答上限
- **THEN** 前者不发送模型请求，后者停止上游；两者都不悄悄修改原问题、材料或回答来制造成功

### Requirement: 错误与诊断必须隔离正文和秘密

模型调用错误 SHALL 只暴露固定安全类别，并由既有编排转换为当前客户端错误协议。日志、异常、配置打印和诊断 MUST 不包含模型密钥、认证头、问题、答案、授权材料、完整出站请求或供应商原始错误体。非成功响应不得先无界读取错误正文再清理，不因错误处理泄露远程响应头中的敏感值。

#### Scenario: 供应商错误夹带秘密
- **WHEN** 上游错误体或传输异常中含密钥、问题或文档正文
- **THEN** 应用只记录固定类别，不记录原始载荷或未脱敏异常，不将其传给客户端

#### Scenario: 巨大错误响应
- **WHEN** 非成功响应包含很大或持续不结束的正文
- **THEN** 系统取消或有界释放响应，不为构造错误消息聚合正文，不再次订阅原响应流

### Requirement: 通用协议就绪必须配合显式多轮预算策略

系统 MUST 将协议接入与多轮预算策略分开判断。默认 verified 模式 SHALL 仅接受绑定实际部署及消息格式、提供核验窗口与完整输入上界的严格扩展；显式 estimated 模式 SHALL 使用服务端配置窗口及本地估算规则，并明确其不证明真实上界。协议配置完整本身不得开启多轮。缺少当前模式所需能力时，新生成 MUST 在创建轮次、领取配额、检索或调用模型前返回 503；已有匹配重放保留原状态核对。严格模式的缺失、异常及身份不匹配 MUST NOT 自动降级为估算。

#### Scenario: 只有通用配置
- **WHEN** 模型地址、密钥和名称有效，未设置预算模式且没有匹配的严格预算扩展
- **THEN** 默认 verified；旧单轮可使用真实协议适配，多轮新生成返回 503，不创建轮次、不检索、不调用模型、不领取配额

#### Scenario: 模型身份与预算不匹配
- **WHEN** verified 模式中的模型或消息格式改变，而预算扩展仍绑定旧身份
- **THEN** 不能复用旧预算声明启用多轮，也不能仅填写窗口使其被视为已核验；不自动改用估算

#### Scenario: 扩展契约的离线验证
- **WHEN** 测试注入匹配身份的确定性严格预算替身
- **THEN** 可以验证消息、预算裁剪和事件桥接，但替身不进入生产装配，也不构成真实模型预算已核验的证明

#### Scenario: 显式选择通用估算
- **WHEN** 部署方显式选择 estimated，模型协议及预算参数均有效，且内置多轮适配为当前实现
- **THEN** 不要求供应商 tokenizer 或严格预算扩展即可启用估算能力，并按 ESTIMATED 处理；其本地估算允许与真实 token 不一致

#### Scenario: 严格策略计算失败
- **WHEN** verified 策略计算抛出异常、返回非法值或多个策略同时匹配同一身份
- **THEN** 按既有运行时拒绝或配置错误处理，不调用估算器、不切换模型、不向上游发送本次生成请求

#### Scenario: 显式估算与已有自定义模型
- **WHEN** 部署已有自定义单轮或多轮模型，并配置了 estimated
- **THEN** 各自定义模型的既有优先级保持不变；估算配置仅选择内置多轮预算策略，不覆盖自定义模型或将其缺失的预算能力视为具备
- **AND** 已显式启用的通用模型配置仍须通过校验

### Requirement: 接入真实模型不得改变现有编排与授权边界

系统 SHALL 保留授权检索唯一入口、来源确认、会话幂等、SSE 事件类型和各入口原有用量结算语义。无结果及检索故障不得调用模型；已启用适配器的模型故障 MUST 走既有失败收尾，不回退旧占位回答、旧历史答案或全库资料。不新增公开模型代理、模型配置管理 API 或客户端模型选择参数。

#### Scenario: 授权检索为空或失败
- **WHEN** 授权检索合法为空，或以既有 SEARCH_UNAVAILABLE 失败
- **THEN** 分别保留原无结果或失败流程，模型调用次数均为零

#### Scenario: 已启用模型生成失败
- **WHEN** 通用适配器已经接管调用但上游生成失败
- **THEN** 单轮输出原协议安全 error，多轮在具备预算扩展时走原失败保存与结算，不输出占位成功 done

#### Scenario: 未知用量与旧单轮兼容
- **WHEN** 真实单轮正常结束但没有最终 usage，或发生失败、取消
- **THEN** 不为统一多轮策略而改写旧单轮响应字段及扣费规则；启用采集时真实用量仍与额度事实分别表达

### Requirement: 估算模式必须使用显式有界的服务端配置

预算配置 SHALL 只由服务端提供；mode 只接受 verified、estimated，默认 verified。启用 estimated 时，窗口 MUST 显式配置且为正整数；换算比例、每消息开销、请求开销和安全余量 SHALL 使用有界整数及明确单位。窗口与预留的较小值 MUST 严格大于多轮输出上限加余量。配置缺失、类型错误、未知模式、数值越界或容量无效 MUST 在建立业务连接前以固定安全错误拒绝，不回显原始值。

#### Scenario: 默认估算参数
- **WHEN** 部署启用 estimated 并提供合法窗口，但没有覆盖估算参数
- **THEN** 每 1024 UTF-8 字节估算 1024 token，每消息额外 16 token，请求额外 64 token，安全余量 512 token
- **AND** 这些默认值只定义启发式行为，不声明任何供应商已核验或默认窗口

#### Scenario: 窗口缺失或容量被余量占满
- **WHEN** estimated 未提供窗口，窗口不在 1–2147483647，或 min(窗口, 单轮预留) 小于等于输出上限加余量
- **THEN** 启动配置校验失败，不把缺失窗口替换为供应商猜测值，也不在运行时强行放行

#### Scenario: 比例和开销越界
- **WHEN** 每 1024 字节的 token 系数不在 1–65536、每消息或请求开销不在 0–65536、余量不在 0–2147483647，或字段不是整数
- **THEN** 拒绝配置；浮点、溢出或不可解析值不得被截断为可用配置

#### Scenario: 单轮输出配置与多轮配置独立
- **WHEN** 部署修改旧单轮输出上限，而多轮输出与预留未变
- **THEN** 多轮预算继续使用其原多轮输出值与预留；估算参数不另行创建或修改账本预留额度

#### Scenario: 未启用模型适配
- **WHEN** 通用模型适配保持关闭
- **THEN** 预算配置本身不启用内置模型调用，不创建远程计数或模型探测请求

### Requirement: 通用估算必须完整覆盖实际消息并保持确定性

estimated SHALL 对最终消息列表中全部 role 与 content 的 UTF-8 字节数之和 B 计算 `ceil(B * P / 1024) + N * M + F`，其中 N 为消息数、P 为每 1024 字节 token 系数、M 为每消息开销、F 为请求开销。系统 MUST 只对总字节数做一次向上取整，包含指令、历史、材料包装及原问题；不将 HTTP 外层传输转义或凭据作为模型消息计数。计算 SHALL 本地、有界、确定性且不修改消息；非法输入或溢出 MUST 拒绝。

#### Scenario: 混合语言及角色参与计数
- **WHEN** 消息为 role=user、content=A 和 role=assistant、content=中😀，P=512、M=2、F=3
- **THEN** B=21、N=2，估算结果为 18，完整包含角色与多字节正文

#### Scenario: 只对全部消息取整一次
- **WHEN** 两条消息均为 role=user、content=A，P=512、M=2、F=3
- **THEN** B=10、N=2，估算结果为 12，不得逐消息向上取整而得到 13

#### Scenario: 材料包装参与计数
- **WHEN** 发送的材料消息包含固定说明、文档/版本/分块/页码字段及 JSON 转义内容
- **THEN** 这些实际消息字符全部参与 UTF-8 字节计数，不能只统计原分块正文
- **AND** 不额外计算 HTTP 外层序列化为同一字符串引入的传输转义，也不读取认证头

#### Scenario: 重复计算不触发副作用
- **WHEN** 对相同消息和冻结参数连续计算或因裁剪重新计算
- **THEN** 相同输入得到相同结果，原消息不变，不发出网络、模型或在线计数请求，也不保存正文

#### Scenario: 数值或编码非法
- **WHEN** 计数运算溢出、出现非法 Unicode/NUL、负数计数或不一致的预算类型
- **THEN** 以固定安全错误拒绝，不按零值或已知上界继续，不泄露问题、材料或原始异常

### Requirement: 估算能力必须与严格能力隔离且兼容既有扩展

系统 SHALL 明确区分 ESTIMATED、VERIFIED 与不可用能力；能力窗口、余量及计数结果 MUST 使用同一类型和冻结配置。既有只提供严格上界的部署方扩展 SHALL 继续按 VERIFIED 使用，不能因新增模式被要求实现估算。估算策略 MUST NOT 通过旧严格上界能力或计数接口声称已核验。配置变更经重启生效，不在一次生成中热切换；严格与估算之间不存在自动失败回退。

#### Scenario: 旧严格扩展保持兼容
- **WHEN** 既有严格多轮扩展只提供原有的预算能力、窗口和上界计数
- **THEN** 新编排仍将其作为 VERIFIED 使用，额外余量为零，不要求新增估算实现

#### Scenario: 旧上界调用方访问估算实现
- **WHEN** estimated 实现被旧严格上界调用方查询能力或直接要求上界值
- **THEN** 其严格上界能力为不支持，上界计数请求被拒绝；只有明确识别 ESTIMATED 的新编排可使用估算值

#### Scenario: 发送前预算复核
- **WHEN** 已选择的消息准备发送给模型
- **THEN** 系统按相同冻结策略复核实际待发送消息；不匹配或超限时不发送，不在复核之后增加未计入的内容

#### Scenario: 选择 estimated 时存在严格策略
- **WHEN** 部署显式选定 estimated，同时存在可匹配的严格预算扩展
- **THEN** 内置多轮按所选估算策略计算，不调用严格策略来隐式覆盖选择或混合两个结果

### Requirement: 估算值不得成为实际用量或费用上限证明

估算计数 SHALL 仅用于输入准入和裁剪，不写入实际 prompt/completion usage，也不替代额度预留。正常确认的实际 usage MUST 完整保存与结算，包括超过估算或预留的值；已有模型调用意图但没有最终统计继续为 UNKNOWN 并按既有预留规则结算，无调用意图时为 NOT_INVOKED 和零 token 结算。上游拒绝、截断或估算不足 MUST 沿用既有失败收尾，不自动重新生成。

#### Scenario: 真实用量超过预留
- **WHEN** 本地估算允许调用，而模型最终确认的输入加输出 usage 超过本轮预留
- **THEN** 完整保留真实统计并按既有 KNOWN 规则结算，不裁成估算值或预留上限，不把预算通过解释为费用硬上限

#### Scenario: 缺少最终统计
- **WHEN** estimated 模式下已有模型调用意图但没有可确认的最终 usage
- **THEN** 真实用量仍为 UNKNOWN、token 字段为空，扣除额度按原预留处理，不以估算值补齐

#### Scenario: 意图保存后发送复核失败
- **WHEN** 模型调用意图已持久化，发送前最后复核失败且本地没有发送 HTTP 请求
- **THEN** 不发送模型请求，但仍按既有意图及缺少确认 usage 的 UNKNOWN 规则收尾，不凭本地计数重写意图或伪造 NOT_INVOKED

#### Scenario: 上游因上下文拒绝
- **WHEN** 本地估算通过但上游因实际窗口不足拒绝，或返回非正常截断结束
- **THEN** 本次生成失败并按原规则收尾，不自动改窗口、删参数、切模式、重新裁剪后再次调用或伪造成功 done

### Requirement: 模型调用必须提供低基数观测

系统 SHALL 为每次模型调用记录结果类别（完成、上游错误、协议错误、限额、超时、取消）、首个文本事件延迟、按模型总期限显式分桶的整次调用耗时、终结类别以及最终用量已知与未知的计数。标签 MUST 为固定枚举，MUST NOT 含模型密钥、问题、答案、材料或供应商原始错误。

#### Scenario: 正常完成
- **WHEN** 模型流正常终结并给出完整最终用量
- **THEN** 完成计数与用量已知计数各增加一次，并记录首个文本事件延迟与整次耗时

#### Scenario: 缺少最终用量
- **WHEN** 模型流正常终结但没有完整最终用量
- **THEN** 完成计数增加而用量未知计数增加，不记录伪造的零用量

#### Scenario: 限额或协议错误
- **WHEN** 调用因限额、协议损坏或超时安全失败
- **THEN** 对应固定类别计数增加，不含供应商错误体、问题或答案
