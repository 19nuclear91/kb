# document-change-notes Specification

## Purpose

为文档版本保存一条由编辑者撰写的变更说明，说明该版本相对固定基准版本改了什么，并通过审核冻结、附原因更正和不可删除的修改历史，让读者能核对说明的来历，同时不改变发布、检索或引用。

## Requirements

### Requirement: 变更说明必须作为版本的独立人工声明

系统 SHALL 为每个文档版本保存至多一条纯文本变更说明及其基准版本。说明 MUST 与文档资料、原件、审核轮次、发布证据和适用期分开；写入不创建文件版本或审核轮次，不改变当前版本、发布状态、检索、引用或问答。说明不进入检索索引、模型上下文或站内通知正文，新版本不继承旧版本的说明。本人更新及周报详情允许按该固定版本的当前访问规则读取其最新说明，不把说明复制为永久摘要；补写或更正不触发新的订阅发布提醒。

#### Scenario: 升级前已有的版本
- **WHEN** 升级后读取任一既有版本的变更说明
- **THEN** 结果为没有说明，说明版本为 0，系统不从正文、标题或评论推断

#### Scenario: 新版本不继承说明
- **WHEN** 文档上传新版本，而上一版本已有变更说明
- **THEN** 新版本没有说明，不复制上一版本的文本或基准

#### Scenario: 说明内容不可被搜索
- **WHEN** 用户搜索只出现在某条变更说明中的词语
- **THEN** 搜索结果不因该说明而命中，问答也不把说明作为来源

#### Scenario: 从个人更新读取说明
- **WHEN** 本人打开订阅更新或周报中的固定发布版本
- **THEN** 当前有该版本读取资格时可查看最新人工说明及补写/更正标记，没有说明时明确为空，不读取另一个版本代替

#### Scenario: 周报生成后更正
- **WHEN** 编辑者更正一个已进入本人周报的历史版本说明
- **THEN** 原周报下次授权读取可显示更正后的文本与标记，原发布身份和说明基准保持，不产生第二次订阅提醒

#### Scenario: 通知与说明独立授权
- **WHEN** 用户持有旧通知但已失去固定版本阅读资格
- **THEN** 不能从通知、周报缓存或已读事实恢复说明正文，原通知存储不包含说明文本

### Requirement: 基准版本必须按写入时的已发布版本确定

基准版本 SHALL 为写入时，同一文档中版本号小于目标版本、且具有发布证据（PUBLISHED 或 OBSERVED_CURRENT）的版本里版本号最大的一个。待审版本每次写入重新确定；版本已对读者可见且已有说明时，写入 MUST 保持原基准。不存在符合条件的版本时返回 409 NO_BASE_VERSION，不保存说明。

#### Scenario: 文档的第一个版本
- **WHEN** 编辑者为文档唯一的版本 V1 写入说明
- **THEN** 返回 409 NO_BASE_VERSION

#### Scenario: 写入后另一版本先发布
- **WHEN** V1 为当前发布版本时，编辑者为待审 V3 写入说明，随后 V2 先于 V3 发布，之后 V3 获批发布
- **THEN** V3 的说明基准仍为 V1，读取结果明确返回基准 V1，不改标为 V2

#### Scenario: 发布后首次写入
- **WHEN** 自动发布空间中 V2 已替换 V1 成为当前版本，编辑者首次为 V2 写入说明
- **THEN** 基准为 V1

#### Scenario: 更正已发布版本的说明
- **WHEN** 已发布 V3 的说明基准为 V1，编辑者附原因更正其文本
- **THEN** 基准保持 V1，不按更正时的版本情况重新确定

### Requirement: 变更说明读取必须沿用版本交互访问规则

`GET /api/documents/{documentId}/versions/{versionId}/change-note` SHALL 返回 documentId、versionId、是否有说明、文本、基准版本 ID 与版本号、是否已更正、是否在对读者可见后才首次写入、说明版本、按当前事实写入时将使用的基准版本（没有时为 null）、当前用户能否修改及审核冻结标记。读取 MUST 校验版本属于该文档并使用既有版本交互访问规则；不存在、归属不符或不可访问统一返回 404。

#### Scenario: 无候选访问资格
- **WHEN** 只有父文档 view、既非上传者和送审者也非合格审核人的用户读取待审版本的说明
- **THEN** 返回 404，不透露该版本是否存在

#### Scenario: 读者查看已发布版本的说明
- **WHEN** 可以查看已发布 V2 的读者读取其说明
- **THEN** 返回说明文本和基准版本，不返回撰写者身份

#### Scenario: 读取第一个版本
- **WHEN** 编辑者读取文档唯一版本 V1 的说明
- **THEN** 结果为没有说明，写入时将使用的基准版本为 null

### Requirement: 待审版本的说明必须由可访问的编辑者写入并在审核中冻结

对从未发布且没有旧兼容访问的待审版本，`PUT` 同一路径 SHALL 要求调用者能按交互访问规则访问该版本，并对文档具有当前 edit（含文档例外 edit），不要求原因，允许把文本设为 null 以清除说明。该版本存在 IN_REVIEW 审核轮次时 MUST 返回 409 REVIEW_IN_PROGRESS；撤回、驳回或取消后可以再次修改。

#### Scenario: 审核中冻结
- **WHEN** 待审版本处于 IN_REVIEW 时提交说明修改
- **THEN** 返回 409 REVIEW_IN_PROGRESS，审核人看到的说明保持不变

#### Scenario: 撤回后修改再送审
- **WHEN** 送审者撤回后，合格编辑者修改说明并重新送审
- **THEN** 修改成功并追加历史，新一轮审核看到修改后的说明

#### Scenario: 有 edit 但无候选访问
- **WHEN** 用户对文档有 edit，但既非上传者、送审者，也非合格审核人
- **THEN** 返回 404，不保存修改

#### Scenario: 提交前版本已经发布
- **WHEN** 编辑者按待审规则修改已有说明且 reason 为 null，但版本在提交前已发布
- **THEN** 返回 409 REASON_REQUIRED，不保存修改

### Requirement: 已对读者可见版本的说明必须首次免原因、修改附原因

对具有发布证据或旧兼容访问的版本，写入 SHALL 要求当前 view 与 edit。当前没有说明时，写入不要求原因，并永久记录该说明在对读者可见后才首次写入。已有说明时，修改 MUST 提交 1–2000 个 Unicode code point 的原因，成功后已更正标记永久为 true；文本设为 null 返回 409 NOTE_REMOVAL_NOT_ALLOWED。文档已删除或归档、空间已归档时返回 404。

#### Scenario: 自动发布空间发布后补写
- **WHEN** 自动发布的 V2 已对读者可见且没有说明，编辑者不带原因写入说明
- **THEN** 写入成功，读取结果标明说明在发布后首次写入，已更正为 false

#### Scenario: 修改已发布说明但缺少原因
- **WHEN** 已发布版本已有说明，修改请求的 reason 为 null
- **THEN** 返回 409 REASON_REQUIRED，不保存修改

#### Scenario: 附原因修改已发布说明
- **WHEN** 合格编辑者附原因修改已发布版本的说明
- **THEN** 修改立即生效，不创建审核轮次，读取结果中已更正为 true

#### Scenario: 尝试清除已发布说明
- **WHEN** 请求把已发布版本的说明文本设为 null
- **THEN** 返回 409 NOTE_REMOVAL_NOT_ALLOWED，说明保持不变

#### Scenario: 更正历史版本的说明
- **WHEN** 合格编辑者附原因更正一个已被新版本取代的已发布版本的说明
- **THEN** 按同一规则生效，其他版本的说明不变

### Requirement: 说明修改历史必须不可删除且不暴露操作者

系统 SHALL 为每次成功写入保存写入时间、写入前后的文本、基准版本、写入时版本是否已对读者可见以及原因，记录不可编辑或删除。`GET .../change-note/history` SHALL 使用与说明读取相同的访问规则，按写入时间倒序以有界游标返回，limit 默认 20、范围 1–100。响应 MUST NOT 包含操作者身份，操作者只进入审计。

#### Scenario: 读者查看说明的修改历史
- **WHEN** 可访问该版本的用户读取修改历史
- **THEN** 可看到每次写入的时间、前后文本、是否发布后写入和原因，看不到操作者

#### Scenario: 尝试修改或删除历史
- **WHEN** 调用方以任何方式尝试编辑或删除已保存的历史记录
- **THEN** 请求被拒绝，历史保持不变

### Requirement: 说明写入必须严格校验输入

`PUT` 请求 SHALL 只包含 text、reason、expectedNoteVersion 三个必需字段，text 与 reason 可为 null。非 null 的 text 与 reason 去除首尾空白后 MUST 为 1–2000 个 Unicode code point，按去除后的文本保存；不得包含 NUL、换行与制表符以外的控制字符或孤立代理项。违反规则、未知或重复字段及尾随 JSON 返回 400；请求体超过 32 KiB 返回 413。

#### Scenario: 说明只有空白
- **WHEN** text 去除首尾空白后为空
- **THEN** 返回 400，不把它当作清除说明

#### Scenario: 说明超长
- **WHEN** text 去除首尾空白后为 2001 个 Unicode code point
- **THEN** 返回 400，不截断保存

#### Scenario: 说明包含换行
- **WHEN** text 包含多段文字和换行
- **THEN** 按纯文本保存，换行保留

### Requirement: 说明写入必须绑定请求并在冲突时拒绝

写入 SHALL 要求 X-Request-Id，去除首尾空白后为 1–128 个非控制 Unicode code point，绑定操作域、操作者、目标版本、预期说明版本与规范化载荷。匹配重试 MUST 先按当前资格重新鉴权，再返回首次回执并标记 replayed=true，不重复追加历史；绑定不符返回 409 REQUEST_MISMATCH。预期版本过期返回 409 NOTE_VERSION_CONFLICT；文本与当前完全相同返回 409 NO_CHANGE。

#### Scenario: 响应丢失后重试
- **WHEN** 首次写入已提交但响应丢失，客户端以同一标识和载荷重试
- **THEN** 返回首次回执且 replayed=true，历史只有一条记录

#### Scenario: 同一标识用于不同文本
- **WHEN** 客户端用已绑定的请求标识提交不同的文本或原因
- **THEN** 返回 409 REQUEST_MISMATCH，不返回原载荷

#### Scenario: 撤权后重放
- **WHEN** 原操作者失去 edit 后重放此前成功的请求
- **THEN** 按当前资格拒绝，旧回执不延续写入资格

#### Scenario: 并发修改
- **WHEN** 两个请求基于同一预期说明版本同时提交不同文本
- **THEN** 至多一个成功，另一个返回 409 NOTE_VERSION_CONFLICT

### Requirement: 说明写入必须与历史、审计和回执原子提交

每次成功写入 SHALL 在同一事务内更新说明、基准与说明版本，并保存历史记录、一条不含说明文本和原因的成功审计及请求回执。任一部分保存失败 MUST 整体回滚，同一标识的后续重试仍按未成功请求处理。

#### Scenario: 审计写入失败
- **WHEN** 说明已更新但成功审计无法保存
- **THEN** 本次写入整体回滚，读取结果仍为写入前的说明

### Requirement: 说明入口必须安全表达失败

说明的读取、历史与写入入口 SHALL 保留登录、主体状态与强制改密门禁，成功与错误响应均标记 no-store。错误、日志与审计 MUST NOT 回显说明文本、原因或底层异常；依赖无法可靠读取时返回安全 503，不伪装为没有说明。

#### Scenario: 依赖故障
- **WHEN** 说明或访问规则所需数据暂时无法读取
- **THEN** 返回 503，客户端不把该版本显示为没有说明

#### Scenario: 写入失败时的错误内容
- **WHEN** 写入因校验或冲突失败，且请求文本中含有内部信息
- **THEN** 错误响应和日志只包含固定原因码，不包含文本或原因
