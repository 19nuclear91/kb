# retrieval-result-collection Specification

## Purpose

为检索质量评测提供可追踪的真实结果采集能力，将指定身份和查询场景通过现有授权搜索得到的最终结果转换成离线评测输入，明确用例覆盖、失败、排名、来源与观测边界，使不同部署配置的比较不因漏采、错用身份或格式转换而失真。

## Requirements

### Requirement: 采集必须通过独立命令行调用现有授权接口

采集工具 SHALL 提供 `--dataset`、`--cases`、`--config`、`--output` 四个必需参数及独立 `--help`。正常运行只通过配置端点的 `GET /api/auth/me` 和 `POST /api/search` 取得身份及最终搜索结果；不得直接读取数据库、调用算法阶段或改变既有评测器的离线边界。未知、重复或缺值参数 MUST 拒绝。

#### Scenario: 正常采集入口
- **WHEN** 调用者提供合法数据集、用例、配置和新输出目录
- **THEN** 工具核对身份并采集既有搜索最终响应，输出供离线评测使用的文件
- **AND** 不启动业务服务、改变搜索模式或直接读取业务存储

#### Scenario: 帮助无需环境
- **WHEN** 调用者仅请求 `--help`
- **THEN** 返回用法和成功退出码，不读取配置、凭据或数据集，不发网络请求、不写文件

### Requirement: 用例必须完整绑定标注场景

工具 SHALL 接受现有 v1 数据集与标注，以及 UTF-8 JSONL 用例。每条用例只包含 `caseId`、`identity` 和 `request`；caseId 集合 MUST 与合法非空标注集完全相同且各出现一次。request 只接受 query 和现有组合筛选字段，数量由运行配置提供。身份别名必须存在，ID、等级和空结果标注遵守既有评测契约；全部可本地判定的错误 MUST 在任何网络调用前拒绝。

#### Scenario: 同问题不同身份
- **WHEN** 两条用例使用相同 query 但不同身份，并分别有唯一 caseId 和对应标注
- **THEN** 工具保留两个独立场景，不按查询文本合并或复用另一身份结果

#### Scenario: 覆盖不完整或重复
- **WHEN** 用例遗漏标注、增加未知 caseId、重复 caseId 或引用不存在的身份别名
- **THEN** 工具失败退出，身份和搜索接口的调用次数均为零

#### Scenario: 无效标签或请求字段
- **WHEN** 标注有重复版本、非法相关等级或矛盾空结果预期，或 request 带 userId、算法模式等未知字段
- **THEN** 工具拒绝整个批次，不发送部分合法用例

### Requirement: 本地输入必须有界且使用一致字节

输入文件 MUST 只读，仅接受明确的本地文件路径；拒绝 URI、网络共享和扫描通配符。配置与数据集清单各最多 1 MiB，用例与标签各最多 32 MiB，JSONL 每行最多 128 KiB，每批最多 10,000 个场景，JSON 深度最多 32。工具 SHALL 拒绝非法 UTF-8、重复 JSON 属性和尾随数据，并使用同一份已读取字节完成校验、摘要和执行，不在批次中重新加载可变输入。

#### Scenario: 输入超限
- **WHEN** 输入没有可靠预报长度而实际读取超过对应字节、行或场景上限
- **THEN** 在限界处拒绝，不继续无界加载，也不发送网络请求

#### Scenario: 读取后文件改变
- **WHEN** 输入已完成本地校验后被其他进程修改
- **THEN** 本次执行与输出摘要仍对应已校验字节，不混用修改后的用例或标注

#### Scenario: 大整数保真
- **WHEN** 标注或预期用户 ID 为合法 Long.MAX_VALUE
- **THEN** 校验与后续绑定精确保留该整数，不经浮点数转换或截断

### Requirement: 令牌必须绑定预期用户并在搜索前核对

每个身份配置 SHALL 指定令牌环境变量名及精确的 expectedUserId，禁止在配置中直接保存令牌。工具 MUST 在批次开始冻结所有引用令牌，并在首个搜索前对全部引用身份逐一查询 `/api/auth/me`。仅接受成功包装、匹配用户、启用状态及非强制改密状态；缺失凭据或任一核对失败必须终止，不自动登录、改密、注销或切换身份。未引用身份不触发请求。

#### Scenario: 错把管理员令牌提供给员工场景
- **WHEN** 环境变量中令牌对应的用户与场景绑定的 expectedUserId 不同
- **THEN** 工具失败退出，不发送任何搜索，不把该身份的结果记录到员工场景

#### Scenario: 多身份预检失败
- **WHEN** 第一身份核对成功，但第二身份失效、停用或需要改密
- **THEN** 整个批次终止，不先采集第一身份的用例，也不更换第二身份

#### Scenario: 运行时会话失效
- **WHEN** 预检通过后某条搜索返回 401 或 403
- **THEN** 将其作为失败停止，不记为空结果、不使用其他身份重试

### Requirement: 网络端点和凭据传播必须受控

配置端点 SHALL 为无用户信息、查询串、fragment 或路径回退的 HTTPS 服务根地址，合法路径前缀必须保留。仅显式 `allowHttpLoopback=true` 时接受 host 为 localhost、127.0.0.1 或 ::1 的 HTTP。工具 MUST 仅向固定身份与搜索路径发送对应 satoken，不发送客户端身份声明，不自动跟随重定向、认证挑战重放或继承额外 Cookie、认证及追踪头。

#### Scenario: 带合法前缀的部署
- **WHEN** 服务根地址有路径前缀 `/kb`
- **THEN** 使用 `/kb/api/auth/me` 和 `/kb/api/search`，不丢失前缀、不将查询拼入 URL

#### Scenario: 上游要求跳转
- **WHEN** 任一接口返回 3xx 和 Location
- **THEN** 本次运行失败，不向 Location 发送令牌或重新发起请求

#### Scenario: 不安全地址
- **WHEN** 配置使用非 loopback HTTP、夹带凭据或 query，或未显式允许本地 HTTP
- **THEN** 在任何网络调用前拒绝配置

### Requirement: 采集请求必须串行且遵守固定数量和筛选

首版 SHALL 按用例文件顺序串行采集，每条请求只提交原 query、完整筛选及统一数量。candidates 默认 50、topK 默认 20，各为 1–200；topK 大于 candidates 保持合法。query 必须为非空白合法 Unicode、不含 NUL、最多 8,000 个 code point；编码请求最多 128 KiB。筛选类型、互斥关系和时间边界 MUST 遵守现有搜索契约，不截断问题、删除条件或提交身份和向量。

#### Scenario: 顺序与数量
- **WHEN** 配置 candidates=20、topK=50，两个用例按 A、B 排列
- **THEN** 参数合法，先完成 A 再发送 B，记录实际数量参数，结果较少不自动补查

#### Scenario: 无效筛选
- **WHEN** 用例具有重复标签、冲突分类、反向时间或错误类型
- **THEN** 本地预检拒绝，不只提交可识别条件

#### Scenario: 原问题超限
- **WHEN** query 超过 code point 上限或实际请求编码超限
- **THEN** 拒绝而不截断，不发出该批次网络请求

### Requirement: 请求期限和响应读取必须有界

连接超时 SHALL 默认 5,000 毫秒、范围 1–60,000；整次请求超时默认 15,000 毫秒、范围 1–300,000 且不小于连接超时；响应上限默认 4 MiB、范围 1 byte–64 MiB。期限必须覆盖连接、响应头、正文读取及解析，大小限制按实际字节生效，JSON 深度最多 32；无长度头也不得无界读取。超时、中断或越限 MUST 停止读取并取消本地请求，不接受迟到成功。

#### Scenario: 持续慢正文
- **WHEN** 已收到成功响应头，但服务持续输出小块而无法在整次期限内完成
- **THEN** 在期限到达时失败，不因持续字节到达重置期限或继续下一用例

#### Scenario: 无长度头超限
- **WHEN** 响应不带 Content-Length 且实际正文超过上限
- **THEN** 停止读取并失败，不先完整聚合后检查

#### Scenario: 调用被中断
- **WHEN** 调用者中断进行中的采集
- **THEN** 当前本地请求取消且后续用例不发送，不宣称远程工作或计费已停止

### Requirement: 成功响应必须通过完整协议校验

工具 MUST 仅接受 HTTP 200、UTF-8 JSON、code=200 且 data 为数组的成功响应；拒绝不支持的内容编码、重复属性、尾随数据、空正文和损坏结构。有有效筛选的请求必须有唯一且精确为 1 的 `X-Search-Filter-Version`；无筛选请求不强制该头。协议失败不得作为正常空结果，也不得删除筛选后重发。

#### Scenario: 合法空结果
- **WHEN** 收到 HTTP 200、code=200、data=[] 且适用的筛选头有效
- **THEN** 记录 status=OK 和空 hits，不推断隐藏文档或不可见原因

#### Scenario: 成功状态但业务失败
- **WHEN** 响应是 HTTP 200 但 code 非 200、缺少 data、data=null 或正文为空
- **THEN** 工具按协议失败停止，不生成成功结果行

#### Scenario: 筛选协议无法确认
- **WHEN** 有效筛选请求得到成功数组，但版本头缺失、重复或不是精确值 1
- **THEN** 拒绝该响应并停止，不接受未经确认的筛选结果

### Requirement: 结果转换必须精确保留身份和原始排名

每项命中 MUST 有精确的正整数 docId、versionId、chunkId，且不超过 Long.MAX_VALUE。任何身份缺失、null、小数、字符串、溢出或重复三元组必须使本次采集失败，不过滤坏项后继续。工具 SHALL 完整保留数组顺序和同版本不同分块，仅输出三元组；不得按 score 重排、合并版本、推断最新版本或保存标题与正文。

#### Scenario: 同版本多个分块
- **WHEN** 返回 A/A/B 三个分块，两个 A 的 chunkId 不同
- **THEN** 原顺序与三个位置均保留，后续评测可按原分块预算计算重复率

#### Scenario: 单个坏项
- **WHEN** 非空结果的一项 versionId 缺失或同一三元组出现两次
- **THEN** 整次采集失败，不修补、静默去重或跳过该项

#### Scenario: 分数与数组顺序不同
- **WHEN** 后一项 score 大于前一项，且 ID 为合法 64 位整数
- **THEN** 仍按服务端数组顺序输出，并精确保留所有 ID

### Requirement: 首个失败必须终止且不得自动重试

身份核对、HTTP、超时或协议失败后，工具 MUST 停止后续请求，不重试本次请求、不重新登录、不更换身份或端点。429/503 及 Retry-After 不触发自动等待重发。任一用例失败不得发布部分成功运行、以空数组替代失败或通过排除样本改善评测；本次诊断必须指向固定类别和安全输入位置。

#### Scenario: 中间用例失败
- **WHEN** A 已成功、B 返回 503、C 尚未发送
- **THEN** B 仅调用一次，C 不发送，整批不发布可交给评测器的成功运行清单

#### Scenario: 返回限流等待时间
- **WHEN** 搜索返回 429 和 Retry-After
- **THEN** 返回失败，不自动等待、循环请求或改用另一个令牌

### Requirement: 完整输出必须兼容现有离线评测格式

所有用例成功后，工具 SHALL 输出 `run.json`、`results.jsonl` 和独立 `collection.json`。运行清单必须仅含现有 v1 字段，使用原数据集身份、实际 labelsSha256、sourceType=RECORDED、resultsFile=results.jsonl。每个结果含 caseId、status=OK、完整有序 hits 和 latencyMs，恰好覆盖所有标注。新增采集元数据不得塞入严格运行清单，既有评测器无需改动即可读取结果。

#### Scenario: 现有评测器直接读取
- **WHEN** 将完整产物的 run.json 与原数据集交给既有 kb-eval
- **THEN** 输入校验通过且保留场景、版本身份、顺序与空结果语义，不需要格式转换或网络访问

#### Scenario: 标注摘要
- **WHEN** 标签文件在预检时包含 CRLF 或额外合法空白
- **THEN** labelsSha256 对应当次读取的实际字节，不对重新序列化的标签计算摘要

### Requirement: 采集元数据必须区分声明和可观测事实

collection.json SHALL 记录运行及端点逻辑标识、工具版本、UTC 起止时间、请求数量与限界、场景数量、身份别名核对结果、数据集/标签/用例/结果摘要和场景绑定摘要。配置及语料身份只作为声明；结果语义必须标为 FINAL_RESPONSE，降级状态为 UNOBSERVED，快照验证为 DECLARED_ONLY。不得声称已核验算法阶段、真实模型配置、冻结的 ACL 或完整在线质量。

#### Scenario: 服务静默降级
- **WHEN** 搜索成功返回，但实际跳过了向量或 rerank
- **THEN** 仍按最终响应采集，元数据不把该结果标成已经验证的混合或 rerank 阶段结果

#### Scenario: 同名快照
- **WHEN** 两次运行声明相同 corpusSnapshotId，但工具无法核对期间是否有版本或 ACL 变更
- **THEN** 保留声明与时间范围，snapshotVerification 仍为 DECLARED_ONLY

#### Scenario: 身份或查询改变
- **WHEN** 相同 caseId 的 query、筛选或 expectedUserId 改变
- **THEN** 场景绑定摘要变化；仅换成同一用户的新 token 不改变该摘要
- **AND** 不为生成摘要把 query、筛选或凭据明文复制到输出

### Requirement: 耗时必须明确为客户端搜索观测

每条 latencyMs SHALL 使用单调计时，覆盖搜索发送前至完整成功响应读取及校验结束，保存非负有限毫秒值。该值 MUST 排除身份预检、本地输入读取、输出写盘和离线评测计算，不代表数据库阶段、算法阶段耗时或吞吐能力。请求失败不能用零耗时冒充成功样本。

#### Scenario: 身份预检耗时较长
- **WHEN** 身份核对耗时长而随后搜索很快完成
- **THEN** 结果 latencyMs 只包含本次搜索请求及验证，不包含先前预检时间

#### Scenario: 响应正文迟到
- **WHEN** 成功响应头很快到达而最后一块正文稍后到达
- **THEN** latencyMs 包括完整正文和验证，不只统计响应头延迟

### Requirement: 输出必须完整发布且不覆盖已有文件

工具 MUST 在网络前拒绝既有输出目标，并只在完整成功后发布新目录。所有产物须先完整准备，目标被竞争创建时必须失败且保留原目标；输入和其他批次不得被覆盖或删除。失败清理仅作用于经路径验证的本次暂存内容；崩溃残留不得被识别为完成批次，也不得自动恢复或续采。

#### Scenario: 已有输出目录
- **WHEN** 调用者指定已存在的输出路径
- **THEN** 工具失败且不发送网络请求，已有目录内容不变

#### Scenario: 发布前竞争或写入失败
- **WHEN** 采集结束后另一个进程创建目标，或产物写入无法完成
- **THEN** 不覆盖目标、不发布部分文件，只清理本次可确认的暂存内容并返回失败

### Requirement: 退出码和诊断必须明确且不泄露内容

工具 SHALL 以 0 表达完整成功，2 表达参数、输入、配置、输出或本地处理失败，3 表达身份、HTTP、超时或响应协议失败；质量门禁仍由既有评测器单独判定。成功 stdout 只输出 COLLECT_COMPLETE，失败使用 COLLECT_ERROR 与固定类别、安全文件角色、行号和字段。所有输出及异常诊断 MUST 不包含令牌、查询/筛选明文、标题、正文、完整 URL、用户名或原始远程错误与异常。

#### Scenario: 上游错误夹带敏感内容
- **WHEN** 非成功响应或异常消息包含令牌、查询或文档正文
- **THEN** 工具仅输出固定错误类别及安全输入位置，返回非零，不复制原文或 cause

#### Scenario: 完整采集后质量不达标
- **WHEN** 采集本身完整成功，但后续 kb-eval 判定质量门禁失败
- **THEN** 采集退出 0，质量失败沿用评测器原退出语义，两种结果不混淆
