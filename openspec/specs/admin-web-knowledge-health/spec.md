# admin-web-knowledge-health Specification

## Purpose

为获准的空间管理员提供可切换单个空间的健康雷达页面，展示六类维护信号、真实统计时间与去重文档清单，并连接既有处理流程，使不同信号的可见范围、日期含义和权限变化得到准确呈现。

## Requirements

### Requirement: 雷达页面必须按当前空间与功能资格加载

`/admin/spaces/:spaceId/health-radar` SHALL 在当前身份、`knowledge:health:read` 及目标空间可管理均确认后读取诊断。空间切换器只列出当前可管理且未归档的空间，切换到相应合法路径；无候选显示无可诊断空间。目录故障与无候选分别表达，不用旧目录继续切换或回退全库，直接访问指定目标仍须独立核验其资格。

#### Scenario: 只有查看资格的空间
- **WHEN** 空间目录同时包含仅可查看空间、已归档可管理空间和未归档可管理空间
- **THEN** 切换器只提供最后一类，不预取其他空间的统计

#### Scenario: 直接访问目标
- **WHEN** 用户直接打开一个合法雷达路径
- **THEN** 页面先核验当前功能及目标管理资格，成功后才读取该空间诊断，不因路径或旧候选获得授权

#### Scenario: 切换器目录暂时失败
- **WHEN** 当前目标已独立确认可管理，但切换器目录读取失败
- **THEN** 切换器显示故障且不可选择旧候选，当前目标诊断可按其已核验的独立结果展示

### Requirement: 页面必须明确展示六类口径与统计范围

页面 SHALL 展示六类数量、受影响文档数、服务端 asOf 和业务日期/时区。责任人与复审四类标明覆盖该空间活动文档；适用期两类标明“仅当前可读的当前发布版本”。数量必须精确显示，不转为不安全浮点数；明确总数按文档去重、各类不可直接相加，不把零信号表达为内容全部正确或全空间不存在过期资料。

#### Scenario: 同一文档两项原因
- **WHEN** 复审逾期和适用期已届满各有 1 项但受影响文档数为 1
- **THEN** 原样展示三项数量并解释去重，不在前端把总数改为 2

#### Scenario: 适用期数量为零
- **WHEN** 服务端成功返回两类适用期数量均为零
- **THEN** 表达为当前可读发布版本中无这两类信号，不声称未授权内容或未声明日期的资料均有效

#### Scenario: 日期含义
- **WHEN** 展示复审逾期与适用期已届满
- **THEN** 分别说明需要责任人重新确认和版本声明截止日已过，不将两者合并为“文档失效”

### Requirement: 筛选与翻页必须采用服务端完整诊断结果

页面 SHALL 提供 ALL 及六个单类筛选，默认 ALL、每页 20 项。选择信号或空间、显式刷新及返回首页均从首页查询；下一页使用当前服务端游标。每次成功结果替换六类数量、并集及当前页，不追加历史页或跨空间合并。清单按服务端顺序显示，一份文档一行且展示该项全部可见原因，前端不自行扫描目录计算数量。

#### Scenario: 切换筛选
- **WHEN** 用户从复审逾期切换到适用期已届满
- **THEN** 清除旧页和游标，从新筛选首页读取；迟到的旧筛选结果被丢弃

#### Scenario: 加载下一页
- **WHEN** 当前页 hasMore 为 true 且用户主动点击下一页
- **THEN** 请求该游标并在成功后替换当前页及全部汇总，不将旧页长期累积在列表中

#### Scenario: 从处理页面返回
- **WHEN** 用户完成既有管理操作后返回雷达
- **THEN** 重新核验资格并从该空间默认首页读取，不根据跳转或操作按钮点击预先扣减数量

### Requirement: 文档清单必须保持最小信息并连接既有动作

清单 SHALL 用文档 ID 标识资源，显示可见原因、服务端允许的责任人和日期；不为补标题额外读取文档详情。每项提供文档管理入口；只有响应明确提供获准适用期版本时才提供固定版本预览及另行标明的文档详情处理入口。预览复用既有流程并重新授权，不能静默切换版本。指定、改派、编辑和复审确认在原页面按各自资格进行，雷达不直接提交写操作或新增忽略、关闭和完成按钮。

#### Scenario: 可管理但不可读
- **WHEN** 文档只有最小维护投影且 applicability 为 null
- **THEN** 显示文档 ID 与获准维护信息并链接管理页，不提供推测的版本链接或补查标题

#### Scenario: 固定版本入口
- **WHEN** 用户点击有适用期信号的固定版本核对入口
- **THEN** 预览绑定响应中的文档和版本身份，沿用原文件读取授权，不静默替换为新版本；文档详情处理入口明确为重新读取文档及其当前可访问版本

#### Scenario: 固定预览期间失去阅读资格
- **WHEN** 既有预览报告访问被拒绝
- **THEN** 关闭预览并清除本次诊断，重新核验资格后才能再次查询，不尝试原件下载或其他版本作为回退

#### Scenario: 责任人不合格
- **WHEN** 文档状态为需重新指定
- **THEN** 显示允许的责任人显示名和改派方向，不猜测离职、停用、密级或撤权原因

### Requirement: 响应必须完整核验并区分故障与空结果

页面 SHALL 核验 KNOWLEDGE_HEALTH_V1、当前空间/筛选、六类固定计数、精确 ID、非空合法原因、唯一文档、日期与分页字段后才展示响应。缺失/未知协议、字段矛盾或请求失败显示不可用并提供显式重试，不回退旧复审 API 拼装雷达、不保留旧统计作为当前成功结果。查询期间清除旧结果并禁止重复翻页，无信号只在完整成功时展示。

#### Scenario: 旧服务不支持
- **WHEN** 新端点不存在、返回不匹配的协议或成功体缺少必要字段
- **THEN** 显示当前服务不可用，不遍历旧清单自行统计或使用部分字段

#### Scenario: 后端返回 503
- **WHEN** 首次、刷新或下一页请求返回 503 或网络失败
- **THEN** 统计和清单显示读取失败及重试，不显示零问题、旧统计时间或自动重复请求

#### Scenario: 成功空页与空空间
- **WHEN** 完整合法响应的当前页为空
- **THEN** 按服务端汇总区分所选类别无项目或当前游标后无项目，不从空页推断整个空间无信号

### Requirement: 归档跨日与撤权必须有明确恢复路径

空间摘要显示归档或诊断返回 409 SPACE_ARCHIVED 时，页面 SHALL 清空诊断并显示空间已归档及返回空间管理入口；不自动取消归档。409 RADAR_DATE_CHANGED 时清除旧游标和结果，提供从首页重新查询。403/404 时清除结果并核对当前资格，不把无权解释为空空间，也不自动切到其他空间。

#### Scenario: 跨午夜继续翻页
- **WHEN** 下一页返回 RADAR_DATE_CHANGED
- **THEN** 提示业务日期已变化并要求用户从首页重新查询，不能继续拼接旧日期结果

#### Scenario: 管理资格撤销
- **WHEN** 用户读取期间失去当前空间管理资格
- **THEN** 旧数量和清单被清除，仍可管理的其他空间只能在重新核验后由用户主动选择

### Requirement: 雷达私有状态必须随页面上下文失效

统计、原因筛选、游标和清单 SHALL 仅保存在当前身份内存。页面隐藏、离开、退出、换号、强制改密或资格失效时清除结果并取消请求；请求代次及身份代次阻止迟到回调。恢复先重新核验身份、功能和目标资格，再从默认首页读取。URL 只含目标空间 ID，不保存筛选、游标或统计；无定时轮询、导出或推送。

#### Scenario: 请求未完成时切换账号
- **WHEN** A 的诊断仍在途时用户退出并以 B 登录
- **THEN** A 的结果和异常都不能恢复到 B 的页面

#### Scenario: 页面隐藏后恢复
- **WHEN** 用户把页面切到后台后再次打开
- **THEN** 原结果已清理，重新核验资格后取得当前首页，不从浏览器持久存储恢复旧统计
