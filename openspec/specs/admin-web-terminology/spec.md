# admin-web-terminology Specification

## Purpose

为企业公开术语词典提供受独立资格保护的管理页面，让维护人员能够查看和维护术语组、别名及错词映射，并理解公开范围、歧义与启停影响。页面准确区分保存回执、当前状态和未知结果，沿用现有身份隔离及版本冲突处理方式。

## Requirements

### Requirement: 词典管理页面必须分别核对读取和写入资格

管理端 SHALL 提供 `/admin/search-terms`，仅当前持有 `search:term:read` 时加载页面及管理数据；创建、编辑和启停另需 `search:term:write`。页面包含术语组和错词映射两个管理视图，使用各自目录与分页，不要求身份目录或可管理空间。普通搜索建议不能作为管理目录数据来源或授权凭据。

#### Scenario: 只读管理者
- **WHEN** 用户只有 search:term:read
- **THEN** 可以查询两个目录，写动作禁用或隐藏，普通空间管理权不能补足写资格

#### Scenario: 只有写资格
- **WHEN** 用户只有 search:term:write
- **THEN** 页面与导航不开放，不因写权限自动请求管理目录

### Requirement: 维护表单必须明确公开范围和关系类型

术语组表单 SHALL 编辑标准名称、简短释义及有类型的别名，错词表单编辑错误表达并从当前管理目录选择明确目标组。保存前须说明启用词条可向全公司有效登录用户提供搜索提示，词典关系不授予文档访问。名称、说明和错误均按安全文本呈现；不能用自由输入目标名称或猜测 ID 替代已确认的稳定目标。

#### Scenario: 建立简称与旧称
- **WHEN** 管理者为某术语添加简称和旧称
- **THEN** 每项关系类型可辨认，提交预览展示规范化后的名称及全公司公开含义

#### Scenario: 错词目标读取失败
- **WHEN** 选择目标组的目录读取失败
- **THEN** 相关保存保持禁用并提供主动重读，不回退普通搜索结果或手填内部 ID

### Requirement: 歧义和命名冲突必须可辨认

页面 SHALL 按服务端事实提示跨组共享表达及歧义，显示可管理的相关标准名称和释义，不附带文档命中数。标准名称重名、错词与合法表达冲突、非法重复项和版本冲突分别使用固定错误类别呈现；共享别名允许保存，不能被客户端一概当作非法重名，也不能静默改为其他表达。

#### Scenario: 同一简称用于两个组
- **WHEN** 管理者保存另一个使用 PM 的术语组且服务端确认成功
- **THEN** 页面说明 PM 将需要搜索用户选择含义，不能声称所有输入都自动采用新组

#### Scenario: 标准名称与错词冲突
- **WHEN** 服务端拒绝把一个已占用错词作为标准名称
- **THEN** 展示对应冲突，保留当前可维护草稿供用户调整，不删除已有错词或自动换名

### Requirement: 启停交互必须展示完整影响

术语组停用确认 SHALL 说明其名称、别名及指向它的纠错建议都退出后续辅助搜索，已有文档不因此被修改。错词自身启停单独表达；目标停用时明确显示映射自身启用但当前不可用于建议。重新启用只恢复仍符合规则的关系。成功后重读当前状态，不能以开关本地变化代替服务端回执。

#### Scenario: 停用被纠错映射引用的组
- **WHEN** 管理者确认停用目标组
- **THEN** 页面说明相关纠错会随目标暂停，不声称映射已删除或其自身 enabled 被修改

#### Scenario: 停用后旧建议仍留在他人页面
- **WHEN** 停用成功且另一用户尚未刷新旧结果
- **THEN** 管理页面只承诺后续搜索及建议采用遵守新修订，不声称撤回已显示文本

### Requirement: 管理列表必须绑定已提交条件和词典修订

名称、状态筛选及目录类型 SHALL 在提交后形成条件快照，修改草稿不改变当前续页条件。列表使用服务端 items、hasMore、nextCursor 和 dictionaryRevision；返回修订冲突时废弃续页上下文，提供重新读取，不拼接新旧页。加载、真实空目录、末页和故障必须区分；词条数量不作为关联文档统计。

#### Scenario: 分页间有人维护词典
- **WHEN** 续页返回修订冲突
- **THEN** 停止续页并提示词典已变化，主动重读从首项开始

#### Scenario: 切换管理视图
- **WHEN** 用户从术语组切换至错词映射
- **THEN** 使用目标目录的条件和游标，前一视图的迟到响应不能追加到新列表

### Requirement: 保存必须绑定固定意图并核对回执

提交 SHALL 绑定目标、操作、规范化载荷、必要 expectedVersion 和 X-Request-Id，在途时阻止重复保存及相反启停。409 时说明冲突并允许重读后重新编辑；响应未知时保留当前有效上下文内的原意图供主动匹配重试或核对，不自动重发。当前读值与草稿相同不证明原请求成功；合法成功回执后重读失败须单独展示，不能改报保存失败。

#### Scenario: 连续点击保存
- **WHEN** 首次保存仍在途
- **THEN** 后续点击不生成第二个意图或新请求标识

#### Scenario: 创建已提交但响应丢失
- **WHEN** 用户选择匹配重试
- **THEN** 使用原请求标识与规范化载荷，不因目录已有同名项就声称原请求已确认

#### Scenario: 编辑与停用冲突
- **WHEN** 保存因 expectedVersion 陈旧返回 409
- **THEN** 重读后由用户重新确认新意图，不自动覆盖先提交的启停事实

### Requirement: 词典管理状态必须服从身份和页面生命周期

目录、名称查询、游标、草稿、选择与回执 SHALL 只保留在当前页面内存；ID、version 和 dictionaryRevision 必须精确。页面隐藏、离开、退出、强制改密或资格失效时清理内容并使旧回调失效；恢复重新核对身份及读取资格，再由用户重新编辑或操作，不自动恢复保存。停止本地等待不表示服务端写入撤销。

#### Scenario: 换号后旧保存返回
- **WHEN** 用户 A 的保存响应在用户 B 登录后到达
- **THEN** 不显示 A 的词条、回执或成功提示，不触发 B 的目录变更

#### Scenario: 后台恢复且资格已撤销
- **WHEN** 页面恢复时当前身份失去 search:term:read
- **THEN** 不加载原目录或表单，不凭缓存模块或旧权限继续维护

#### Scenario: 大整数和标记文本
- **WHEN** 词条 ID 超出 JavaScript 安全整数范围且名称含 HTML 标记
- **THEN** 保留精确身份，名称按文本显示，不执行标记或保存到持久存储
