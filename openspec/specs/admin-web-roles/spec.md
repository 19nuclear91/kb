# admin-web-roles Specification

## Purpose

为功能角色提供目录、生命周期和权限配置界面，使用服务端角色及权限目录表达真实授权事实，使角色编码、功能资格和资源 ACL 引用之间的边界在管理操作中保持清晰。

## Requirements

### Requirement: 角色页面必须读取服务端目录与权限详情

角色页 SHALL 要求 `identity:role:read`，读取角色目录、选中角色详情及完整功能权限目录，展示角色 ID、稳定 code、显示名和已绑定权限。权限说明 SHALL 来自目录，界面可按用途分组，但 MUST 不推导前缀继承、通配权限或角色名称代表的资格。

#### Scenario: 管理员角色不含某权限
- **WHEN** 名为 ROLE_ADMIN 的角色详情没有某权限绑定
- **THEN** 页面将该权限显示为未授予，不按角色名称补勾

#### Scenario: 目录包含其他业务权限
- **WHEN** 服务端目录包含空间、文档、死信或 Embedding 功能权限
- **THEN** 页面完整展示实际目录，并按操作者的角色写入资格提供逐项操作，不仅截取身份管理前缀

### Requirement: 创建角色必须保持初始空权限

创建角色 SHALL 要求 `identity:role:write`，提交唯一 code、名称及请求标识。成功后 SHALL 展示返回角色且初始权限为空，后续权限配置为独立操作；新建表单不得暗中套用管理员模板或默认授权。

#### Scenario: 新建角色成功
- **WHEN** 服务端接受唯一 code 和有效名称
- **THEN** 页面定位新角色并展示空权限集，提示后续配置权限

#### Scenario: code 已存在
- **WHEN** 服务端返回编码冲突
- **THEN** 页面说明编码已使用并允许修改输入，不覆盖已有角色

### Requirement: 角色改名必须保持 code 不可变

角色改名 SHALL 使用独立请求标识，仅编辑显示名，code 在已有角色详情和改名表单中只读。客户端 MUST 遵循现有接口，不为角色改名或权限操作虚构服务端未提供的版本字段。

#### Scenario: 修改显示名
- **WHEN** 操作者提交新显示名
- **THEN** 请求不试图改写 code，成功后以返回详情刷新名称和真实权限事实

### Requirement: 角色权限必须逐项提交且以确认结果展示

授予或撤销单项权限 SHALL 要求 `identity:role:write`，使用目录中的完整 permission code、granted 和独立请求标识。每项操作提交前须明确目标和动作，同一角色有待确认写操作时不得并发提交其他修改；操作结束后核对角色详情和本人权限，不用一组本地勾选声称批量原子保存。

#### Scenario: 单项变更成功
- **WHEN** 用户确认授予一项权限并收到成功详情
- **THEN** 以服务端确认结果更新该项并核对本人权限，再允许下一项修改

#### Scenario: 撤销最后管理员资格被拒
- **WHEN** 权限撤销返回最后管理员保护分类
- **THEN** 页面保持已确认的权限绑定并说明拒绝原因，不继续执行任何后续修改

#### Scenario: 提交结果不确定
- **WHEN** 权限修改未取得可靠响应
- **THEN** 该角色修改保持待核对状态，可重读或匹配重试，不能直接继续一批授权请求

### Requirement: 删除角色必须说明引用约束且禁止级联代办

角色删除 SHALL 要求 `identity:role:write`，明确确认目标 code 和名称，使用独立请求标识。删除存在用户绑定或空间/文档 ACL 引用的角色被拒时，页面须显示引用约束，不自动解除绑定或撤销 ACL，不虚构引用数量或有权读取的引用明细。

#### Scenario: 角色仍有引用
- **WHEN** 服务端返回角色仍被引用的分类
- **THEN** 页面保持角色存在，提示先处理用户绑定或资源授权引用，不提供绕过保护的强制删除

#### Scenario: 无引用角色删除成功
- **WHEN** 服务端确认删除角色
- **THEN** 刷新角色目录并清空该角色详情和表单，不继续对已删除目标提交权限修改

### Requirement: 角色配置必须保持功能资格与资源授权独立

角色页面 SHALL 明确其配置的是功能操作权限；角色存在、获得管理功能或拥有某个 code，不代表可以阅读、下载任意文档。页面 MUST 不通过角色详情额外加载资源正文、完整成员目录或 ACL 引用明细，相关资格仍由各自接口判断。

#### Scenario: 授予空间管理功能
- **WHEN** 操作者给角色授予空间管理功能权限
- **THEN** 页面只确认功能权限变更，不宣称该角色持有者因此获得全部文档阅读权限
