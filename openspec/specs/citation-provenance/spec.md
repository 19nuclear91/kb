# citation-provenance Specification

## Purpose

为检索和问答引用提供固定版本、可核对且受当前权限约束的来源契约，使用户能够读取仍存在的原分块，并在分块失效时明确退回原版本文件入口，而不误跳最新内容或把来源提示当作原件精确坐标。

## Requirements

### Requirement: 检索引用必须绑定命中分块的版本

系统 SHALL 为新检索结果返回同一命中事实对应的 `docId`、`versionId`、`versionNo` 和 `chunkId`。版本身份 MUST
来自该分块所属版本，不得通过后续读取文档当前版本补全。检索 SHALL 继续只召回当前已发布版本中符合授权规则的分块；`versionNo`
仅用于展示，不替代 `versionId`。

#### Scenario: 两种检索路径返回一致的版本身份

- **WHEN** 调用方分别执行纯文本检索和具备可用向量配置的混合检索
- **THEN** 每个返回分块均携带正确的文档、版本、版本号和分块 ID
- **AND** 历史非当前版本、未发布内容和无权内容不会因增加版本字段进入召回结果

#### Scenario: 检索后发布了新版本

- **WHEN** 一次检索命中了版本 V1，随后文档发布版本 V2
- **THEN** 该次检索结果及由其形成的引用仍标识 V1，不补写 V2 的身份或版本号

### Requirement: 来源元数据必须保留未知值与提示语义

系统 SHALL 在检索、AI 上下文、SSE 引用和可用片段查询之间保留 `chunkIdx`、`pageNo`、`headingPath`、`structureType`、
`sourceLineStart`、`sourceLineEnd`、`sourceCharStart`、`sourceCharEnd` 和 `sourceLocator`。缺失来源 SHALL 保持未知。来源字段
MUST 仅表示解析器报告的来源提示，不承诺原件精确坐标、整块覆盖页范围或逐字高亮。

#### Scenario: 已有来源字段完整透传

- **WHEN** 命中分块具有页码、标题路径和来源范围
- **THEN** 各引用环节保留这些字段的值，不重新推断或替换其坐标

#### Scenario: 历史分块没有来源元数据

- **WHEN** 命中分块没有页码、章节或来源范围
- **THEN** 新响应中的相应字段为 `null`，正文及完整版本身份仍可用于核对
- **AND** 系统不使用页码 0、标题推测或字符串 `"null"` 表示已知来源

#### Scenario: 来源范围大于引用正文

- **WHEN** 分块来自合并的来源块或其正文在本轮被裁剪
- **THEN** 来源范围仍作为原分块的提示保留，不宣称是裁剪后正文在原件中的精确区间

### Requirement: SSE 引用只声明本轮参考来源

系统 SHALL 从本轮上下文预算筛选后的参考列表生成 `citation`，并保持其版本身份和来源元数据；被预算完全排除的分块不得产生引用。
`contextTruncated` SHALL 标识该分块正文是否经过本轮预算裁剪。引用 MUST 表示本轮参考材料，不证明模型实际采用了该片段，更不证明答案中每句话都得到该片段支持。

#### Scenario: 总预算只容纳部分参考材料

- **WHEN** 第一分块完整保留、第二分块仅保留前缀、第三分块被预算完全排除
- **THEN** 仅前两个分块产生引用，`contextTruncated` 分别为 `false` 和 `true`
- **AND** 传入模型适配器的参考材料与这两个引用具有相同身份，裁剪不破坏 Unicode 字符

#### Scenario: 查询裁剪过的引用

- **WHEN** 用户查询一个 `contextTruncated=true` 且仍可读取的引用
- **THEN** 查询返回该版本中完整的存储分块，而不是承诺返回当轮 prompt 的逐字快照

#### Scenario: 模型未采用参考材料或调用失败

- **WHEN** 引用已经发出，但模型未采用其中某片段、随后出错，或本轮使用占位应答
- **THEN** 该事件仍只表示本轮参考来源，不增加已使用、逐句验证或生成成功的承诺
- **AND** 保持既有 `citation`、`delta`、`done`、`error` 事件类型及终止行为

### Requirement: 指定版本引用查询必须校验完整归属

系统 SHALL 提供 `GET /api/documents/{documentId}/versions/{versionId}/citations/{chunkId}`，要求路径 ID 为正整数，按文档和指定版本的当前 view 及发布／候选参与资格读取。仅当分块同时匹配该文档及该版本时，查询 SHALL 返回 AVAILABLE 和完整存储正文。查询 MUST 不要求该版本仍为当前版本，不按分块序号替代分块 ID；候选核对不使其进入检索或 RAG。

#### Scenario: 查询仍存在的原分块

- **WHEN** 用户可查看指定文档和版本，且三个 ID 与一个存储分块完全匹配
- **THEN** 响应为 HTTP `200`，使用既有成功响应封装，并在 `data.status` 中返回 `AVAILABLE`
- **AND** 数据包含 `docId`、`docTitle`、`versionId`、`versionNo`、请求的 `chunkId`、带完整正文和来源提示的 `chunk` 以及原版本文件入口

#### Scenario: 版本不属于请求文档

- **WHEN** 请求的 `versionId` 实际属于另一个文档
- **THEN** 返回与目标不存在或无权查看相同的 HTTP `404`，不返回版本、分块正文或文件入口

#### Scenario: 请求 ID 不合法

- **WHEN** 已通过身份检查的请求包含非正整数或超出支持范围的路径 ID
- **THEN** 返回 HTTP `400`，不尝试推断或替换为当前版本

#### Scenario: 普通读者猜测待审分块
- **WHEN** 用户只有父文档 view，没有新未发布版本的参与资格
- **THEN** 即使版本和分块 ID 匹配也统一 404，不返回 CHUNK_UNAVAILABLE、标题或原件入口

### Requirement: 无匹配分块必须明确降级且不猜测历史

系统 SHALL 在用户仍可查看指定文档和版本、但没有匹配分块时，返回 HTTP `200`、成功封装、`data.status=CHUNK_UNAVAILABLE` 和
`chunk=null`，并保留原版本身份及按权限提供的原版本入口。该状态 MUST 仅表示当前没有匹配片段，不断言该 ID
曾属于此版本或一定因重解析被删除，也不宣称永久失效。

#### Scenario: 同版本重解析替换了分块

- **WHEN** 版本 V1 的旧分块 C1 被删除重建，新分块 C2 即使具有相同 `chunkIdx`，用户仍请求 C1
- **THEN** 返回 `CHUNK_UNAVAILABLE`，不返回 C2 的正文或把 C2 当成原引用
- **AND** 文件入口仍指向 V1，不重定向当前版本

#### Scenario: 分块 ID 属于其他文档或版本

- **WHEN** 请求文档和版本可查看，但 `chunkId` 属于另一文档、另一版本或根本不存在
- **THEN** 均返回相同的 `CHUNK_UNAVAILABLE` 结果形状
- **AND** 不透露该分块实际是否存在、实际归属、正文或其他来源信息

### Requirement: 引用身份不得随内容发布或向量重建漂移

系统 SHALL 允许通过固定三元组读取仍存在且当前可访问的历史版本分块。新版本发布或 Embedding 重建 MUST NOT
将旧引用改指向其他版本或分块；引用核对不依赖向量配置是否可用。该能力不保证已经删除或被重解析替换的分块长期可恢复。

#### Scenario: 发布后继续核对历史版本

- **WHEN** 文档当前版本从 V1 变为 V2，但 V1 和被引用分块仍存在且可访问
- **THEN** 查询旧引用返回 V1 的分块正文和文件入口，而不是 V2 的内容

#### Scenario: 仅重建向量或进入向量维护状态

- **WHEN** Embedding 配置切换、向量重建或向量维护状态变化，但文档版本和分块身份未变
- **THEN** 固定引用的核对结果不因向量状态变化而失效或发生正文替换

### Requirement: 引用读取必须使用当前授权并隐藏不可见目标

系统 SHALL 每次重新解析认证主体、当前密级、view、当前空间、例外、删除及版本访问资格。已发布历史与旧兼容版本按各自规则核对，新未发布版本另要求候选参与资格；管理资格不蕴含正文访问。空间归档、主体停用或无有效授权 MUST 阻止读取；不存在、已删除、归属不符或不可见统一 HTTP 404，不提供失效详情或入口。

#### Scenario: 已有引用不能保留被撤销的访问权

- **WHEN** 用户获取引用后其角色、部门、空间授权或文档例外发生变更，使其不再具有 `view` 权限，随后再次查询
- **THEN** 返回统一的 HTTP `404`，不因先前获得过该引用而返回正文、标题或降级入口

#### Scenario: 文档升密或搬迁后重新判定

- **WHEN** 文档升密超过用户当前密级，或搬迁到用户不可查看的空间后收到新的查询
- **THEN** 引用不可读取，不沿用引用生成时的密级、原空间或已清除的例外授权

#### Scenario: 空间归档优先于文档例外

- **WHEN** 文档所在空间已经归档，即使用户仍有文档例外或空间管理资格
- **THEN** 新的引用查询返回 HTTP `404`，不提供原文片段或文件入口

#### Scenario: 会话存在但主体已停用

- **WHEN** 仍持有会话的用户或其主部门已经停用
- **THEN** 新查询不能取得正文、来源信息或入口，按资源不可见返回 HTTP `404`

#### Scenario: 认证和强制改密门禁仍然生效

- **WHEN** 请求没有有效登录会话，或有效会话处于强制改密状态
- **THEN** 分别按既有门禁返回 HTTP `401` 或 `403`，新增查询不成为白名单例外

#### Scenario: 管理员没有内容查看授权

- **WHEN** 操作者只有管理权限或 `download`，而没有目标文档的 `view`
- **THEN** 引用查询不返回片段或降级详情，不能用管理或下载资格替代查看资格

#### Scenario: 审核人失去候选参与资格
- **WHEN** 审核人取得候选引用后失去 review，且不具有上传者或送审者身份
- **THEN** 新的候选引用读取返回 404，仍有父文档 view 也不保留候选读取资格

### Requirement: 原版本文件入口必须分别执行查看与下载权限

系统 SHALL 在可查看的引用查询结果中提供指定版本的 `previewPath`，且仅在独立 `download` 判定通过时提供 `downloadPath`
，否则后者为 `null`。这些入口 MUST 使用受保护的业务路径，并在访问时再次鉴权；引用查询成功不形成持续授权。预览格式支持范围和下载权限
SHALL 沿用既有文件接口契约。

#### Scenario: 用户只有查看权

- **WHEN** 用户具有目标版本的 `view`，但不具有 `download`
- **THEN** 可用或失效引用结果均提供固定版本的预览业务路径，`downloadPath=null`
- **AND** 用户直接构造下载路径也不能绕过下载权限

#### Scenario: 用户可下载但文件不能安全预览

- **WHEN** 用户同时具有 `view` 和 `download`，但原文件不属于既有安全预览格式
- **THEN** 查询提供原版本的两个业务入口，预览仍可返回 HTTP `415`，下载按独立权限处理
- **AND** 不把接口返回预览路径解释为对预览格式支持的保证

#### Scenario: 返回入口后权限被撤销

- **WHEN** 用户获得引用结果中的文件路径后，相关权限被撤销、文档升密或所在空间归档，再请求该路径
- **THEN** 文件接口按新状态拒绝访问，不接受先前引用结果作为授权凭据

### Requirement: 新旧 JSON 和 SSE 契约必须支持明确降级

系统 SHALL 保留既有检索 JSON 及 SSE 引用字段的名称与类型，并以新增字段扩展。SSE SHALL 用 `provenanceStatus=VERSIONED`
表示具备完整三元组，用 `UNVERSIONED` 表示旧数据缺少版本身份；前者不保证片段仍可读取。缺少 `versionId` 时 MUST NOT 补当前版本或伪造
ID，且不得构造版本级查询入口。

#### Scenario: 新 AI 服务接收旧检索响应

- **WHEN** 检索结果仍具有合法的 `docId` 和 `chunkId`，但缺少或没有 `versionId`
- **THEN** 该项仍可作为普通参考材料，SSE 保留旧字段并返回 `versionId=null`、`provenanceStatus=UNVERSIONED`
- **AND** 缺失的可选来源信息保持未知，不把缺失版本转换成 0 或最新版本

#### Scenario: 新检索响应被旧客户端读取

- **WHEN** 能忽略未知 JSON 字段的旧客户端读取新检索或 SSE 响应
- **THEN** 原有字段及事件类型保持可用，客户端无需理解新增来源字段才能继续处理旧信息

#### Scenario: 上游提供损坏的身份数据

- **WHEN** 检索项缺少合法 `docId` 或 `chunkId`，或提供了非正整数、非整数类型的版本身份
- **THEN** 不为该项伪造可解析引用，不将它加入本轮参考列表
- **AND** 同一响应中其他合法检索项仍可继续处理

### Requirement: 引用核对不得暴露底层存储与持久授权

系统 SHALL 通过受保护的 JSON 响应提供片段正文和相对业务入口，成功查询响应使用 `Cache-Control: no-store`。响应 MUST NOT
包含对象存储键、存储服务地址、签名直链、会话凭据或其他文档正文；拒绝响应不得附带引用数据。查询 SHALL 为只读核对，不触发重解析、Embedding
重建或模型生成。

#### Scenario: 可用和失效响应不泄露存储信息

- **WHEN** 用户取得 `AVAILABLE` 或 `CHUNK_UNAVAILABLE` 查询结果
- **THEN** 响应带有禁止存储缓存的指令，文件入口仅包含对应文档和版本的业务路径
- **AND** 不含存储键、签名直链或凭据，也不生成引用快照或触发模型调用

#### Scenario: 被拒绝的请求没有旁路数据

- **WHEN** 引用查询被身份、权限、归属或参数校验拒绝
- **THEN** 错误响应不附带片段正文、标题、来源定位或可访问入口
