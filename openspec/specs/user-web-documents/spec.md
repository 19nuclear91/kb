# user-web-documents Specification

## Purpose

为普通用户建立文档浏览、上传处理、版本查看和授权搜索的浏览器交互契约，使界面准确反映服务端处理状态与独立操作权限，并通过固定版本引用和受保护文件入口查看原始材料，避免上传、阅读与下载资格相互混淆。

## Requirements

### Requirement: 文档中心必须使用当前用户的真实读取结果

文档中心 SHALL 提供全部文档、可见空间及元数据组合筛选和分页，通过 POST /api/documents/query 读取当前可查看文档，按服务端原排序呈现。空间目录可管理或可见 MUST NOT 被当成文档可读取的保证；列表 SHALL 区分加载、空集合与失败，total 和 items 均采用服务端结果。标题筛选限于文档标题字面匹配，文档正文检索继续使用搜索入口。

#### Scenario: 文档仅通过例外可见
- **WHEN** 用户能够查看一个文档，但其所属空间不在可查看空间目录中
- **THEN** 全部文档列表仍显示服务端返回的该文档
- **AND** 页面不借此枚举或猜测不可见空间的名称

#### Scenario: 仅可管理空间或空间已归档
- **WHEN** 空间目录包含仅可管理或已归档空间
- **THEN** 用户端不将其作为可阅读内容的保证，归档空间不进入普通文档筛选候选
- **AND** 文档展示只采用受保护列表响应

#### Scenario: 组合筛选没有结果或读取失败
- **WHEN** 查询合法成功返回空页，或服务端返回依赖故障
- **THEN** 分别显示当前条件下无可查看文档或读取失败，不通过移除条件自动扩大结果

### Requirement: 上传必须选择独立的可上传空间并使用实际密级字典

上传弹窗 SHALL 使用当前可上传空间候选及真实密级字典，允许选择空间、文件和可选标题。页面 MUST NOT 从查看、manage、角色名称或文档所有者推断上传资格，不写死密级数量和名称；服务端校验为实际提交的最终判定。

#### Scenario: 用户只有空间编辑权
- **WHEN** 用户没有某空间 view 或 manage，但上传候选包含该空间
- **THEN** 页面允许选择该候选提交上传，不要求输入空间 ID 或获得管理权限

#### Scenario: 密级字典包含新增值
- **WHEN** 服务端字典包含 0–3 之外的合法密级，或字典读取失败
- **THEN** 前者按返回的实际数值提供选项，后者阻止不完整表单提交并显示读取失败
- **AND** 页面不伪造级别名称或擅自引入服务端没有的上传密级上限

### Requirement: 上传提交与解析发布必须分别展示

用户端 SHALL 区分文件上传、后端已受理和版本解析发布，成功受理后保存返回的文档及版本身份。上传和新版本上传 SHALL 防止重复点击；网络结果不确定时 MUST NOT 自动重发或宣称上传失败一定未落库，也不得因为取得 contentHash 提供越权秒传。

#### Scenario: 上传成功后尚未完成解析
- **WHEN** 上传返回成功，而版本仍处于待处理或解析状态
- **THEN** 页面显示已提交及实际处理状态，不将其显示为已可检索
- **AND** 后续状态查询绑定本次返回的 versionId

#### Scenario: 上传成功但没有后续查看权
- **WHEN** 用户具备上传资格，上传成功后的详情或进度因当前 view 不足返回 404
- **THEN** 页面保留本次提交成功提示并显示当前无法查看后续状态
- **AND** 不自动扩大查看权限、不持续轮询该拒绝，也不把它改报为文件上传失败

#### Scenario: 上传响应丢失
- **WHEN** 文件提交后的网络响应丢失
- **THEN** 页面显示结果尚未确认并允许用户核对文档列表，不自动重复上传创建新版本

### Requirement: 版本详情必须准确跟踪选中版本的处理状态

详情页 SHALL 展示服务端允许的元数据与版本列表，按选中 versionId 查询状态，区分当前发布版本、索引处理及审核状态。页面 SHALL 展示排队、处理中、退避、维护等待、待送审、审核中、驳回、撤回、索引待刷新、已发布及真实解析问题，不编造百分比或把 indexed 当作已发布；非终态轮询 MUST 有间隔和失败上限并随页面离开暂停。隐藏版本不补猜 ID 或数量。

#### Scenario: 新版本尚未替换旧版本
- **WHEN** 当前版本 V1 已发布，新上传的 V2 仍在解析或审核
- **THEN** 页面分别显示 V1 为当前版本、V2 为当前允许读取的处理／审核状态，不以 V1 成功或 V2 indexed 冒充 V2 已发布

#### Scenario: 向量维护或解析截断
- **WHEN** 进度返回 EMBEDDING_MAINTENANCE，或版本返回解析截断/问题摘要
- **THEN** 页面分别显示维护等待或相应解析提示，不把维护等待标成失败，不伪造缺失正文

#### Scenario: 页面离开或权限拒绝
- **WHEN** 用户离开详情页、页面隐藏，或轮询返回 401、403、404
- **THEN** 该轮询停止，恢复页面时先重新读取当前事实，不继续无界后台请求

#### Scenario: 普通读者看不到候选版本
- **WHEN** 普通读者只能取得 V1，V2 为未发布候选
- **THEN** 列表不展示 V2 占位、状态、文件名或隐藏数量，不尝试按连续版本号补查

### Requirement: 文档操作按钮必须结合独立能力和版本状态

详情页 SHALL 依据当前独立操作能力、所选版本的访问及审核状态控制下载、新版本上传、失败重试和审核相关操作；整文档删除 SHALL 仅按父文档当前可查看事实及 canDelete=true 开放，不受所选版本是否已发布、可读或可重试影响。元数据编辑 SHALL 另要求 canEditMetadata=true 和最新资料读取成功。能力读取失败或缺少对应字段不默认启用删除或编辑。重试 MUST 满足 edit 与对应版本可重试条件，候选刷新走独立确认。文档级 canDownload 等标记不保证所选未发布版本可读，实际操作仍重新鉴权，拒绝后更新页面事实。

#### Scenario: 可查看但不可下载或编辑
- **WHEN** 用户可读取详情，但能力响应的 canDownload、canUploadVersion、canRetry、canDelete 和 canEditMetadata 均为 false
- **THEN** 页面保留查看行为，禁用或隐藏相应操作，不依据管理员名称或 ownerId 重新启用

#### Scenario: 版本可重试且能力允许
- **WHEN** 选中版本处于可重试失败状态且当前版本操作能力允许
- **THEN** 用户可以向该明确版本发起一次重试，并显示新返回的处理状态
- **AND** 提交期间防止重复点击，超时不自动重发

#### Scenario: 点击前授权已被撤销
- **WHEN** 页面曾取得 true 标记，但实际下载、上传版本、元数据编辑或删除请求被新权限拒绝
- **THEN** 页面按最新拒绝更新操作状态，不继续依赖旧标记重试放行

#### Scenario: 父文档可下载但候选不可访问
- **WHEN** 文档级 canDownload=true，但所选新候选版本的访问未确认或被拒
- **THEN** 不按文档级标记启用该版本下载，清理失效的预览和入口

#### Scenario: 旧服务未返回删除能力
- **WHEN** 能力响应没有 canDelete 字段，或当前能力读取尚未成功
- **THEN** 删除操作保持禁用，不用 canUploadVersion、canRetry 或旧缓存推断删除能力

#### Scenario: 旧服务未返回元数据编辑能力
- **WHEN** 能力响应没有 canEditMetadata 字段
- **THEN** 元数据编辑保持禁用，不以 canUploadVersion 或其他权限标记替代

### Requirement: 搜索必须只消费现有授权检索能力

搜索页 SHALL 通过 POST JSON 提交 query 及有界数量参数，展示服务器返回的有序片段、标题和版本信息。首期 SHALL 搜索全部当前可见内容，不发送未支持的空间筛选或使用旧 GET 检索；失败不能伪装为空结果，空结果不得推断存在不可见文档。页面须按 8000 个 Unicode code point 的默认上限校验查询，不静默截断；服务端是最终判定。400、413、429 和 503 SHALL 按搜索上下文呈现，容量拒绝不得误报为部门 AI 额度不足，Retry-After 不触发自动重发。

#### Scenario: 提交搜索
- **WHEN** 用户输入关键词并提交
- **THEN** 请求发往不含关键词的固定 POST 路径，页面按实际响应顺序展示结果
- **AND** 页面地址、持久存储和日志不保存该关键词

#### Scenario: 未命中和依赖故障
- **WHEN** 检索成功返回空列表，或接口返回 503
- **THEN** 前者显示未找到可用结果，后者显示检索暂不可用，两种状态可区分

#### Scenario: 查询超过字符上限
- **WHEN** 用户输入超过 8000 个 code point 的查询，或输入包含 NUL 或孤立代理项
- **THEN** 页面提示修正输入并阻止提交，不截断后发送；补充字符按一个 code point 计算

#### Scenario: 服务端拒绝输入
- **WHEN** 搜索返回 400 或 413
- **THEN** 页面分别显示查询输入不符合要求或搜索请求过大，不把搜索正文超限描述为上传文件过大
- **AND** 只在当前页面保留输入，不显示被拒请求的成功结果

#### Scenario: 搜索用户并发超限
- **WHEN** 搜索返回 429，可选带有 Retry-After
- **THEN** 页面提示搜索请求过于频繁、稍后重试，不提示部门 AI 额度不足
- **AND** 不自动再次搜索、不循环倒计时发请求；用户可以在条件允许时主动重新提交

#### Scenario: 合法的降级结果
- **WHEN** 搜索通过 BM25 或原候选排序回退返回合法成功结果
- **THEN** 页面按响应原顺序显示片段，不自行重排、补取或自动重复请求以追求非降级结果

#### Scenario: 新请求发出后旧请求才返回
- **WHEN** 用户重新提交搜索、离开页面或切换身份，旧请求随后才返回
- **THEN** 旧成功、错误及 Retry-After 信息不得覆盖新页面状态，取消本地等待不被解释为服务端工作已经退出

### Requirement: 引用抽屉必须绑定原始文档版本和分块

搜索和问答 SHALL 复用固定版本引用查看交互，按返回的 docId/versionId/chunkId 核对片段。AVAILABLE 展示完整存储片段及来源提示；CHUNK_UNAVAILABLE 只表示当前没有匹配片段，并提供服务器返回的原版本入口。缺少版本身份或读取被拒时 MUST 不猜测、补最新版本或保留旧正文。

#### Scenario: 引用产生后发布新版本
- **WHEN** 用户点击命中 V1 的引用，而文档当前版本已变成 V2
- **THEN** 抽屉仍核对 V1，不自动显示 V2 或用相同 chunkIdx 替换旧分块

#### Scenario: 原分块不可用
- **WHEN** 引用接口返回 CHUNK_UNAVAILABLE 且仍提供 V1 的文件路径
- **THEN** 抽屉提示片段当前不可用，保留原版本文件入口，不宣称永久删除或曾存在该分块

#### Scenario: 来源未知或当前被拒
- **WHEN** 引用缺少 versionId，或核对接口返回 404
- **THEN** 前者不构造版本引用请求，后者清除对应旧片段、标题和文件入口
- **AND** 页码或来源范围缺失保持未知，不生成精确原件高亮承诺

### Requirement: 预览和下载必须分别消费受保护文件入口

用户端 SHALL 通过带认证头的同源业务请求读取指定版本文件，不拼接令牌、对象存储地址或签名直链。预览仅按现有 PDF 和纯文本支持范围展示，下载按独立权限执行；读取前重新处理实际授权结果，临时文件资源在关闭、切换或退出后 SHALL 释放。

#### Scenario: 有查看权但没有下载权
- **WHEN** 用户可预览某版本但不具备其 download 权限
- **THEN** 页面可以请求受保护预览，不将预览资格解释为下载资格，也不绕过下载拒绝

#### Scenario: Office 文件不能预览
- **WHEN** 指定版本预览返回 415
- **THEN** 页面提示当前格式不支持在线预览，只有独立下载资格允许时才提供下载操作

#### Scenario: 切换版本或关闭预览
- **WHEN** 用户从 V1 切换到 V2、关闭预览或退出登录
- **THEN** V1 的临时 Blob 地址和页面文件状态被释放，不在新上下文恢复旧文件

### Requirement: 文档详情的管理入口必须仅作为提示

详情页 SHALL 在文档所属空间位于当前空间目录且 `manageable=true`，或持有 `document:security-level:write` 时显示进入 `/admin/documents/:documentId` 的管理入口。入口 MUST 仅作为交互提示，不作为任何管理操作的授权凭证；只有已确认的来源参与计算，未确认或读取失败的来源 SHALL 视为不满足。详情页 MUST 不为显示入口额外调用管理文档清单或密级接口，入口状态也不影响详情、版本、预览和下载的既有行为。

#### Scenario: 所属空间可管理
- **WHEN** 详情返回的 spaceId 在空间目录中 manageable=true
- **THEN** 详情页显示管理入口，进入后由文档管理面板按各区块资格独立读取

#### Scenario: 只持有密级权限
- **WHEN** 所属空间不可管理，而用户持有 `document:security-level:write`
- **THEN** 详情页显示管理入口，面板只开放其资格允许的区块

#### Scenario: 没有任何管理资格
- **WHEN** 所属空间不可管理且用户未持有 `document:security-level:write`
- **THEN** 详情页不显示管理入口，其余详情功能保持不变

#### Scenario: 提示已过期
- **WHEN** 入口显示后空间 manage 授权被撤销，用户随后进入管理面板
- **THEN** 面板按最新读取结果呈现，不因入口曾显示而开放管理操作

#### Scenario: 空间目录读取失败
- **WHEN** 空间目录读取失败，且用户未持有 `document:security-level:write`
- **THEN** 详情页不显示管理入口，不以旧目录推断管理资格

### Requirement: 用户端必须提供受保护的我的收藏入口

用户端 SHALL 在主要导航提供 `/favorites`“我的收藏”页面，支持直接访问、刷新和登录后的合法站内返回。页面 MUST 在当前身份确认且已完成强制改密后加载，并与文档中心采用相同的会话生命周期；启用收藏不依赖 AI 会话开关或管理资格。

#### Scenario: 未登录直接访问收藏
- **WHEN** 用户未登录而直接打开 `/favorites`
- **THEN** 进入登录流程，不预取收藏；登录和必要改密完成后可返回该站内页面

#### Scenario: AI 会话未开放
- **WHEN** 用户已正常登录，但 AI 会话功能关闭
- **THEN** 仍可以打开“我的收藏”和使用文档收藏按钮

### Requirement: 文档与搜索收藏按钮必须使用有界批量状态

文档列表、详情和搜索结果 SHALL 提供按文档身份操作的收藏按钮。每次本页资源结果确定后，页面 MUST 对不同文档 ID 去重并批量读取本人状态，不按行或分块逐项请求。状态分为已收藏、未收藏、待确认及不可用；未知或失败不得默认为未收藏，同页同文档的多个入口 SHALL 保持一致。

#### Scenario: 搜索命中同文档多个分块
- **WHEN** 本页多个搜索结果来自同一文档
- **THEN** 状态批次中该文档只出现一次，收藏或取消成功后所有对应按钮显示一致状态
- **AND** 结果的原始排名、版本和分块身份保持不变

#### Scenario: 收藏状态暂不可读
- **WHEN** 文档或搜索已正常读取，但收藏状态查询失败
- **THEN** 相关收藏按钮禁用并提示状态待确认，提供主动重读入口，不将失败显示成未收藏
- **AND** 不把独立的收藏读取故障伪装成文档或搜索无结果

#### Scenario: 批量响应省略某个目标
- **WHEN** 当前合法批量响应未包含本页原先显示的一个文档
- **THEN** 页面将该文档视为当前不可访问，移除相关旧标题、片段和收藏入口，并关闭对应引用或预览
- **AND** 不把省略项补为 `favorited=false`，不展示目标是否存在或为什么失效

### Requirement: 收藏交互必须提交明确目标并核对不确定结果

按钮 SHALL 分别提交收藏或取消目标，同一文档在本页提交期间互斥。页面 MUST 以服务端成功结果更新状态；网络、超时或其他无法确认提交结果的失败 SHALL 提示结果待确认并允许只读核对，不自动重发或反转。核对结果只表示当前状态，不冒充原请求回执；未核对完成前保持写入禁用。

#### Scenario: 连续点击收藏
- **WHEN** 用户在同一文档的一次收藏请求尚未结束时再次点击
- **THEN** 本页只发送一次写请求，同文档其他入口也不能发起相反操作

#### Scenario: 写入响应丢失
- **WHEN** 收藏或取消提交后网络响应丢失
- **THEN** 页面保留待确认提示，不显示已确认成功或自动回滚为旧状态
- **AND** 用户可主动批量读取对应状态；仍无法确认时继续保留不确定状态

#### Scenario: 状态核对发现其他客户端的新操作
- **WHEN** 原写入结果不确定期间，另一客户端修改了同一收藏，随后核对返回当前状态
- **THEN** 页面展示查询所得当前状态，不声称已证明原写入成功或失败；后续相反操作须由用户重新明确发起

#### Scenario: 写入前文档被撤权
- **WHEN** 用户点击收藏后服务端返回目标不可访问
- **THEN** 页面移除该文档的旧内容和收藏入口，按既有身份门禁处理 401/403，不依靠旧状态继续提交

### Requirement: 我的收藏必须按服务器可见列表分页展示

“我的收藏” SHALL 展示当前可见文档标题、当前版本、密级、收藏时间及取消入口，按服务器固定收藏创建顺序和不透明游标继续加载。页面 MUST 区分加载、空集合、失败和末页，不展示全局收藏数或不可见文档占位；页内取消成功后移除该项，重新读取时以服务端事实为准。

#### Scenario: 没有当前可见收藏
- **WHEN** 列表成功返回空 items 且无后续页
- **THEN** 页面显示“暂无可查看的收藏”，不推断原先没有收藏或没有隐藏文档

#### Scenario: 首个版本尚未发布
- **WHEN** 收藏项 currentVersionId 和 currentVersionNo 为 null
- **THEN** 页面显示“尚未发布”，仍可进入文档详情，不伪造版本或可预览保证

#### Scenario: 继续加载与读取故障
- **WHEN** 用户点击继续加载，或者该次读取失败
- **THEN** 前者使用服务器返回的 nextCursor 并防止并发重复加载；后者提示失败并保留有效的重试入口，不伪造末页

### Requirement: 收藏跳转必须遵守文档与引用各自的版本身份

点击收藏项 SHALL 进入 `/documents/{documentId}`，由文档详情读取当前信息并执行独立预览、下载及版本操作检查。用户在搜索结果中收藏文档 MUST NOT 改写该搜索结果的原版本引用；收藏状态也不得被解释为 view、download 或 edit 的后续授权凭据。

#### Scenario: 收藏之后发布新版本
- **WHEN** 文档从 V1 更新到 V2 后用户打开收藏
- **THEN** 详情按当前文档信息显示 V2，仍通过实时能力与文件接口控制操作

#### Scenario: 收藏搜索中的旧版本材料
- **WHEN** 用户收藏一条引用 V1 的搜索结果，而文档当前已为 V2
- **THEN** 收藏目标为文档，原结果的引用点击仍使用 V1；“我的收藏”打开文档时采用当前详情规则

### Requirement: 收藏页面状态必须隔离身份和迟到请求

收藏状态与列表 SHALL 仅保留在当前会话和页面内存中，使用精确文档 ID。身份切换、退出、强制改密或页面离开 MUST 中止活动读取并拒绝旧结果；恢复页面时重新核对身份和当前资源。写入完成前发出的旧状态查询 MUST NOT 覆盖该写入之后已确认的状态，同页同文档状态须按请求代次处理。

#### Scenario: 用户切换时响应迟到
- **WHEN** A 的收藏列表或写入响应返回前，当前页面已切换到 B
- **THEN** A 的结果不能填充 B 的列表、状态或成功提示

#### Scenario: 收藏前的状态查询晚到
- **WHEN** 较早的批量查询包含未收藏状态，但其响应在收藏成功之后才到达
- **THEN** 该旧响应不能把已确认的按钮改回未收藏

#### Scenario: 大整数身份和安全展示
- **WHEN** 收藏项文档 ID 超出 JavaScript 安全整数范围，或标题含 HTML 标记
- **THEN** 后续请求保持整数身份精确，标题按安全文本展示，不执行 HTML，也不把收藏内容写入浏览器持久存储或遥测

#### Scenario: 从后台恢复时权限已改变
- **WHEN** 用户恢复“我的收藏”页面，而部分文档已被撤权或归档
- **THEN** 核对期间遮蔽旧内容，重新读取后只显示当前可见收藏；迟到旧页不能重新追加已失效内容

### Requirement: 审核私有内容不得进入普通版本摘要

文档中心及普通版本列表 SHALL 只消费当次授权投影，不展示待审意见或未经当前候选资格检查的新版文件资料。上传受理可使用返回的版本 ID 跟踪本人最小状态；没有 view 时仍不能读取正文、意见或文件。默认文件入口继续指向当前发布版本，不自动切到最高版本号。

#### Scenario: 版本号最高但尚未通过
- **WHEN** 当前已发布 V1 而 V2 为最高版本号且仍待审
- **THEN** 默认阅读与文件入口仍为 V1；只有明确选择且有资格时才打开 V2 的候选界面

### Requirement: 详情页删除必须明确作用于整份文档

用户端 SHALL 在 `/documents/{documentId}` 详情页提供单文档删除入口。确认前 MUST 重新读取当前详情及删除能力；仅两者就绪且 canDelete=true 时允许确认。确认界面 SHALL 以安全文本展示当前标题，说明删除影响整份文档及全部版本、取消未完成处理和审核、当前不支持恢复；不得枚举隐藏版本或声称原件已彻底擦除。此入口不提供单版本删除、批量删除或恢复。

#### Scenario: 选中历史版本后删除
- **WHEN** 用户选中 V1，而文档当前发布版本是 V2，随后打开删除确认
- **THEN** 界面明确操作对象是整份文档及全部版本，不显示“删除 V1”或仅影响当前选择的含义
- **AND** 确认后仅向该文档的 `DELETE /api/documents/{documentId}` 提交，不携带 versionId 或版本筛选

#### Scenario: 首个版本尚未发布
- **WHEN** 文档当前没有发布版本，但当前详情可读取且 canDelete=true
- **THEN** 用户仍能确认删除整份文档，不要求存在可预览、已发布或可重试的版本

#### Scenario: 确认前事实变化
- **WHEN** 用户打开确认后，重新读取显示无删除资格、文档不可访问或读取失败
- **THEN** 确认提交保持禁用，不使用打开弹窗前的资格或标题继续操作
- **AND** 只有重新取得合法当前事实才能重新确认

#### Scenario: 取消确认或没有业务提交
- **WHEN** 用户取消尚未提交的删除确认，或确认前读取未完成
- **THEN** 不发送 DELETE 请求，不修改文档状态

### Requirement: 删除提交必须防止本页重复和冲突操作

删除 SHALL 使用既有认证会话及精确文档 ID，提交无请求体的 `DELETE /api/documents/{documentId}`，不虚构幂等回执能力。进入删除确认后，本页 SHALL 阻止新发起的上传、重试、审核、评论及收藏写入；已在途的同页写入必须结束或进入明确的结果未确认提示后才能提交删除。删除请求在途时 MUST 防止重复提交，关闭预览并暂停本页相关轮询；暂停或取消浏览器请求不得宣称服务端操作已撤销。

#### Scenario: 连续点击确认
- **WHEN** 同一文档的删除请求尚在途，用户连续点击或重复触发表单提交
- **THEN** 本页只发出一次删除请求，重复事件不创建第二个请求

#### Scenario: 其他写入仍在途
- **WHEN** 本页已有上传、重试、审核、评论或收藏写入尚在等待结果
- **THEN** 删除确认不得提交，也不得通过卸载其界面将其当作已取消成功
- **AND** 已知结果未确认的写入须向用户提示可能已执行，再由用户明确确认整文档删除

#### Scenario: 确认期间发起其他操作
- **WHEN** 删除确认、提交或结果核对尚未结束，用户尝试启动本页其他文档写操作
- **THEN** 新操作被阻止，不形成两个相互独立的可提交窗口

#### Scenario: ID 超出 JavaScript 安全整数
- **WHEN** 文档 ID 为合法的长整型大整数
- **THEN** 删除与核对请求均使用精确原 ID，不经浮点转换或截断

### Requirement: 删除成功必须以明确响应为依据并清理页面资源

客户端 SHALL 仅在当前会话、目标与请求仍有效且取得既有删除接口合法成功响应后显示删除成功。成功后 MUST 停止该详情页的轮询、文件读取及其他关联请求，释放预览临时资源，清理版本、审核、评论、收藏等本页旧状态，并返回重新读取的文档中心。成功提示 SHALL 只在当前会话内短暂显示，不将标题或删除状态保存到持久存储；不得以列表读取失败推翻已确认的删除成功。

#### Scenario: 明确成功后返回列表
- **WHEN** DELETE 返回合法成功响应
- **THEN** 详情页退出且文档中心重新请求当前可见列表，展示一次当前会话的删除成功提示
- **AND** 已打开的预览被关闭并释放，迟到的旧详情或版本响应不能恢复已退出的内容

#### Scenario: 删除成功但列表读取失败
- **WHEN** 删除已获确认，而返回文档中心后的列表查询失败
- **THEN** 页面保留已确认的删除结果，同时单独显示列表加载失败和重读入口
- **AND** 不因此重发 DELETE 或声称文档未删除

### Requirement: 删除结果未确认时必须只读核对当前事实

删除已发出后遇到网络中断、超时、无法可靠解析成功响应或可能发生在提交之后的服务错误，客户端 SHALL 标记结果未确认，提供用户主动触发的只读核对与返回列表入口，MUST NOT 自动重发 DELETE。核对 SHALL 重新读取当前详情与能力；404 仅表示当前不可访问，200 仅表示查询时仍可访问，均不得冒充原请求回执。核对失败保持未确认；再次删除必须取得新的有效事实并经过用户重新明确确认。

#### Scenario: 响应丢失而核对返回 404
- **WHEN** 删除响应丢失，后续详情或能力核对返回 404
- **THEN** 清除本页旧标题、版本、正文和文件入口，显示文档当前不可访问
- **AND** 不显示删除成功，不解释其原因是删除、归档或撤权

#### Scenario: 核对时文档仍可访问
- **WHEN** 结果未确认后的详情与能力查询成功，canDelete 仍为 true
- **THEN** 显示当前仍可访问且原删除结果未确认，不宣称原请求失败或回滚
- **AND** 重新删除须再次展示整文档影响并由用户确认，不自动重新提交；旧请求可能仍在服务端执行

#### Scenario: 仍可查看但不能再删除
- **WHEN** 核对成功且 canDelete=false
- **THEN** 保留当前可查看资料和未确认提示，禁止新的删除提交

#### Scenario: 核对再次失败
- **WHEN** 只读核对遇到网络或服务故障
- **THEN** 保持结果未确认及删除禁用，允许用户再次主动核对或返回列表，不启动无界轮询

### Requirement: 删除拒绝必须遵守当前身份与资源边界

明确拒绝删除时，客户端 SHALL 保留真实拒绝事实，按既有会话规则处理 401 和 403；资源 404 MUST 使用目标不存在或当前不可访问的统一表现，不作为成功。仍保持有效身份时 SHALL 重新核对详情与能力；重新读取前不得继续以旧 canDelete 提交，目标不可访问时清除其旧内容。

#### Scenario: 点击前 edit 被撤销
- **WHEN** 确认时拥有 canDelete=true，但 DELETE 随后因当前授权被拒绝
- **THEN** 页面展示拒绝并重新核对当前事实；新能力为 false 时删除保持禁用

#### Scenario: 删除请求直接返回 404
- **WHEN** DELETE 本身返回 404
- **THEN** 界面显示目标不存在或当前不可访问并清理旧内容，不显示删除成功

#### Scenario: 登录失效或必须改密
- **WHEN** 删除期间会话失效、主体停用或进入强制改密状态
- **THEN** 页面遵守既有身份门禁，停止保护请求，不把原会话的操作结果显示给后续身份

### Requirement: 删除交互必须隔离会话文档和请求代次

确认、提交、核对和成功提示 SHALL 绑定当前会话及文档。退出、身份变化、切换文档、页面隐藏或离开详情时 MUST 清理私有界面、停止本地活动请求并使旧回调失效；恢复时重新核对身份及当前资源，不自动恢复确认或重发删除。取消本地等待不证明服务端未执行，历史响应不得触发新页面跳转或把旧删除结果转为当前成功。

#### Scenario: 文档切换后删除响应迟到
- **WHEN** A 文档的删除尚未返回，用户已经进入 B 文档
- **THEN** A 的旧响应不能关闭 B、清除 B 的资料、显示 B 已删除或把页面带回列表

#### Scenario: 页面隐藏后恢复
- **WHEN** 删除确认或请求等待期间页面隐藏，随后用户恢复页面
- **THEN** 原确认界面失效，恢复先核对身份及资源，不重复发送删除或以读取结果重建成功提示

#### Scenario: 删除前读取在删除后返回
- **WHEN** 删除前发起的详情、能力、审核或评论读取在删除提交后才返回
- **THEN** 旧结果不能重新启用操作、覆盖核对结果或恢复已清理的私有内容

### Requirement: 文档详情必须提供文档级资料展示和编辑

详情 SHALL 展示当前标题、人工摘要、分类路径及标签启停标记，编辑时重新读取完整元数据与独立版本，提交标题、摘要、单分类或未分类及至多 20 个标签。界面 MUST 明确这是整文档即时生效的资料，不随当前选择的文件版本切换，也不因启用文件审核显示待审成功。正文、摘要和名称均按安全文本展示。

#### Scenario: 从历史版本打开编辑
- **WHEN** 用户选中历史文件版本后打开“编辑资料”
- **THEN** 表单显示整文档当前元数据和 metadataVersion，不将修改目标表述为仅该历史版本

#### Scenario: 需审空间保存资料
- **WHEN** 元数据保存成功而文件版本仍待审
- **THEN** 页面提示资料已更新并重新读取详情，仍按服务器事实展示文件审核状态

### Requirement: 元数据编辑必须正确处理冲突和不确定回执

提交 SHALL 绑定完整规范化资料、expectedMetadataVersion 及请求标识，防止重复点击。409 应提示资料或目录已变化，允许重新读取及人工重新编辑，不自动覆盖新值；响应不确定时保留原意图供匹配重试或只读核对。成功回执后重新读取当前资料，读取失败不得改报保存失败，回执版本不作为当前资料快照。

#### Scenario: 搬迁使表单过期
- **WHEN** 用户编辑期间文档被搬迁，保存返回版本或分类冲突
- **THEN** 页面重新核对当前空间、资料及候选，旧分类不能直接用于新空间重试

#### Scenario: 回执成功而详情暂不可读
- **WHEN** 服务端确认保存成功，但随后重新读取失败
- **THEN** 保留已确认保存提示并单独呈现读取失败，不重复提交原保存

### Requirement: 元数据写入必须参与详情页操作协调

元数据提交 SHALL 与既有详情页删除协调共用在途和结果未确认事实。删除确认期间阻止新的元数据保存，已在途保存未结束时禁止确认删除；已知未确认保存应作为删除前的明确提示。删除成功、切换文档、身份变化、页面隐藏或离开清除编辑草稿、候选和旧回调，恢复不自动保存。

#### Scenario: 保存仍在途时删除
- **WHEN** 元数据保存尚未结束，用户打开整文档删除确认
- **THEN** 删除不能提交，不能通过关闭编辑弹窗把保存当作已撤销

#### Scenario: 离开文档后保存响应迟到
- **WHEN** A 文档保存响应到达时页面已进入 B 文档
- **THEN** 不更新 B 的资料、版本、候选或成功提示，不触发旧页面跳转

### Requirement: 组合筛选必须区分草稿和已提交条件

页面 SHALL 提供标题关键词、空间、分类及未分类、全局标签、文件类型和更新时间范围。多个标签明确显示“全部匹配”，父分类明确包含后代。条件只在用户提交后生效并回到首页，分页使用已提交条件；修改草稿不得悄悄改变续页请求。筛选通过请求体发送，不写入地址栏或持久存储，迟到响应不能覆盖新查询。

#### Scenario: 修改筛选草稿后翻页
- **WHEN** 用户修改标签草稿但尚未提交，随后翻页
- **THEN** 翻页仍使用上次已提交条件，提交新条件才清空旧结果并回到首页

#### Scenario: 同时选中两个标签
- **WHEN** 用户提交“项目 A”和“制度”
- **THEN** 页面提交两个稳定 tagId 并提示全部匹配，不在客户端以任一标签过滤或重排服务端结果

### Requirement: 分类和标签候选必须遵守用途与失效规则

文档编辑 SHALL 读取该文档的编辑候选，文档中心筛选 SHALL 读取授权筛选候选，均支持有界续页。选择分类前使用明确空间上下文，切换空间清除旧分类及旧候选。未分类是独立选项；停用标签在已有资料中可保留或移除，不能作为新增选择。候选读取失败不得构造手填 ID 或静默清空已有字段。

#### Scenario: 切换筛选空间
- **WHEN** 用户已选 A 的分类，随后把空间改为 B
- **THEN** 清除 A 的分类选择并加载 B 的候选，A 的迟到响应不进入 B 的选择器

#### Scenario: 当前资料带停用标签
- **WHEN** 编辑表单载入的文档含停用标签，而新候选只包含启用项
- **THEN** 表单仍显示该既有关联和停用标记，用户可保留或移除，不因候选省略而自动删掉
