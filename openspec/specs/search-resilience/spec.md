# search-resilience Specification

## Purpose

为授权检索建立可配置的时间、输入输出和实际执行容量边界，使浏览器搜索与 AI 召回在依赖变慢、响应损坏或并发过载时能够可靠降级或明确失败，同时保留当前权限、版本和向量身份约束，并提供可核对的故障观测。

## Requirements

### Requirement: 检索输入必须在执行前有界校验

检索 SHALL 接受非空白、合法 Unicode 且不含 NUL 的 query，默认上限为 8000 个 Unicode code point；超限或非法返回 400，不静默截断。请求体默认上限为 128 KiB，超限返回 413，实际读取字节必须受限，不仅信任 Content-Length。candidates 和 topK 各为 1–200，省略或 null 时默认 candidates=50、topK=candidates；topK 大于 candidates 时保持按实际候选截取的兼容行为。可选组合条件 MUST 遵守 search-filtering 的字段类型、数量和交叉校验规则，未知或重复字段及尾随 JSON 返回 400。被拒输入 MUST 不调用模型或执行召回。

#### Scenario: 查询达到边界
- **WHEN** 查询含 8000 个合法 code point，且请求体和数量参数均合法
- **THEN** 长度校验通过，补充字符不被按两个字符计算

#### Scenario: 超长或损坏字符
- **WHEN** 查询超过上限、包含 NUL 或孤立代理项
- **THEN** 返回 400，不调用 Embedding、rerank 或数据库召回，不回显查询内容

#### Scenario: 请求未声明长度
- **WHEN** 无 Content-Length 的请求实际正文超过 128 KiB
- **THEN** 在越过限界时返回 413，不先把无界正文全部载入内存

#### Scenario: 合法的独立数量参数
- **WHEN** candidates=20 且 topK=50
- **THEN** 请求合法，最终返回数量不超过实际取得的 20 个候选，不因新限制改成 400

#### Scenario: 无筛选且数量显式为空
- **WHEN** 请求有合法 query，candidates 或 topK 显式为 null
- **THEN** 沿用对应缺省值，不因新增筛选校验拒绝原本合法的无筛选请求

#### Scenario: 筛选输入无效
- **WHEN** 请求包含重复标签、冲突分类、反向时间、非法筛选类型、未知或重复字段
- **THEN** 返回 400，不通过忽略条件或强制类型转换执行部分搜索

### Requirement: 一次搜索必须共享绝对截止时间

合法请求通过已有会话与强制改密门禁、开始搜索处理时 SHALL 建立单调时钟截止时间，默认总预算 8 秒，覆盖权限解析、连接与锁等待、控制事实、词典读取与一致性核验、匹配与查询扩展、Embedding、分类关系与全部筛选计算、召回、重排及结果准备。各阶段 MUST 使用剩余总预算，不重置计时；默认预留 500 毫秒用于结果准备和响应交付。截止后不得接受迟到成功或启动下一阶段，应向应用响应链路交付明确失败；网络向客户端实际送达时间不计入该执行预算。搜索候选请求独立取得同样的总预算，包含其授权、目录读取和响应准备。

#### Scenario: 前置阶段耗时
- **WHEN** 权限解析与控制读取已经消耗部分总预算
- **THEN** 后续阶段只使用剩余时间，不再获得新的 8 秒

#### Scenario: 总预算耗尽
- **WHEN** 截止时间到达且没有可交付的合法结果
- **THEN** 搜索以 503 结束等待，取消在途工作，不把迟到结果改写为成功

#### Scenario: 没有可见范围
- **WHEN** 当前权限已可靠解析为无可见范围
- **THEN** 文档命中为空，不调用外部模型，不披露是否存在不可见文档；ASSISTED 仍按公开词典契约取得或核验辅助信息，其读取失败不能伪装成功空建议

#### Scenario: 分类和标签筛选耗时
- **WHEN** 分类后代或标签关联计算消耗召回剩余预算
- **THEN** 后续召回及响应使用原截止，不另开无预算的文档 ID 预查询或重置阶段计时

#### Scenario: 候选目录读取超时
- **WHEN** 已通过准入的搜索候选请求在权限、目录读取或响应准备期间超时
- **THEN** 按既有 503 与实际工作退出规则收尾，不以空目录表示成功，也不因响应结束提前释放在途容量

#### Scenario: 词典查询接近总截止
- **WHEN** 词典核验和匹配消耗部分预算，剩余时间不足以执行向量阶段
- **THEN** 按原阶段预算规则跳过向量，仍使用一致查询计划完成受限 BM25；总预算不足时明确失败，不另给词典或召回一个新时限

### Requirement: 阶段预算必须为必要召回保留时间

查询 Embedding、数据库召回和 rerank SHALL 分别使用默认 2 秒、3 秒和 1.5 秒的阶段上限，并进一步受总剩余预算约束。进入 Embedding 前 MUST 为数据库召回及响应预留时间；预算不足时直接跳过向量生成。进入重排前没有可用阶段预算时 SHALL 返回已有授权候选。阶段上限覆盖对应调用的连接、等待、响应读取和解析；本地实现也受同一截止时间约束。

#### Scenario: Embedding 时间不足
- **WHEN** 前置工作结束后剩余预算只够必要召回与响应准备
- **THEN** 跳过 Embedding，执行受权限约束的 BM25，记录预算降级

#### Scenario: 重排预算不足
- **WHEN** 授权候选已经取得，但剩余时间不足以执行 rerank
- **THEN** 按重排前顺序截取 topK，不等待重排、不重新检索

#### Scenario: 外部调用持续分段响应
- **WHEN** 远程服务不断发送小块响应，始终没有完成一个合法结果
- **THEN** 整个阶段仍受绝对截止时间约束，不能通过持续字节到达无限续期

### Requirement: 搜索并发必须按实例及可信用户双重约束

app SHALL 对所有搜索调用统一实施实例级准入，默认每实例最多 8 个实际在途请求、每个可信内部用户在该实例最多 2 个，无等待队列。用户已达上限返回 429，其他实例容量不足返回 503；两者均带正整数秒 Retry-After，默认 1。两种计数 MUST 原子取得或整体回滚；身份取自已验证会话，多令牌不能绕过同一用户限制。此限制不宣称跨实例统一额度。

#### Scenario: 浏览器与 AI 同时检索
- **WHEN** 同一用户通过浏览器及 AI 直调同一 app 实例
- **THEN** 两条路径共享该用户和实例的并发计数

#### Scenario: 同一用户已占满
- **WHEN** 用户已有两个实际在途请求，再提交第三个请求
- **THEN** 立即返回 429 和 Retry-After，不排队、不调用外部服务或召回

#### Scenario: 实例已占满
- **WHEN** 实例已有八个实际在途请求，未达到本人上限的用户发起搜索
- **THEN** 立即返回 503 和 Retry-After，不产生第九个后台请求

#### Scenario: 双重拒绝和部分领取
- **WHEN** 用户和实例都达到上限，或准入只能取得其中一个名额
- **THEN** 前者按用户限制返回 429，后者不残留单侧占用，不产生待执行队列

### Requirement: 响应结束不得提前释放实际执行容量

搜索超时或取消 SHALL 停止新阶段、取消在途调用并丢弃迟到结果。一个请求占用的实例和用户名额 MUST 保留到其全部实际执行工作退出；响应已发出、取消已请求或句柄显示完成不能代替真实退出。相关执行线程、外部调用和取消调度 MUST 有固定容量，不以新增无界线程或队列绕过限制。重复结束和退出回调只能释放一次。

#### Scenario: 上游忽略取消
- **WHEN** 搜索已经超时返回，但远程调用仍未实际退出
- **THEN** 原请求仍计入实例和用户占用，新请求受到剩余容量限制；迟到返回不会恢复原响应

#### Scenario: 可选阶段超时后成功降级
- **WHEN** Embedding 已超时，BM25 成功返回，而旧 Embedding 工作仍在退出中
- **THEN** 可以交付合法 BM25 结果，但原请求名额持续保留至旧工作退出

#### Scenario: 多个结束信号竞争
- **WHEN** 总超时、客户端取消与工作完成同时到达
- **THEN** 只选择一个响应终态，并在全部工作退出后恰好释放一次容量

### Requirement: 可选阶段降级必须保留授权和向量身份

合法配置下 Embedding 超时、限流、服务或响应错误，以及维护或实例缺少当前 profile 时 SHALL 降级为 BM25。实际向量比较前 MUST 复核当前 profile 与 epoch。rerank 超时、容量不足、服务或协议错误 SHALL 回退本次重排前授权候选的原顺序。降级不得更换主体、放宽 ACL/密级/发布/归档/版本约束或任何已提交组合筛选条件、使用旧答案或跨请求结果缓存；一次请求不自动重试远程模型或重新执行召回。

#### Scenario: Embedding 返回期间开始重建
- **WHEN** 查询向量生成后，实际检索前 profile、epoch 或维护状态已经变化
- **THEN** 当前请求执行受相同权限及组合筛选约束的 BM25，不用旧向量比较新 profile 数据

#### Scenario: 重排上游限流
- **WHEN** rerank 返回 429 而本次授权候选已经取得
- **THEN** 返回满足全部筛选的原候选 topK，记录降级，不把供应商限流冒充调用用户并发超限

#### Scenario: 控制或权限事实读取失败
- **WHEN** 当前权限、控制状态或数据库召回无法可靠完成
- **THEN** 明确失败，不凭旧事实或无权限条件再次检索

#### Scenario: 组合条件无命中
- **WHEN** 已提交空间、分类、标签、类型或时间的交集没有任何合法命中
- **THEN** 正常返回空结果，不减少条件或改用全局候选来填满 topK

### Requirement: 远程重排结果必须完整验证后使用

非空候选的重排响应 SHALL 提供恰好 min(topK, actualCandidates) 项有效结果。每项 index MUST 为精确整数、在本次候选范围内且不重复，relevance_score MUST 为有限数值；不得截断小数或溢出值、补零分或跳过坏项后接受部分响应。任何一项或结构无效都使本批整体回退。合法结果按分数降序、同分按原候选位置排序，返回正文和引用身份仅取自对应原候选。

#### Scenario: 小数和重复下标
- **WHEN** 响应包含小数、越界、溢出或重复 index
- **THEN** 整批回退原排序，不返回重复分块或错误匹配正文

#### Scenario: 缺项或非法分数
- **WHEN** 结果条数不符、缺少分数，或分数为 NaN、Infinity 或非数值
- **THEN** 整批回退，不把响应解释成零命中

#### Scenario: 相同分数与伪造正文
- **WHEN** 两个合法结果同分，且远程响应额外提供正文或来源字段
- **THEN** 同分按原候选位置稳定排列，正文、版本和来源仍使用本次原候选

### Requirement: 检索相关载荷必须在解析和发送前受限

查询 Embedding 响应默认最多 1 MiB，rerank 响应默认最多 256 KiB，rerank 出站 JSON 默认最多 2 MiB，搜索成功响应及 AI 接收检索响应默认最多 4 MiB。限界 MUST 覆盖实际编码或解码字节、无长度头的流及解析过程；超过可选阶段限界时整体降级，合法召回结果无法在响应上限内交付时明确失败，不静默裁剪正文或来源。外部错误体不得无界读取或进入日志。

#### Scenario: 重排请求材料过大
- **WHEN** 本次候选编码后的重排请求超过限界
- **THEN** 跳过远程重排并返回原候选顺序，不截断原分块冒充完整材料

#### Scenario: 无长度头的远程大响应
- **WHEN** 上游未声明 Content-Length 且实际响应超过限界
- **THEN** 停止读取并释放响应资源，不先完整反序列化再检查大小

#### Scenario: 搜索结果无法有界交付
- **WHEN** 授权召回结果编码后超过搜索响应上限
- **THEN** 返回明确不可用错误，不用不完整 JSON、部分正文或空列表表示成功

### Requirement: 检索失败必须具有稳定且安全的信号

搜索 SHALL 保留各入口规定的成功响应结构；非法输入返回 400、正文超限返回 413、用户并发超限返回 429、实例满载或可识别的依赖/预算不可用返回 503。增强入口另以 400 与固定类别 ASSISTANCE_LIMIT_EXCEEDED 表示辅助规模超限，以 409 与 ASSISTANCE_STALE 表示已验证建议的修订变化或到期。401/403 继续表达已有认证与资格门禁，未知内部错误保留 500。AI 的检索故障 SHALL 通过既有 error 事件附加固定 code=SEARCH_UNAVAILABLE，页面映射为“检索暂不可用，请稍后重试”，不展示远程错误体或推断文档存在性。

#### Scenario: 可选阶段失败但成功返回候选
- **WHEN** Embedding 或 rerank 发生允许的降级且有合法结果
- **THEN** 搜索仍返回成功结果，降级事实通过受控观测呈现，不误报整体不可用

#### Scenario: AI 检索故障到达页面
- **WHEN** 单轮或多轮已建立流，而本轮检索失败
- **THEN** 发送安全 error 事件及 SEARCH_UNAVAILABLE，页面显示固定检索不可用提示，随后按既有规则核对轮次

#### Scenario: 未知错误码
- **WHEN** 前端收到旧服务没有 code 的 error，或未知 code
- **THEN** 使用现有通用错误提示并核对状态，不回显未经白名单映射的 message

#### Scenario: 区分过期和伪造
- **WHEN** 可验证上下文已过期，或上下文损坏、身份和条件绑定不匹配
- **THEN** 前者返回 409 ASSISTANCE_STALE，后者返回 400，不把任意非法输入都当成可自动刷新的版本冲突

### Requirement: AI 检索参数与等待预算必须独立合法

AI SHALL 使用独立检索等待预算，默认 10 秒，覆盖请求到合法响应解析完成，不复用模型生成超时。配置的 topK MUST 为 1–200；候选数为 min(200, max(50, 4 × topK))，计算不得溢出。AI MUST 不自动重试检索；超时和取消停止读取，合法空集合之外的错误不得被折叠为空结果。

#### Scenario: 较大的合法 topK
- **WHEN** AI topK=100
- **THEN** 发送 candidates=200、topK=100，参数不会被搜索接口因超过上限拒绝

#### Scenario: 非法数量配置
- **WHEN** AI topK 小于 1 或大于 200
- **THEN** 配置校验失败，不启动一个会持续发出非法搜索请求的实例

#### Scenario: 模型生成预算较长
- **WHEN** 模型生成超时配置为 60 秒
- **THEN** 检索仍使用独立 10 秒预算，不因模型配置延长搜索等待

### Requirement: 降级和容量占用必须可观测且不泄露查询

系统 SHALL 提供检索结果类别、固定阶段耗时、降级原因、准入拒绝、实际在途和响应结束后仍执行的低基数指标，并使其可经业务应用的指标导出端点被监控系统抓取；阶段耗时直方图 MUST 按既有阶段与总预算显式分桶。AI 检索客户端 SHALL 以固定类别记录检索失败原因，区分拒绝、超时、依赖故障与协议损坏。日志与指标 MUST 不包含查询、正文、令牌、完整远程异常或按用户/请求/profile 任意身份扩张的标签。配置项须校验正值、容量关系、阶段与总预算及响应预留关系，非法值不得静默回落默认值。

#### Scenario: 成功降级与整体失败
- **WHEN** 一次请求成功降级为 BM25，另一次因数据库超时失败
- **THEN** 运维可区分阶段降级和整体失败，不将两者都记录为零命中

#### Scenario: 取消后仍执行
- **WHEN** 请求已返回而其底层工作尚未退出
- **THEN** 实际在途及结束后仍执行指标保持占用，实际退出后下降

#### Scenario: 非法预算或容量配置
- **WHEN** 总预算不大于响应预留、阶段上限超过可执行总预算，或用户上限超过实例上限
- **THEN** 配置校验失败并只报告配置项，不静默调小或输出敏感配置值

#### Scenario: 导出端点抓取
- **WHEN** 监控系统抓取业务应用的指标端点
- **THEN** 取得上述检索指标，阶段耗时直方图包含 2 秒、3 秒、1.5 秒与 8 秒的边界桶

#### Scenario: AI 检索失败分类
- **WHEN** AI 检索因超时、拒绝、依赖故障或协议损坏失败
- **THEN** 失败原因以固定类别计数，不含问题文本或远程错误体

### Requirement: 查询 Embedding 与 rerank 出站调用不得携带内部追踪上下文

查询 Embedding 与 rerank 的远程调用 MUST NOT 携带追踪传播头或 baggage，也 MUST NOT 携带调用用户的会话令牌；该约束对预算路径与默认客户端路径同等成立。供应商响应中的追踪头 MUST NOT 改写本地追踪上下文。

#### Scenario: 远程调用请求头
- **WHEN** 搜索触发远程 Embedding 或 rerank 调用
- **THEN** 请求仅含服务端配置的认证头与请求体，不含 `traceparent`、`tracestate`、baggage 或 satoken

#### Scenario: 两条调用路径一致
- **WHEN** 同一 profile 分别经预算路径与默认客户端路径发起调用
- **THEN** 两条路径的请求头规则一致，均不携带追踪上下文

### Requirement: 增强工作必须共享原搜索准入与退出边界

原搜索、ASSISTED、ORIGINAL 和搜索候选 SHALL 共享既有实例与可信用户准入、无等待队列及实际工作退出后释放规则。词典读取和匹配也计入占用，不因词典处理在召回前执行而绕过容量。取消或超时须停止新阶段、取消在途工作并隔离迟到结果，仍在执行的词典工作占用原名额，不创建无界线程、请求或队列。

#### Scenario: 多入口占满同一用户名额
- **WHEN** 同一用户已有普通搜索和增强请求占满默认两个实际在途名额
- **THEN** 再次提交 ORIGINAL 或建议采用返回 429 与 Retry-After，不作为另一类免费容量放行

#### Scenario: 词典读取未退出
- **WHEN** 请求已超时响应但词典底层读取仍未退出
- **THEN** 原用户名额与实例名额继续占用，迟到读取不能恢复原结果或提前释放容量

### Requirement: 匹配与扩展必须在召回前完整检查规模

ASSISTED 默认最多处理 8 个不重叠匹配位置，每个歧义位置最多 8 个组候选，累计选择最多 8 项，自动扩展新增表达最多 32 个、其文本与包装合计最多 2048 个 code point。各阶段最终查询表达还须满足原查询字符上限。任一超限 SHALL 在模型调用与召回前返回 ASSISTANCE_LIMIT_EXCEEDED，不截断候选伪装唯一、不部分采用选择或悄悄丢弃原文；ORIGINAL 不受词典匹配数量影响。

#### Scenario: 一个简称有过多含义
- **WHEN** 同一匹配位置存在 9 个启用组
- **THEN** 返回辅助规模超限，不只取前 8 项后对外声称候选完整或自动选定一项

#### Scenario: 合法长查询扩展后过长
- **WHEN** 原 query 未超限，但加入全部应采用表达后超出最终查询上限
- **THEN** 在首次 Embedding 和召回前拒绝辅助执行，用户可明确以相同完整原文选择 ORIGINAL

#### Scenario: 多个选择中一项非法
- **WHEN** 累计选择中的一个目标不属于对应片段
- **THEN** 整个请求按非法输入拒绝，不先搜索其他合法选择

### Requirement: 词典读取失败不得隐式变成原词成功

ASSISTED 中词典修订、关系或建议核验无法可靠取得时 SHALL 返回安全 503，不使用未核验旧快照、成功空词典或自动 ORIGINAL 代替。已成功核验的零匹配与真正空词典可以正常搜索；ORIGINAL 和旧入口须不依赖词典。查询相关的有限工作预算须覆盖匹配与结果准备，不靠每次加载完整无界词典证明限界。

#### Scenario: 空词典与读取失败
- **WHEN** 首次空词典可靠返回 revision=0，或读取发生超时
- **THEN** 前者以空扩展完成合法搜索，后者返回 503，两种情况不混淆

#### Scenario: 词典坏而原检索可用
- **WHEN** 用户主动使用 ORIGINAL 或旧接口且其必要依赖正常
- **THEN** 正常执行原检索，不额外要求词典健康，也不发送辅助成功说明

### Requirement: 增强响应与外部载荷必须共同受限

结果和全部辅助字段 SHALL 共同纳入既有默认 4 MiB 搜索成功响应上限，在完整编码和交付前核对。不得先发送成功命中再拼接未核验说明，超限时明确失败；辅助字段也不得单独截断成合法空建议。传往 Embedding 与 rerank 的编码载荷继续遵守原限额、超时、取消和降级规则，采用建议不会获得新的外部调用重试额度。

#### Scenario: 结果加建议超过响应限额
- **WHEN** hits 单独未超限但完整响应超过上限
- **THEN** 返回明确不可用错误，不交付不完整 JSON 或省略建议后冒充完整辅助结果

#### Scenario: 重排请求超限
- **WHEN** 已授权材料与本次有效表达使重排载荷超限
- **THEN** 按既有规则回退原授权候选顺序，不删除筛选或重发另一组查询

### Requirement: 辅助状态观测必须使用有限类别

系统 SHALL 在现有搜索观测中区分 ORIGINAL、ASSISTED、成功无词条、成功有扩展或建议、辅助超限、建议失效和词典不可用，并观测词典阶段耗时及实际执行占用。标签只能采用固定模式、阶段和原因，不含 query、词条名称或 ID、dictionaryRevision、selectionContext、用户或任意查询派生值。不得以建议生成数作为搜索成功或真实质量提升证明。

#### Scenario: 辅助失败与正常零匹配
- **WHEN** 一个请求未匹配任何词条，另一个因词典不可用失败
- **THEN** 运维可以按固定类别区分，不把两者都记为无建议成功

#### Scenario: 多次维护和查询
- **WHEN** 词典修订持续增加且用户提交不同查询
- **THEN** 不因词条、修订和查询值增长而产生任意基数标签，不输出输入内容
