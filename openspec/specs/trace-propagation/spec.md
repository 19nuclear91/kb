# trace-propagation Specification

## Purpose

为跨部署单元的请求与任务执行建立统一追踪上下文契约：在网关边界生成、在内部调用间传播、对外部供应商隔离，并保证日志与遥测输出不泄露敏感内容。

## Requirements

### Requirement: 追踪上下文必须在网关入口生成且不信任入站头部

系统 SHALL 在合法请求进入受控网关时生成新的追踪上下文，并以 W3C 形式在内部调用间传播。客户端提供的 `traceparent`、`tracestate` 与 baggage MUST 被忽略或剥离，MUST NOT 成为服务端上下文的来源，也 MUST NOT 成为拒绝请求的理由；对外响应 MUST NOT 返回追踪标识。

#### Scenario: 客户端自带追踪头

- **WHEN** 入站请求携带自造的 `traceparent` 或 `tracestate`
- **THEN** 系统按自身生成的新上下文处理该请求，不采用客户端标识，也不因该头部拒绝请求

#### Scenario: 认证拒绝路径

- **WHEN** 未认证请求在网关被拒绝
- **THEN** 该拒绝同样处于本次新生成的上下文中，其日志可用同一标识关联
- **AND** 响应体与响应头不包含追踪标识

#### Scenario: 浏览器可见响应

- **WHEN** 任意合法或拒绝响应返回浏览器
- **THEN** 响应头与 CORS 暴露清单中不含任何追踪标识

### Requirement: 内部调用必须沿用同一追踪上下文

网关到业务应用、网关到 AI、AI 到业务应用以及业务应用到 AI 的内部 HTTP 调用 SHALL 携带并沿用同一追踪上下文，跨单元后 trace 标识不变。该头部 MUST NOT 参与内部服务签名校验，MUST NOT 被当作身份、授权或幂等来源。

#### Scenario: 请求跨单元

- **WHEN** 浏览器经网关发起一次受控请求并由业务应用处理
- **THEN** 网关与业务应用记录该请求时使用同一 trace 标识

#### Scenario: 多轮生成期间

- **WHEN** 一次多轮生成触发 AI 到业务应用的内部会话调用
- **THEN** 该轮生成期间的全部内部调用共享同一 trace 标识

#### Scenario: 内部协议校验

- **WHEN** 内部调用按既有签名协议校验
- **THEN** 新增追踪头部不改变签名结果，也不被解释为可信身份

### Requirement: 对外部目标调用不得携带追踪上下文

系统 MUST NOT 向本系统之外的任何 HTTP 目标发送追踪传播头或 baggage，包括模型、embedding、rerank、第三方解析与 SSO 供应商。该约束 MUST 对复用默认客户端构建方式与使用专用隔离客户端的调用同等成立。

#### Scenario: 供应商请求头

- **WHEN** 系统调用模型、embedding、rerank 或第三方解析服务
- **THEN** 请求中不含 `traceparent`、`tracestate` 或 baggage 字段

#### Scenario: 供应商返回追踪头

- **WHEN** 供应商响应中包含追踪相关头部
- **THEN** 系统不采用其值改写本地追踪上下文

### Requirement: 日志必须携带追踪标识且不记录敏感内容

各部署单元的日志 SHALL 在存在追踪上下文时输出 trace 与 span 标识；请求携带 `X-Request-Id` 时 SHALL 额外输出该标识并保持二者语义独立——匹配重放复用 `X-Request-Id` 但产生新的 trace。日志与追踪属性 MUST NOT 包含查询、正文、令牌、授权码或 state、请求头值及 URI 查询串。

#### Scenario: 单次请求关联

- **WHEN** 一次受控请求经过网关与业务应用
- **THEN** 各单元日志可用同一 trace 标识关联

#### Scenario: 匹配重放

- **WHEN** 客户端以相同 `X-Request-Id` 重放一次写入
- **THEN** 日志中该标识与首次一致，而 trace 标识为新的

#### Scenario: 敏感内容不入日志与属性

- **WHEN** 请求包含查询文本、检索词、会话令牌或 SSO 回调的授权码与 state
- **THEN** 这些值不出现在日志与追踪属性中，日志只保留固定阶段与安全类别

### Requirement: 异步任务执行必须具有独立可关联的追踪

Worker 每次任务执行 SHALL 开启一条以该次执行为根的追踪上下文，覆盖第三方解析调用、向量生成与索引发布，并出现在该次执行的全部日志中，即使执行发生在与调度线程不同的工作线程。系统 MUST NOT 通过任务表字段或其他方式暗示该上下文与原始上传请求同属一条 trace。

#### Scenario: 解析执行日志

- **WHEN** 一次解析任务开始执行
- **THEN** 该次执行的全部日志共享同一 trace 标识
- **AND** 原有任务与版本标识继续按原样记录

#### Scenario: 任务重试

- **WHEN** 同一任务因失败被重新领取并执行
- **THEN** 每次执行使用各自独立的 trace 标识

#### Scenario: 未接入第三方解析

- **WHEN** 解析接入不可用而任务保持排队
- **THEN** 不产生该次执行的解析追踪，也不记录为成功执行

### Requirement: 追踪必须显式启用且非法配置拒绝启动

追踪 SHALL 默认关闭：不生成上下文、不注入头部、不导出跨度。显式启用时 MUST 要求导出目标地址、采样率大于 0 且不超过 1，并要求 baggage 传播关闭；配置缺失、越界或类型错误 MUST 在建立业务连接前以固定安全错误拒绝启动，不回显目标地址或凭据。

#### Scenario: 默认关闭

- **WHEN** 未配置追踪
- **THEN** 系统不产生跨度、不注入传播头，也不因缺少导出目标而拒绝启动

#### Scenario: 启用但配置不完整

- **WHEN** 追踪已启用但缺少导出目标地址，或采样率越界、baggage 开启
- **THEN** 启动以不包含地址与凭据的固定错误拒绝

#### Scenario: 关闭追踪不影响指标导出

- **WHEN** 追踪保持关闭而指标导出已启用
- **THEN** 指标端点与既有业务行为不受影响
