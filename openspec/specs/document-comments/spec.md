# document-comments Specification

## Purpose

为知识库已发布版本提供轻量、可追踪的公开讨论，保持评论与原文版本身份一致，并通过当前查看和独立评论资格限制访问与写入；将私有审核意见、删除后的正文和模型知识来源隔离，避免讨论成为权限或发布旁路。

## Requirements

### Requirement: 评论必须绑定有发布证据的固定版本

评论及回复 SHALL 绑定完整 documentId、versionId，不复制到新版本、不按 chunkIdx 重定位。仅具备实际发布证据或升级观察当前发布证据的版本可评论；新未发布版本及仅有旧兼容访问、无发布证据的历史版本 MUST 拒绝评论。允许访问的旧已发布版本可继续讨论，不要求仍为当前版本。

#### Scenario: V2 发布后读取 V1 评论
- **WHEN** 用户打开 V1，而当前发布已为 V2
- **THEN** V1 评论仍留在 V1，V2 不自动获得这些评论或把它们视为新版意见

#### Scenario: 待审或旧兼容无发布证据
- **WHEN** 上传者可预览待审 V2，或旧 V0 只有 indexed 与兼容访问标记
- **THEN** 不因此开放评论，前者继续使用私有审核意见，后者不补造发布记录

### Requirement: 评论读取与写入必须分别验证当前资格

读取 SHALL 要求当前启用主体、有效主部门、完成改密、目标版本 view、密级及未删除未归档。发表和回复另要求空间或文档例外 comment；view、edit、review、manage、所有者及角色名称 MUST NOT 替代 comment。无会话 401，身份门禁 403，不存在或资源不可查看统一 404，可查看但缺 comment 的写请求为 403。

#### Scenario: 可查看但不可发表
- **WHEN** 用户有 view 而没有 comment
- **THEN** 可以读该发布版本的公开评论，发表或回复拒绝；不因此失去原阅读功能

#### Scenario: 只有 comment 或撤权
- **WHEN** 用户有 comment 但无 view，或此前可读而当前升密、搬迁、归档或撤权
- **THEN** 不能取得评论正文、作者、数量或回复入口，旧评论关系不保留访问

### Requirement: 评论正文必须纯文本且有界

创建 SHALL 只接受 body 及可选根评论 parentId，body 去首尾空白后为 1–4000 个合法 Unicode code point，允许换行，拒绝 NUL、非法代理和未知字段；不能静默截断。响应按安全文本展示，不执行 HTML、Markdown 图片或远程链接，首期不支持编辑、附件、富文本、点赞或提及。

#### Scenario: 标记文本与超长输入
- **WHEN** 正文含脚本／图片标记，或超过字符上限
- **THEN** 前者仅作为文本保存与展示，后者 400 且不写入部分正文或事件

### Requirement: 回复必须限制为单层且保持同版本归属

回复 SHALL 仅指向同一文档版本中未删除的根评论；不能回复另一条回复、其他版本或已删除根节点。根评论删除后保留已有合法回复，显示无正文的删除占位，但禁止追加新回复。

#### Scenario: 试图深层或跨版本回复
- **WHEN** parentId 是一条回复、另一版本评论或不存在目标
- **THEN** 不创建回复；有权限的同版本结构冲突为 409，不可见／不存在目标保持安全 404

#### Scenario: 根评论删除后读已有回复
- **WHEN** 根评论作者删除正文，而合法回复仍存在
- **THEN** 根节点不返回原正文，已有回复按当前版本权限独立显示，不级联删除他人文字

### Requirement: 评论创建必须绑定本人并幂等

创建 SHALL 使用服务端身份和时间，X-Request-Id 为 1–128 个非控制 Unicode code point；按操作域、操作者、目标版本、父节点及规范化正文绑定。匹配重试重新鉴权后返回原评论身份，不产生重复正文、回复事件或通知；同标识不同内容为 409，删除后重试不得复活原正文。

#### Scenario: 响应丢失与并发创建
- **WHEN** 同一用户对同版本同内容使用同标识并发重试
- **THEN** 至多一个评论和一条对应创建事实，返回相同身份并标记重放

#### Scenario: 删除后匹配重试
- **WHEN** 原评论已由本人删除，客户端重试原创建
- **THEN** 返回已删除的最小回执，不重新写正文、更新时间或再发回复通知

### Requirement: 删除只能由本人执行且不得保留可读正文

删除 SHALL 仅允许当前有效作者处理自己在指定文档版本下的评论，清除正文并保留最小归属、结构及幂等墓碑，成功及本人重复删除为 204。删除不要求仍有 comment 或文档 view，不能借此读目标内容；他人／不存在统一 404。首期不提供管理员代删、恢复或修改接口。

#### Scenario: 撤权后删除本人评论
- **WHEN** 有效作者已无目标 view，但保留本人评论身份并请求删除
- **THEN** 可清除本人正文，不返回文档、其他评论或删除前内容

#### Scenario: 管理员删除他人评论
- **WHEN** 操作者具备空间 manage 或全局管理资格而不是评论作者
- **THEN** 返回安全 404，不利用管理资格代删

### Requirement: 评论与回复必须分别有界分页

根评论 SHALL 按固定创建位置倒序分页，回复按创建位置正序独立分页；limit 默认 20、范围 1–100，返回 items、hasMore、nextCursor，不嵌入无界回复。游标绑定文档、版本、根节点及查询类型，均先检查当前版本资格；作者和父节点身份必须精确，不返回隐藏总数或用户目录资料。

#### Scenario: 热门评论的大量回复
- **WHEN** 一个根评论具有超过一页回复
- **THEN** 只读取当前有界页，明确提供后续游标，不为主列表加载全部回复

#### Scenario: 复用其他版本游标
- **WHEN** V1 游标被用于 V2 或其他根评论
- **THEN** 返回 400，不混入旧版本数据或延续原访问资格

### Requirement: 评论业务事实必须与通知及报表解耦

根评论创建、回复创建和删除 SHALL 分别保存可去重的无正文事实，与正文／墓碑和回执原子提交。回复收件人为根评论作者，排除自身；通知派生失败不回滚已提交评论。删除正文 MUST 不删除已确认的最小创建事实，历史创建数量不因删除重算成从未发生。

#### Scenario: 回复成功但通知暂不可用
- **WHEN** 回复和源事件已提交而站内通知派生失败
- **THEN** 回复仍成功，提醒可按原事件重试，不再次创建回复

#### Scenario: 源事件保存失败
- **WHEN** 评论正文已写但无法提交对应事实
- **THEN** 整个创建回滚，不返回已确认评论或让报表出现无来源计数

### Requirement: 评论不得成为知识检索或审核公开旁路

评论、回复及其正文 SHALL 不进入全文／向量索引、Embedding、RAG 或会话来源；私有审核意见也不得因批准被转成评论。所有评论响应包括拒绝 MUST no-store，依赖故障为安全 503，不伪装为空讨论；日志、审计和通知不得记录正文、意见、令牌或原始异常。

#### Scenario: 评论写入含待审材料
- **WHEN** 用户显式输入文本作为公开评论
- **THEN** 系统按评论的版本和权限保护，不自动将其视为已发布知识或复制到其他版本；不承诺语义识别用户自行粘贴的敏感内容

#### Scenario: 读取或授权依赖失败
- **WHEN** 版本、权限或评论无法可靠查询
- **THEN** 返回 503，不展示旧缓存、虚假零评论或已删正文
